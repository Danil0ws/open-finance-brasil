1. What Happened and what were you expecting?

From ticket 4445:

While running the "payments-api-qrdn-good-proxy-test" test we noticed that the conformance suite is changing the payment payload.

The tool is excluding the “ibgeTownCode” field from the request (Payment consent request JSON with QRDN embedded). This exclusion causes errors in our components due to the comparison we make between consent data X payment data.

Although the field is not mandatory, we understand that from the moment we create the consent and payment with this field, it should be maintained.
