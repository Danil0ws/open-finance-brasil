Olá, @jessicamanfio 

Investigamos aqui. O endpoint do Mock Bank está saudável: uma chamada direta ao `.well-known/openid-configuration` responde normalmente (HTTP 200).

O 403 que vocês recebem é o CloudFront recusando a requisição na borda porque o header `Host` que chega até ele não corresponde ao domínio do Mock Bank. 

Nossa suspeita é que o proxy (Axway) que encaminha a chamada está enviando no `Host` o domínio de vocês, em vez do domínio de destino.

Reproduzimos os dois cenários — as linhas `>` são o que foi enviado, a linha `<` é a resposta:

Correto (Host = Mock Bank) → 200:

```
> GET /.well-known/openid-configuration HTTP/2
> Host: auth.mockbank.openbankingbrasil.org.br
< HTTP/2 200
```

Errado (Host = outro domínio) → 403, idêntico ao print de vocês:

```
> GET /.well-known/openid-configuration HTTP/2
> Host: api-platfu-of.apps.arodvplatfupi31.arocorpp.bradesco.com.br
< HTTP/2 403   (The request could not be satisfied. Bad request.)
```

Caso queiram refazer o teste (as linhas `>` mostram o Host enviado e a linha `<` o resultado):

```
# Correto — chamada direta ao Mock Bank → deve retornar 200
curl -v https://auth.mockbank.openbankingbrasil.org.br/.well-known/openid-configuration

# Errado — forçando um Host de outro domínio → reproduz o 403
curl -v https://auth.mockbank.openbankingbrasil.org.br/.well-known/openid-configuration \
  -H "Host: api-platfu-of.apps.arodvplatfupi31.arocorpp.bradesco.com.br"
```

Sugestão: no encaminhamento do Axway para o Mock Bank, garantir que o `Host` (e o SNI) sejam `auth.mockbank.openbankingbrasil.org.br`. Vale conferir no log de saída do Axway qual valor de `Host` está indo na chamada, assim vocês confirmam o valor exato do lado de vocês.

Ficamos à disposição caso continuem com a inconsistência. Caso queiram reabrir o ticket, pedimos a evidência de que esse ponto foi corrigido, assim procuraremos em outro local o motivo da falha.
