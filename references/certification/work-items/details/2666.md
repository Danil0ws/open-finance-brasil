## 📝 Descrição

Test **enrollments_api_automatic-payments_automatic-pix-scheduling_1-2_test-module_v2-2** fails when the AS omits refresh_token in the response of the refresh_token grant, even though this is allowed by RFC 6749 §5.1 (OPTIONAL) and §6 (AS MAY issue a new refresh token).

---

**Observed reference (log NNEDRNlbMlFQ2GD)**: POST /token with refresh_token grant returns 200 with scope nrp-consents but no refresh_token field. The test result is PASSED, but Schedule3Days crashes in performFinalCleanup with UnexpectedTypeException: \[...\] refresh_token, but JsonNull was found → final FAILED.

* Evidence is inside the SD ticket: https://servicedesk.openfinancebrasil.org.br/SREdit.jsp?QuickAcess&id=173087

```
{
  "access_token": "eyJhbGciOiJQUzI1NiIsInR5...",
  "expires_in": 600,
  "refresh_expires_in": 0,
  "token_type": "Bearer",
  "id_token": "eyJhbGciOiJSU0EtT0FFUCIsImVu...",
  "not-before-policy": 0,
  "scope": "recurring-payments openid payments nrp-consents enrollment:urn:safrapf:enrl:547d80d228e247a3ae69c28d637a5d42"
}
```

**Comparison (log AikpFDDL3OCeZmK)**: Same test, other AS, the AS echoes the same refresh_token back → PASSED.

* Evidence in the test scheduler: https://results.conftpp.directory.openbankingbrasil.org.br/scheduler/AikpFDDL3OCeZmK/index.html

```
{
  "access_token": "kl5RmSKLInTXWwQJln-p9w3N-...",
  "expires_in": 300,
  "id_token": "eyJhbGciOiJSU0EtT0FFUCIsImVuY...",
  "refresh_token": "277GMwfqCUiYN6oiCX4ZpqIC...",
  "scope": "recurring-payments openid payments nrp-consents enrollment:urn:uber:3337646e-2d19-493d-8dc3-e055a0c022ec",
  "token_type": "Bearer"
}
```

---

**Expected behavior**

Not echoing the refresh_token isn't typical for OPF ASs. The test should be improved to preserve the previously stored refresh_token when the field is omitted from subsequent responses.
