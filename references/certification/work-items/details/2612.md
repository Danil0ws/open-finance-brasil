## 📝 Descrição

Hi, we have been facing some erros trying to run the test `payments_api_consent-purpose-validation-unhappy-path-invalid-combination_test-module_v5` for the payments API v5 certification. The test request body sends an invalid combination (purpose: IMMEDIATE + schedule.single with a future date), which is the intended invalid scenario. However, the request body is also missing the required field `data.payment.schedule.additionalInformation`, which is mandatory for schedule objects per the Open Finance Brazil Payments API v5 specification.

The server correctly performs field-level validation before business-rule validation, and therefore returns `PARAMETRO_NAO_INFORMADO` (missing required field) before ever evaluating the `PROPOSITO_INVALIDO` condition.

**Relevant decoded request payload (abbreviated):**

```
{
    "data": {
      "payment": {
        "purpose": "IMMEDIATE",
        "schedule": {
          "single": {                                                                                                            
            "date": "2026-04-09"
          }                                                                                                                      
          // additionalInformation is absent here                                                                             
        }
      }
    }
  }
```

The test request body should include a valid `additionalInformation` value inside `data.payment.schedule`, so that the only invalid aspect of the request is the purpose + schedule combination. This ensures the server reaches the business-rule validation and can return `PROPOSITO_INVALIDO` as expected.

Alternatively, if the intent is to validate that `PROPOSITO_INVALIDO` takes precedence over field-level errors, the specification should explicitly define the validation ordering for this scenario.

References

- Open Finance Brazil Payments API v5 spec — POST /payments/v5/consents
- Error codes: PROPOSITO_INVALIDO, PARAMETRO_NAO_INFORMADO

#### Current Behavior:

---

The server returns PARAMETRO_NAO_INFORMADO instead of PROPOSITO_INVALIDO:

```
{
  "code": "PARAMETRO_NAO_INFORMADO",
  "title": "Parâmetro não informado.",
  "detail": "Parâmetro .data.payment.schedule.additionalInformation obrigatório não informado."
}
```

#### Expected Behavior:

---

`{ "code": "PROPOSITO_INVALIDO" }`
