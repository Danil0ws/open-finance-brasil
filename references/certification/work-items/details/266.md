## 📝 Descrição

## 1. Current Issue

In line with the current objective of the Initial Structure of doing automated DCR tests against all organisations in production Raidiam has executed a test where it uses a Valid tls credential issued from the Sandbox Directory and expects the server to not authorize the DCR.

When doing this execution we have noticed that despite all orgs not accepting the DCR Request, the organisations also do not have a consistent error return:

Down below we highlight a few of those:

The institution Responds with 400 -

![image](/uploads/5da728984e4a031d52f81a8de60500e7/image.png)

The institution Responds with 401 -

![image](/uploads/00a70cb02d3754362fd0b7cd52e4c5bb/image.png)

The institution responds with a handshake failure - 

![image](/uploads/862889817eb81deded69182f7c2cff8c/image.png)

Raidiam's opinion here is that we follow with the handshake failure as that would be a TLS failure given the bad certificate, which should be handled at that layer. It shouldn't thus be capable of reaching the point of returning an HTTP Response.

It's worth mentioning the large majority of banks implemented either a 400 or a 401 in this case.

## 2. Decision

To move forward here we would require the groups to decide on one of the following test scenarios

A) Test will only be a failure if server returns a 201. All failure on creating the DCR will be accepted

B) Test will expect a failure on the tls_handshake

C) Test will expect an error code. Also required to decide between 400 and 401.


We will implement the defined scenario once done
