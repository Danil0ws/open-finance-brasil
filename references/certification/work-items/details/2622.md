## 📝 Descrição

We are facing an error when triggering fido-registration on the Mock Bank. Based on our analysis, the issue seems to occur because the Mock Bank is not recognizing the clientDataJSON.origin field as a valid origin. However, this origin is correctly registered in the directory and is present in the software_origin_uris attribute of the software statement. Could you please help us investigate this scenario?

Hi @benisson , looking at our logs we can see two things:

1. In the `/fido-registration-options` request, you sent `platform: "CROSS_PLATFORM"` with `rp: "apps.bb.com.br"`.
2. Then in `/fido-registration` you sent `clientDataJSON.origin: "android:apk-key-hash:..."`.

The validation enforced by Mock Bank (per Enrollments API v2.2.0) checks that `clientDataJSON.origin` is one of the values registered in your SSA's `software_origin_uris`, **and** that it is consistent with the `platform` declared in the registration-options request. Since you declared `CROSS_PLATFORM` (typically a roaming/web context) but sent an Android app origin, the values are inconsistent.

For an Android app journey, please send `platform: "ANDROID"` in the registration-options request — then `android:apk-key-hash:...` will be the expected origin format (and accepted, provided it is registered in `software_origin_uris`, as confirmed in the resolution of #2097).

If you intend to keep `CROSS_PLATFORM`, the origin should be the relying party's `https://` URL (e.g. `https://apps.bb.com.br`), and that value also needs to be registered in `software_origin_uris`.
