## 📝 Descrição

As per the OBBR specs it says that apart from 422 error response, the response type should be application/json.
However the conformance suite while testing those scenarios sends `accept`  header as application/jwt.

The Accept header is for an agent to specify content it would like. Since, outside of functional tests, agents will always exclusively want an application/jwt response, that is what is always specified for /payments.

I refer you to the passage in [rfc 2616](https://datatracker.ietf.org/doc/html/rfc2616):

> If an Accept header field is present, and if the server cannot send a response which is acceptable according to the combined Accept field value, then the server SHOULD send a 406 (not acceptable) response.

I also refer you to the definition of SHOULD in [rfc2119](https://datatracker.ietf.org/doc/html/rfc2119). It is recommended that this happens. But it is not mandatory.

We do not deal in multiple accept headers, because this would imply that a response of application/json may be appropriate for a non-errored response in /payments. Which is not the case.

@georgemc The problem with this is client is expecting a particular content-type and because the code is returning another the framework will give error for `HttpMediaTypeNotAcceptableException ` . You can check the below link for more reference:

https://www.baeldung.com/spring-httpmediatypenotacceptable

The accept header mean that the client is only expecting that particular response type so unless server has that it will not be able to send it.

Even though the tests "know" that an error may come back as application/json, the expectation by consumers for an API is that application/jwt is always going to be returned. Setting the accept header to this is always correct.
