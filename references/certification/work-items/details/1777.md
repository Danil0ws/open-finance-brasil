#### Current Behavior:

---

During execution of FVP tests:

* fvp_automatic-payments_api_sweeping-accounts-core_test-module_v1

During request to POST Pix recurring-payments endpoint, the following risk signals are sent as TRUE:

```
"isCallInProgress": true,
"isDevModeEnabled": true,
"isMockGPS": true,
"isEmulated": true,
"isMonkeyRunner": true,
"isCharging": true,
"antennaInformation": "string",
"isUsbConnected": true,
```

And expecting response 201 CREATED from Authorization Server.

As this fields are optional, what we need evaluation from WG is:

* Should this risk signals be sent?
* In case they should, should them be sent as false?

Hi All! Following this discussions, we at Raidiam recommend two actions on theses test:

Since risk evaluation is managed by each instituion, we cannot defined which risk signal should or not be sent so that a payment is successful.  In that sense, we understand there are two actions:

1. **Short Term:**  We should not send clear "harmfull" risk signals, that could indicate that a payments is no legitimate. On this case, we recommend not sending the following risk signals, as they are optional: 

```
"isCallInProgress": true,
"isDevModeEnabled": true,
"isMockGPS": true,
"isEmulated": true,
"isMonkeyRunner": true
```

2. **Long Term:** Whenever a Test is moved to the FVP, there should be considered a suscesull test if a payment is fails for risk assesment, in APIs like Enrollments and Automatic Payments, where there is risk signals involved. god to bear in mind that this can affect some test behaviors, blocking some production tests.
