Hello @dianzuo.chen. Thanks for the report. 

The static QR Code carries `***` in tag 62-05. Per the BCB [Manual de Padrões para Iniciação do Pix (v2.9.0)](https://www.bcb.gov.br/content/estabilidadefinanceira/pix/Regulamento_Pix/II_ManualdePadroesparaIniciacaodoPix.pdf), section 2.6.2, `***` is the standard marker for **absence** of TxId, not a populated value.

The OFB [Payments API v5.0.0-rc.1](https://gitlab.com/raidiam-conformance/open-finance/certification/-/blob/master/src/main/resources/swagger/openBanking/payments/payments-5.0.0-rc.1.yml#L646) also restricts TxId to `[a-zA-Z0-9]` (max 25 chars), so `***` cannot be a valid TxId. In this scenario the spec explicitly states `transactionIdentification` **must not** be sent.

Please adjust your implementation to accept the request without `transactionIdentification` when the static QR Code carries `***` in tag 62-05.

Best regards
