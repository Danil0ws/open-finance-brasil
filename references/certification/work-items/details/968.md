Hi Bruno! Thanks for the ticket!

The short answer here is that the ispb should not be different from the for the debtor account field. The ispb should match exactly the one for the debtor account in use, which is the ASPSP. Anyways, the user could be requested to change this information when he is redirected.

In the specific case of this test, the Conformance Suite is trying to send the same information for both the debtor and creditor account fields, waiting for the response 422 - CONTAS_ORIGEM_DESTINO_IGUAIS. This test is being changed at https://gitlab.com/raidiam-conformance/open-finance/certification/-/issues/818 to support this error at both the POST Consents Endpoint ou GET Consents, after the redirect. In that sense, the consent does not need to be created, and this error can be returned at the consent creation at the POST Consents call.

We are happy to help with any additional needs!
