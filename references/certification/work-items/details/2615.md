## 📝 Descrição

This request was made in SD **180833.**

We would like to request your assessment regarding a potential misalignment between the FVP behavior and the current specification related to the **reserved balances** endpoint in the Accounts API.

In the scenario executed by the test **accounts_api_reserved_balances_permissions_v2**, the CS performs a call to the reserved balances endpoint **without the `ACCOUNTS_BALANCES_READ` permission**, expecting a **403 (Forbidden)** response.

However, according to the official documentation:\
https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/193658890/Orienta+es+-+DC+Contas#Orienta%C3%A7%C3%B5es-sobre-Reservas-de-saldo

> “For institutions that do not offer the reserved balance product, the API must return 404 (Not Found).”

In the analyzed case, the participant returned **404**, indicating that the reserved balance product is not available, which appears to be compliant with the specification.

This leads to a potential conflict:

* The FVP assumes the endpoint exists and validates permissions (expecting 403)
* The specification states that, if the product does not exist, the correct response should be 404

From a conceptual standpoint, permission validation (403) presumes that the resource exists. If the product is not available, a 404 response should take precedence.
