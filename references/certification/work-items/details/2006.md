![image.png](/uploads/24133423dbbd9e04b878596810c879de/image.png)

By convention dates are send on request and response payload in UTC Timezone.

As test was executed at 20/01/2025 22:23:31 GMT-0300 (Brasilia Standard Time), that means that dates send during test module execution will be for the date  21/01/2025 01:23:31 UTC.

This is exactly what is done by conformance suit as can be seen below on steps:

> Call the POST recurring-consents endpoint with automatic pix fields, with referenceStartDateTime as D+1, interval as SEMANAL, a fixed Amount of 0.50 BRL, and sending firstPayment information with amount as 1 BRL, date as D+0

Conformance Suit sent on Post recurring-consents request:

```
"referenceStartDateTime": "2025-01-22T01:23:32Z",
...
        "firstPayment": {
          ...
          "date": "2025-01-21",
          ...
```

And later in step:

> Call the POST recurring-payments endpoint with the information defined firstPayment payload

When Conformance suit Called Post recurring-payments endpoint sending in the  payload:

```
 "date": "2025-01-21",
```

Therefore conformance suit is operating as expected.

The failure during test module execution was caused because the payment at hand moved to status "**SCHD"** instead of the expected "**ACSC"**, that can be due to the Timezone being used to manage payment status.

Please make sure that dates are being treated in the correct timezone so that test runs successfully when executed after 21:00 GMT-03.

Happy to help!
