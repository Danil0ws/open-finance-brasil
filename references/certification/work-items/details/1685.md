## 📝 Descrição

In test automatic-payments_api_negative-consents_test-module_v1, regarding the POST Recurring Consent, when I send the expiration date before start date, the behavior expeted by the test plan is 422 - PARAMETRO_INVALIDO.

But according to the specification shouldn't be 422 - DETALHE_PAGAMENTO_INVALIDO?

In OAS what I see is: Detalhes do pagamento: Valida se determinado parâmetro informado obedece às regras de negócio (DETALHE_PAGAMENTO_INVALIDO). I think this scenario should be a case where the business rules is not met.

For the error 422 - PARAMETRO_INVALIDO, the document points that should be used for: Formatação de parâmetros: Valida se parâmetros informados obedecem a formatação especificada (PARAMETRO_INVALIDO). In this scenario, I'm sending the date in correct format, but the business rule is not met (start date should come before the the expiration date).

Could you confirm which should be the correct error for this scenario?

Thank you in advance!
