Thanks for the ticket!

We understand your concern; however, the point you raised is exactly what this test is designed to validate: that a consent can only be created if the creditor fields contain valid data. Specifically, if a POST recurring-consents attempt is made with either two PJ accounts or one PF account as the creditor, the implementation should return a 422 error (`DETALHE_PAGAMENTO_INVALIDO`). The values sent in this test module are intentionally incorrect to validate this behavior.

Therefore, there is no corrections on the CS side. To a successful execution, the implementation needs to be adapted so that it aligns with the test summary.
