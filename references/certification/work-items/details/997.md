## 1. What happened and what were you expecting?

Phase 2v2 operational limits test behaviour/summary step in bold below should be changed from:

> * With the authorized consent id (1), refresh Access Token using the Refresh Token• With the authorized consent id (1), call the GET Accounts Transactions-Current API with the saved Resource ID (R_1) Once, send query parameters fromBookingDate as D-6 and toBookingDate as Today, **require 26 records returned** - Expect a 200 response - call the GET Accounts Transactions-Current API again with page_size=25 and page=1 to force next link. Fetch the links.next URI 

To:

> * With the authorized consent id (1), refresh Access Token using the Refresh Token
> * With the authorized consent id (1), call the GET Accounts Transactions-Current API with the saved Resource ID (R_1) Once, send query parameters fromBookingDate as D-6 and toBookingDate as Today, **require a next link to be** returned - Expect a 200 response - call the GET Accounts Transactions-Current API again with page_size=25 and page=1 to force next link. Fetch the links.next URI 

The change should be applied to all similar steps at Phase 2v2 operational limits tests.
