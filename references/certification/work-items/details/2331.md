## 📝 Descrição

## Expected behavior
- The value sent for paymentReference by the POST /recurring-payments should be **R/D+1/P1M** according to the referenceStartDate set in the consent. As the definitions for the field paymentReference says on the pattern R/<start>/<duration>, the <start> should be the start of it's cicle. And the referenceStartDate says it represents the start of charge cicle.

## Observed behavior
- The description on test says the referenceStartDate is **D+1** and the paymentReference is **R/D+3/P1M**.

**Criado em**: 29/09/2025, 15:14:19

@NanerX Thanks for pointing this out. According to the spec, paymentReference must point to the cycle start date, not to the payment execution date. In this test the consent was created with referenceStartDate = D+1 and interval P1M. Therefore, the first cycle’s reference should be R/\<D+1\>/P1M, even if the first debit is executed on D+3 due to scheduling rules.

We'll work on fixing this.
