Basically the task here, so we don't get any more issues with this is to confirm and update the following unhappy test modules:

payments-api-qres-wrong-amount-proxy-test,
payments-api-qres-mismatched-proxy-test,
payments-api-qrdn-with-qres-code-test


Can expect a finished state on three possible steps, validating the following error codes:

if you fail on the POST Consents you should send DETALHE_PGTO_INVALIDO on the 422 -> Success

If you fail on the POST Payments you should send COBRANCA_INVALIDA on the 422 -> Success

If you create payment but you will have to Reject it in any state on the polling, thus you must send RJCT with the reason being ELEMENT_CONTENT_FORMALLY_INCORRECT as a response of the GET Payments. It will also allow intermediary states PDNG and PART.
