Hi Rodrigo! Thanks for the ticket!

As mentioned at the swagger, the 422 message is reserved for consents that are expired or rejected. In the case of an Awaiting_authorization consent, there is no authorization_code, in that sense, we have to access the endpoint using a client credentials token.

As per swagger, an invalid token should return a 401 message, as mentioned below:

![image.png](/uploads/de3027a7db5104c87c127e03d519e412/image.png)

In that sense, there is no correction in the conformance suite. We are happy to help with any additional needs!
