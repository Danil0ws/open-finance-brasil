Hi @jaquelineduque 

This situation is happening because in the step:

• Call the GET recurring-payments {recurringPaymentId}
• Expect 200 - Validate Response and ensure status is SCHD

Your API responded with:

`    "status": "RCVD",`

Instead of the expected:

`"status": "SCHD"`

The conformance test engine only triggers the next step — specifically:

-  Call the PATCH recurring-payments {recurringPaymentId} endpoint

— if the GET response returns the expected status SCHD.

Since your response returned RCVD, the engine did not proceed with the PATCH, and therefore the test failed, as the cancellation logic could not be validated.
