## 📝 Descrição

1. What Happened and what were you expecting?

Now that the QR Code tests have been merged with the payments API tests, the certification engine should not send the QR Code for the /payment endpoint in tests where QR Codes are not required. 

By sending the QR Code for tests not involving this functionality, the consent differs from the payment and the backend will reject it.

Or, we'd require an additional JSON payload configuration field to include a payload with a QR Code and another payload for the non-QR code tests.

1. Test Id

Example of failed test where QR Code was incorrectly sent: https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=9wiZeSAUpqiB4JC&public=true

Example of passing test where QR Code was omitted from config JSON:
https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=AK8G4Jqcx9YLuBe&public=true

Note that these are mutually exclusive. When the QR Code is configured, only the QR Code tests pass and the payment api tests fail.
