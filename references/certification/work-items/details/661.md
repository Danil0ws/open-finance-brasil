Erick, how are you? 

The Informa [#352](https://mailchi.mp/df89691e6c7e/open-banking-informa-9330628?e=9b9743fbe2) have this guidance for the PATCH endpoint: 

"**Serão aceitos client credentials e authorization code para não haver uma quebra abrupta**.
Testes serão criados para o fluxo via client credentials para certificar as detentoras de conta que estão aderentes à especificação e será realizado um informa para aviso as iniciadoras com as orientações necessárias" 

Until yet, we didn't have other "Informa" changing PATCH situation. 

All related "informas" defined Informa #352 as reference and standard. 

In our analysis, this is a breaking change in production when PISP will not be allowed to use the token they already have the ownership of. The conformance test expects an error when refresh_token is used and that will break PISP's implementations that haven't been ajusted to changes required.

ASPSP should keep the behavior of generating both types of tokens unitl all PISP providers have implemented the Client Credentials flow.

That being said, until this test is required there's no need for you to implement this, however, this will be an expected behavior for the future.
