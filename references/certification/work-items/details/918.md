Thanks for the ticket! 

The test failed because it expects the POST Consents to be successful with status 201 and the authorization server incorrectly responded with a 422 status. It follows below the summary step in which the test is failing:

> Calls POST Consents Endpoint with invalid creditor account, using DICT as the localInstrument
> * Expects 201- Validate Response

As you mentioned, the test indeed expects either a 201 or 422 `DETALHE_PAGAMENTO_INVALIDO` or `PAGAMENTO_RECUSADO_DETENTORA` but at POST Payments, not POST Consents.

Therefore, there is no corrections on the CS side. To a successful execution, the implementation needs to be adapted so that it is conformant to the expected behaviour stated at the test summary.
