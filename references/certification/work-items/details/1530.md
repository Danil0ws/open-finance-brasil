After better evaluating, it seems that the problem is with the server response and not the test.

During the step "Call pix/payments endpoint", the server responded `POST /pix/recurring-payments` with:
![image](/uploads/41dfc52060045eb3266cfa5b83501ef0/image.png)

Whereas during "GET pix/payments endpoint to check if all payments are there", the server responded `GET /pix/recurring-payments?recurringConsentId=urn:VOIT:pix-4f0de304-6af0-4941-992b-505c8f2ff05f` with:
![image](/uploads/e130a9f91bf47298a4828a306911ea18/image.png)

The same recurring payment ID: 530fa759-7a36-4d6d-a269-3d5c60f0e30c is associated with two different end to end IDs which was detected by the test.

Therefore, after you adjust this you shouldn't have any further problems with the test.
