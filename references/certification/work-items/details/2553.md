Hi,

After analysing the execution of the **payments_api_consumed-consent_test-module_v5** scenario, we identified why the expected error (422 – CONSENTIMENTO_INVALIDO) was not returned in the step:

• Calls the POST Payments with the EndtoEndId field\
• Expects 422 CONSENTIMENTO_INVALIDO - Validate error message

The API returned **201 with a self link**, meaning a new payment was successfully created, instead of rejecting the request.

The `POST /payments/v5/pix/payments` call that should have failed also succeeded and returned **201 with a self link**, which triggered the “Validate Self link” step instead of the expected validation of error 422.

Please adjust the token flow in this scenario and re-run the test.

Let us know if you need any additional details.
