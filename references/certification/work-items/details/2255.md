## 📝 Descrição

Dear team, good evening.

During the execution of the test credit-portability_api_invalid-consent_test-module_v1, we encountered a failure in the step:

Call the GET Loans Contracts endpoint – Expect 200 – Validate the response and retrieve all contractIds with productSubType as CREDITO_PESSOAL_SEM_CONSIGNACAO

The GET request to the Loans Contracts endpoint returns a successful HTTP 200 response and includes multiple contracts associated with the customer. Among these, four contracts explicitly contain the expected productSubType value: CREDITO_PESSOAL_SEM_CONSIGNACAO.

However, despite the presence of these valid entries, the test fails with the following message:

ExtractContractIdByProductSubType – No contract found with matching productSubType

This indicates that the test logic is not correctly identifying or extracting the relevant contract IDs from the response payload, even though the data is present and matches the expected criteria.

We suspect a possible issue in the implementation of the extraction logic or in the filtering mechanism applied to the productSubType field. It may be related to:

- Case sensitivity in the string comparison
- Unexpected whitespaces or formatting in the productSubType values
- Incorrect parsing or iteration over the response array
- Misalignment between the test configuration and the actual API response schema

We kindly request a review and correction of the test logic to ensure it properly identifies and processes contracts with the specified productSubType, as per the test's intended behavior.

Please let us know if further logs or response samples are needed.

Thank you.
