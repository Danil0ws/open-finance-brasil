## 📝 Descrição

We are having difficulties executing the test scenarios:
- **automatic-payments_api_sweeping-accounts-core_test-module_v1**
- **automatic-payments_api_sweeping-accounts-limits_test-module_v1**

The test plan configuration has CNPJ 98380199000125 configured in the "businessEntityIdentification" field, this was necessary to fulfill the requirements of test module:
**automatic-payments_api_sweeping-accounts-root-cnpj_test-module_v1**

It turns out that with this test configuration, the other two modules mentioned above,  present an error in their execution because the same CNPJ 98380199000125 ends up being used as "proxy" when creating the payment.
For the **automatic-payments_api_sweeping-accounts-root-cnpj_test-module_v1**, this is not a problem as validation of final payment status has been removed from the test requirements (issue https://gitlab.com/raidiam-conformance/open-finance/certification/-/issues/1424). However, for the other two modules mentioned, the final payment status validation still exists, and therefore the tests fail to be executed.

In another open issue (https://gitlab.com/raidiam-conformance/open-finance/certification/-/issues/1509), there was guidance to use the fields "brazilCpf" and "brazilCnpj" to indicate a different pix key (document), however in the tests we carried out, even when another document was indicated in the "brazilCpf" and "brazilCnpj" field, the test execution still uses the "businessEntityIdentification" field to compose the businessEntity and creditor.
Could you please validate this behavior, and advise us on the required adjustments to the test plan so that the 3 modules described can be executed with the same configuration?

Note: it is worth noting that the fields "brazilCpf" and "brazilCnpj" do not appear for editing in "form" mode, we added them in "JSON" editing mode.
