Hi,

Thanks for opening the ticket! The test failed because, when conformance suit executed the following step:

> **Fetch Credit Card Transactions Current next link using resource_id_1**

It called:

> GET /accounts/{creditCardAccoutId}/transactions-current?fromTransactionDate=2024-02-21&toTransactionDate=2024-02-27&page-size=1

And received the following links on the response_body:

> “links":{ "self":"https://api-bmg-m.sensedia.com/open-banking/credit-cards-accounts/v2/accounts/39fa9ec190eee7b6f4dff1100d6343e10918d044c75eac8f9e9a2596173f80c9/transactions-current?page=1&page-size=1&fromTransactionDate=2024-02-21&toTransactionDate=2024-02-27",
>
> "first":"https://api-bmg-m.sensedia.com/open-banking/credit-cards-accounts/v2/accounts/39fa9ec190eee7b6f4dff1100d6343e10918d044c75eac8f9e9a2596173f80c9/transactions-current?page=1&page-size=1&fromTransactionDate=2024-02-21&toTransactionDate=2024-02-27", 
>
> "next":"https://api-bmg-m.sensedia.com/open-banking/credit-cards-accounts/v2/accounts/39fa9ec190eee7b6f4dff1100d6343e10918d044c75eac8f9e9a2596173f80c9/transactions-current?page=11&page-size=1&fromTransactionDate=2024-02-21&toTransactionDate=2024-02-27"}

Afterwards the conformance suit executes the following step:

> \[2\] Fetch Credit Card Transactions Current next link using resource_id_1

Which uses the next link provided in the previous call which contains page=11 in it, as the request_uri.

Therefore, in this regard, conformance suit is operating as expected, to make sure the test module can be executed successfully, please ensure that the next link of correctly provided in the response_body for GET /accounts/{creditCardAccoutId}/transactions-current.
