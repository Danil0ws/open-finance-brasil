@ptheys 
A request without any Accept header field implies that the user agent
   will accept any media type in response.  If the header field is
   present in a request and none of the available representations for
   the response have a media type that is listed as acceptable, the
   origin server can either honor the header field by sending a 406 (Not
   Acceptable) response or disregard the header field by treating the
   response as if it is not subject to content negotiation.

In this case, because the Bank can respond with either a JWT or a JSON (Errors are JSON) the majority of participants have 'correctly' elected to ignore the Accept header. However as @jools_houston_raidiam has said, we have seen cases where banks have replied with a content-type of JSON but the response body was a JWT. What we will do is change this request so it is a JWT but add an explicit test with a WARNING if a Bank chooses to 406 the request to try and improve interoperability. If there was only one possible response type for this message then yes we woudld expect banks to 406 this.
