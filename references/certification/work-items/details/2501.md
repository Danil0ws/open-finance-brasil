Hi,

Thank you for your analysis.

The documentation for _Webhook Versioning v1.3.0-rc.2_ defines the **logical structure of the webhook notification endpoint**, not the format of the **base webhook URI** that must be registered in the Software Statement or during Dynamic Client Registration.

For the enrollments webhook tests, the expected behavior is:

* The institution registers **only the base webhook URI**, for example:

  https://web.conformance.directory.openbankingbrasil.org.br/test-mtls/a/{alias}
* The Conformance Tool then **dynamically composes the final webhook notification endpoint** by appending the API path, such as:

  /open-banking/enrollments/v2/enrollments/{enrollmentId}

![image.png](/uploads/3cfc7fda8b6bf75a4a5d2c1f61a6e647/image.png){width=900 height=47}

This behavior is explicitly described in the test summaries for both:

* `enrollments_api_webhook-data-changed_test-module_v2-2`, and
* `enrollments_api_webhook-revoked_test-module_v2-2`.

Therefore, the absence of `/open-banking/webhook` in the registered base URI is expected and correct. The webhook path is constructed by the test according to the API and event being validated.

Both test modules follow the same logic and are consistent with the specification.

Please let us know if you need further clarification.
