Hi @samuel.andrade2 

We have analyzed the situation and we confirmed that the test failure is not due to incorrect behavior of the conformance suit. Instead, it is caused by an inconsistency in your API's pagination implementation, specifically concerning the `links.next` field.

The objective of the `bank-fixed-incomes_api_resources_test-module_v1` test is to ensure that the resource IDs available in the Resources API are the same as those returned by your `Investments` API. To achieve this, the conformance engine:

1. Obtains the available resource IDs from the Resources API.
2. Calls your `Investments` API to retrieve the list of investments.
3. Compares these IDs for consistency.

A critical point here is that the CS needs to **traverse all pages** of your `Investments` API to collect all IDs for a complete comparison. It does this by following the pagination links provided in your API's response, especially the `next` link.

Your log shows that, in your response for `open-banking/bank-fixed-incomes/v1/investments?page-size=1000`, the `links` object is structured as follows:

`"links": { "self": "``https://api.dev.mercantil.finansystech.com.br/open-banking/bank-fixed-incomes/v1/investments``", "first": "``https://api.dev.mercantil.finansystech.com.br/open-banking/bank-fixed-incomes/v1/investments``", "prev": "``https://api.dev.mercantil.finansystech.com.br/open-banking/bank-fixed-incomes/v1/investments``", "next": "``https://api.dev.mercantil.finansystech.com.br/open-banking/bank-fixed-incomes/v1/investments``", "last": "``https://api.dev.mercantil.finansystech.com.br/open-banking/bank-fixed-incomes/v1/investments``" }`

The issue lies in the `next` link. As per the Open Finance Brasil Pagination specification (https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17377470/Pagina+o), the `next` link **must** point to the **next page of results**. In your current implementation, the `next` link is returning the URL of the **first page** (`/investments` without the `page` parameter).

This behavior causes the CS to enter an **infinite loop**, repeatedly requesting the same page, as the `next` link never directs it to the subsequent page. After numerous calls to the same URL, the test eventually times out and fails. The "expected 202" status mentioned in your failure log ("obtained status 200 expected status "ACCEPTED"") is a secondary effect of this timeout, as the test is waiting for the pagination polling to complete before validating the final status.

Please check the response from a mock bank:

`"links": { "self": "``https://matls-api.mockbank.poc.raidiam.io/open-banking/bank-fixed-incomes/v1/investments?page-size=25&page=1``", "first": "``https://matls-api.mockbank.poc.raidiam.io/open-banking/bank-fixed-incomes/v1/investments?page-size=25&page=1``", `

`"next": "``https://matls-api.mockbank.poc.raidiam.io/open-banking/bank-fixed-incomes/v1/investments?page-size=25&page=2``", // <--- Correct: Points to the next page `

`"last": "``https://matls-api.mockbank.poc.raidiam.io/open-banking/bank-fixed-incomes/v1/investments?page-size=25&page=3``" }`

This is a successful example: https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=kqWKOM4TzkpCNmu&public=true
