## 📝 Descrição

Following the implementation in [PDC-356](https://openfinancebrasil.atlassian.net/projects/OFB/versions/10328/tab/release-report-all-issues), the error messages `ERRO_NAO_MAPEADO` and `DATA_EXPIRACAO_INVALIDA` were added to the Consent API. However, there was no mention of the two error messages that are generally present in the Service APIs: `PARAMETRO_NAO_INFORMADO` and `PARAMETRO_INVALIDO`, which are usually returned with a 422 status code when a mandatory parameter is missing or poorly formatted.

We would like to confirm with the Working Group (WG) **what should be expected at the POST Consents endpoint when a mandatory field is not sent or is incorrectly formatted**. Should a 422 error with `ERRO_NAO_MAPEADO` be returned in this case? Or is another status code expected in this situation?
