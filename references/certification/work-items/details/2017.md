Hello,

The rule behind the expected DETALHE_PAGAMENTO_INVALIDO response is based on the validation of the creditorAccount details between the recurring consent and the payment request.

The test ensures that a payment cannot be executed if the **creditorAccount** in the payment request does not match the one defined in the **consent**.

According to the test steps:

- The POST recurring-consents request includes a random creditorAccount number.
- The consent gets authorized with that creditorAccount.
- The POST recurring-payments request is then sent, but this time using the creditorAccount number as defined in the consent.

The expectation is that the payment should fail with 422 DETALHE_PAGAMENTO_INVALIDO if the payment request does not match the authorized consent details.
If a random account number is used in the consent and the same is used in the payment, it does not necessarily belong to the correct creditor.
