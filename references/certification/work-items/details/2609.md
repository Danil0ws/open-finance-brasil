#### Current Behavior:

---

During the execution of some FVP tests — for example, **fvp_dcr_automatic-payments_api_automatic-pix-invalid-parameters_open_test-module_v2-2** — we identified an unexpected behavior related to the **/reg** endpoint.

We observed that:

* The test logs show only **one call** to the **/reg** endpoint;
* However, our application receives **two distinct requests** for this same endpoint;
* The first request **does not appear in the test logs** and uses a **different JWT** from the second one;
* This rules out the possibility of duplication caused by our infrastructure.

This behavior is causing the test to fail with the following error:

> **software_statement_already_in_use**

This happens because the second request attempts to reuse a software statement that was already consumed in the first call.

Based on these findings, it appears that the **FVP test engine is triggering two calls to the /reg endpoint**, while only one of them is recorded in the available logs.

**Criado em**: 10/04/2026, 04:05:46

Hi @rogeriorocha083, thanks for reporting this.

We identified the root cause. The `dcr-fvp_test-plan` is a Manual FVP test plan that mirrors the Automatic FVP. Unlike other Manual FVP plans, the test modules in this plan already handle their own DCR lifecycle internally: they register, test, and delete the client on their own.

However, 6 `fvp_dcr_automatic-payments_*_v2-2` modules were added to this plan without being excluded from the Manual FVP pre-registration step. This results in two POST `/reg` requests for the same software statement: one from the pre-registration and one from the test module itself. Authorization servers that correctly reject duplicate registrations return 400 `software_statement_already_in_use` on the second call, causing the test to fail.

A fix is in progress. We will update this issue once it is deployed.
