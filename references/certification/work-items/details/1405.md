Hi,

Thanks for opening the ticket!

In this case the test module failed because, when the conformance suit called the POST pix/payments endpoint, It received a response body in which all of the 5 payments created had the same paymentId (FDA0E1E8-679B-4D8C-A40C-6B40CC944108) and endToEndId (E44471172202402231500ycNgsirxix2). Therefore when PATCH payments endpoint is called sending the the first paymentId, this paymentId is equal to all of the other ones. The same behavior happens when GET payments endpoint for the 4 payments left expecting SCHD. As the conformance suit is working as expecting regarding this matter, please make sure to check and ensure that the response_body to the POST pix/payments is correct.

Feel free to open new issues if you have any other doubts,

Happy to help!
