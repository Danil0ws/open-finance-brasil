## 📝 Descrição

## Summary

  Test module \`accounts_api_core_test-module_v2-5\` fails on the assertion

  \``assertField1isRequiredWhenField2IsPresent(data, "partieCompeCode", "partieNumber")`\`

  even when the counterparty institution has no COMPE (número-código), which the

  Open Finance Brasil v2.5 spec explicitly allows.

  The validator applies the rule unconditionally to every transaction (including

  Pix), but the spec makes partieCompeCode conditionally required — only when the

  institution actually has a número-código.

###   Spec text (Open Finance Brasil v2.5 — accounts API)

  ====================================================

>   partieCompeCode:
>
>     type: string
>
>     maxLength: 3
>
>     pattern: ^\\d{3}$
>
>     example: 001
>
>   Restriction (from the spec):
>
>   "É de preenchimento obrigatório quando a instituição possuir o número-código."
>
>   (Mandatory only when the institution has a número-código.)

###   Offending code

  ==============

`  protected void assertTypeAndPartieCnpjCpfConstraint(JsonObject data) {`

`      ...`

`      assertField1isRequiredWhenField2IsPresent(data, "codeISPB", "partieCnpjCpf");`

`      assertField1isRequiredWhenField2IsPresent(data, "partieCompeCode", "partieNumber");`

`  }`

###   Why this is incorrect

  =====================

  **1. Pix infrastructure uses ISPB exclusively. Counterparty data for Pix**

     **transactions carries ISPB but not COMPE — they are identifiers for different**

     **settlement systems (SPI/Pix vs. STR).**

  **2. Per BACEN's STR participant list     (****https://www.bcb.gov.br/estabilidadefinanceira/relacao_instituicoes_funcionamento****,**

     **ParticipantesSTR.pdf), there are legitimate STR participants without a**

     **número-código — Infraestruturas do Mercado Financeiro, Secretaria do Tesouro**

     **Nacional, and several payment institutions (IPs).**

  **3. For these participants, the spec explicitly allows partieCompeCode to be**

     **absent. The current validator rejects responses that comply with the spec.**

##   Expected behaviour

  ==================

  The validator should require **partieCompeCode** only when the counterparty

  institution is known to have a número-código (e.g., by cross-referencing the

  codeISPB against the BACEN participants list), or the cross-field assertion

  should be removed entirely so the OAS schema can enforce only the field's own

  format constraints.

  **Impact**

  ======

  \`accounts_api_core_test-module_v2-5\` fails with FAILURE for any conformant

  implementation that:

  - emits partieNumber for the counterparty account, and

  - omits partieCompeCode because the institution does not have one.

  Failure message:

  **"Field 'partieCompeCode' is required when field 'partieNumber' is present"**
