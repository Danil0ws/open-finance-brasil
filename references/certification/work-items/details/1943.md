## 📝 Descrição

When running the automatic payments API tests, I noticed that the compliance engine is sending the "JWT" ​​payload with the iss field value invalid according to the technical specification. It is sending the CNPJ instead of the organisationID listed in the directory.

This error is happening in all tests of version 2 of automatic payments. (automatic payments and sweeping accounts)

Hi All! Thanks for the ticket!

After further evaluating the logs sent, we have concluded that the issue is happening because you are sending a BRSEAL (Signature Certificate), where a BRCAC (Transport Certificate) in the test plan Configuration. The conformance suite populates the field its from the payload signature by getting the field OU from the BRCAC certificate, which by default, should be filled with the OrgID, as shown bellow:

![image.png](/uploads/8f6852201ab7bb67de3d99ea1fa3c920/image.png){width=448 height=367}

Given that a BRSEAL was provided at the test config where it should be a BRCAC, the test is fetching this field and sending at payload signature. 

IN that sense, the confirmance suite is sending the field correctly. IN order to have succesfull execution, please fill the [mtls](http://mtls.ca) field with a BRCAC at the test plan configuration, instead of a BRSEAL. For additional guidance on how to fill the test pkan configuration, please check https://gitlab.com/raidiam-conformance/open-finance/certification/-/wikis/Release-Phase-2-Version-2-Test-Plans#filling-out-the-configuration-fields.

We are happy to help with any additional needs!
