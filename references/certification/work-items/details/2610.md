## 📝 Descrição

**Observed Behavior:**

The `ValidateCaChainReturnedPhase2Phase3` class (used by the `fvp-payments-consents-server-certificate-v2` test module) performs a **GET** request to the base `/open-banking/consents/v{N}/consents` endpoint as part of the TLS CA chain validation.

This endpoint only supports **POST** according to the Consents API specification. The GET call returns a 404, and this interaction is reported to the PCM with:

* `httpMethod: GET`
* `endpoint: /open-banking/consents/v3/consents`
* `statusCode: 404`

This has been flagged by participating institutions as impacting their availability and latency metrics, since these calls are non-conformant with the API specification.

---

**Affected plans:** `dcr-fvp_test-plan`, `dcr-fvp-homologation_test-plan`, `dcr-fvp-yacs_test-plan`

---

**Expected Behavior:**

The consents endpoint should use **POST** (matching the API spec), consistent with how the payments endpoints are already configured
