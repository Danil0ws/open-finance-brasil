Hello @170791daniel. 

After the enrollment is approved (AUTHORISED), the test is **not** waiting for a webhook just to confirm the status. At this stage, it expects an incoming webhook with eventType = DATA_CHANGED, meaning that at least one of these fields has already been updated in the detentora system: transactionLimit, dailyLimit, or expirationDateTime.

After receiving the webhook, the Suite calls GET /enrollments/{enrollmentId} and checks that **at least one** of those fields is different from the value observed in the previous steps. If you send DATA_CHANGED before updating any of them (or if the GET still returns the same values), the test will fail.

To pass: update one of those fields first, ensure the GET reflects the new value, and then send the DATA_CHANGED webhook.

Please feel free to reopen this issue if further assistance is needed.
