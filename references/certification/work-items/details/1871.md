Thanks for opening the ticket!

The test being run by Automatic FVP is v3.0.1 of consents API,

As discussed in this issue: https://gitlab.com/raidiam-conformance/open-finance/certification/-/issues/1691

For v3.0.1 there was no error code for invalid date being used during consent creation, therefore GT determined that, for this specific version, conformance suit should allow any of the error messages on enum for 422. 

This matter has been fixed in v3.1.0 of consents.
