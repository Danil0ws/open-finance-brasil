## 📝 Descrição

## 1. What Happened and what were you expecting?
Under the section `Make PUT request to client configuration endpoint with subjectdn for second certificate` we expected the test suite to make the PUT call with the original certificate that was used for registration. Instead, it uses the new certificate for authentication, and this fails in our case as we're using certificate bound registration tokens. 

This test passes if we disable that functionality, but I am wondering if using the second certificate for that PUT call is intentional?

This is deliberate behaviour.

The intent of the test is to ensure that the relying party retains the ability manage the client when their original certificate has expired, so verifying that the client can be managed using the "new" certificate is an important part of that.
