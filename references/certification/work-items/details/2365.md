## 📝 Descrição

#### Current Behavior:

Olá! O teste automatic-payments_api_automatic-pix-revoked_test-module_v2n2 da RC-2 da automatic payments 2.2.0 está exigindo após o cancelamento do pagamento que a consulta de todos os pagamentos (GET /recurring-payments) tenha no registro do pagamento com status CANC, a propriedade cancellation (com reason igual a CANCELADO_AGENDAMENTO).

#### Expected Behavior:

No entanto, a especificação do end-point GET /recurring-payments não possui a declaração da propriedade cancellation para versão 2.2.0. Logo a aplicação devolve apenas o status CANC, uma vez que não há outra propriedade condicionada ao status CANC. Entendemos que o motor não deveria exigir o cancellation, já que não existe na especificação.

Boa tarde prezados,

Conforme alinhado na issue #2303, o comportamento do teste será alterado para:

We need to change the step:

* Call the GET <s>recurring-payments sending the recurringConsentID on the header</s>
* Expect 200 - Validate Response and both paymentIDs are retieved, with the correct status for it, as ACSC for the first payment and CANC, with **cancellation.reason as CANCELADO_AGENDAMENTO** for the second payment.

**New behavior:**

* Call the GET recurring-payments/{recurringPaymentId} for the first payment
* Expect 200 - Validate Response and ensure status is ACSC
* Call the GET recurring-payments/{recurringPaymentId} for the second payment
* Expect 200 - Validate Response and ensure status is CANC, with **cancellation.reason as CANCELADO_AGENDAMENTO**

**_Essa alteração será contemplada na versao estável de AP que está prevista para o dia 21/10._**
