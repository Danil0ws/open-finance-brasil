## 📝 Descrição

## Context

During analysis of the payments-apes_test-plan_v5, it was identified that the FVP/client is sending POST /pix/payments requests for localInstrument = APES without the mandatory proxy field.

Example observed request:

`{
  "localInstrument": "APES",
  "qrCode": "...",
  "payment": {...},
  "consentId": "...",
  "authorisationFlow": "FIDO_FLOW"
}`

The request contains qrCode, but does not contain proxy.

## Specification

According to [Payments API v5 ](https://raw.githubusercontent.com/OpenBanking-Brasil/all-services-repo/refs/heads/main/api_payment_initiation_-_open_finance_brasil/5.0.0-rc.1.yaml)specification:

* For localInstrument = APES, qrCode is mandatory.
* For localInstrument = APES, proxy must also be provided with the Pix key.

Therefore, requests without proxy are invalid and participant servers may legitimately reject them.

## Expected Behavior

When localInstrument = DICT, APDN, APES, QRDN ou QRES, send the proxy field.
