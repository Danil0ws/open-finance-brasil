Thanks for opening the issue!

The failure on test execution happened due to the following circumstance: 

Conformance Suit called:

• Call the GET recurring-payments sending the recurringConsentID on the header\
• Expect 200 - Validate Response and both paymentIDs are retrieved, with the correct status for it (ACSC)

As conformance suit expected to receive a 200 response from server to check that the payments had status ACSC, it in turn received an error code 400 from server as can be seen bellow:

![image.png](/uploads/2416fffbfba323df59e6f6932d67bb39/image.png)

Therefore, conformance suit is operating as expected, make sure that the Server responds successfully to a:

**GET automatic-payments/v1/pix/recurring-payments** Request

Just reminding that, if the consent was deleted after reaching status CONSUMED, it must still be usable to call the endpoint aforementioned, otherwise it becomes useless to check on payments status after they have been transitioned to 'ACSC'
