## 1. What happened and what were you expecting?

The test customer-business_api_businessentity-personal-permissions_test-module_v2 is expecting a 400 response, which is not suitable according to Phase 2 documentation → Orientações - [DC] Consent (https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/219480491/Orienta+es+-+DC+Consentimento). 

![image](/uploads/031c0a9a031e1e8dfdbc300fbe485fc9/image.png)

During the request for consent creation, the appropriate response to validate should be Status Code 422.

We are aware that there are enhancements in the APIs that will affect the "Orientações" pages on the outermost part of the consents section. The same happens in the **consents_api_negative_test-module_v2** and **consents_api_bad-consents_test-module_v2** test scenarios. The test expects an error 400 when the documentation shown in the image above states that an error 422 should be returned in these cases. Analyzing the documentation further, in the general consent guidelines(https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/219480491/Orienta+es+-+DC+Consentimento) it is informed that a 422 must be returned for cases of permissions sent other than the grouping, however in the consent specification v2(https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/207716438/Informa+es+T+cnicas+-+DC+Consentimento+-+v2.2.0) it is informed that it must be returned a 400 for this case. There are two different pieces of information for the same case.
