Hi, Rodrigo!

Thank you for reaching us.

After inspecting the HTTP request/response trace, we confirmed that the test engine (initiator) correctly sent the `purpose` field with the value `"IMMEDIATE"` in the consent creation request (POST /consents), which is compliant with the v5 specification.

However, in the **response** payload returned by your server, the field is spelled as **`"porpuse"`** instead of **`"purpose"`**. This typo causes the OAS schema validator to treat the field as missing, since `porpuse` is not a recognized property, resulting in the validation failure.

Let us know if you have any questions.
