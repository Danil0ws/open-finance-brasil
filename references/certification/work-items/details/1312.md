## 📝 Descrição

## 1\. What happened and what were you expecting?

According to the test description, when the status is PARTIALLY_ACCEPTED after the first user approves the consent, the test is supposed to try to create a payment and expect a 422 CONSENTIMENTO_PENDENTE_AUTORIZACAO error, but the test suite is expecting a 201 code here.

The suite is supposed to detect this 422 error, and then wait at most 10 minutes for the other users of the account to approve the consent, so it can change to AUTHORISED status. Only after this the test suite can create a payment correctly and expect a 201 status.

• Redirects the user to authorize the created consent - Expect Successful Authorization\
• Calls the GET Consents Endpoint\
• Expects 200 - Check the status is “PARTIALLY_ACCEPTED” and validate the response\
**• Calls the POST Payments Endpoint\
• Expects 422 - CONSENTIMENTO_PENDENTE_AUTORIZACAO\
• Poll the GET Consents endpoint for 10 minutes with the ConsentID created while consent is "PARTIALLY_ACCEPTED"**\
• Call the POST Payment Endpoint\
• Poll the Get Payments endpoint with the PaymentID Created while payment status is RCVD, ACCP or ACPD\
• Call the GET Payments Endpoint\
• Expected Accepted state (ACSC) - Validate the Response

(The bolded part is not working)

As it is right now, besides contradicting the test plan, it also makes it difficult to have time to authorise with the other users before the payment creation attempt.
