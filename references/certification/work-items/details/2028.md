#### Current Behavior:

---

During test module, Conformance Suit executed Two Pooling sequences.

**In the first one:**

`• Call the POST recurring-payments endpoint with the information defined firstPayment payload • Expect 201 - Validate Response →`**`• Poll the GET recurring-payments {recurringPaymentId} while the Status is RCVD, ACCP or ACPD`**` • Call the GET recurring-payments {recurringPaymentId} • Expect 200 - Validate Response and ensure status is ACSC`

During this pooling sequence to check status on the first payment, Conformance suit continues to Calls GET recurring-payments while it receives response from the server containing a payment with status:

* "RCVD",
* "ACCP"
* "ACPD"

If a different status is obtained, such as PNDG or ACSC, the pooling sequence waits for 30 seconds and then verifies if payment status is at the expected ACSC state.

During this pooling sequence:

* One of the possible status that is not being contemplated during pooling: **PNDG** .

**In the second pooling:**

`• Call the POST recurring-payments endpoint with the a payment for D+2, and amount as 0.5 BRL →• Poll the GET recurring-payments {recurringPaymentId} while the Status is RCVD, ACCP or ACPD • Call the GET recurring-payments {recurringPaymentId} • Expect 200 - Validate Response and ensure status is SCHD`

During this pooling sequence, Conformance suit Calls GET recurring-payments while it receives response from the server containing a payment with status:

* "RCVD",
* "ACCP"
* "ACPD"

If a different status is obtained, such as PNDG, ACSC or SCHD the pooling sequence waits for 30 seconds and then verifies if payment status is at the expected SCHD state.

During this pooling sequence:

* One of the possible status that is not being contemplated during pooling and should be added: **PNDG** .
* One of the checked status should not be expected while pooling: **ACPD**

At this pooling sequence **ACPD** is not a possible state for the payment as it is achieved only after **SCHD** state. So payment can not reach SCHD after reached ACPD.

If the server had provided an **ACPD** state during pooling, the pooling sequence would continue until tests had failed, therefore ensuring that the payment never reached the desired **SCHD** state.

#### Expected Behavior:

---

Given that PNDG state was deliberately chosen not to be included during pooling, to ensure correct implementation of intermediary payment status, what we need evaluation from Squad Sandbox is:

* Should we return to expect PNDG payment state during pooling phase?
