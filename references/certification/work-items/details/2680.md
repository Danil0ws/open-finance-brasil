## 📝 Descrição

Queria compartilhar um contexto rápido: nosso time de Segurança está revisando alguns pontos de controle, e **o download de logs em arquivo ZIP** entrou como um item de atenção. A preocupação é que arquivos compactados **reduzem a capacidade de inspeção prévia pelas ferramentas de segurança** e, por serem um formato comumente usado em incidentes, acabam exigindo um cuidado extra.

Antes de pedir qualquer exceção interna, gostaríamos de entender com vocês se existem **alternativas para exportar/baixar os logs sem ZIP**, de forma a **mitigar o risco**. Por exemplo: exportação em **CSV/TXT/JSON**, arquivos individuais (não compactados), ou **coleta via API/integration**.

Paralelamente, se com "plano completo" estiver se referindo a um módulo de teste em HTML, hoje o .json contém a mesma completude de informações, só não traz a visão "friendly".

Complementando:

Na FVP Manual existe uma camada adicional de autenticação que rejeita qualquer request via API sem sessão de login válida. Por isso, realizar chamadas utilizando o Bearer token do `https://web.fvp.directory.openbankingbrasil.org.br/tokens.html` sozinho não passa.

Para consumir os próprios logs na FVP via API, você deve realizar, **em até 60 minutos após a execução do teste**, chamadas contendo:

1. **Auth Type:** No Auth (não enviar Bearer).
2. **Cookies** (copiados de uma sessão de browser logada na FVP):
   * `AWSELBAuthSessionCookie-0`
   * `JSESSIONID`

**Importante:** a identidade que vira `testOwner` na FVP é a do login que rodou o teste pela UI. Usar Bearer do portal resultaria em filtro por outra identidade e retornaria lista vazia.

Tanto no Motor, quanto na FVP, você pode obter mais informações clicando no botão Tokens após fazer login:

Olá @guilherme.melo4. Obrigado por trazer esse ponto.

A Suíte de Conformidade já expõe os mesmos dados em formatos não-compactados (CSV/JSON) via REST API autenticada. Resumo do que está disponível:

**Documentação e autenticação**

* Swagger UI: 

  https://web.conformance.directory.openbankingbrasil.org.br/swagger-ui/index.html
* Geração de tokens de acesso: https://web.conformance.directory.openbankingbrasil.org.br/tokens.html

**Endpoints que retornam logs sem ZIP** (grupo `log-api` no Swagger):

| Endpoint | Formato | Uso |
|----------|---------|-----|
| `GET /api/log` | JSON paginado | Listagem de testes |
| `GET /api/log/{id}` | JSON | Logs completos de um teste específico - mesmo conteúdo que vai no `.json` dentro do ZIP, servido direto |
| `GET /api/log/logs.csv` | CSV | Exportação tabular dos logs |

**Importante sobre autorização e ownership:** o token utilizado precisa pertencer ao mesmo usuário que executou o teste (o `testOwner`). A API filtra os resultados pelo dono do token. 

* Se o teste foi rodado por outra conta, a chamada retorna `200 OK` com lista vazia (`[]`), não um erro. 
* Para acessar logs de testes publicados por terceiros, basta adicionar o parâmetro `?public=true` (ex.: `GET /api/log/{id}?public=true`), que devolve os dados caso estejam marcados como públicos.

**Recomendação para o time de Segurança:** integrar via API (`/api/log/{id}` para JSON ou `/api/log/logs.csv` para CSV) utilizando tokens gerados no Motor de Conformidade, sempre garantindo que o token usado seja o do owner dos testes a inspecionar. Isso elimina o ZIP do fluxo e permite inspeção integral pelas ferramentas de segurança no formato nativo.

Ficamos à disposição para auxiliar com qualquer dúvida sobre os campos retornados ou sobre o fluxo de autorização.
