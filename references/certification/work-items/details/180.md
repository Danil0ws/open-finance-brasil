## 📝 Descrição

Hi,

we are facing a difficulty with the test "payments-api-qres-good-phone-number-proxy-test". Currently, here at Banco PAN we have a security policy that prevents two identical PIX's from being performed on the same day (same QRCode, proxy and value).

Because of this, we were only able to run the above test once a day and this has greatly disrupted the certification process. A suggestion to solve the problem would be to randomize the transaction value.

Could you evaluate the possibility?

Note: for the other tests we managed to get around the problem by modifying the test plan settings.

Thanks

The main challenge here is that if we randomize the transaction value, we will also have to dynamically generate the QRES codes, which now are all static values.
The dynamic generation of the QRES would account for the main challenge here as it is not simply a string concatenation, but we also must calculate the CRC for the string using the 0x1021, C.I. 0xFFFF polynom.
This change would also need to be patched into the following test modules, which currently all use a different static QRES string:

- payments-api-qres-good-email-proxy-test
- payments-api-qres-good-phone-number-proxy-test
- payments-api-qres-wrong-amount-proxy-test
- payments-api-qres-mismatched-proxy-test
- payments-api-qres-mismatched-consent-payment-test
- payments-api-qres-with-transaction-identifier-test

It’s almost certainly a doable update, but we would need to evaluate the effort needed and define prioritization so we could move forward with such change.

It’s worth noting that dynamically generating the QRES might also be a good thing to avoid hard coded responses on the test.
