We agree with you - Objective is to make sure deprecated fields are not being used by server, however a 400 is not the correct return here.

We have noticed that on the newest version of the APIs we have removed the field `additionalProperties: false` so there's no requirement for the Financial Institutions to refuse any request just because an unknown field has been sent - This would only be the case if we block additionalProperties.

We will update the test to accept a 201 on the POST Consents, however we will make sure that the institution does not return `transactionFromDateTime`, the deprecated field, on either the POST Consents response_body or the GET Consents response_body


New Test behaviour should be:


displayName =
- "Ensures the server refuses a consent v2 creation request if the fields transactionFromDateTime and transactionToDateTime are present"

summary = 

- "Call the POST Consents API request including fields transactionFromDateTime and transactionToDateTime on the request body"
- "Expect a 201 Created Response - Make sure that the response does not contain the fields transactionFromDateTime and transactionToDateTime"
- "Call the GET Consents API request with created Consent"
- "Expect a 200 OK Response - Make sure that the response does not contain the fields transactionFromDateTime and transactionToDateTime"
