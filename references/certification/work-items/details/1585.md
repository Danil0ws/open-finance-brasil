## 📝 Descrição

## 1. Erro na interpretação dos requisitos do campo startDateTime

Conforme relatado na issue [1584](https://gitlab.com/raidiam-conformance/open-finance/certification/-/issues/1584 ), o teste está informando um startDateTime no passado, uma vez que o objeto é construído antes da execução da requisição. Levando em consideração os requisitos funcionais para o startDateTime presentes no swagger, este campo, se informado, deve possuir uma data no futuro, se a data desejada for a atual(agora), o campo não deverá ser enviado. Logo, caímos na restrição:
**[Restrição] Preenchimento obrigatório quando o consentimento de pagamento passa a valer em data (dia e hora) futura**

Do contrário, não faria sentido o parâmetro ser opcional.

We will send this to the WG so they can review the specification! but just to clarify, the current restriction is:

* It is mandatory to be sent when it's a future date

and not:

* If the field is sent, the date should be in the future

These are different things. Where the first enables the startDateTime to be sent in the past, the second not.

Hi Adelino! Thanks for the ticket!

As mentioned at the swagger, the field startDateTime is mandatory when the consent starts in the future, but **there is no restriction that it should not be sent or accepted if it's in the past.**

This was specifically chosen to enable two possible paths for the initiator. If the consent start now, it can:

* Send the parameter with now
* Not send the parameter

We are happy to help with any additional needs!
