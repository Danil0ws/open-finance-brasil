Hi, @mtocura 

Thanks for the ticket!

We understand your question; however, an invalid token is one that, when introspected, would return invalid (e.g., a random string), which is not the case here. The token has a valid structure but an incorrect scope. This differentiation is essential to distinguish between an invalid token and one with an incorrect scope. Otherwise, errors 401 and 403 would be interchangeable.

Therefore, there are no corrections needed on the CS side. For successful execution, the implementation must be adapted to align with the summary description.

Feel free to open another ticket if you get any other issue! Happy to help!
