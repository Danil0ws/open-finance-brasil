Hi @Francisco_Gomes and @antonio.lopes2,

As it is described for the PATCH consent/{consentId} on the spec:

> Esse endpoint deve ser usado para cancelar, a pedido do cliente pagador, as transações que estejam em uma das seguintes situações: Agendada com sucesso (SCHD) ou retida para análise (PDNG).

In this test module, conformance suit executed the following steps:

• Call the PATCH PaymentId Endpoint with the first PaymentID\
• Expect 200 - Check if status is CANC, and cancellation reason is CANCELADO_AGENDAMENTO. Check if cancelledFrom is INICIADORA

And afterwards:

• Call the PATCH ConsentId Endpoint\
• Expect 200 - Check if the list has the 4 paymentIds left, and the statusUpdateDateTime is after the time of the reques

When **PATCH consents/{consentId}** was called to change the status of the remaining 4 payments, it received as a response:

```
{
  "aud": "3a5ea40d-b088-5118-ac8d-869964bfd67a",
  "data": [
    {
      "paymentId": "316753f8-b265-4ff3-8ad0-5cf5e1ac1dc5",
      "statusUpdateDateTime": "2024-03-11T13:57:37Z"
    },
    {
      "paymentId": "5425666b-98b9-4ef3-b6c4-a37a39ec3d01",
      "statusUpdateDateTime": "2024-03-11T13:57:37Z"
    },
    {
      "paymentId": "ad846d3a-8eec-40f1-ac22-7071b688518a",
      "statusUpdateDateTime": "2024-03-11T13:57:37Z"
    },
    {
      "paymentId": "ce447425-e055-420c-9b10-378e8f24100d",
      "statusUpdateDateTime": "2024-03-11T13:57:37Z"

    {
      "paymentId": "f925477f-e406-4a77-b12a-fa640bc4fb73",

    }
  ],
  "meta": {
    "requestDateTime": "2024-03-11T13:57:38Z"
  },
```

In this scenario, conformance suit expected that for all the 4 payments that were still in status SCHD before the PATCH endpoint being called StatusUpdateDate was after RequestDateTime. As can be seen from the extract of the response, although conformance suit expected a list of the 4 payments, it actually received a list with all 5 created payments, which included the first payment that was changed the first PATCH call. As in this first payment the StatusUpdateDate if before the **P**ATCH consents/{consentId} RequestDateTime conformance suit returned the error as expected.

Therefore in this regard conformance suit is operating as expected, to be able to run the test module accordingly please make the **P**ATCH consents/{consentId} response included the list o payments have status as described by the spec.
