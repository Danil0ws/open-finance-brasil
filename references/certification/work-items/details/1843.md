#### Current Behavior:

---

During step: `[1] Fetching Account Transactions current`, conformance suit calls Transactions current for the first time.

Server returns in payload:

```
"next":".../transactions-current?page=2&page-size=25&pagination-key=9gico4li12h955id9a2bb2ibb6k1ekde5b35hg9abd33b5cck7cekmd8bliea56bb6ekm7hd36acc9"
```

Which contains `pagination-key` query parameter on it, necessary for operational limits tracking.

Afterwards, Conformance Suit proceeds to call Transactions current 240 times (step: `[240] Fetching Account Transactions current`), so it reaches it’s operational limit.

After calling for the 240 it proceeds to the following step:

`[1] Fetching Accounts Transactions Current next link`

In which Conformance suit is supposed to get the next link provided in `Transactions current`, call.

Although instead of using the provided next link, Conformance suit made the following request:

**GET**

```
.../transactions-current?fromBookingDate=2024-10-04&toBookingDate=2024-10-10&page-size=1
```

As can be seen this URI does not contain the query param `pagination-key` and therefore it is counted towards the operational limit, being blocked by the server.

#### Expected Behavior:

---

Conformance Suit should use the provided next link instead of building one. That is because `pagination-key` is necessary for pagination requests not to surpass the operational Limit.
