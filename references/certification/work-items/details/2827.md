## 📝 Descrição

Servidor de Autorização PicPay está experimentando erro para autorizar consentimento com permissões amplas, mas com DCR liberando scope para apenas um produto da lista de permissões solicitadas. 

Exemplo de erro relacionado relatado https://gitlab.com/raidiam-conformance/open-finance/certification/-/work_items/2816

#### Current Behavior:
1. DCR é feito com scopes apenas para produto alvo do teste, ex "openid consents funds resources"
2. Consentimento é feito com permissões para todos os produtos de Investimento contexto Open Finance, permissões que geram scopes "bank-fixed-incomes credit-fixed-incomes variable-incomes treasure-titles funds"
3. Autorização do consent finaliza com erro, pois Servidor de Autorização não permite que consent com todos escopos de investments seja autorizado para DCR com apenas contexto de funds

#### Expected Behavior:
1. DCR é feito com scopes apenas para produto alvo do teste, ex "openid consents funds resources"
2. Consentimento é feito com permissões para apenas produto alvo do teste, ex "FUNDS_READ"
3. Autorização do consent finaliza com sucesso, pois as configs estão adequadas
- uma variante seria DCR com scope amplo, assim tudo estaria permitido


#### Evidence:
Módulos que evidenciamos os erros:
- funds_api_alphanumeric_cnpj_test-module_v1-1
- bank-fixed-incomes_api_alphanumeric_cnpj_test-module_v1-1
- credit-fixed-incomes_api_alphanumeric_cnpj_test-module_v1-1
- variable-incomes_api_alphanumeric_cnpj_test-module_v1-3
