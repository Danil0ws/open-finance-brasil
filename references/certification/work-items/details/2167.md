## 📝 Descrição

**Description:**

We have identified a potential issue related to **operational limits** when executing Customer Data tests via FVP.

Currently, FVP runs a series of tests against participants for both **Service Initiation** and **Customer Data** APIs. The issue arises because, according to the [Open Finance Brasil Operational Limits documentation](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17924220/Limites+operacionais), participants can define strict limits for some endpoints — in certain cases, as low as **4 requests per month**.

The problem is that the current FVP Customer Data test plan **calls each endpoint once**. If the test is executed more than 4 times (e.g., for retesting or participant-side validation), the participant may **start receiving 423 errors** due to operational limits being exceeded.

> ⚠️ **Note:** This issue is **not currently impacting any institution that we are aware of**, but it **could happen** depending on test frequency and participant configuration.

This poses a risk, especially considering that:

* The **execution team cannot control how many times** a participant triggers the test.
* The **same test plan may be run independently** by participants.

### Suggested Next Steps

We recommend discussing within the Working Group a sustainable solution. Some possible directions include:

* Establishing a **process or policy** in the documentation to guarantee successful execution of FVP Customer Data tests. One suggestions is to establish extended SLAs in case operational limits are exceed, so that FVP wait until a test can be run again
