Hello @hrezend. While we wait for your logs so we can provide more concrete evidence, we can already clarify your point: these two modules are not “testing timezone” in the same generic way, so they do not share the same execution window.

Each one targets a different business condition:

* **payments_api_timezone_test-module_v5 (21:00–23:59 UTC -3):** the purpose is to validate date/time handling and ensure the server processes the request correctly while the local date is still the same day in UTC -3. The window is defined to reliably place the test within that end-of-day context.
* **payments_api_consent-bulk-cancel_negative_timezone_test-module_v5 (after 22:00 UTC -3):** this is a **cut-off / time-window rule** test for bulk cancellation. The scenario only exists **after 22:00 (UTC -3)**, when certain scheduled occurrences become non-cancellable. Running it at **21:01** does not meet the precondition, so it is expected to fail.

So the intent is not to “consider UTC -3” with a single shared range, but to execute each test within the specific time window required by the rule it is validating.

If this explanation is enough to address the question about the summaries, please feel free to close this issue. Otherwise, once you share the logs, we will investigate and come back with our findings.
