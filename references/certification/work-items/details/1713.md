## 📝 Descrição

#### Current Behavior:

---

In enrollments_api_webhook-revoked_test-module

During the following steps:

* Call the GET enrollments endpoint
* Expect a 200 response - Validate the response and check if the status is "AWAITING_ENROLLMENT"
* Call the PATCH enrollments endpoint
* Expect a 204 response
* Expect an incoming message for enrollments, which must be mtls protected - Wait 60 seconds for both messages to be returned
* Return a 202 - Validate the contents of the incoming message, including the presence of the x-webhook-interaction-id header and that the timestamp value is within now and the start of the test
* Call the GET enrollments endpoint
* Expect a 200 response - Validate the response and check if the status is "REVOKED", cancelledFrom is INICIADORA and revocationReason is REVOGADO_MANUALMENTE

Test moves from status AWAITING_ENROLLMENT to REVOKED which should not be possible according to the specification:

[https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/405995575/M+quina+de+estados+-+v1.3.1+-+SV+V+nculo+de+dispositivo](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/405995575/M+quina+de+estados+-+v1.3.1+-+SV+V+nculo+de+dispositivo "https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/405995575/M+quina+de+estados+-+v1.3.1+-+SV+V+nculo+de+dispositivo")

#### Expected Behavior:

---

When enrollment is in status: AWAITING_ENROLLMENTIt can only move to the REJECTED status and not the REVOKED one. 

REVOKED is only possible if in status AUTHORISED.

Therefore, to ensure test module fulfills it's purpose of enrollment Revocation it's behavior will be changed to ensure AUTHORISED status is reached before PATCH endpoint is called.
