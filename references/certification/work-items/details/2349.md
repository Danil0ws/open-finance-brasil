Hi, 

Thanks for contacting us!

The main objective of this test is to ensure that your server enforces **mandatory validations** when processing a sweeping payment. Specifically, the test is validating that a sweeping payment **cannot** be successfully executed if critical, mandatory account information is missing or incomplete.

The test sequence is designed to trigger a specific business rule validation failure:

1. The test creates a recurring consent (`POST /recurring-consents`) using sweeping accounts fields, but without ensuring all mandatory data points for a functional sweeping payment are present.
2. It then attempts to create the recurring payment (`POST /recurring-payments`).
3. **The Expected Result:** The test expects your API to reject this payment with a **`422 Unprocessable Entity`** status code and the error code **`DETALHE_PAGAMENTO_INVALIDO`**.

The `DETALHE_PAGAMENTO_INVALIDO` error code is used when a parameter informed in the payment details does not adhere to the business rules. If your payment is succeeding with a `201 Created` status, it means your API is not enforcing the necessary validation rules for the sweeping account fields, allowing an invalid payment to be scheduled.

Please, feel free to reach out in case of further questions!
