## 📝 Descrição

I believe there is a problem with the QR Codes used for the QRES tests.

In any QRES test, when consulting the information stored in the QR Codes in DICT, they don't have a "bank" registered, this causes issues while trying to validate the data like "ispb" for the receiver of the QR Code.

This proxy key "cliente-a00001@pix.bcb.gov.br" has been set by the central bank on the Dict homolog environment for all the tests under the OPen Banking Scope. This key has been set against a virtual PSP that accepts all payments that are sent towards it. 

We had +60 Banks that managed to use this same proxy key to pass on the DICT, MANU and INIC tests https://github.com/OpenBanking-Brasil/conformance.

The QRCode tests are merely using the proxy key already used in prior phases, and no banks have raised this issue.

With this in mind, we would need more evidence on why this is a real issue to be able to bring this to the Central Bank.

One suggestion here is to show under the DICT documentation that this field is mandatory on the homolog environment so we can point to the Regulator that there might be an issue here.
