## 📝 Descrição

## 1. What happened and what were you expecting?
Now, the test expects failure on authorize consent. Before, the error is expect on post payment. Is there a documentation that explain this new behavior? 
Looking documentation, I found this:
```
1. Validações na criação do consentimento (POST /consents)
 1.1 Orientações Iniciais
  1.1.1 Não devem ser retornadas informações associadas ao usuário/cliente (ex. insuficiência de saldo, conta inexistente/bloqueada), uma vez que o cliente ainda não autorizou o consentimento / consumo de seus dados para o pagamento.
```

I know this expected behavior is after user's auth and the above doc concerns POST consent, but validate this behavior on auth consent looks like accumulation of responsibility of authorization api.
