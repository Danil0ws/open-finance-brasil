## 📝 Descrição

## 1\. What happened and what were you expecting?

The test module is applying a sychronous validation to check wheter the debtorAccount = 'SLRY' and is expecting a 422 response. This validation is no longer valid since it should be done in an asynchronous way as defined in the [Validações section, item 5.1.5 and 5.2.](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/239337826/Informa+es+T+cnicas+-+SV+Pagamentos+-+v4.0.0-beta.4)

![image.png](/uploads/769affe9a25f270e8156cac2e1852e38/image.png){width="427" height="175"}

![image](/uploads/bae539d04bfe02a4c4f14ec262fd18b6/image.png){width=508 height=260}

In addition to this, this behaviour is also described in the [Guia de Experiência do Usuário](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17378535/Guia+de+Experi+ncia+do+Usu+rio), page 138. ![image](/uploads/c7300cddb3b37687d3dd055a5977030b/image.png){width="348" height="185"}

Thanks for opening the ticket!

As described in the following specification:

Although debtorAccount = 'SLRY’ was a possible accountType in the previous specifications, it is no longer a valid field as it does not exist in the accountType ENUM, as described in the latest available specification:

https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/264307138/Informa+es+T+cnicas+-+SV+Pagamentos+-+v4.0.0-rc.1

![Screen_Shot_2024-01-23_at_18.42.15_PM](/uploads/6f3691a63817642642570d771129bcd5/Screen_Shot_2024-01-23_at_18.42.15_PM.png)

Therefore the conformance suit is correctly validating the accountType as SLRY and expecting 422 PARAMETRO_INVALIDO as it is no longer a valid accountType in the most recent specification. 

As conformance suit is operating as expected, to ensure a successful run of the test module ensure that:

1. When Post Consents is called with a invalid accountType such as SLRY, the response_code is 422 PARAMETRO_INVALIDO
