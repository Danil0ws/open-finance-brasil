Hi Rafael! Thanks for the reply!

In the scenario you mentioned, the security specs state that we **may** remove, but don't have to, when there's a difference between the scopes and permission in the consent request, as stated at "para permitir o acesso aos dados definidos em elemento Permission do Consentimento (Consent Resource Object) relacionado".

In this case, we are referring to a scenario where the scope request had to be narrowed because the openid scope should not be requested at Consents token request when the Authorization grant is client_credentials, and not because of differences between permissions and scopes. Therefore, the claim pointed at the security specs does not apply to this case.

The support for this specific case is available at [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749#section-3.3), which states that:

"If the issued access token scope is different from the one requested by the client, the authorization server MUST include the "scope" response parameter to inform the client of the actual scope granted."

In that sense, when there's any change in the scope, the server must send the scope parameter with the actual scope granted, so the client is informed of it. 
In a practical way, since the Conformance Suite request "openid payments" scope on the client_credentials grant, the server must only respond with the scope "payments" so that the client knows that the openid scope was not granted. 

Happy to help with any other questions! Please, feel free to reopen the ticket if you think the issue remains.

Hi Rafael! Thanks for the ticket

As specified at [Informa #218](https://mailchi.mp/18107e66cfae/open-banking-informa-9162397?e=9b9743fbe2), the openid scope should not be requested at Consents token request when the Authorization grant is client_credentials. In that sense, the [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749#section-3.3) states that:

"If the issued access token scope is different from the one requested by the client, the authorization server MUST include the "scope" response parameter to inform the client of the actual scope granted."

Based on these specifications, the test expects that when issuing an access token for Consents with scope "payments openid", the server response scope parameters will only contain "payments", so the client is informed of the actual scope granted.

Please, feel free to reopen the ticket in case you think the issue remains.
