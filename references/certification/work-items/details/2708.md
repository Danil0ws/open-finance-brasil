Olá @felippesilvaOPF.

Identificamos que a falha ocorreu durante a etapa de preparação do teste (pré-DCR). O problema foi causado por uma inconsistência no client pré-registrado utilizado pelo scheduler para esse servidor de autorização.

Essa inconsistência foi gerada após duas execuções agendadas para o mesmo teste, e contra o mesmo Server, serem disparadas ao mesmo tempo. Ambas identificaram ausência de client pré-registrado naquele momento e seguiram com o processo de criação, resultando em um estado inconsistente na base da FVP.

![image.png](/uploads/a73ba6abd26c2c54e40013f8fa4f4f33/image.png){width=900 height=279}

Realizamos a correção manual no ambiente, restabelecendo o estado esperado para o client utilizado nessas execuções. Em paralelo, mapeamos um improvement para que esse problema não seja bloqueante caso condições tão específicas se repitam.

Por ora, solicitamos que não agendem testes idênticos no que diz respeito a Test Module + Authorisation Server + data de execução dos steps agendados.

Sugerimos nova execução desse teste, e pedimos que nos informem caso o problema persista.

Att,
