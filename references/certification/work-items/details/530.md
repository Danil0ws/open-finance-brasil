Hi Daniel! Thanks for the ticket!

Checking the logs, the endpoint response indeed does not have a "scope", as seen below:

{"access_token":{Access_token},"token_type":"Bearer","expires_in":599}

According to the [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749#section-5.1), the scope parameter on the token endpoint response is only optional if it is identical to the scope requested by the client. In that sense, since the CS requested "payments openid" as the scope, and the expected scope for the response is only "payments", the scope parameter becomes mandatory on the token endpoint response.

Please, feel free to reopen the ticket if you think the issue remains!
