## 📝 Descrição

### Problem

During the step:

> • Creates consent with incomplete credit card permission group ("CREDIT_CARDS_ACCOUNTS_BILLS_READ","CREDIT_CARDS_ACCOUNTS_READ","RESOURCES_READ")

It triggers a request to create a consent with the following payload:

```json
{"data":{"permissions":["CREDIT_CARDS_ACCOUNTS_BILLS_READ","CREDIT_CARDS_ACCOUNTS_READ","RESOURCES_READ"],"loggedUser":{"document":{"identification":"38340223810","rel":"CPF"}},"expirationDateTime":"2023-07-20T22:29:28Z"}}
```
Then it will `Check for HTTP 400 response from consent api request for incomplete credit card permission group` and the test will fail.


### Expected Behavior

The API should answer 201 / created for this set of permissions, according to docs: 

[Dados Cadastrais e Transacionais [1]](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17369300/Dados+Cadastrais+e+Transacionais#Fluxo-b%C3%A1sico-de-consentimento)

[Mapeamento de roles, scopes e permissions das APIs de Dados Cadastrais e Transacionais [2]](https://openfinancebrasil.atlassian.net/wiki/download/attachments/7996438/Mapeamento_scopes_roles_permissions.xlsx?api=v2)

This set of permissions should `PASS`, because `CREDIT_CARDS_ACCOUNTS_BILLS_READ` does not require permissions other than `"CREDIT_CARDS_ACCOUNTS_READ"`(Agrupamento) and `"RESOURCES_READ"`(Recursos).

Hi,

Thanks for the ticket! 

As you said, the access to the Accounts API endpoint mentioned does not require other permissions besides `"CREDIT_CARDS_ACCOUNTS_READ"` and `"CREDIT_CARDS_ACCOUNTS_BILLS_READ"`. However, the API being tested in the `consents_api_negative_test-module_v2` is Consents API and as mentioned in the [Consents Swagger v2.1.0-rc2.0](https://openbanking-brasil.github.io/openapi/swagger-apis/consents/2.1.0-rc2.0.yml):

> "The recipient must obligatorily send, in the consent creation request, all the permissions of the data groups for which he wants consent, according to the table below"

In the table, the group of permissions in question is:

![image](/uploads/78c7c9f4d3a821f8302e17483affe7ba/image.png)

Note that the test uses an incomplete credit card permission group (missing `"CREDIT_CARDS_ACCOUNTS_BILLS_TRANSACTIONS_READ"`) to validate that a failure is returned but in your case it gets, incorrectly, a pass (status 201). That said, the test failed because it is not conformant to the swagger. To a successful execution, the implementation needs to be adapted so that it follows the behaviour mentioned in the test summary.

Feel free to open another ticket if you get any other issue! Happy to help!
