## 📝 Descrição

#### Description:

---

Currently for Customer Data APIs, we have the following rule at the [Security Profile](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/245760001/EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0+Implementers+Draft+3#7.2.2.-Authorization-server): 

5. shall ensure access tokens are issued with sufficient scope necessary for access to data specified in the Permission element of a linked Consent Resource object;

In that sense, even if some scopes are not sent on the PAR endpoint, the Authorization Server should adjust the access token scope to match what has been defined under the permission element for the consent. But in the case the scope "openid" is not sent at the PAR Endpoint, we understand that it's not explicitly defined if an ID Token be sent back along the authorization code after the redirect, since the "response_type": "code id_token" is still defined at the PAR request.

In that sense, we would like a **clarification for the Security WG on the following question**:

1. In case the scope "openid" is not included  and the "response_type": "code id_token" is defined at the PAR request, should an id token be sent back along with the authorization code?

Hi @christianraidiam, I just tested this scenario on my implementation ([o2b2-auth-server](https://github.com/ranierimazili/o2b2-auth-server)), and if I try to call PAR endpoint with the request object setting _response_type: "code id_token"_ but without include the _openid _scope on scope attribute, I receive the following error message:

```json
{
    "error": "invalid_request",
    "error_description": "openid scope must be requested for this response_type"
}
```

Looking at [OpenID Connect Core 1.0 spec](https://openid.net/specs/openid-connect-core-1_0.htm), on section 3.1.2.1. Authentication Request that defines the request object that must be sent to the authorization server (using PAR or not), on scope attribute definition we see:

> **scope**<br>
> REQUIRED. OpenID Connect requests **MUST contain the openid scope value**. If the openid scope value is not present, the behavior is entirely unspecified. Other scope values MAY be present. Scope values used that are not understood by an implementation SHOULD be ignored. See Sections 5.4 and 11 for additional scope values defined by this specification.

Also, describing the authorization server validation responsabilities when receiving this object, we see the following on section 3.1.2.2.  Authentication Request Validation, item 2:

> 2. Verify that a scope parameter is present and **contains the _openid_ scope value**. (If no openid scope value is present, the request may still be a valid OAuth 2.0 request but is not an OpenID Connect request.)

Considering the definitions above, it's impossible to say if an _id_token_ should be issued or not when calling PAR endpoint without send the _openid_ scope, because it's an invalid scenario... will never happen or if so, an error (or something unexpected) should occur before the issuing tokens moment.
