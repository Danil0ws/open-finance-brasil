## 📝 Descrição

## **Current Behavior**

The test dynamically generates `startDateTime` at test creation time (`2026-04-02T18:50:08Z`), producing the value `2026-04-02T18:50:10Z`.

By the time the `POST sign-options` request is executed (`2026-04-02T18:51:50Z`), approximately **1 minute and 40 seconds** have elapsed since the `startDateTime` value was generated.

Mercado Pago rejects the request with:

However:

1. The value `2026-04-02T18:50:10Z` **is valid RFC-3339 format** as required by the specification
2. The specification describes `startDateTime` as: _"Data e hora em que o consentimento deve passar a ser válido"_ — **there is no rule requiring this field to be in the future**
3. The error message claims a **formatting issue**, but the format is correct — the actual rejection appears to be based on the value being in the past relative to request time
