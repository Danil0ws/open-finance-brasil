#### Current Behavior:
As described in the [Product Requirements documentation](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/905740665/Documento+de+Requisitos+do+Produto+-+PC+Portabilidade+de+Cr+dito+-+CPC#3.1.6-Regra-de-Limita%C3%A7%C3%A3o-e-Avalia%C3%A7%C3%A3o-da-Proposta:~:text=O%20valor%20da%20opera%C3%A7%C3%A3o%20da%20nova%20proposta%20n%C3%A3o%20deve%20exceder%20o%20saldo%20devedor%20do%20contrato%20original), the value of the new proposal operation must not exceed the outstanding balance of the original contract.

![Screenshot_2025-07-28_at_15.03.56](/uploads/77b2869ca61d13f2e100aca951e6015a/Screenshot_2025-07-28_at_15.03.56.png)

When implementing this validation on the POST `/portabilities` endpoint, we identified that some tests that should create a credit portability start to fail on creation because they send payloads where the **total value of the proposal exceeds the outstanding balance**. Examples:

* **Test credit-portability_api_core_test-module_v1**
    * Outstanding balance: R$ 50.52190852
    * Payload sent:
        * `installmentAmount` = 50
        * `totalNumberOfInstallments` = 2
    * Proposal amount: R$ 100.00 (above the outstanding balance)

* **Test credit-portability_api_invalid-status_test-module_v1**
    * First request
    * Outstanding balance: R$ 46.95311304
    * Payload sent:
        * `installmentAmount` = 50
        * `totalNumberOfInstallments` = 12
    * Proposal amount: R$ 600.00 (above the outstanding balance)

* **Test credit-portability_api_invalid-contract-terms_test-module_v1**
    * First request
    * Outstanding balance: R$ 50.52190852
    * Payload sent:
      * `installmentAmount` = 50
      * `totalNumberOfInstallments` = 7
    * Proposal amount: R$ 350.00 (above the outstanding balance)
    ---
    * Second request
    * Outstanding balance: R$ 50.52190852
    * Payload sent:
        * `installmentAmount` = 50
        * `totalNumberOfInstallments` = 2
    * Proposal amount: R$ 100.00 (above the outstanding balance)
    ---
    * Third request
    * Outstanding balance: R$ 50.52190852
    * Payload sent:
        * `installmentAmount` = 50.52190852
        * `totalNumberOfInstallments` = 2
    * Proposal amount: R$ 101.04381704 (above the outstanding balance)

* **Teste credit-portability_api_cancelled-portability_test-module_v1**
    * Outstanding balance: R$ 156
    * Payload sent:
        * `installmentAmount` = 50
        * `totalNumberOfInstallments` = 12
    * Proposal amount: R$ 600.00 (above the outstanding balance)

#### Expected Behavior:
It was expected that the test payloads would send proposal amounts that do not exceed the outstanding balance.

The behaviour of these tests will be changed in version **rc.1**. You can check here in Portabilidade RC.1 -\> https://gitlab.com/raidiam-conformance/open-finance/certification/-/wikis/Credit-Portability-API

Example: test **credit-portability_api_core_test-module_v1**

**ChangeLog:** 

**• Adicionado - Chamada GET Loans Contracts/{contractId}/payments para receber propriedade data.contractOutstandingBalance** 

**• Adicionado - Campo da proposta data.proposedContract.contractAmount.amout igual ao valor da propriedade data.contractOutstandingBalance do contrato original** 

**• Adicionado - Chamada GET Loans Contracts/{contractId} para receber propriedade data.instalmentPeriodicity e companyCnpj** 

**• Adicionado - Campo da proposta data.proposedContract.instalmentPeriodicity igual ao valor da propriedade data.instalmentPeriodicity do contrato original** 

**• Adicionado - Validação de CNPJ obtido pela api de emprestimos e o CNPJ fornecido pela Proponente ao solicitar portabilidade de crédito**
