## 📝 Descrição

Hi Master,

We are testing the Payment ITP enrollment flow and found an intermittent issue on Mock Bank side for Enrollments v2.

#### Participant:
- participantId: c8f0bf49-4744-4933-8960-7add6e590841
- applicationId: 44db0e03-d7fb-478e-9573-a66e254c587a
- organisationId: 96748716-9b96-448c-a2b7-2abf9762af8e
- enrollmentId: urn:raidiambank:enrollment:5600e454-b960-4dd8-a9ec-8d02186e563d

#### Problem:
During the same enrollment flow, GET /open-banking/enrollments/v2/enrollments/{enrollmentId} occasionally returns:

```
{
  "message": "no Route matched with those values",
  "request_id": "a3edd45c9a447e4a9519d47ce95ef37d"
}
```
However, the same enrollment flow also shows other Enrollments v2 APIs succeeding, and a later GET on the same enrollmentId succeeds as well.

#### Could you please confirm:
1.Is https://obb.qa.oob.opus-software.com.br/open-banking/enrollments/v2/enrollments/{enrollmentId} an expected resource endpoint for this participant in Mock Bank?

2.Why would the same GET /enrollments/v2/enrollments/{enrollmentId} sometimes return 404 no Route matched with those values, but later succeed for the same enrollmentId?

3.Is there any intermittent routing, gateway, or endpoint registration issue between obb.qa.oob.opus-software.com.br and matls-api.mockbank.poc.raidiam.io for Enrollments v2?

#### Concern:
From our side, this looks intermittent rather than a deterministic request issue:

- the same participant and same enrollmentId were used
- surrounding enrollment APIs succeeded
- later queries for the same enrollmentId succeeded

This makes the flow unstable because the client cannot tell whether the enrollment is invalid or the bank endpoint routing is temporarily inconsistent.
