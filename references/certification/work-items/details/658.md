Hi, I have a couple of questions regarding the tests that were updated for https://mailchi.mp/df89691e6c7e/open-banking-informa-9330628?e=%5BUNIQID%

Are any of the tests asserting this new `It must issue an access_token through a grant_type of type client credentials in status “CONSUMED” (for phase 3).` clause in the security profile?   I see they’re making client_credentials requests, but only requesting `payments` scopes in order to create the consent (like how they were before). Am I incorrect there?

Hi,

The grant_type "client_credentials" is used to authenticate an application against a server, outside of the context of a user.

That being said there's no link between any existing consent, regardless of its state, and the ability of the client to issue tokens using this grant_type. This condition also implies that dynamic scopes, which are bound to a user, cannot be granted using a grant_type : client_credentials.

Our understanding of the situation is that the server will need to map the consentId with the Application that is requesting it, via it's client_id. This means that when you call the GET Payments/{PaymentId} you must ensure that the PaymentId is linked to the application client_id to allow access, returning a 403/401 in case it doesn't.
