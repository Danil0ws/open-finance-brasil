## 📝 Descrição

Hi, in the `payments-consents-api-negative-tests-v2`, there is a step where the test suite creates a consent with an invalid currency type set. 

The test suite uses a value of `XXX`, however this code is technically valid according to the ISO 4217 standard as it indicates "no currency". 

If `XXX` is expected to be an error in the API, are there other special case / reserved codes that need to be errors as well (e.g. `XTS`)? From what I've seen so far, some libraries won't catch this because they're just checking if the 3-letter code exists in a standard list.

Or is currency always expected to be `BRL`?

Hi Dylan! Thanks fot the ticket!

Although compliant to the ISO 4217, the current [Phase 3v2 swagger](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/18055346/Informa+es+T+cnicas+-+Pagamentos+-+v2.0.0) only specifies that Brazilian currency should be sent on the API, as in:

![image](/uploads/ee9e89fe64c0f429f996f609d7ff1c90/image.png)

In that sense, the only accepted value here for the while should be the Brazilian currency (BRL).

Happy to help with anything else! Please, feel free t reopen the ticket if you think the issue remains!
