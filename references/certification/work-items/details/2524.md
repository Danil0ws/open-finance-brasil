## 📝 Descrição

Hello team,

We encountered an issue during the execution of the conformance tests regarding the `Accept` header negotiation.

**Description:** The test suite is currently sending the header `Accept: application/json` when calling the endpoint: `/open-banking/automatic-payments/v2/recurring-consents/{recurringConsentId}`.

![image.png](/uploads/e5ee7a4cce0a29682aad7cb44b338dfa/image.png){width=900 height=379}

However, our application enforces strict content negotiation filters required by the specification. Since this endpoint returns a signed response, we expect the client (the test suite) to request `application/jwt`.

**Evidence:** As shown in the attached image, other tests in the same suite correctly send `Accept: application/jwt`.

![image.png](/uploads/a5b1d35034efe4effe4369891665eb83/image.png){width="900" height="261"}

**Expected Behavior:** The test should send `Accept: application/jwt` for this endpoint.

**Actual Behavior:** The test is sending `Accept: application/json`, causing our server to reject the request with a `406 Not Acceptable` (or similar) error.

Could you please adjust this test case to use the correct media type?
