#### Current Behavior:
---
The automatic-payments_api_automatic-pix-extraday-core_test-module_v2 test (contained in plan automatic-pix-payments-retry_test-plan_v2) has behavior that create a extraday payment for D+1, and expect status SCHD. After certify the status SCHD, the test calls PATCH to cancel the payment and expects a negative response (HSC 422) from API with code in response equals to PAGAMENTO_NAO_PERMITE_CANCELAMENTO. This is a incorrect behavior according automatic payment documentation (written below in Portuguese).

"[Restrição] Para o Pix automático (“recurringConfiguration” igual a “automatic”) tanto o recebedor quanto o pagador poderão realizar o cancelamento, sendo permitido ao recebedor a solicitação de cancelamento até as 22:00 (Horário de Brasília) e ao pagador até as 23:59 (Horário de Brasília) do dia anterior à data de efetivação do pagamento, exceto para os casos de novas tentativas em dias subsequentes, onde apenas o recebedor pode cancelar, também até as 22:00h."

#### Expected Behavior:
---
The last step to cancel (PATCH) should be updated to expect a success response (execution until 21h59pm UCT-3), and/or the test should have a restriction time to execution (Validate if the current time is set between 10h01pm UTC-3 and 11:59pm UTC-3 - Return failure if not as defined on the test summary)

Hi George! Thanks for the ticket!

As highlighted in the API specification you mentioned, payment cancellation applies "exceto para os casos de novas tentativas em dias subsequentes, onde apenas o recebedor pode cancelar, também até as 22:00h."

In the case of the test modules referenced, we are attempting an extraday payment, which qualifies as a subsequent payment, meaning only the recipient can cancel it. Since the PATCH payment request is being executed by the logged-in user, who is the payer, the test correctly expects a 422 - PAGAMENTO_NAO_PERMITE_CANCELAMENTO response.

Therefore, your server should reject these requests to ensure a successful execution.
