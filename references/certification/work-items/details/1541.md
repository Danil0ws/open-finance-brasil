After analyzing the provided test log, it is possible to state that it is indeed considering the initially configured time os 120 seconds set on the test configuration for Webhook sync wait time, if you are mentioned another configured time please provide more details to facilitate the investigation.

Regarding the claim: Failing to inform that the SSA 5-minute mark has already passed.

According to the[ Open Finance Brasil Financial-grade API Dynamic Client Registration 1.0](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/240649661/EN+Open+Finance+Brasil+Financial-grade+API+Dynamic+Client+Registration+1.0+Implementers+Draft+3)

> ### 7.1. [Authorization server](https://openbanking-brasil.github.io/specs-seguranca/open-banking-brasil-dynamic-client-registration-1_ID3.html#name-authorization-server-2 "https://openbanking-brasil.github.io/specs-seguranca/open-banking-brasil-dynamic-client-registration-1_ID3.html#name-authorization-server-2")
>
> The Authorization Server shall support the RFC RFCs Dynamic Client Registration (DCR) [RFC7591](https://tools.ietf.org/html/rfc7591 "https://tools.ietf.org/html/rfc7591"), Dynamic Client Management (DCM) [RFC7592](https://tools.ietf.org/html/rfc7592 "https://tools.ietf.org/html/rfc7592") and [OpenID Registration](https://openid.net/specs/openid-connect-registration-1_0.html "https://openid.net/specs/openid-connect-registration-1_0.html")
>
> In addition, the Authorization Server
>
> 3. shall validate that the `software_statement` was issued (iat) not more than 5 minutes prior to the request being received;

Therefore it is up to the Authorization Server to validate if the SSA 5-minute mark has already passed and not the conformance suit as the client.

To be able to run the test successfully make sure to choose a lower Webhook sync wait time thus ensuring the 5-minute mark is not surpassed.

Feel free to reopen this issue if you have any other questions
