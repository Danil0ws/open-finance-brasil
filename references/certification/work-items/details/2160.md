## 📝 Descrição

**Description:**

In the Credit Portability API (`v1.0.0-beta.1`), the [Swagger YAML](https://raw.githubusercontent.com/OpenBanking-Brasil/openapi/main/swagger-apis/credit-portability/1.0.0-beta.1.yml) for the `POST /portabilities` response defines several required fields that are **not actually declared** in the corresponding object schema.

### Schema in question:

```
POSTResponseCreditPortability:
  type: object
  required:
    - data
  properties:
    data:
      type: object
      minItems: 0
      description: Conjunto de informações de contratos de empréstimos/financiamentos mantidos pelo cliente na instituição credora e para os quais ele tenha fornecido consentimento
      required:
        - contractId
        - contractNumber
        - ipocCode
        - portability
        - productType
        - productSubType
        - creationDateTime
```

However, when defining the `properties` inside `data`, only the following are actually declared:

* `portabilityId`
* `status`
* `creationDateTime`

### Problem:

* Fields such as `contractId`, `contractNumber`, `ipocCode`, `portability`, `productType`, and `productSubType` are listed as required, but **do not appear at all** in the object definition.
* As a result, the object fails schema validation and **does not appear correctly in generated Swagger UIs or client SDKs**:
  * ![image.png](/uploads/741d78c3c4510029046bf59e1b45663e/image.png){width=1069 height=558}

### Request/Suggestion:

1. **Clarify expected behavior:**
   * Should the fields `contractId`, `contractNumber`, `ipocCode`, `portability`, `productType`, and `productSubType` exist in the `POST /portabilities` response object?
   * If yes, please define them explicitly in the `properties` section.
   * If not, they should be removed from the `required` list to avoid inconsistencies.
2. **Update the OpenAPI spec accordingly**, so that:
   * Required fields are **only listed if their corresponding schema definitions exist**.
   * Schema is valid and usable by automated tooling (Swagger UI, code generators, validators, etc.).

> **Note:** In this schema, the `data` field is defined as `type: object`, but includes the keyword `minItems: 0`. This is not applicable. The `minItems` constraint is only valid for fields of type `array`, where it specifies the minimum number of elements required. For objects, this keyword has no effect and should be removed to avoid confusion or schema validation errors in tools that consume the specification.
