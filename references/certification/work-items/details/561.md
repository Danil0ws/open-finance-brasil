## 1. What Happened and what were you expecting?
In test "payments-api-idempotency-test-v2", when execute step "Call the POST Payments, with the same payload as the previous request but different idempotency id", conformity tool is sending same "endToEndId" that was send in previous step. In this case, we are returning error error because field "endToEndId" can not be used again.

Hi Daniel! Thanks for the ticket!

Following the [idempotency guidelines for Payments V2](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/24182812), a request with a different idempotency key should be treated as a different request. Therefore, the behavior for the test should be what has been updated at #557, since no validations should be made with an invalid consent.

Feel free to reopen the ticket if you think the issue wouldn't be correct by the new summary posted at #557 !
