Correct for FAPI, there's no requirement to have a refresh token and i believe, you can even have long lived access tokens, based on [5.2.2.  Authorization server - 21](https://openid.net/specs/openid-financial-api-part-1-1_0.html#authorization-server) - _should issue access tokens with a lifetime of under 10 minutes unless the tokens are sender-constrained;_

In Terms of Dependencies: For Phase 2 there's also an implicit requirement that a refresh token is issued.

Here We have that Consent has up to 12 months of a lifetime and, as an Access Token has at most 900 seconds, if you issue only an access token you would technically have an Authorised Consent that would have at most 15 minutes of life-time.

![image](/uploads/a9ff7225add36773b11b6cd7b2edb1a3/image.png)

### Comentário 8
**Autor**: Erick Domingues (@erick.domingues1)
**Criado em**: 12/01/2023, 20:06:35

Hi,

FAPI Brazil supersedes FAPI which in turn supersedes OAUTH (RFC6749), so, even if the RFC says it's optional when FAPI Brazil inform that it "shall support refresh tokens;" we will always expect it to be returned.

This is also enforced on the payments state machine that will expect the refresh token to be used once the AT 15 minutes life time is expired - https://openfinancebrasil.atlassian.net/wiki/spaces/DraftOF/pages/9896178/M+quina+de+Estados+-+v2.0.0+-+Pagamentos

That being said, we can only update the tests to support any additional scope if this requirement is well-defined on the existing documentation.
