## 📝 Descrição

**Observed behavior** 

On POST `/consents`, the PCM event always reports `additionalInfo.personType = "PF"`, even when the consent payload is for a legal entity (PJ). The handler reads `businessEntity` from the response body, but the POST `/consents` response (schema `ResponseConsent`, v3.3.1) does not include that field, so the check always fails and falls back to `"PF"`.

**Expected behavior**

Per the PCM rule for POST `/open-banking/consents/v3/consents` (role `CLIENT`), `personType` must be derived from the **request payload**: `"PJ"` when `data.businessEntity` is present, `"PF"` otherwise.
