## 📝 Descrição

In the corporate (PJ) scenario, where multiple approvers are required, the consent must go through the PARTIALLY_ACCEPTED status. However, the test expects the consent status returned in the GET request to be APPROVED, which prevents successful execution.

Currently, all corporate accounts in the institution require multiple approvers, which means the consent cannot reach the APPROVED status directly without first transitioning through PARTIALLY_ACCEPTED.

Considering that today (2026-02-27) is the deadline for executing the **fvp-enrollments_api_payments-core_open_test-module_v2-2** scenario, it will not be possible to achieve a successful result due to this behavior.

The same issue also occurs in the FVP tests for the other modules:
 
Production Functional Tests for Payments E2E – API Version 4;

Production Functional Tests for Automatic Sweeping Payments – API Version 2.2;

Production Functional Tests for Automatic Pix Payments – API Version 2.2;

How should we deal with this?
