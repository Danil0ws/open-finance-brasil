Hi, @alinnezanin ,

Thank you for opening the issue!

After reviewing the provided test logs, I found that the failure occurs during the attempt to create the first payment. 

When test module callis `POST recurring-payments` for the first payment, it is expected a **201** response,

but instead received a **422 UNPROCESSABLE_ENTITY** error from the Authorization Server.

It seems that the test module did not reach the second payment attempt, as the first payment creation failed. Therefore, the issue doesn't appear to be related to the second payment having the same `paymentReference`.

The conformance suite seems to be working as expected in this regard. If you have additional logs or comments, feel free to add them here, and reopen the issue,
