Therefore, we cannot run all tests in a single plan because of this DCR.

Hi @marcelino.junior, thanks for bringing this up.

We have published an adjustment to the **Enrollments API - v2.3.0-rc.1 - Payments - Conformance Suite** test plan and to the **enrollments_api_embedded-revoked-top-origin-rejection_test-module_v2-3** test module.

The test plan now includes two new fields:

* `registration_client_uri`
* `registration_access_token`

We have also removed the DCR step from the revoked test module. The test will now perform only DCM, using the registration information provided through these fields. This should allow you to proceed with the test module without attempting a new DCR.

**Could you please rerun the test and confirm whether it completes successfully?**

For regression testing purposes, the Mock Bank allows more than one DCR for the same Software Statement. Because of this difference in behavior, the issue was not reproduced during before the release. Thanks for raising it and helping us identify the gap.

Please feel free to reopen this ticket if you encounter any further issues.
