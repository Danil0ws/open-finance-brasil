Hi @rodrigo.machado1!

Thanks for opening the ticket!

The cause of the failure is not that conformance suit is expecting the inclusion of the field expirationDateTime, but the fact that it is being sent empty. The conformance suit identifies whether this fields is being sent, and in cases where it is, then it checks its content. We understand the correct behavior is that optional fields should only be sent when they have been filled with some information, so they cannot be empty. If there is no information to be added to the optional field, then it should not be included in the body of the response at all.

Therefore, to ensure that the test module runs successfully, make sure that:

1. When POST automatic-payments/v1/recurring-consents is called not sending expirationDateTime in request_body, the response does not include expirationDateTime in the response body, not even if empty.

This is a standard adopted to ensure that conformance suit is able to validate fields that are sent in the responses,

If you understand that this behavior should be reviewed, please create a ticket directory specifically to the appropriate Wortgroup.
