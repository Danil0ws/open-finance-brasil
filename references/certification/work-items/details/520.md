## 1. What Happened and what were you expecting?

According to the [Informa #218](https://mailchi.mp/18107e66cfae/open-banking-informa-9162397?e=9b9743fbe2) and also to the [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749#section-3.3) invalid scopes should be **ignored** from the response.

We understand that we shoudn't return the openid scope in token request with client_credentials according to the [Informa #218](https://mailchi.mp/18107e66cfae/open-banking-informa-9162397?e=9b9743fbe2), but we understand that in this cenario, when the scopes consents openid payments are sent, if the client has the scope consents and the client_credentials flow is used, this scope (consents) could be in response. Could you confirm to us?

Hi Eduardo and Rafael! 
Indeed, it is a similar scenario, but different in some ways.

In this case, there is an error at the Conformance Suite since we are now sending the "consent" scope when we shouldn't, since the only scope required to access the payments API is "payments". If it was the case to send both the "payments" and "consents" scope, if the implementation supported both, it should return the "consents" scope as well. If not supported by the implementation, the scope should have been narrowed to only "payments".

In the case of #519, the conformance suite also requests the "openid" scope in a client_credentials flow, when it is not permitted. Therefore, it is expected that the implementation will narrow the scopes sent to the ones permitted,  as stated at https://www.rfc-editor.org/rfc/rfc6749#section-3.3.

In a nutshell, this issue is unexpected behavior for the CS and we will fix it. I will post the updates here.

Thanks for the ticket!
