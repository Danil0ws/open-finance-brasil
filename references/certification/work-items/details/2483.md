## 📝 Descrição

**Environment / Evidence**

* Public conformance test log: [https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=OdBO2CuGWnmd5q4&public=true](https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=OdBO2CuGWnmd5q4&public=true)
* Reference: Open Finance Brasil Swagger (see screenshot attached)

**Description**
When the engine makes the initial request to create a payment consent (`POST https://mtls-openfinance.opb.bricks.dev.fsapps.io/open-banking/payments/v5/consents`), the payload is missing the field `data.payment.porpuse`.

This field is **required** when `payment.type` is `PIX`, according to the Open Finance Brasil API definition (Swagger).

**Steps to Reproduce**

1. Run the conformance flow for PIX payments (v5)
2. Observe the first call to:
   `POST /open-banking/payments/v5/consents`
3. Inspect the request body sent by the engine.

**Actual Result**

* The request body does **not** include `data.payment.porpuse`.

**Expected Result**

* The request body **must** include `data.payment.porpuse` whenever `payment.type=PIX`, to comply with the spec and pass validation.

**Attachment**

* Swagger screenshot showing `data.payment.porpuse` as required for `PIX` (see image in the issue).
