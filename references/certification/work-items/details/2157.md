Hi Rogerio! Thanks for the ticket!

According to the [Open Finance Brazil Security Specification](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/245760001/EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0+Implementers+Draft+3#7.2.2.-Authorization-server), the Authorization Server must ensure that access tokens are issued with sufficient scopes to access the data specified in the `Permission` element of a linked Consent Resource.

This means that even if a specific scope is not included in the redirect request, if it's present in the permissions of the consent, it **must** be included when issuing the access token.

In the test below, the resource permissions are correctly defined in the consent (as shown in the image). 

![image.png](/uploads/a3bbf7b2d5c4e499b9ccb2bb405f2e46/image.png){width=1551 height=127}

Therefore, the Authorization Server should have added the corresponding `resources` scope to the access token during issuance.

As such, there is no issue with the Conformance Suite in this case. If your server correctly includes the required scope, the test should proceed without further problems.

Let us know if you need any additional support—we’re happy to help!
