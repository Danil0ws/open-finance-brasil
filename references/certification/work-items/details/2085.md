"casos de novas tentativas em dias subsequentes, onde apenas o recebedor pode cancelar, também até as 22:00h"

Hi @rogeriorocha083 

Thanks for contacting us.

The test behavior is aligned with the specification, and the rejection message PAGAMENTO_NAO_PERMITE_CANCELAMENTO is expected in this scenario. According to the documentation:

_"Casos de novas tentativas em dias subsequentes, onde apenas o recebedor pode cancelar, também até as 22:00h."_

In this test, even though the recipient is the one initiating the cancellation, the rejection is expected because the test scenario is designed to validate cases where the payment status does not allow cancellation.

**Looking at the test steps:**

- The test retrieves the consent information and confirms that the isRetryAccepted flag is set as true, meaning the transaction is eligible for retries.

- A secondary payment attempt is scheduled and successfully reaches the SCHD status.

- The test then attempts a cancellation via PATCH /pix/recurring-payments/{recurringPaymentId}, which is expected to return 422 - PAGAMENTO_NAO_PERMITE_CANCELAMENTO.

This behavior occurs because the system enforces business rules that prevent cancellation in specific cases. If the original payment attempt has already failed and a retry attempt is scheduled, the system ensures that the cancellation does not interfere with this automatic retry logic.
