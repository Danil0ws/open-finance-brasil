#### Current Behavior:
---
O fluxo de erro do teste é uso indevido de um token client_credentials, aguardando status 401 (deveria aceitar também status 403, [como discutido aqui](https://gitlab.com/raidiam-conformance/open-finance/certification/-/issues/1436#note_1805659888)), ao invés de indicar erro de negócio que retorna status 422.

#### Expected Behavior:
---
O fluxo descrito na documentação está muito genérico, de fato. No entanto, entendemos que os fluxos de erro que devem finalizar com rejeição do consentimento devem ser erros de negócio que finalizam com status 422.

![image](/uploads/3390f2745c034908d3bf921be30a980b/image.png)

Outros tipos de erro, como uso indevido de um token client_credentials (status 401 ou 403) ou demais erros 4xx ou 5xx, não deveriam finalizar com a rejeição do consentimento. Agradecemos desde já por considerarem.

Hi Eri! I agree with you. Security issues should not trigger any business logic, as moving the status for the consent.

Because its clearly stated at the specification that any error at this endpoint should move the consent to REJECTED, we suggest for the WG the following:

* Change the description of the POST Consents Authorize Payload so that it is clear that only 422 errors should move the consent to REJECTED.

Given this, we propose that the test module shold be changed as follows:

Ensure payment without redirect cannot be executed if Enrollment status is "AWAITING_ACCOUNT_HOLDER_VALIDATION".\
• Call the POST Enrollments Endpoint\
• Expect a 201 response - Validate the response and check if the status is "AWAITING_RISK_SIGNALS"\
• Call the POST Risk Signals endpoint sending the appropriate signals\
• Expect a 204 response\
• Call the GET enrollments endpoint\
• Expect a 200 response - Validate the response and check if the status is AWAITING_ACCOUNT_HOLDER_VALIDATION\
• Call POST consents with valid payload, sending the correct EnrollmentID\
• Expects 201 - Validate response\
• Call POST Consents Authorize With Mocked Payload on the FidoAssertion using the client_credentials token\
• Expects 401 **or 403**\
• Call the GET consents endpoint\
• Expects 200 - Validate if status is **AWAITING_AUTHORISATION**

We will wait the WG confirmation to make the change, since differs from what is stated at the specification.
