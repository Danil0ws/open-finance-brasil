## 📝 Descrição

## 1. Requirements

Squad Sandbox together with the Security WG required that all dcr-subjectdn tests stop sending Brazilian-specific attributes in human-readable format based on the current [DCR Specification](https://github.com/OpenBanking-Brasil/specs-seguranca/blob/main/open-banking-brasil-dynamic-client-registration-1_ID2-ptbr.md#an%C3%A1lise-do-distinguished-name-do-certificado--certificate) and be sent on numerical format.

This means that the fields below should always be sent in OID numeric format:
- businessCategory
- jurisdictionCountryName
- serialNumber

 
## 2. Update Needed

For all tests, on the first call, which is testing if the organisation is accepting human-readable OID format for all attributes, the Brazilian-specific fields should be sent on numeric OID. Meaning this:


"tls_client_auth_subject_dn":"jurisdictionCountryName=BR,businessCategory=Private Organization,UID=368bceef-6096-4e1a-a702-64c07d12c98a,serialNumber=43142666000197,CN=tpp.sandbox.openbanking.org.br,OU=74e929d9-33b6-4d85-8ba7-c146c867a817,O=Open Banking Brasil,L=Sao Paulo,ST=SP,C=BR"

Should become:


"tls_client_auth_subject_dn":"1.3.6.1.4.1.311.60.2.1.3 =BR, 2.5.4.15 =Private Organization,UID=368bceef-6096-4e1a-a702-64c07d12c98a,2.5.4.5=43142666000197,CN=tpp.sandbox.openbanking.org.br,OU=74e929d9-33b6-4d85-8ba7-c146c867a817,O=Open Banking Brasil,L=Sao Paulo,ST=SP,C=BR"

List of tests to be updated
- dcr-subjectdn
- resources-api-dcr-subjectdn
- resources-api-dcr-subjectdn-v2
- payments-api-dcr-subjectdn
