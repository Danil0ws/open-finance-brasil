## 1. What happened and what were you expecting?

Hello.

We are facing a little issue involving the scope when call an API POST Consents. 

When we are executing the test payments_api_contenttype-jwt-refreshtoken_test-module_v3,we received scope "openid payments" when the test call POST /consents.

Looking the official document, the tokens that will be used for consents endpoints should have only scope "payments".

"Os tokens utilizados para consumo nos endpoints de consentimentos devem possuir o scope `payments` e os `endpoints` de pagamentos devem possuir os `scopes`, `openid` e `payments`." 

Could you analyze this issue?

Hi Vitor! Thanks for the ticket!

According to the [security specs](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/82083996/EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0+Implementers+Draft+3#7.2.2.-Authorization-server), the authorization server: 

* shall not reject an authorisation request requesting scopes broader than those necessary to access data specified in the Permissions element of a linked Consent Resource object;

In that sense, although the endpoint really expects the "payments" scopes, a request with broader request shouldn't be denied.

We are happy to help with any additional needs!
