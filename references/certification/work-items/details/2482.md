## 📝 Descrição

**Observed behavior/evidence:**

The FVP Scheduler is creating new tickets for additional failure evidence instead of appending the evidence to the original ticket. This happens because the Scheduler/automation is not linking the executions to the same test, due to a mismatch in the test module name used for correlation.

Example:

Ticket #121125 - Original ticket opened for a failure in **Step 1**.

![image.png](/uploads/dcf28707a2176f474d0b15707497d31d/image.png){width=423 height=78}

Ticket #152601 - A new ticket is created by the Scheduler/automation when **Step 2 fails**, instead of updating **#121125** with the new evidence.

![image.png](/uploads/a61fa7bcba0e4e835ba8be7418ceeef3/image.png){width=491 height=102}

---

**Expected behavior:**

The Scheduler/automation must correlate executions of the same test module and always attach new evidence to the existing ticket, rather than opening a new one. To do that, it should use a normalized/raw test module name (without step/version suffixes) for ticket matching.

* Example normalization:
  * FVP original test name: 
    * automatic-payments_api_automatic-pix-scheduling-retry**~~\_1-3_test-module_v2-2~~**
  * Service Desk automation test name: 
    * automatic-payments_api_automatic-pix-scheduling-retry
