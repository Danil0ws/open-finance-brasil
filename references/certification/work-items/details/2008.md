## 📝 Descrição

**Observed Behavior:**
 Test: automatic-payments_api_automatic-pix-intraday-core_test-module_v2

Executes the following steps:
* Step: Call the POST recurring-payments endpoint, using an access token derived from the refresh token in the configuration. Send a new E2EID, date as D+0, set the amount as double the original value, and include the paymentId in originalRecurringPaymentId. Expected Response: 422 DETALHE_TENTATIVA_INVALIDO - Validate Error Message.
However, the test does not account for asynchronous validations as allowed by the specification. 
The documentation indicates that field validations in retries against the original payment can be performed asynchronously, as stated in:
6.1.21 Detalhe tentativa inválida: Validates whether the parameters provided are consistent with the original payment attempt (DETALHE_TENTATIVA_INVALIDO).

Current implementation only validates 422 DETALHE_TENTATIVA_INVALIDO synchronously. Other tests already account for similar asynchronous behavior, such as:
* automatic-payments_api_automatic-pix-invalid-dates-later_test-module_v2 

**Observed Error:**
* Test fails if a 201 CREATED response is returned, as asynchronous behavior is not being considered for this scenario. 
Expected Behavior: Update the test to handle both synchronous and asynchronous validations. Steps to include:
* Expect: 422 DETALHE_TENTATIVA_INVALIDO or 201 CREATED - Validate Response. 

Evidence (test ID): https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=ynNWCCnfCNnzdrf
