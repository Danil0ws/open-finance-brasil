## 📝 Descrição

## 1\. What happened and what were you expecting?

As specified at 3v4 for beta.4, when repeated dates are sent at the schedule.custom array, the error PARAMETRO_INVALIDO should be returned.

In that sense, the new summary/behavior for the test should be:

Ensure that consent for recurring payments cannot be created if it exceeds the consent limit rules\
• Call the POST Consents endpoints with the schedule.daily.startDate field set as D+60, and schedule.daily.quantity as 672\
• Expects 422 - DATA_PAGAMENTO_INVALIDA\
• Call the POST Consents endpoints with the schedule.weekly.dayOfWeek field set as SEGUNDA_FEIRA, schedule.weekly.startDate field set as D+10, and schedule.weekly.quantity as 104\
• Expects 422 - DATA_PAGAMENTO_INVALIDA\
• Call the POST Consents endpoints with the schedule.monthly.dayOfWeek field set as 01, schedule.monthly.startDate field set as D+150, and schedule.monthly.quantity as 20\
• Expects 422 - DATA_PAGAMENTO_INVALIDA\
• Call the POST Consents endpoints with the schedule.custom.dates field set as D+100 and D+732\
• Expects 422 - DATA_PAGAMENTO_INVALIDA\
• Call the POST Consents endpoints with 2 identical items at schedule.custom.dates field, set as D+1 and D+1\
**• Expects 422 - PARAMETRO_INVALIDO**
