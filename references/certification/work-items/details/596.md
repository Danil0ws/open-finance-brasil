## 📝 Descrição

As discussed at #511, the payments-api-qres-with-transaction-identifier-test-v2 should also accept the error message to be sent at GET Payments. Therefore, the updated summary/behavior for the test should be:

**Ensures that a payment consent created with a QRES and a transaction identifier is rejected**

- Call POST Consents with localInstrument as QRES \n
- Expects 201 - Validate Response
- Redirects the user to authorize the created consent
- Call GET Consent
- Expects 200 - Validate if status is "AUTHORISED"
- Call POST Payment Endpoint with a transactionIdentification
- Expects 422 DETALHE_PAGAMENTO_INVALIDO
- Validate Error Message

If no errors are identified:
- Poll the Get Payments endpoint with the PaymentID Created while payment status is RCVD, ACCP or ACPD
- Expects a payment with the definitive state (RJCT) status and RejectionReason equal to DETALHE_PAGAMENTO_INVALIDO
- Validate Error message
