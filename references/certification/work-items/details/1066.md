Hi Fernando,

The failure in the test in not due to the validation in the ROLEs. The reason is because the well-known from the authorization server only contains "openid" as a scope supported: **\[ "openid"\]**. However, the payments API is published in the directory, so it should support the scope payments from the well-known perspective.

Note that from https://openid.net/specs/openid-connect-discovery-1_0.html#ProviderMetadata 

**scopes_supported: JSON array containing a list of the OAuth 2.0 [RFC6749] scope values that this server supports.**

So the scopes_supported field should contain all scopes supported by the server, and not the APIs that they are allowed to use.

Furthermore, the table you are referring to on https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/82051199/EN+Open+Finance+Brasil+Financial-grade+API+Dynamic+Client+Registration+1.0+Implementers+Draft+3#7.2.-Regulatory-Roles-for-OpenID-and-OAuth-2.0-Mappings, states that the scopes in the table are the APIs the institution is allowed to use, and not the scopes that the server supports:

**Those roles reflect the institutions authorization from the Central Bank and, consequently, the APIs they are allowed to use.**

In conclusion, the test does two types of validation:

1. If the scopes in the well-known from the Authorization Server are in line with the APIs published by the server.
2. If the scopes in the well-known from the Authorization Server are in line with the ROLEs created by the organization.
