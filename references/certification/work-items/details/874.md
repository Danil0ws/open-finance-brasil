## 1. What Happened and what were you expecting?

The consent generated by the tool provides the following bank account details:

        "creditorAccount": {
          "ispb": "18236120",
          "issuer": "0001",
          "number": "10085879",
          "accountType": "CACC"
        }
In consent, the localInstrument is the DICT, using the CPF (proxy) key: 06098692564

However, when our core bank queries the CPF key 06098692564 in production, DICT returns the bank account data with an account type other than CACC:

      "Entry": {
        "Key": "06098692564",
        "KeyType": "CPF",
        "Account": {
          "Participant": "18236120",
          "Branch": "1",
          "AccountNumber": "10085879",
          "AccountType": "TRAN",
          "OpeningDate": "2018-12-01T01:22:21.006Z"
        },
        "Owner": {
          "Type": "NATURAL_PERSON",
          "TaxIdNumber": "06098692564",
          "Name": "E****k ******** D*********s"
        },
        "CreationDate": "2020-10-08T16:18:41.969+0000",
        "KeyOwnershipDate": "2020-10-08T16:18:41.968+0000"
      },

Note that the TRAN account type is not the same as CACC, and our institution validates this information and won't let the transaction proceed, generating an error in the FVP tool.
