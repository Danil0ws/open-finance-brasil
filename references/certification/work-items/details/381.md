## 1. What Happened and what were you expecting?

Hi, [per "Open Finance Brasil Informa" number 218](https://mailchi.mp/18107e66cfae/open-banking-informa-9162397?e=321948ea97), consent creation calls without the `openid` scope shall be accepted.

Would this be OpenID FAPI compliant? Will such an implementation pass the international OpenID FAPI conformance suite?

Please note that the international OpenID certification is a base requirement for the Brazil OBB certification. So, while a Brazil-specific test for this could be developed, would such an implementation remain compliant with international OpenID FAPI specs? Or would it break OpenID FAPI once participants need to renew their certification?

Thanks in advance for your thoughts on this.

The idea behind this was that we had servers refusing client credentials `grant_type=client_credentials`. that wasn't requiring the openid scope on payments-consents request. This was leading to interoperability issues on production.

Participant did think this was required because of the [following line on the specification](https://openbanking-brasil.github.io/openapi/swagger-apis/payments/1.2.0.yml)

` Os tokens utilizados para consumo dos endpoints desta API devem possuir os scopes openid e payments.`

### Comentário 4
**Autor**: Joseph Heenan (@joseph.heenan)
**Criado em**: 01/09/2022, 22:19:59
**Atualizado em**: 02/09/2022, 12:28:12

consent creation is done using an access token obtained using the client credentials grant. The `openid` `scope` has no defined meaning in that grant. The FAPI conformance suite (and functional suite) both do not pass `scope=openid` when obtaining an access token using `grant_type=client_credentials`.
