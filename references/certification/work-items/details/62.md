## 📝 Descrição

Hello, the test "Payment-api-negative-tests" uses a consent consumed in the call of the endpoint "POST /payments/v1/pix/payments" and expects a return 422 with the code "PAGAMENTO_DIVERGENTE_DO_CONSENTIMENTO or VALOR_INCOMPATIBLE" but the correct thing is to validate the "CONSENTIMENTO_INVALIDO".

I think there are two problems:

1- The "Payment-api-negative-tests" test change payment currency value to "ZAR" and the currency value should be only "BRL" according to https://openbanking-brasil.github.io/areadesenvolvedor/#tocS_PaymentPix. It's correct to say that http status for currency different from "BRL" should be 400, right?

2-**The correct expected error code should be `PAGAMENTO_DIVERGENTE_DO_CONSENTIMENTO` for "Payment-api-negative-tests" test.**

When an attribute into payment creation request, which is not "value" attribute, is different from consent attributes the expected error is 422 `PAGAMENTO_DIVERGENTE_DO_CONSENTIMENTO`. 

If payment attribute "value" is different from consent attribute "value", the error should be 422 `VALOR_INCOMPATIVEL`.

If payment creation request try to consume a consent with diffrent from `AUTHORISED`, the error should be 422 `CONSENTIMENTO_INVALIDO`
