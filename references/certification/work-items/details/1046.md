## 1. What happened and what were you expecting?

In the test case consents_api_multiple-consents-extension-cond_test-module_v2 We understand that after the completion of the multiple jurisdiction pending, according to the specification, if there is an attempt to extend this, the response should be a 422 DEPENDE_MULTIPLA_ALCADA, but in the case where it has not yet been completed, the behavior should be the same? In the case of other APIs, the v2.0 implementation guide says that 403 forbidden should be returned with the code STATUS_RESOURCE_PENDING_AUTHORISATION, while the multi-level is not completed.

Could you clarify what the expected behavior is in the two situations, if the extension attempt is made while the multiple jurisdiction is not resolved and if the extension attempt is made after the multiple jurisdiction is completed?

Hi Eduardo! We've got the response from the WG, and since there will be an authorization_code and valid access token even if only one grants validates the consent, the response should also be 422 - DEPENDE_MULTIPLA_ALCADA in this case. 

Worth mentioning that the error message 403 - STATUS_RESOURCE_PENDING_AUTHORISATION mentioned is mentioned for the resource APIs, and not the consent one.

By any means, we have asked the WG to add the 403 error message at the swagger as well.

We are happy to help with any additional needs!
