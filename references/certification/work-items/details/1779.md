The test: enrollments_api_expired-prerisksignal-enrollment_test-module_v1;

Has the following objective: Ensure that enrollment is expired in 5 minutes when status is set as AWAITING_RISK_SIGNALS;

Therefore Conformance suit has to wait 5 minutes to test the desired REJECTED state.

According to NRJ specifications available at[ Máquina de estados - v2.0.0-beta.1- \[SV\] Vínculo de dispositivo](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/511803449/M+quina+de+estados+-+v2.0.0-beta.1-+SV+V+nculo+de+dispositivo)

While status is on AWAITING_RISK_SIGNALS, the enrollment is rejected if after 5 minutes it does not transition to the next status. As can be seen in:\
![image.png](/uploads/f537a6f95346bc3a25d00ba24310a811/image.png){width="426" height="274"}

According to The [Security spec](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/240649123/EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0#5.2.2.-Authorization-server)

> #### 5.2.2. Authorization server
>
> 1. shall issue access tokens with an expiry no greater than 900 seconds and no less than 300 seconds;

Taking all of that into consideration, the behavior of the Conformance suit in this scenario will be improved so that:

* Conformance suit Calls token endpoint to fetch a new Access token with grant Client Credentials after waiting for the 5 minutes, so that it is guaranteed that a valid token is used.
