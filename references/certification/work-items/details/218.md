## 1. What Happened and what were you expecting?

Hi, this isn't an issue with the conformance engine per se, but it's something we need to address in production.

Are there restrictions on the contents of the `sector_identifier_uri` field? 

For example, must the specified URI (or its hostname domain) be contained under the TPP's software statement somewhere? Or may clients submit any arbitrary URI in this field?

The reason we ask is, when the authentication server finds this field, it MUST verify the redirect_uris against the list returned by the URI endpoint. So, if there is no restriction, then the Directory's URIs get bypassed and a malicious user could specify any arbitrary URI in the redirect_uri field and then provide their own list of valid redirect_uris inside `sector_identifier_uri`.

I think the logical rule would be to restrict this field to always point to the Directory?

E.g. https://keystore.sandbox.directory.openbankingbrasil.org.br/74e929d9-33b6-4d85-8ba7-c146c867a817/368bceef-6096-4e1a-a702-64c07d12c98a/redirect_uris.json

Otherwise this listing will get bypassed by the TPPs.

Thanks in advance for your advice concerning this.
