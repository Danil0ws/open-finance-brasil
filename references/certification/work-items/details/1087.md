## 📝 Descrição

Hi, I noticed that the requests in `payments_api_recurring-payments-consent-limit_test-module_v4` are not sending the `x-fapi-interaction-id` header. 
![Screen_Shot_2023-11-29_at_11.56.41_AM](/uploads/be416856fd18702a6c9ebb0c22f44f40/Screen_Shot_2023-11-29_at_11.56.41_AM.png)

From my understanding in a case such as this we should return status code 400 (and such is enforced in modules such as `payments_api_consents_negative_test-module_v4`). Anyway if this is unintended behavior, it is blocking the tests for the moment.
