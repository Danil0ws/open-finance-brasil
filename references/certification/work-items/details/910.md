## 📝 Descrição

Test payments_api_qres-with-transaction-identifier_test-module_v3 is suggesting we should return error when transactionId is sent. But that's not true anymore: 


– QRES - Caso o QR Code estático possua o dado <i><<i/>TxId<i>><i/> preenchido, o campo transactionIdentification deverá ser preenchido com este valor, caso o QR Code não possua o <i><<i/>TxId<i>><i/> o campo transactionIdentification não deverá ser preenchido. O <i><<i/>TxId<i>><i/> deve conter até 25 caracteres alfanuméricos ([a-z|A-Z|0-9]).  

Source: https://raw.githubusercontent.com/OpenBanking-Brasil/openapi/main/swagger-apis/payments/3.0.0-rc.1.yml


The qres from the tests does not have txId: 
![image](/uploads/be01d6863b1802498c9ba31e0f976edf/image.png)

So that test should either be removed or not ask for errors.

Hi,

As you mentioned, `payments_api_qres-with-transaction-identifier_test-module_v3` expects an error to be returned when POST Payments sends `transactionIdentification` along with the QRES used by the test.

Considering that the specification mentions the cited field should only be sent when the QR code displays the data <<a>TxId> and that in this test the QR code being sent does not have the data <<a>TxId>, the test indeed should expect an error if a `transactionIdentification` is returned.

In other words, the test is in accordance with the specification's requirement highlighted in bold below:

>– QRES - Caso o QR Code estático possua o dado <<a>TxId> preenchido, o campo transactionIdentification deverá ser preenchido com este valor, **caso o QR Code não possua o <<a>TxId> o campo transactionIdentification não deverá ser preenchido.** O <<a>TxId> deve conter até 25 caracteres alfanuméricos ([a-z|A-Z|0-9]).

In that sense, could you elaborate on your doubt?
