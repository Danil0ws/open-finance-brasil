Hi All!

We've taken this issue to be discussed at the Specifications WG and the resolution is stated at INFORMA 309:

"Reforçamos que os campos totalPages e totalRecords foram retirados dos endpoints da v2.0.0 da API de Iniciação de Pagamentos, conforme proposta intitulada “Proposta para retirada dos campos totalPages e totalRecords na API de Iniciação de Pagamentos – P39” aprovada na 128ª Reunião do Conselho Deliberativo do dia 11/08/2022, pois não retornam resultados pagináveis. "

In that sense, the behavior will be required at Payments API V2 and, therefore, it will continue to be enforced by the Conformance Suite. 

We understand that errors may be implemented generically by some participants which may cause additional difficulties to implement it, but the fields totalRecords and totalPages should not be sent at the responses to successful execution.

Thanks for the feedback, and we are happy to help with any additional needs!

@christianraidiam ,

In the Open Finance documentation there is an [item](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17377470/Pagina+o#Meta) informing about the mandatory attributes totalPages and total Records.

![image](/uploads/957356d13e85e28e81a1209b00af81b0/image.png)


In the Phase 2 APIs specification (versions 2.0.1), the attributes totalPages and totalRecords are required on error objects. Here's an example:

![image](/uploads/0466352ee6ff7fd6ff4fd413b4ad1111/image.png)

Commonly, error handling is architecturally implemented generically, which is our case.

Therefore, we adopt architectural solutions to handle errors both within our systems, security engine and API Gateway.

As a result, these divergences of mandatory information in error objects architecturally impact our solutions (systems, security engine and API Gateway).

We request that you standardize the content of the meta attribute (totalPages, totalRecords and requestDateTime) for all APIs in order to avoid this type of problem.

Hi All! Thanks for the ticket!

You are actually receiving this error because you are sending the totalRecords field on the response, and that is not on the swagger:

**Response**:

{ "errors": [ { "code": "400", "title": "BAD_SIGNATURE", "detail": "A assinatura do payload é inválida" } ], "meta": { "totalRecords": 1, "totalPages": 1, "requestDateTime": "2023-01-25T11:29:05Z" } }

**Swagger**:
![image](/uploads/a585773c9c7ac23b5316b38b9cb3822d/image.png)

Fields that are not on the swagger can be sent on the payload, but they need to follow [Extensibilidade Specs](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17377516/Extensibilidade), and comply with the regex ^(\[A-Z\]{4})(-)(.\*)$. That's why the test is failing.

In this specific case, for example, the field should be sent as RAID-totalRecords, with these four initial letters as the unique identifiers from your institution.

In that sense, the field totalRecords should be either removed from the response or adapted to comply with the regex for additional Fields.

We are happy to help with any additional needs!
