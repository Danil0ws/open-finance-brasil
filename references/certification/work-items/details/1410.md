## 📝 Descrição

## 1\. What happened and what were you expecting?

During the test, a POST payment is being sent by the suit with both "manual" and "automatic" RiskSignals.

![image.png](/uploads/37fde6c5f666a461547306d510fd1e6c/image.png)

Although the object RiskSignalsPayments is not described as "OneOf", by following logic, it is. The descriptions below add this restriction:

![image.png](/uploads/982e76534b29efceaad9688120e1739e/image.png)

![image.png](/uploads/4fb472c2f39d4e7e0332663b09b6b242/image.png)

Unless there is a case when the user IS and, at the same time, IS NOT present during payment, either "manual" or "automatic" should be used, but not both.

Please let me know if I'm missing a case when both cases apply.

Hi,

Thanks for bringing this to our attention.

We understand that the [**Automatic Payments**](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/289243438/Informa+es+T+cnicas+-+SV+Pagamentos+Autom+ticos+-+v1.0.0-rc.2)  specification might not be clear regarding riskSignals.manual and riskSignals.automatic and thus we are going to be addressing it to the appropriate work group to reach a understanding on the following points:

* As it is not clear when the transaction is going to happen in the presence of the user or not, when should each of the fields (manual, automatic) should be sent when POST Pix payments is called?
* In the way it currently is, the specification allows both fields to be sent, In case this fields are mutually excluding, then should the spec be updated so that “one of” is added?

Updates on this matters will be posted in this issue,
