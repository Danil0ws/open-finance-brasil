## 📝 Descrição

#### Current Behavior:
---
When a GET `/v4/consents/{consentId}` is made to MB after the consent expiration time, it incorrectly changes the consent status to REJECTED.

In the test provided in the evidence, the following is observed:

- A POST `v4/pix/payments` is successfully executed.
- Multiple GET `/v4/consents/{consentId}` return the correct consent status as expected (from `AUTHORISED` to `CONSUMED`).
- However, a GET `/v4/consents/{consentId}` made after the consent expiration unexpectedly changes the consent status to `REJECTED`.


#### Expected Behavior:
---
According to the state machine diagram, a consent status can not be updated to any other once it passes the status `CONSUMED`.
