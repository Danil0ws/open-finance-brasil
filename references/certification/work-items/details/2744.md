## 📝 Descrição

* Test module: `accounts_api_core_test-module_v2-5`
* Validator: `GetAccountsBalancesOASValidatorV2n5`

---

**Current behaviour**

Validator applies the following pattern to `AccountBalancesDataAvailableAmount.amount`:

`pattern:   ^\d{1,15}\.\d{2,4}$
maxLength: 20
`

Any negative value returned by the participant (e.g. `-9.54`) is rejected with:

`src: GetAccountsBalancesOASValidatorV2n5
result: FAILURE
msg: Value from element amount doesn't match the required pattern on the GetAccountsBalancesOASValidatorV2n5 API response
path: $.data.availableAmount.amount
`

Evidence: https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=YkvNt4ltSNtGR2n

Response payload:

`{
  "data": {
    "availableAmount": { "amount": "-9.54", "currency": "BRL" },
    "blockedAmount": { "amount": "353.70", "currency": "BRL" },
    "automaticallyInvestedAmount": { "amount": "-9.54", "currency": "BRL" }
  }
}
`

---

**Expected behaviour**

Validator should apply the pattern currently published by DTO for v2.5.0-estável:

`pattern:   ^-?\d{1,15}\.\d{2,4}$
maxLength: 21
`

Negative values (`-9.54`, `-1000.0400`) must pass validation. Only values that genuinely violate the pattern should produce `FAILURE`.

---

**Background**

DTO published Accounts v2.5.0-estável on 2026-04-24 with the pattern currently shipped by the motor (no `-?`). On 2026-05-05, DTO updated the same stable spec, re-adding `-?` and bumping `maxLength` to 21. The motor was released on 2026-05-15 using the pre-update snapshot (captured on 2026-04-16, DCL-743), so the validator is aligned with an outdated version of the spec.

References:

* Current v2.5.0-estável Swagger (DTO Confluence): https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1739096092/Swagger-+API+Contas+v2.5.0
* DTO commit that changed the pattern on 2026-05-05: https://github.com/OpenBanking-Brasil/all-services-repo/commits/main/api_accounts\_-\_open_finance_brasil/2.5.0.yaml
