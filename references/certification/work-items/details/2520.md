Hello @siddharth.eswaramoorthy Thanks for raising this.

`type`, `required`, and `properties` are [OpenAPI/JSON Schema](https://raw.githubusercontent.com/OpenBanking-Brasil/all-services-repo/refs/heads/main/api_payment_initiation_-_open_finance_brasil/5.0.0-beta.1.yaml) keywords (schema metadata), not payload fields. They describe how the Schedule schema is defined (e.g., “this is an object”, “these properties exist”, “these properties are required”), so they won’t appear as fields in the request/response body in Swagger UI.

In the [spec](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1283522868/Informa+es+T+cnicas+-+SV+Pagamentos+-+v5.0.0-beta.1), `payment.schedule` is defined as a $ref to #/components/schemas/Schedule, and Schedule is rendered in Swagger as the object you see (with additionalInformation and the oneOf options like ScheduleSingle, ScheduleDaily, etc.). The UI shows the resulting model, not the underlying schema keywords.

![image.png](/uploads/a35afe1267cda170f21610f9b7b2a619/image.png){width=900 height=276}\
So there’s no missing API field, the changelog entry is effectively reporting schema keywords, not new request/response attributes.

Please feel free to reopen this issue if needed.

Best regards
