Hi,

Thanks for opening the issue!

The failure in the mentioned test module happened due to the following reason:

When Conformance Suit executed: 

• Call the GET recurring-payment endpoint with the recurringConsent ID in the header.

It received from the Server a response_body missing the field paymentReference.

As described for paymentReference in the available specification:

**\[Restrição\] Campo de preenchimento obrigatório caso seja um pagamento de Pix automático, caso não respeitado, a instituição detentora deve retornar erro HTTP 422 com o código DETALHE_PAGAMENTO_INVALIDO.**

As this is a case of Automatic Pix, this field is required to be filled.

You can Find evidence of a successful execution of this test module trough the following file:

[test-log-automatic-payments_api_automatic-pix-intraday-core_test-module_v2-private_key_jwt-pushed-openbanking_brazil-plain_response-LCBOrE0dAeQhIUY.zip](/uploads/795ffd6bcaa38d45fe3a156dc74df4f6/test-log-automatic-payments_api_automatic-pix-intraday-core_test-module_v2-private_key_jwt-pushed-openbanking_brazil-plain_response-LCBOrE0dAeQhIUY.zip)

Make sure that all required fields have been filled for this endpoint response so that test module can be executed successfully!
