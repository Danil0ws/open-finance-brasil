Hi,

Thanks for opening the ticket!

Indeed as described the test module executes two response_code validations one following the other:

1. The first validation  expects a 200 response status which is correctly met by the implementation, this validation is done on top of the GET consents/{consentId} response, which happened just before this validation .
2. The second validation expect a 422 response status code. This specific validation regards the response_status_code related to the POST consents request, which is called just before the GET consents/{consentId} request. The 422 response is correctly expected as the test module is validating the creation of a consent for a DateTime grater then 1 year.

Therefore regarding this matter the conformance_suit is operating as expected. To ensure the test module can be executed successfully please make sure that:

1. When POST consents is called with DateTime grater then 1 year the response_status_code is 422.
