## 📝 Descrição

What is the expected behavior for the following cases:

The ITP sends a payload to create 10 payments at once through the POST /payments/v4/pix/payments endpoint, one of the payments was malformed, should the provider respond with an error and no payment should be created? Or should the provider return with success and only the payments that were successfully created?

The same goes for canceling payments through the PATCH /open-banking/payments/v4/pix/payments/consents/{consentId} endpoint, if there is an error canceling one of the consents payments, should the provider respond with an error and no payments should be canceled? Or should it cancel the ones that it can and return success? Or cancel the ones it can and return an error?

### Comentário 1

**Criado em**: 19/02/2024, 10:12:02

IF the ITP sends a payload to create multiple payments at once and one of the payments is malformed, than the provider have to move all the payments to RJCT with the rejectionReason FALHA_AGENDAMENTO_PAGAMENTOS.

This information is in the header of the API, in the section "Validações para pagamentos recorrentes". The same goes to the PATCH.
