## 📝 Descrição


#### Current Behavior:
---
The test does a PATCH to cancel a scheduled payment and expects a 422 with PAGAMENTO_NAO_PERMITE_CANCELAMENTO 

#### Expected Behavior:
---
According with the API description, it's possible to cancel a schedule payment in the previous day until 10 p.m. and the PAGAMENTO_NAO_PERMITE_CANCELAMENTO should be thrown if the payment status is different from SCHD or PDNG, what is not the case. If not allowed in the period, it should throw CANCELAMENTO_FORA_PERIODO_PERMITIDO.

**Here is the description:**

Esse endpoint deve ser usado para cancelar as transações que estejam em uma das seguintes situações:
Agendada com sucesso (SCHD), retida para análise (PDNG). Caso a requisição seja bem sucedida, a transação vai para a situação CANC.
Caso o status do pagamento seja diferente de SCHD/PDNG ou alguma outra regra de negócio impeça o cancelamento, a requisição PATCH retorna HTTP Status 422 com o code PAGAMENTO_NAO_PERMITE_CANCELAMENTO.
Caso receba um 422, a iniciadora deve fazer uma requisição GET no pagamento para verificar a situação atual dele, bem como detalhes associados.
[Restrição] Para o Pix automático (“recurringConfiguration” igual a “automatic”) tanto o recebedor quanto o pagador poderão realizar o cancelamento, sendo permitido ao recebedor a solicitação de cancelamento até as 22:00 (Horário de Brasília) e ao pagador até as 23:59 (Horário de Brasília) do dia anterior à data de efetivação do pagamento, exceto para os casos de novas tentativas em dias subsequentes, onde apenas o recebedor pode cancelar, também até as 22:00h.

Hi @marcelino.junior 

The conformance test was designed to validate a payment retry scenario on a subsequent day (known as an "extraday retry"). Following the specification for a **PATCH** request:

> **\[Restrição\]** ... exceto para os casos de **novas tentativas em dias subsequentes**, onde **apenas o recebedor pode cancelar**, também até as 22:00h.

![image.png](/uploads/d78fb8f71667e652bbc11162849bbe63/image.png)

Note:

* Your server is the payer in this test. 
* The payment is a new attempt (an extraday retry). 

According to the restriction above, the payer does not have permission to cancel a new payment attempt on a subsequent day. Therefore, the correct behavior of your API, and what the conformance suit expects, is for the cancellation attempt (`PATCH`) to return an error.

The `422` with the code `PAGAMENTO_NAO_PERMITE_CANCELAMENTO` is the expected response to validate that your implementation is correctly applying this business rule.

Please, feel free to reach out in case of further questions!
