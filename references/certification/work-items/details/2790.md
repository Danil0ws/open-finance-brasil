Prezados, bom dia.

Analisamos o log da execução `9XcCMxshDNknoCv` (test-id) do teste `credit-portability_api_portability-payment_core_alphanumeric_cnpj_test-module_v1` (motor `4bcd515282`, execução de 2026-07-01).

**Sobre o ponto de "não achar a API POST /portabilities"**

A falha ocorre na condição `GetCreditPortabilityV1Endpoint`, dentro do bloco _"Iterating through contractIds to find a contract with expected eligibility status → Checking Contract No.1"_. Essa condição **não está tentando chamar** `POST /portabilities` — ela é uma etapa de **descoberta**: percorre os `ApiResources` do `authorisation_server` no diretório de participantes buscando uma entrada com:

* `ApiFamilyType == "credit-portability"`,
* `ApiVersion` casando `^1\.[0-9]\.[0-9]$`, e
* algum `ApiDiscoveryEndpoint` terminando em `/open-banking/credit-portability/v{n}/portabilities`.

O endpoint `/portabilities` é usado apenas como âncora para localizar a URL-base da família `credit-portability` publicada por vocês no diretório. Uma vez encontrada essa base, o motor monta e chama de fato `GET /credit-operations/{contractId}/portability-eligibility`, exatamente como descrito no sumário do teste. Portanto, a chamada esperada nesse momento do fluxo está correta e alinhada ao que o sumário indica.

**Sobre o ponto de que a URL está disponível no diretório**

Confirmamos, pelo próprio log, que a API `credit-portability` v1.0.0 está registrada no diretório com todos os endpoints esperados (inclusive `/portabilities` e `/credit-operations/{contractId}/portability-eligibility`). **Porém**, essa registro está publicado em um `authorisationServerId` **diferente** daquele configurado no alias do teste.

* `authorisationServerId` do alias do teste: `993f85ba-4618-462f-bed1-5efd38feedb8`
* `authorisationServerId` onde a API `credit-portability` está publicada no diretório: `b8eaca3a-b5f9-475c-9686-c44198d01720` (Opus QA)

A busca de endpoints on-demand do motor (para APIs invocadas mais adiante no fluxo, como `credit-portability`) usa o `authorisation_server` identificado pelo `authorisationServerId` configurado no alias. Como o AS `993f85ba` não publica a família `credit-portability` no diretório, a condição não localiza a URL-base e o teste é interrompido.

**Como prosseguir**

Pedimos que verifiquem no diretório de participantes qual das opções melhor se aplica ao ambiente de vocês:

1. **Publicar a API `credit-portability` v1** também no AS `993f85ba-4618-462f-bed1-5efd38feedb8`, mantendo o alias do teste como está; ou
2. **Ajustar o alias do teste** para apontar `authorisationServerId` = `b8eaca3a-b5f9-475c-9686-c44198d01720`, que já publica a família `credit-portability` no diretório.

Após ajuste, rodem novamente o teste e nos retornem em caso de nova falha.
