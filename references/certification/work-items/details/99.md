On the following test modules 

consent-api-status-test
consent-api-status-declined-test
consent-api-expired-consent-test
resources-api-test

The conformance suite is refusing the creating of the consent claiming that the grouping is invalid. "Consent endpoint response not a valid permissions grouping"

Upon further inspection of a log: http://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=s7Q1mea9gtbPD8L

I understand that the conformance suite expects that the BANK returns the whole block of permissions set on "Operações de Crédito", however, given that it lacks all of the FINANCINGS and UNARRANGED_ACCOUNTS permissions (BUT includes LOANS and INVOICED FINANCINGS) a fail is being return.

I'm not sure if this behavior is compliant with the existing specifications. Looking at https://openbanking-brasil.github.io/areadesenvolvedor/swagger/swagger_consents_apis.yaml we have that

> A receptora deve enviar obrigatoriamente, no pedido de criação de consentimento, todas as permissions dos agrupamentos de dados as quais ela deseja consentimento. Caso a instiuição receptora envie permissões divergentes ao agrupamento especificado na tabela, a transmissora deve rejeitar o pedido da receptora dando retorno HTTP Status Code 400.

This means that the permissions sent at the request of the POST Consents should be always sent with a full data group. If the group is lacking it must return a 400. 

>  A transmissora deve retornar, da lista de permissions requisitadas, apenas o subconjunto de permissions por ela suportada, removendo da lista as permissions de produtos não suportados e retornando HTTP Status Code 201.

This means that they can remove from the list all non-supported permissions. However, it's not clear if this means that they can reduce the DATA GROUPs. From a UX perspective given that the user is consenting to a group, we understand that the permissions must be maintained. We need clarifications

@talles.fp  - We have been told numerous times that banks must support from a protocol point of view a complete and specific GROUP. Even if a Bank does NOT support all of the elements in the group (like with financings) the consent and user experience guidelines do not support sub splitting this. I agree that it is sub-optimal however this is the direction we have been given and what has been implemented for months.

We have been told and informed categorically that Banks can not alter what consumers are given access to from a grouping wise, even if the bank does not support them.

For example, 

Cartão de Crédito    | Faturas                       | CREDIT_CARDS_ACCOUNTS_READ                               |
      |                      |                               | CREDIT_CARDS_ACCOUNTS_BILLS_READ                         |
      |                      |                               | CREDIT_CARDS_ACCOUNTS_BILLS_TRANSACTIONS_READ            |
      |                      |                               | RESOURCES_READ         

By your logic, a bank can choose now NOT to support CREDIT_CARDS_ACCOUNTS_BILLS_TRANSACTIONS_READ as part of this response. The requirement for Banks to display the groups and consent to whole groups only was taken to the Board and voted on by GT's and ultimately it was required to support only whole groups because the UI/UX and Legal GTs (from memory) stated that they did not support Banks having UI/UX's that allow them to support a mix and mashup of permissions. 

We challenged this at the time and suggested that actually TPPs should be able to select exactly what they want e.g TPPs might only need Bank Accounts and Credit Cards and Credit Card Transactions but not Bank Account Transactions but this was categorically rejected as not being required. 

Instead the Banks are required to filter permissions to the GROUPS of permissions they support provided that they are whole groups only. If they can not honour any of the groups they should reject it. 

Until this is clarified (again) we aren't proposing to change the tests however I personally agree that with this 'GROUP' Banks should be allowed to only support a subset of the permissions. However, if you say that banks can support only a subset of the permissions does it apply to this group and this group only?
