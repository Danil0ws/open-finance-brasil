## 📝 Descrição

# **New fields in test plan configuration**

In Post Payments Consent endpoint, on request, the debtor account field has the following description:

> debtorAccount DebtorAccount\
> description:\
> Object that contains the identification of the payer's source account.\
> Information about the payer's source account can be brought into the link to the holder if the initiator has collected this information from the customer. Otherwise, it will be collected from the holder and brought to the initiator as a response to the creation of the link.

In Both test plans:

* fvp-payments-e2e_open_test-plan-v4
  * OBB_PROFILE_PROD_FVP
* fvp-payments-e2e_test-plan-v4
  * OBB_PROFILE_PROD_RESTRICTED_FVP

Make the following changes:

1. Test modules should not require the following Fields to be filled in test plan config:

`    "debtorAccountIspb"
    "debtorAccountIssuer"
    "debtorAccountNumber"
    "debtorAccountType"
    "paymentAmount"`

2. This fields should not appear on config Form

---

**Verify Incorrect proxy in FVP POST /payments request:**

In Both test plans:

* fvp-payments-e2e_open_test-plan-v4
  * OBB_PROFILE_PROD_FVP
* fvp-payments-e2e_test-plan-v4
  * OBB_PROFILE_PROD_RESTRICTED_FVP

1. Verify if `data.proxy` field in the `POST /payments` request is populated correct Pix key:
2. If it is being populated with: `cliente-a00001@pix.bcb.gov.br`\
   This Pix key is not configured or linked to the user running the test, which causes institutions to reject the request due to the invalid key. Logs of the failed request are also attached for reference.
