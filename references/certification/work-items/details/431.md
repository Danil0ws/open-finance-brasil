## 1. What Happened and what were you expecting?
After the consent is authorised, the Consents API is called so the test can validate the operational limits configured. Is of our understand that the Consents API is protected with the consents scope, however, the test uses the token generated after the authorization_code wich doesn't have this scope, only the consents:"consentId". 
Because of this behaviour, the Consents API throws a HTTP status 403 not allowing the test to continue.

### Comentário 5
**Autor**: Erick Domingues (@erick.domingues1)
**Criado em**: 29/09/2022, 18:08:34

When we redirect the user to authorize the consent we are asking for the following scopes on the conformance suite

scope=openid%20consents%20customers%20consent:urn:bradesco:3f3623d1-57db-4f01-af3c-fbec6aa18112&

however, when you create the token you remove the consent and add the resource scope.

"scope":"resources customers openid consent:urn:bradesco:3f3623d1-57db-4f01-af3c-fbec6aa18112"

So effectively your server is removing this scope from the oidc flow.

Our understanding is that when using the authorization_code flow the application should be granted both scopes that can be used only by the client and the scopes that are specific for the user. This should thus allow the application to use the authorization code flow to access the consent API.
