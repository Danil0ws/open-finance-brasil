## 📝 Descrição

## 1\. What happened and what were you expecting?

\-\> In payments_api_negative_test-module_v4, conformance suit executes the following steps:

• Calls the POST Payments Endpoint with a different currency\
• Expects 422 PAGAMENTO_DIVERGENTE_CONSENTIMENTO

It sends in the request body: data.payment.currency: “ZAR”

\-\> in payments_api_consents_negative_test-module_v4 it executes the following:

3\. Ensure error when invalid currency is sent\
• Calls POST Consents Endpoint with currency as "XXX"\
• Expects 422 PARAMETRO_INVALIDO - Validate error message

According to the [payments spec](https://openbanking-brasil.github.io/openapi/swagger-apis/payments/?urls.primaryName=4.0.0-rc.2#/Pagamentos/paymentsPostPixPayments):

```
2.0 Validações na criação do pagamento - Síncrono (POST /payments)
 2.2 Casos de erro sintáticos e semânticos, previstos com retorno HTTP Code 422 - Unprocessable Entity (detalhamento adicional na documentação técnica da API):
  2.2.1 Sintáticos
   2.3.1.2 Formatação de parâmetros: Valida se parâmetros informados obedecem a formatação especificada (PARAMETRO_INVALIDO).
  2.2.2 Semânticos
   2.2.2.6 Divergência entre pagamento e consentimento: Valida se dados do pagamento são diferentes dos dados do consentimento (PAGAMENTO_DIVERGENTE_CONSENTIMENTO)
```

What should be the expected response PAGAMENTO_DIVERGENTE_CONSENTIMENTO or PARAMETRO_INVALIDO?
