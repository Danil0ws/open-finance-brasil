## 1. What Happened and what were you expecting?

The payments-dcm-subject-dn-test test does not accept private_key_jwt for authentication method.

Even though the MTLS client identification, for which the test is designed, works perfectly in our implementation and has been certified before.

Shouldn't this test accept either auth-method and simply perform MTLS as usual, regardless of the auth method informed?

The client metadata under test, `tls_client_auth_subject_dn`, has no defined effect when using private_key_jwt client authentication.

Put another way, clients authenticating using private_key_jwt would NOT be expected to use DCM to update `tls_client_auth_subject_dn` when their certificate changes.
