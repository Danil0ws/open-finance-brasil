## 1. What happened and what were you expecting?

The test performs a POST payment. We are returning a 201 with the payment detail and self link as https://obbr-api.sandbox.openbanking.daycoval.com.br/open-banking/payments/v4/pix/payments, which is the URI of the POST call. Validation fails saying the self link does not match the regex, which expects that the self link contains the paymentId https://obbr-api.sandbox.openbanking.daycoval.com.br/open-banking/payments/v4/pix/payments/139fb3d7-4597-4ea8-ba62-2c673eb8c601. I don't think that's correct based on the documentation. Also, the test tries to make a GET request without sending the paymentId on the request URI.

According to what is described in[ API Payment Initiation POST pix/payments endpoint Self link field](https://openbanking-brasil.github.io/openapi/swagger-apis/payments/?urls.primaryName=4.0.0#/Pagamentos/paymentsPostPixPayments):

![image.png](/uploads/bc2910d07b38ff7af33ce91d3d81960a/image.png)Self link should address the URI that leads to the first item, meaning the first paymentId present in the response body. Also, conformance suit is operating according to the determined pattern defined in the specification.

To execute the test module successfully make sure that self link addresses the paymentId so GET pix/payment/{paymentId} can be accessed.
