Hi Christian. 

We are having a similar problem on our side. I understood that we actually need to have a valid proxy/Pix key from another institution belonging to the same user so the Pix key details can be fetched and the transfer sent. Both approaches described by you does not work for us because, on both cases, the provided `proxy` in the request body will be either the configured loggedUser CPF or the CPF as described in the test summary. To make it work, this proxy must exist somewhere else so the Pix transfer can be executed.

Although we could register a Pix key on our side with that CPF, that Pix key would point to the same account initiating the transfer. Within our institution, we cannot transfer funds from a given account to that same account.

Linking this issue with the question raised on #1307, one approach that can easily work for us is to have an account with the CPF from the test summary on our side and have the `proxy` being `cliente-a00001@pix.bcb.gov.br`. This key can be found by our testing partner and we can send transfers funds to it. Approaches 1 and 2 as described by you requires us to have that CPF as Pix key registered in a different institution within our Pix integrator.

So my question is: could it be possible that approach 2 is leveraged with the proxy being `cliente-a00001@pix.bcb.gov.br` by default? Or even better, could we manually configure the `proxy` being sent by the test in the test configuration? That way we have the flexibility from approach 1, while approach 2 also works.

**Autor**: Christian Eloysio (@christianraidiam)
**Criado em**: 09/02/2024, 13:03:24

Hi Hugo! Thanks for the Ticket!

For the automatic payments, since the credits has to be the same as the logged user in the case of Personal Accounts, you have two options:

1. Insert the loggedUser at the config, and this will be used to fill out the information about the logeedUser and creditor at the consent, and the proxy on the payment execution. Note that this alternative will require you to have registered this use at the PIX Tester with this PIX key (CPF) so that the payments are successful. The same applies if you fill out the config with a CNPJ.
2. The second option is to not provide this information at the config, so we will fill this information with pre-registered information, using the CPF as written in the test summary. This alternative will require you to have the pre filled cpf registered at your institution, so you can use the credentials to login.

Without this, the payment information as proxy/creditor account would not match the information given at the consent, making the test to fail.

We are happy to help with any additional needs!
