Hi, @Gabriel_sr 

The test failed because the implementation is not conformant to the behaviour highlighted in bold below:

>5. Ensure x-fapi-interaction-id is validated, and sent back when not requested
>
> * Calls POST consents Endpoint with the x-fapi-interaction-id as "123456"
>
> * Expects 400 or 422 PARAMETRO_INVALIDO - Validate Error message, **ensure a valid x-fapi-interaction-id is sent on the response and its a UUID as RFC4122**

CS calls POST consents sending an invalid `x-fapi-interaction-id` ("123456") and then expects the implementation to:
- identify it by a 400 or 422 response,
- send back a valid x-fapi-interaction-id.

To a successful execution in this test module, the implementation needs to be adapted so it's conformant to the behaviour described in the test summary.
