Hi,

Thanks for the ticket!

It seems that a recurring consent was created using the v1 of automatic payments:
![image](/uploads/8736958759c5714f8c06a45b4710978f/image.png)

But the payment attempt was made using the v2:
![image](/uploads/6fbf025adefc6af471ff275fa3408550/image.png)

In this case, MB is correct in returning an error, as the consent version must match the version used in the payment flow. We recommend adjusting your implementation to ensure both steps use the same version — once aligned, the flow should work as expected.

Let us know if you need any further support — happy to help!
