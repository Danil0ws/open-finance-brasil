## 📝 Descrição

**Observed behavior**

The module customer-business_api_alphanumeric_cnpj_test-module_v2-3 requires at least one alphanumeric CNPJ in GET /business/financial-relations, path $.data.procurators\[\*\].cnpjCpfNumber, via EnsureAtLeastOneAlphanumericCnpjFound. Data holders fail this step because their procurators carry a CPF.

**Expected behavior**

Although the field is named cnpjCpfNumber, a procurator/representative is by definition a natural person: in the customers v2.3.0 BusinessProcurator schema the civilName field (civil name of a natural person) is required, and the type values are REPRESENTANTE_LEGAL and PROCURADOR, both natural persons. So this field will only ever hold a CPF in practice, and never a CNPJ. Requiring an alphanumeric CNPJ there demands a value that cannot occur, so the check must be removed from procurators. The alphanumeric CNPJ check should remain only where a CNPJ actually occurs (the business own cnpjNumber and parties with documentType CNPJ).
