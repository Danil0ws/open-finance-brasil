## 📝 Descrição

### 🐞 GitLab Issue: Failure in `POST /portabilities` due to missing `contractAmount`

#### Current Behavior:
During the execution of the test `credit-portability_api_core_test-module_v1`, identified by Test ID `E9AR02APXLuVD95`, the final step failed when calling the `POST /portabilities` endpoint. The expected response was `202 Accepted`, but the actual response was `422 Unprocessable Entity`.

The failure was caused by the absence of the required field `contractAmount` in the request payload. This field is essential for the portability request and must be populated with the value returned by the `GET /loans/contracts/{contractId}/payments` endpoint.

#### Expected Behavior:
The `POST /portabilities` request must include all required fields, especially `contractAmount`, which represents the outstanding balance of the contract. According to the Open Finance Brasil API specification, missing required fields must result in a `422` response [1](https://banco365-my.sharepoint.com/personal/fred_vieira_bb_com_br/Documents/Arquivos%20de%20Chat%20do%20Microsoft%20Copilot/test-log-credit-portability_api_core_test-module_v1-E9AR02APXLuVD95.html).

> “If a required field is missing in the request body, the API must respond with HTTP status code 422 (Unprocessable Entity).”  
> — https://openbanking-brasil.github.io/areadesenvolvedor/#/apis

#### Evidence:
- **Test Name**: `credit-portability_api_core_test-module_v1`  
- **Test ID**: `E9AR02APXLuVD95`  
- **Plan ID**: `XLGhyw4QOGOCF`

### ✅ Recommended Fixes

#### 1. **Ensure Proper Data Extraction**
The test flow correctly calls the following endpoints to gather required data:
- `GET /loans/contracts` → retrieves `companyCnpj`
- `GET /credit-operations/{contractId}/portability-eligibility` → confirms eligibility
- `GET /loans/contracts/{contractId}` → retrieves `instalmentPeriodicity`
- `GET /loans/contracts/{contractId}/scheduled-installments` → retrieves `totalNumberOfInstalments`
- `GET /loans/contracts/{contractId}/payments` → retrieves `contractOutstandingBalance` (used as `contractAmount`)

However, the final payload sent to `POST /portabilities` omitted `contractAmount`.

#### 2. **Correct the Payload Construction**
Ensure the payload includes all required fields. Example:

```json
{
  "data": {
    "institution": {
      "creditor": {
        "companyCnpj": "00000000000191"
      }
    },
    "instalmentPeriodicity": "MENSAL",
    "proposedContract": {
      "totalNumberOfInstalments": 36
    },
    "contractAmount": 5154.21
  }
}
```

#### 3. **Validate Schema Compliance**
Before sending the request, validate the payload against the OpenAPI schema to ensure all required fields are present and correctly typed.
