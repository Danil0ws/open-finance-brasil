## 📝 Descrição

#### Current Behavior:

---

The **`automatic-payments_api_rejected-consent_test-module_v2n1`** test makes a GET request with the request_uri [**https://mtls-openfinance.homolog.asaas.com/open-banking/automatic-payments/v2/recurring-consents/{id}/{id}**](https://mtls-openfinance.homolog.asaas.com/open-banking/automatic-payments/v2/recurring-consents/%7Bid%7D/%7Bid%7D) immediately after making a PATCH request with the request_uri [**https://mtls-openfinance.homolog.asaas.com/open-banking/automatic-payments/v2/recurring-consents/{id} **](https://mtls-openfinance.homolog.asaas.com/open-banking/automatic-payments/v2/recurring-consents/%7Bid%7D)**.**

#### Expected Behavior:

---

The expected behavior is to make the request to the endpoint without having duplicated IDs in the request_uri, as follows: [**https://mtls-openfinance.homolog.asaas.com/open-banking/automatic-payments/v2/recurring-consents/{id} **](https://mtls-openfinance.homolog.asaas.com/open-banking/automatic-payments/v2/recurring-consents/%7Bid%7D)**.**

Boa tarde prezados,

A situaçao está ocorrendo pois o GET consents busca o `consentId` enviado no selflink do response anterior.

No step:

**Call PATCH consents - Expects 200**

Na resposta ao PATCH **recurring-consents/urn:asaas:e91869c1-568d-46d1-b024-826a05541d18,** o seu servidor retornou:

"links": {

"self": "https://mtls-openfinance.homolog.asaas.com/open-banking/automatic-payments/v2/recurring-consents/**urn:asaas:e91869c1-568d-46d1-b024-826a05541d18/urn:asaas:e91869c1-568d-46d1-b024-826a05541d18"**

Sendo assim, o GET buscou os dois `consentId` enviado no `self`.

Voce pode verificar um teste executado com sucesso através do link: https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=TRDbrj4It8MVDLI&public=true.

Sinta-se livre para reabrir o ticket ou abrir um novo, caso necessite de suporte adicional.
