Thanks for the ticket!

The test failed because it never meets its requirement of reaching status `REJECTED` with the right `data.rejection.reason.code` value, which is `CONSENT_MAX_DATE_REACHED`. In the GET Consents response the implementation incorrectly returns the rejection reason code `CONSENT_EXPIRED`, as shown below:

![image](/uploads/c1c01f9a12376bada078fd2fc2a3c9c8/image.png)

Therefore, it's important to clarify that the failure identified by CS is indeed valid - I do understand the engine failure message can be confusing and we will enhance that. However, it is important to state that this enhancement does not obstruct your path to a successful execution in any way, once the current error happens due to an incorrect implementation behavior, which needs to be adjusted to align with the test summary.
