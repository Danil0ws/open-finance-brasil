Prezados,

Obrigado pelo reporte e pelo detalhamento do cenário.

Após análise do comportamento do teste **resources_api_unavailable_test-module_v3-1**, esclarecemos que o objetivo deste cenário é validar a implementação do tratamento de recursos que estejam nos estados **TEMPORARILY_UNAVAILABLE** ou **UNAVAILABLE**.

No fluxo do teste, após a autorização do consentimento, é realizado o polling da API **GET /resources** por até 10 minutos, aguardando que ao menos um recurso seja retornado com status **TEMPORARILY_UNAVAILABLE** ou **UNAVAILABLE**. A partir deste recurso, o teste valida o comportamento esperado das APIs de dados (ex.: accounts, contracts), incluindo o retorno de erro 403 com o código correspondente ao status do recurso.

De acordo com a especificação do Open Finance, os status previstos para os recursos listados na API Resources são:

* **AVAILABLE**: indica que o recurso encontra-se disponível e o(s) consentimento(s) associado(s) possui(em) status AUTHORISED.
* **UNAVAILABLE**: indica que o recurso não está mais disponível, por exemplo, em caso de conta encerrada.
* **TEMPORARILY_UNAVAILABLE**: indica que o recurso encontra-se temporariamente indisponível, embora o(s) consentimento(s) associado(s) possua(m) status AUTHORISED. Exemplo: conta temporariamente bloqueada por suspeita de fraude.
* **PENDING_AUTHORISATION**: indica a existência de pendências para o compartilhamento do recurso, por exemplo, em caso de alçada dupla, quando é necessário o consentimento de mais de um titular.

Neste cenário específico, o teste falhou porque, durante todo o período de polling, a API retornou apenas recursos com status **AVAILABLE**, não sendo possível validar o comportamento esperado para recursos indisponíveis.

Ou seja, a falha não está relacionada a erro de implementação da API em si, mas sim ao fato de que não houve, no período da execução, nenhum recurso em estado de indisponibilidade para que o teste pudesse seguir com as validações subsequentes.

Caso a instituição não possua cenários reais de indisponibilidade de recursos no ambiente de testes, pode ser necessário simular ou disponibilizar ao menos um recurso nestes estados para permitir a execução completa deste cenário.

Permanecemos à disposição para apoiar na análise, caso necessário.
