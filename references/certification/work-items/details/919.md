The test failed because the POST Consents is incorrectly receiving a 422 status from the authorization server. This test module aims to ensure that an error is returned when an invalid email is sent as proxy and it does so in the later steps mentioned below:

> * Calls the POST Payments with invalid email as proxy 
> * Expects 201 or 422 DETALHE_PAGAMENTO_INVALIDO or PAGAMENTO_RECUSADO_DETENTORA 

Therefore, there is no corrections on the CS side. To a successful execution, the implementation needs to be adapted so that it is conformant to the expected behaviour stated at the test summary.
