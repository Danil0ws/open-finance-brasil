## 📝 Descrição

The fields [transactionFromDateTime_e_transactionToDateTime_], which by the swagger were optional, will be removed on our next API release. 

For this reason we would like to ask you to remove all the tests that send those two fields (or edit those tests so they don't send over those two fields.

This spec change will be rolled out on the worst-case scenario on Sunday night. For this reason, it is important to have this change by Monday 13am - GMT on the conformance suite.

**PLEASE INFORM US IF YOU CANNOT DEPLOY THIS CHANGE IN TIME SO WE CAN POSTPONE THIS SPEC CHANGE**

Hi Erick,

For the understanding of TPPs that are implementing the revised behaviour.
Can you confirm the following:

- TPPs will not be able to request a reduced date range on the Consent API so this will be removed from the tests.

- Customers should not expect their Bank to apply any transcationDateRange filters that may be displayed by the TPP at the Bank and so language to that effect should be communicated by TPPs.

- TPPs will need to technically inform their customers that Banks will share 12 months data with them but that the TPP as per LGDP will not request the data even though it technically will be Authorized to access to a larger data set than is potentially consented by the customer.


- TPPs will not be able to specify a specific range of data for their Bank to **Authorize** but instead the expectation is that the 'last twelve months' will be available from the point of request.

- TPPs should understand that access is essentially 'rolling' from the point of access being Authorized (not requested).

- Both the Banks and TPP agree that a Bank can not make **more** than the last years data available to the TPP as it is now necessary for all parties to understand technically what is available to the TPP so that appropriate language can be presented by all parties. e.g A Bank should not make 5 years available to the TPP without a customer **and the TPP** knowing that a TPP has technical access to more data than what the customer has consented too and what it thinks is available. (Basic security).

- As the headers to filter transaction data are not mandatary e.g fromBookingDate, toBookingDate: https://openbanking-brasil.github.io/areadesenvolvedor/swagger/swagger_accounts_apis.yaml. TPPs should be informed that the change of this API for Banks to not enforce  consent ranges they may have agreed with customers AND given that the filter parameters to restrict data ranges are not mandatory, will result in Banks transmitting data from the earliest possible date (i.e one year ago).

Note: I strongly recommend, with the change of this consent process, for LGDP and Data Minimisation principles, to consider making these headers mandatory if present on the API.

We can add some tests on the functional side to confirm that Banks will only share the last years worth of data with a TPP. 

We will let you know when it is done.
