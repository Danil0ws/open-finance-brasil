Hi @rogeriorocha083. Thanks for asking.

Yes, the Payments v.5.0.0 [spec](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1283522868/Informa+es+T+cnicas+-+SV+Pagamentos+-+v5.0.0-beta.1) states that for scheduled payments the schedule fields are mutually exclusive, and that the maximum consent horizon is two years counted from the consent creation timestamp (/data/creationDateTime).

It also clarifies that single payments must use the single object only. So the test is validating that your implementation correctly computes the recurrence range (daily/weekly/monthly) and rejects consent creation when the resulting schedule would go beyond that 2-year window, returning **422 / DATA_PAGAMENTO_INVALIDA**.

> **\[Restrição\] Mutuamente excludente com o campo date. Este campo é obrigatório no caso de agendamento. Neste caso, o campo date não deverá ser informado. O prazo máximo para o consentimento deverá ser de dois anos, contando a partir da data de criação do consentimento retornada na criação do mesmo (campo /data/creationDateTime). Agendamento de pagamento único deve utilizar exclusivamente o objeto “single”.**

Feel free to reopen this issue if further assistance is needed.
