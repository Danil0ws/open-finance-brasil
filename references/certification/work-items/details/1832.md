Thanks for opening the ticket:

During Enrollment Authorization Server set the dailyLimit and transactionLimit to be:

```
    "dailyLimit": "1000.00",
    "transactionLimit": "1000.00"
```

When Conformance Suit is executes the first payment flow is sends on request:

```
  "payment": {
        "currency": "BRL",
        "amount": "1000.00"
      },
```

To which Server responded a 422 with the following Payload:

```
 {
      "code": "VALOR_ACIMA_LIMITE",
      "detail": "O valor da transferência é maior que o limite de transação diário do usuário",
      "title": "Valor acima do limite"
    }
```

Given that the amount being requested during POST Payments is not higher than the dailylimit stablished during enrollment, Conformance Suit is correctly expecting a 201 during this request. Afterwards Conformance Suit would call Post Payments a second Time in which the 422 would be expected.

As conformance Suit is working as expected in this regard, the aforementioned adjustment needs to be made Server Side.
