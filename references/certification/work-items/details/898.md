Hi,

This issue was recently taken to discussion at the WG and following their September 1st decision the test module will be updated as described below:

Ensure that payment fails when the localInstrument is QRDN but the qrcode is a QRES (Reference Error 2.2.2.8)

* Call POST Consent with localInstrument as QRDN but the “qrcode” field with a valid static QRcode
* Expects 422 - DETALHE_PAGAMENTO_INVALIDO
* Validate Error message

If no errors are identified:

* Expects 201 - Validate response
* **Redirects the user**
* **Ensure an error is returned and that the authorization code was not sent back**
* **Call GET Consent**
* **Expects 200 - Validate if status is "REJECTED" and rejectionReason is QRCODE_INVALIDO**
