#### description:

O sumário do teste enrollments_api_invalid-parameters_test-module_v2 na Ferramenta de Validação de Plataformas (FVP) está desalinhado com a especificação técnica mais recente da API de Enrollments v2. O comportamento esperado pelo teste atual corresponde à versão 1.3.0 da especificação, enquanto o correto seria validar de acordo com a versão 2.1.0, resultando em falhas de teste incorretas para instituições que implementaram a versão mais recente corretamente.

#### Current Behavior:
---
Hoje o teste enrollments_api_invalid-parameters_test-module_v2 está com o seguinte sumario/comportamento:

Ensure that enrollment can't be requested if request parameters are sent wrongly
• Call the POST enrollments endpoint, don't send an x-fapi-interaction-id on the header
• Expect a 400 response
• Call the POST enrollments endpoint, sign the message with an incorrect private key
• Expect a 400 response
• Call the POST enrollments endpoint without sending the issuer field, but with accountType as CACC
• Expect a 422 response - Validate Code CONTA_INVALIDA
• Call the POST enrollments endpoint without sending the debtorAccount.accountType field
• Expect a 422 response - With Code CONTA_INVALIDA
• Call the POST enrollments endpoint and send an invalid permission value Expect a 422 response - With Code PERMISSOES_INVALIDAS
• Call the PATCH Enrollments {EnrollmentID}
• Expects 204


#### Expected Behavior:
---
O sumário/comportamento correto deveria ser:

Ensure that enrollment can't be requested if request parameters are sent wrongly
• Call the POST enrollments endpoint, don't send an x-fapi-interaction-id on the header
• Expect a 400 response
• Call the POST enrollments endpoint, sign the message with an incorrect private key
• Expect a 400 response
• Call the POST enrollments endpoint without sending the issuer field, but with accountType as CACC
• Expect a 422 response - Validate Code PARAMETRO_NAO_INFORMADO
• Call the POST enrollments endpoint without sending the debtorAccount.accountType field
• Expect a 422 response - With Code PARAMETRO_NAO_INFORMADO
• Call the POST enrollments endpoint and send an invalid permission value
• Expect a 422 response - With Code PERMISSOES_INVALIDAS
• Call the POST enrollments endpoint sending the debtorAccount.accountType field as SLRY
• Expect a 422 response - With Code PARAMETRO_INVALIDO

#### Evidence:
---
O sumário FVP produtivo atual do teste **enrollments_api_invalid-parameters_test-module_v2** está desatualizado, levando em consideração a planilha **https://gitlab.com/raidiam-conformance/open-finance/certification/-/wikis/uploads/708ab45b3301a49743ffea5c7e0f7aae/20250205_open_fvp_test_summary_v2.xlsx**, onde, está com o mesmo sumário da planilha **https://gitlab.com/raidiam-conformance/open-finance/certification/-/wikis/uploads/f5bacd131055bd6d1849e131e978831b/20240704_JSR_Test-Modules_v1.3.0.xlsx**, ou seja, da versão 1.3.0 do teste.

O correto seria está de acordo com a planilha da certificação da versão 2.1.0: **https://gitlab.com/raidiam-conformance/open-finance/certification/-/wikis/uploads/e19be8921bca5abba4187655e0bc0493/JSR_-_2.1.0.xlsx**
