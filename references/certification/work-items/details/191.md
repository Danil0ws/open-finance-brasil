## 📝 Descrição

Hi, this isn't an issue per se, but a Request for Info on how the rules for the refresh token tests for scheduled PIX far into the future will work.

Refresh token expiration will now be set to last the same period as the consent itself (correct?). We understand this is minimum 24 hrs and up to 365 days?

So how will tests work for this scenario? How will the certification engine test for a refresh token that will expire, say, 300 days into the future?

We appreciate any comments and/or pointers as to how the rules for this scenario will be applied.

Hi Jose, 

Unfortunately, we are not in a position to confirm how the refresh tokens work for PIX Scheduling so we can't confirm this behavior. Supposing they follow the behavior that you mentioned, they would be no different than the refresh tokens issued for customer data APIs which also can have a duration of up to 365 days.

At the moment the conformance suite only has the capacity of running tests for a few minutes, so the only restriction that is currently being checked is if the refresh tokens are being rotated on multiple token calls made on a short interval of time - They shouldn't.
