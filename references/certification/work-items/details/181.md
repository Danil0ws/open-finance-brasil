## 📝 Descrição

## 1. Issue Found

Behavior must be defined by the Specifications WG

We have received a certification request that sent the field **"ocorrencia"** on the Error Response as noted below: 

```
{
  "aud": "9415f224-9f58-56b5-af4c-085b4438e4eb",
  "iss": "9415f224-9f58-56b5-af4c-085b4438e4eb",
  "jti": "f8a960f8-4dfe-4d18-a7fa-f10f9f60e634",
  "iat": 1643211187,
  "errors": [
    {
      "code": "PAGAMENTO_DIVERGENTE_DO_CONSENTIMENTO",
      "title": "PAGAMENTO_DIVERGENTE_DO_CONSENTIMENTO",
      "detail": "Dados do pagamento divergentes dos dados do consentimento."
    }
  ],
  "meta": {
    "requestDateTime": "2022-01-26T15:33:06Z",
    "ocorrencia": "CHOM00000063628280800101"
  }
}
```

This is currently an invalid return if we check the swagger because on the field meta:

    Meta:
      type: object
      description: Meta informações referente à API requisitada.
      required:
      .....
      additionalProperties: false

The additionalproperties is noted as false, which means **"ocorrencia"** should not be sent

However, if we check the description errors on https://openbanking-brasil.github.io/areadesenvolvedor/#convencoes-de-payload we have that:

- O objeto errors será um array de zero ou mais objetos. Os atributos deste objeto serão os descritos abaixo:
    - obrigatoriamente o atributo code contendo um código de erro específico do endpoint;
    - obrigatoriamente o atributo title contendo um título legível por humanos do erro deste erro específico;
    - obrigatoriamente o atributo detail contendo uma descrição legível por humanos deste erro específico;
    - opcionalmente o objeto meta contendo dados adicionais sobre o endpoint que seja relevante para o erro.

This might allow this additional field "ocorrencia" to be sent

We can also say that those fields should be covered under https://openbanking-brasil.github.io/areadesenvolvedor/#extensibilidade

## 2. Definition

We need a definition from the WG on what to do with this submission

* (1) Accept it as a PASS and allow those fields to be sent in the future.
* (2) Accept it as a PASS and enforce that additionalfields should not be sent, only on the next certification round.
* (3) Accept it as a CONDITIONAL PASS and require an update in the next X days.
* (4) Refuse it and enforce that additionalfields should not be sent on all certifications that arrive.
