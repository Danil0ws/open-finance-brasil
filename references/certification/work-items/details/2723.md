#### Current Behavior:
---
When running the `payments_api_pix-withdraw-exceeds-limit_test-module_v5` test, the conformance suite **replaces the `qrCode` and `amount` fields** in the consent payload with values defined internally by the test module (chave `cliente-a00001@pix.bcb.gov.br` with amount `1500.00`), but **does not update the other related fields** (`proxy`, `transactionIdentification`, `creditorAccount`, etc.), which continue to carry the values originally configured in the PSP's test alias.

This produces an internally inconsistent consent payload: the `proxy` field declares a Pix key that is not present anywhere inside the injected `qrCode`.

#### Expected Behavior:
---
When the conformance suite overrides the `qrCode` in the consent payload, it must also override the related fields so the resulting payload is internally consistent.
