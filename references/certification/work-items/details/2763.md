## 📝 Descrição

O que é esperado?\
\
O cenário de teste payments_api_pix-withdraw-exceeds-limit_test-module_v5 requer a utilização de dois QR Codes dinâmicos gerados pelo Pix Tester, ambos configurados com:\
\
valor.retirada.saque.modalidadeAlteracao = 1\
\
Além disso, os dois QR Codes devem possuir o mesmo valor para o campo prestadorDoServicoDeSaque (FSS Claim).\
\
O que aconteceu?\
\
Durante a execução do teste, a Conformance Suite falha com a seguinte exceção:

* Caught exception from test framework: getString called on something that is not a string: 1

Análise\
\
Ao analisar o payloadJWS gerado pelo Pix Tester, foi verificado que o campo:\
\
valor.retirada.saque.modalidadeAlteracao\
\
está sendo retornado com o valor 1, conforme esperado pelo cenário.\
\
Entretanto, o valor está sendo serializado como number:\
\
"modalidadeAlteracao": 1\
\
e não como string:\
\
"modalidadeAlteracao": "1"\
\
Mesmo quando o valor é enviado originalmente como string, o payloadJWS gerado pelo Pix Tester o retorna como numérico.\
\
Aparentemente, a Conformance Suite tenta processar esse campo utilizando getString(), resultando na exceção:\
\
getString called on something that is not a string: 1\
Possível causa\
\
O Pix Tester está normalizando o campo valor.retirada.saque.modalidadeAlteracao para o tipo numérico durante a geração do payloadJWS, enquanto a Conformance Suite aparentemente espera receber esse valor como string.\
\
Solicitamos a validação desse comportamento para confirmar se o tipo retornado pelo Pix Tester está correto para o cenário em questão, acredito que o motor de testes deveria aceitar tanto number quanto string.
