Hi Aurélio! The problems is not which date your are inserting there, but the format being inserted. As stated at [RFC 7519](https://datatracker.ietf.org/doc/html/rfc7519#section-4.1.6), the value for fat should be a NumericDate value.

`NumericDate` is the last definition in [Section 2. Terminology](https://www.rfc-editor.org/rfc/rfc7519#section-2), and is defined as the number of **seconds** (_not milliseconds_) since Epoch:

> A JSON numeric value representing the number of seconds from 1970-01-01T00:00:00Z UTC until the specified UTC date/time, ignoring leap seconds. This is equivalent to the IEEE Std 1003.1, 2013 Edition \[POSIX.1\] definition "Seconds Since the Epoch", in which each day is accounted for by exactly 86400 seconds, other than that non-integer values can be represented. See RFC 3339 \[RFC3339\] for details regarding date/times in general and UTC in particular.

In case you send a valid numericDate value, you should not have any further problems. You can also check this by pasting you jwt at https://jwt.io and hover over the iat value. It willl show the "Invalid Date"flag in this case.
