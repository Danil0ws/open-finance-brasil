Hi, thank for reaching out with your question

This is the standard behavior expected for header parameter x-fapi-interaction-id, as can be seen on [Financial Services – Financial API document from OIDF](https://openid.net/specs/openid-financial-api-part-1-wd-01.html)

[![image.png](/uploads/61a2b8ef34a86617a546d3b50d0f50b2/image.png)](https://openid.net/specs/openid-financial-api-part-1-wd-01.html)

Therefore, we understand that, being the case that the investments api specification does not state this behavior, this regards an issue related to specification and it shall be addressed to the workgroup so that the specification is updated with this information.

Hi @caio.tranjan. We have different expected behavior depending on the api. For example:
- accounts API "Um UUID RFC4122 usado como um ID de correlação entre request e response. Campo de geração e envio obrigatório pela receptora (client) e o seu valor deve ser “espelhado” pela transmissora (server) no cabeçalho de resposta. Caso não seja recebido ou se for recebido um valor inválido, a transmissora deve gerar um x-fapi-interaction-id e retorná-lo na resposta com o HTTP Status Code 400. A receptora deve acatar o valor recebido da transmissora."

The investments API´s documentation, however, are different:
- variable income (in this issue) api: "Um UUID RFC4122 usado como um ID de correlação entre request e response. Campo de geração e envio obrigatório pela receptora (client) e o seu valor deve ser "espelhado" pela transmissora (server) no cabeçalho de resposta."

Can you share the investments api version that you mentioned on your response?
