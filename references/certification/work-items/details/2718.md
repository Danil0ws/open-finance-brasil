#### Current Behavior:

---

When processing a Pix Saque payment with localInstrument = QRES where the static QR Code contains a populated value (EMV field 62, subfield 05), the payment engine omits the transactionIdentification field from the payment request forwarded to the Pix infrastructure. Because this field is mandatory under those conditions per the Open Finance Brazil specification, the payment is rejected by the Pix network and never reaches the expected ACSC (Accepted Settlement Completed) state. The conformance test flow that validates this scenario fails at the polling step.

#### Expected Behavior:

---

According to the Open Finance Brazil specification for SV Pagamentos v5.0.0 ([link](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1767146337/Informa+es+T+cnicas+-+SV+Pagamentos+-+v5.0.0)), the following rule applies for localInstrument = QRES:

▎ If the static QR Code has the field populated, the transactionIdentification field must be filled with that value. If the QR Code does not have , the transactionIdentification field must not ▎ be included. The must contain up to 25 alphanumeric characters (\[a-z|A-Z|0-9\]).

The payment engine should parse the from the QR Code and forward it as transactionIdentification in the payment request whenever that value is present. This would allow the transaction to be accepted by the Pix network and reach the ACSC state.

Additionally, an alternative or complementary approach would be to allow the transactionIdentification value to be explicitly configured in the test plan configuration — similar to how it is handled in the Functional QRDN Tests for Payments API (Based on Swagger version: v5.0.0) test plan — so that the value can be supplied directly when the QR Code parsing is not feasible or when testing specific scenarios that require a known, fixed transactionIdentification.

#### Evidence:

---

- Endpoint: POST /open-banking/payments/v5/pix/payments
- localInstrument: QRES
- qrCode (decoded from JWT body): 00020126950014br.gov.bcb.pix013640049 01d-bd85-4769-8e52-cb4c42c506dc0221 Jornada pagador 88393030899999008 52040000530398654065 30.11 5802BR5903Pix6008BRASILIA 62290525d1145278da8b49718bab741dd 6304976E
- present in QR Code (field 62, subfield 05, 25 chars): d1145278da8b49718bab741dd
- Observed behavior: transactionIdentification is absent in the payment sent downstream, causing rejection.
- Expected behavior: transactionIdentification should be set to d1145278da8b49718bab741dd.
