Hi,

Thanks for the ticket! 

The test failed because the server never returns a payment status different than the states RCVD, ACCP or ACPD, which are not final states. That being, the payment can not reach a final state and consume the consent.

Therefore, the CS side seems to be working properly. To a successful execution, the implementation needs to be adapted for the final state ACSC to be eventually returned so the polling can stop and the test continue. Below, it follows the test summary step in which the test keeps stuck due to the implementation returned responses:

> • Poll the Get Payments endpoint with the PaymentID Created while payment status is RCVD, ACCP or ACPD

Feel free to open another ticket if you get any other issue! Happy to help!
