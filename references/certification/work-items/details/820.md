## 📝 Descrição

## 1\. What Happened and what were you expecting?

Here we discovered the 401 problem in the funds api call, it is caused by a problem in the call that the raidiam engine makes to authorize

We will need a ticket to be opened there to correct this

The problem occurs when they make the call in the cia in the url

https://oauth2.opf.hom.api.itau/as/par.oauth2

and in the url /authorize

![MicrosoftTeams-image (36).png](/uploads/10109072e1166214582c54a83431d9ba/MicrosoftTeams-image__36_.png)

the engine is duplicating the scope consent:urn:itau:consentId

As a result, the access token generated in exchange for the authorization code does not contain the scope consent:urn:itau:consentId and then the exchange fails during the call to the funds api

Hi Caroline! Thanks for the ticket!

According to the [security specs](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/82083996/EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0+Implementers+Draft+3#7.2.2.-Authorization-server), the Authorization Server:

5. shall not reject an authorisation request requesting _scopes_ broader than those necessary to access data specified in the Permissions element of a linked Consent Resource object;

In that sense, since the conformance suite is sending the correct scope twice and the scope is correct, the token issued shouldn't have this problem, even though the scope is duplicated.

By any means, as this test is not intended to test this behavior, we will fix it as soon as we can.

Happy to help with any additional needs!
