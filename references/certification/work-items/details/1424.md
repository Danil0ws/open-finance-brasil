## 📝 Descrição

## 1. What happened and what were you expecting?
According to the test description, we are expected to have a PJ account with one of those 4 CNPJs and the test will use the first one (`98380199000125`) as `proxy`.

When we search for this Pix key in our provider, we are able to find it with the following data:
```json
{
   "branch": "2463",
   "number": "1812551584",
   "ispb": "99999060",
   "key": "98380199000125",
   "type": "cnpj",
   "name": "Lucio Pelucio Ltda.",
   "type": "legal_person"
 }
```

When we send the Pix transfer, we usually expect that the homolog environments from the creditor account to receive and process the transfer. The thing here is that the ISPB does not exist. Therefore, the Pix will be never actually completed.

In order for the CNPJ tests to pass, is it expected that we mock the Pix transfer result to a "successful response" regardless the fact that was not actually sent to a valid homologation environment from the receiver?

Thanks.

Hi,

As discussed with the WG, the behavior on this test module will be changed so that it does not validate if the created payment has actually been executed.

The expected behavior after the change is as follows:

Ensure a payment using sweeping account can be successfully executed when the creditors are all from the same company. For this test, it is required that one of the following CNPJs are informed at the “brazilCNPJ” field, and also regirestred at the testing institution: 98380199000125, 98380199000206, 98380199000397, or 98380199000478. If this field is not informed in the config, the test will be skipped.

* Call the POST recurring-consents endpoint with sweeping accounts fields, sending the creditor account with 4 cnpjs, all of them containing the same root
* Expect 201 - Validate Response and ensure status as AWAITING_AUTHORISATION
* Call the GET recurring-consents endpoint
* Expect 201 - Validate Response and ensure status as AWAITING_AUTHORISATION
* Redirect the user to authorize consent
* Call the GET recurring-consents endpoint
* Expect 201 - Validate Response and ensure status is AUTHORISED
* Call the POST recurring-payments endpoint , and the creditor as the first cnpj
* Expect 201 - Validate Response
* <s>Poll the GET recurring-payments {recurringPaymentId} while the Status is RCVD, ACCP or ACPD</s>
* <s>Call the GET recurring-payments {recurringPaymentId}</s>
* <s>Expect 200 - Validate Response and ensure status is ACSC</s>
* Repeat the payments process and validation, but now sending the creditor with a different cnpj sent at the consent

We appreciate your comprehension,

Happy to help!
