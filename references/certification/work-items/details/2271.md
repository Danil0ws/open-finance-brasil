**Description:**

We have just run the test `automatic-payments_api_automatic-pix-scheduling_1-2_test-module_v2` against several institutions and encountered the following issues:

* **Nubank PF and PJ:** Both returned `422 Unprocessable Entity` with the error "Parâmetro inválido" on the `POST /recurring-payments` request.

* **Mercado Pago PF:** A `RuntimeException` was thrown during test execution.

Please review the logs attached in the comments (private).

Here is a summary of the issues encountered:

**General Considerations:** The task to address these issues will be broken down by institution. The Mercado Pago issue is considered closed. A test improvement will be created for the Nubank issue. The Digio issue remains under investigation.

#### **1. Nubank (PF and PJ)**

**Issue:** A `422 Unprocessable Entity` error with a generic `PARAMETRO_INVALIDO` message was returned on the `POST /recurring-payments` request.

**Analysis:** The root cause is likely a case-sensitivity issue with the `accountType` field within the configuration. The Conformance Suit sends `"accountType": "Tran"`, while the correct value according to the specification should be `"accountType": "TRAN"`.

**Next Steps:** This requires a **test improvement**. We will update the conformance suit to automatically convert this field to uppercase if a participant enters a lowercase value in the configuration, ensuring compliance with the specification.

#### **2. Digio (PF)**

**Issue:** The test failed with a `401 UNAUTHORIZED` error on the `/token` endpoint before redirection.

**Analysis:** Our investigation confirms that the DCR was successful and the correct static Client ID was used. The current hypothesis is that this may be an intermittent issue.

**Next Steps:** Waiting for dev team ( @PMartins03 ) , we'll delete the client in the database.

#### **3. Mercado Pago (PF)**

**Issue:** A `RuntimeException` was thrown during test execution.

**Analysis:** This was likely an intermittent problem caused by a timing issue or another test running concurrently. A subsequent test run was successful.

**Next Steps:** This case is **considered closed** due to its intermittent nature and the successful re-execution of the test.
