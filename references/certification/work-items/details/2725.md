## 📝 Descrição

Ao processar um pagamento Pix Saque com localInstrument = QRES onde o QR Code estático contém um valor preenchido (campo EMV 62, subcampo 05), o mecanismo de pagamento omite o campo transactionIdentification da solicitação de pagamento encaminhada para a infraestrutura do Pix. Como este campo é obrigatório nessas condições de acordo com a especificação do Open Finance Brazil, o pagamento é rejeitado pela rede Pix e nunca atinge o estado ACSC (Accepted Settlement Completed) esperado. O fluxo de teste de conformidade que valida este cenário falha.

De acordo com a especificação Open Finance Brazil para SV Pagamentos v5.0.0 ( [link ](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1767146337/Informa+es+T+cnicas+-+SV+Pagamentos+-+v5.0.0)), a seguinte regra se aplica para localInstrument = QRES:

Caso o QR Code estático possua o campo preenchido, o campo transactionIdentification deverá ser preenchido com esse valor. Caso o QR Code não possua , o campo transactionIdentification não deve ▎ ser incluído. Deve conter até 25 caracteres alfanuméricos (\[az|AZ|0-9\]).

* Ponto final: POST /open-banking/payments/v5/pix/payments
* localInstrument: QRES
* qrCode (decodificado do corpo JWT): 00020126480014br.gov.bcb.pix01148451388700010103080000000052040000530398654041.005802BR5903Jao6014SAO_JORGE_DOES62290525unkdBLTVu2qQ6I1poakw1PxC66304542E
* presente no QR Code (campo 62, subcampo 05, 25 caracteres): unkdBLTVu2qQ6I1poakw1PxC6
* Comportamento observado: transactionIdentification está ausente no pagamento enviado downstream, causando rejeição.
* Comportamento esperado: transactionIdentification deve ser definido como unkdBLTVu2qQ6I1poakw1PxC6.
