The test makes a POST recurring-consent without sending the field `creationDateTime` because this field is not included in the consent request schema, as shown below ([API Automatic Payments v2.0.0-beta.2](https://raw.githubusercontent.com/OpenBanking-Brasil/openapi/main/swagger-apis/automatic-payments/2.0.0-beta.2.yml)):

![image](/uploads/147642ecb1b75466daa7f9a1ea933dbc/image.png)

This field appears only in the 201 response schema. So the expected behavior here is that the holder (detentora) should generate this field with the date and time when the consent was created and then use it to populate the field `data.recurringConfiguration.sweeping.startDateTime` when it is not provided by the initiator (iniciadora).

Therefore, there is no corrections on the CS side For a successful execution, the implementation needs to be adjusted to comply with the specifications.
