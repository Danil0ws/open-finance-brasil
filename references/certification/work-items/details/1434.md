## 1. What happened and what were you expecting?

For this test, first a client_credentials token is needed to perform the consents creation. After the token is created another token must be issued, this time an authorization_code, containing the recurring consent ID as one of its scopes.

During the payment POST /automatic-payments/v1/pix/recurring-payments call the authorization_code token containing the recurring consent ID has to be used to authorize the request, however the test is sending in this request the client_credentials token, and hence a 401 Invalid consent is returned.

For this specific test run the access token rmC4ePuhBU6GRA5d7UzOrmg0GoARwOl5vabda86ROXf should be used in the POST payment request instead of 2lVSKpAUOVhfKtAvC3ksRq9xjBeq5Wy8bIMUvywG-e7.
