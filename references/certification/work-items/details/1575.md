## 📝 Descrição

I have an error validating the 2-year limit for "monthly" schedules.
 
The engine configures it this way: Payment every 1st day for 20 months, with the first payment starting 150 days from the current date.

In this scenario, the first appointment takes place on 09/01/2024, after 20 months the last appointment will take place on 04/01/2026, which is less than 2 years.

Making it impossible to validate the exception message in some periods of the month.

Thanks for opening the ticket!

According to the most recent [Payment Initiation spec](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/305594722/Informa+es+T+cnicas+-+SV+Pagamentos+-+v4.0.0-rc.2) available:

> Quantidade máxima permitida para agendamentos recorrentes

> A quantidade máxima de pagamentos que podem transitar do iniciador para o detentor são de 60 pagamentos, independente do modelo de recorrência definido no consentimento, **respeitando o prazo máximo de dois anos para agendamentos.** Caso a opção de recorrência enviada pelo iniciador não respeite a regra acima, o detentor deve retornar o erro 422 "PARAMETRO_INVALIDO" com o detalhe "Quantidade permitida de pagamentos excedida"

Additionally in the [POST /consent schema](https://openbanking-brasil.github.io/openapi/swagger-apis/payments/?urls.primaryName=4.0.0-rc.2#/Pagamentos/paymentsPostConsents) the schedule field has the following description:

> O prazo máximo para o consentimento deverá ser de dois anos, contando a partir da data de criação do consentimento retornada na criação do mesmo (campo /data/creationDateTime)

Therefore when conformance suit sends in the POST /consent request:

```
},
  "schedule": {
    "monthly": {
      "quantity": 20,
      "dayOfMonth": 1,
      "startDate": "2024-08-31"
    }
  }
```

Given that the creationDateTime field is "2024-04-03T15:05:08Z", and the startDate field is "2024-08-31", the date "2024-08-31" + 20 months would result in 2026-05-01, which is more than two years after 2024-04-03, which is the date the consent was created.

Therefore conformance suit is operating as expected and on conformity with the latest spec.

Feel free to open a new issue if you have any more questions,

Happy to help!
