## 📝 Descrição

The consents_api_negative-extensions_test-module_v3-3-1 and consents_api_negative_test-module_v3-3-1 modules are failing for expirationDateTime values exceeding 12 months.
This is because the tests currently still enforce a 12-month restriction on the expirationDateTime field.
However, for version 3.3.1, this restriction is expected to be removed.

Hi,

The failures in the **consents_api_negative-extensions_test-module_v3-3-1** and **consents_api_negative_test-module_v3-3-1** modules are occurring because your implementation is rejecting an `expirationDateTime` set far in the future, for example:

"expirationDateTime": "2300-01-01T00:00:00Z"

As of **version 3.3.1**, this is the **expected behavior** from the tests’ perspective. The previous 12-month restriction on the `expirationDateTime` field was intentionally removed, and the API must now accept **any valid expiration date**, regardless of how far in the future it is.

Currently, your server is rejecting this consent expiration date, which is causing the test failures. According to the v3.3.1 specification, the server **should accept the provided expirationDateTime** as long as it is a valid datetime value.

Please let us know if you need any additional clarification.
