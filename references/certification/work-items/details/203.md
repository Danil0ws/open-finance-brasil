## 1. What Happened and what were you expecting?

The test is not accepting a 201 on the POST Payments Request. This behavior should be accepted as it's also possible for this test to accept the 201 and fail on a RJCT sent during the Pooling Phase

![image](/uploads/f1f52c76dd9bd837990fd8e55c503eca/image.png)

![image](/uploads/52c058dd6aced8a358a4b0080a8352a8/image.png)

![image](/uploads/41c3516e62e636274b5c34254750f383/image.png)

Also worth noting that on previous versions of this test the 201 was accepted, so this has appeared as a byproduct of another update. https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=d3cuEGDVFuev2bK&public=true

I'm not sure this has any relation with the test but some fields are being sent on the POST Payments response that are not compliant with the existing spec

    "paymentId": "PY202203111125059ADD4686F3C344",
    "consentId": "urn:semear:6e37d094-63a4-498a-9c01-ebd251178fd0",
    "creationDateTime": "2022-03-11T14:25:59Z",
    "statusUpdateDateTime": "2022-03-11T14:25:59Z",
