@iago.almeida 

For the Case presented on the ticket, we have that the test is synchronous and we only generate the expected webhook URI once we receive the response of the POST Payments endpoint call.

Unfortunately, on the test, we are receiving the webhook call after the POST Payment is done, but before the response is received from your server, so we treat the webhook call as unexpected

![image](/uploads/1ff3a9f8d1e6ed1f40942153d6273ba1/image.png)

We will need to evaluate how this can be handled on the test and also check if it's valid behaviour.

If you increase the time the server responded with the webhook call by a few ms we should get a pass. If this is not possible we will need to evaluate the solution above.
