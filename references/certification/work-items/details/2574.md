## 📝 Descrição

Prezados,

Em análise aos tickets **167310** e **167312** da **FVP Automática**, identificamos que a falha apresentada no módulo de teste **"fvp-consents_api_negative_test-module_v3-3-1"** relacionado ao código de erro "COMBINACAO_PERMISSOES_INCORRETA" refere-se às permissões enviadas no processo de consentimento. No caso mencionado, estão tentando criar um consentimento para empresa (PJ), mas sem informar o `businessEntity` (CNPJ). Isso configura um cenário como se fosse Pessoa Física (PF), o que não é permitido para as marcas.

Ou seja, por não informarem o CNPJ, o fluxo nem chega à validação das combinações de permissões incompatíveis, que seriam verificadas em um cenário correto.

Para deixar mais claro: ao criar um consentimento, é necessário enviar uma série de permissões, onde algumas combinações podem ser inválidas. Essa validação ocorre apenas se os dados obrigatórios forem corretamente fornecidos (neste caso, o CNPJ). Como o teste está sendo realizado sem o CNPJ, o sistema retorna um erro antes de chegar à validação das permissões. 

Portanto, o status de erro retornado reflete corretamente o problema causado por quem está executando o teste.

* Erro 400: A requisição foi malformada, **omitindo atributos obrigatórios**, seja no payload ou através de atributos na URL.
* Erro 422: A sintaxe da requisição está correta, mas não foi possível processar as instruções presentes.

Adicionalmente, também se estabelece que o campo `businessEntity` é opcional:

![image.png](/uploads/afe149e07aeebea161edff524d1628b4/image.png){width="900" height="315"}

Sendo assim, **não se espera erro 400 apenas pela ausência do campo businessEntity.**

1. A falha apontada neste teste não é o motivo para a abertura dos tickets da FVP Automática citados na descrição. Há outras falhas, como por exemplo:

Prezados,

O erro “Brand itauemps não permitida para este tipo de consentimento” ocorre porque a ferramenta está sendo executada sem um CNPJ em uma marca que atende exclusivamente PJ.

Por conta disso, o fluxo é interrompido antes de alcançar a validação de permissões que o cenário de teste busca verificar. O erro não está no cenário configurado, mas sim na execução do teste com dados incompatíveis (CPF em vez de CNPJ).

Para que o cenário de validação de permissões seja testado corretamente, é imprescindível que a requisição contenha o campo `businessEntity` preenchido com o CNPJ. Sem isso, não será possível avançar para a etapa de validação esperada.
