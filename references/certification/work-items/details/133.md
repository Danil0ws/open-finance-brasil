1. What Happened and what were you expecting?

The server returned a 422 with code": "VALOR_ACIMA_LIMITE" for negative POST Payments. He passed.

He should have failed as 422 on POST Payments needs a COBRANCA_INVALIDA to be returned

We should validate on all Negative QRCode scenarios that:

POST Consents
- Can Return a 201 Created
- It can also return a 422 with the error being DETALHE_PGTO_INVALIDO

POST Payments
- Can Return a 201 Created - Status can be PDNG or PART
- It can also return a 422 with the error being COBRANCA_INVALIDA

POLL on the Get
- Can have PNDG or PART intermediary status
- Must end with RJCT with Rejection Reason: "ELEMENT_CONTENT_FORMALLY_INCORRECT"
