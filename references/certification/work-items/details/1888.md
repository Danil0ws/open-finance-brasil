#### Current Behavior:
---

Additionally, the 'document' field contains the expression ^\d{14}$ requiring 14 digits. What is the standard for filling in these fields (rel and document) in the case of Individual customers?

As discussed in the Squad Sandbox on November 25th, it was requested that the Conformance Suite throws a **warning** instead of a **failure** when participants attempt to execute the test module using CPF information on the following configuration fields :

* **contractDebtorName**
* **contractDebtorIdentification**

During further analysis the following points were raised:

1. Currently, for participants to pass the complete test, they need to input specific data, in the configuration fields:
   * **Contract Debtor Identification**
   * **Contract Debtor Name**\
     ↑ As defined by beta.1 specification these fields are expected to contain CNPJ data.
2. The scope of the validator in which the failure would occur if CPF information is provided, is to check all information in the **recurringConfiguration** field and validate it against the swagger.
3. It is not possible to isolate and select between "**Warning**" of "**Failure**" whether a failure on **recurringConfiguration** occurs because:
   * A CPF is being sent in the **contractDebtorIdentification** field, or
   * A mandatory field was omitted, for example.
4. Changing the validator to return a warning instead of a failure would affect all validations within the **recurringConfiguration** field, not just those related to **contractDebtorIdentification** when CPF data is sent.

Therefore, what we need tho validate is:

* Can we proceed to make the validation of all the fields inside **recurringConfiguration** return a "**Warning**" instead of a "**Failure**"?
