Hello @zhidong.tan. Thanks for raising this. This 422 validation was incorrectly triggered by a previous warning.

As a temporary workaround, please avoid the warning `Found multiple keys in JWKS of the correct type, but none with matching kid hint` in this test run. If this warning is raised before the second consent call, the flow may incorrectly execute the 422 validation branch even when the consent response is 201. Ensuring proper kid matching for the authorization response ID Token decryption key prevents this issue and allows the test to continue on the expected 201 path.

We'll keep you posted on updates regarding this fix.

Best regards
