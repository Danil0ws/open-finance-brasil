Hi guys,

The payments-api-test-bad-cnpj test is calling /payments/v1/pix/payments with cnpjInitiator property with "00000000000000" value, witch is an invalid CNPJ value. Test case is expecting HTTP Code 401, but since it's an invalid data, shouldn't it expect a 400 code? API specs says nothing about checking cnpjInitiator against SSA.

Hi,

The functional requirement as communicated by the GT Security is that participants are only to accept requests for payments by initiating organisations that are part of the open banking ecosystem. In the case of the CO-operative banks, it is possible that they may be initiating transactions on behalf of cnpj’s that are their sister organisation. We were required to add a test to ensure that participants will reject a request for a payment that is not on the roles api of the directory of participants.

This requirement has been challenged by other working groups but it has not yet been rescinded by the security working group.

In addition, banks are required to return a 422 as a jwt if the message is structurally valid ie a jwt. The only time a 400 bad request should be returned is when there is an invalid signature. This is as per the security specifications for signing and sending jwts. The Security WG and as i understand it, Banco Central, want all responses wherever possible signed.

Feed back on the clarity of the specifications has been made to the specifications team.

The roles api for sandbox is available publicly here: https://data.sandbox.directory.openbankingbrasil.org.br/roles
