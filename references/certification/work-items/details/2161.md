## 📝 Descrição

#### Current Behavior:
---
The test module `automatic-payments_api_automatic-pix-consent-edition-restrictive_test-module_v2` is failing with the error:
> "Validate PATCH consent response: EnsureRecurringConsentFieldsAreAsInPatchRequest: The field maximumVariableAmount has been indefinitely extended, so it should not exist in the response data"

Per Issue #2152, if the `maximumVariableAmount` field is not updated in a PATCH request, it must not appear in the PATCH response. However, it appears that the test validation is inadvertently evaluating the GET response, which contains the field.
#### Expected Behavior:
---
- The test should only validate the PATCH response:
  - **No Update:** If `maximumVariableAmount` is not updated, it should not appear in the PATCH response regardless of the GET response.
  - **With Update:** If the field is updated, it should appear in the PATCH response and be validated accordingly.
#### Evidence:
---
- **PATCH Response (Field Not Updated):**
  - [Test execution link](https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=uNlLlcHy1zBxZ0b) that `maximumVariableAmount` is absent from the PATCH response when no update occurs.
- **Forced Error:**
  - [During test execution](https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=TaP5o2bLUIAoAZO), when `maximumVariableAmount` is deliberately removed from the GET response, the test fails with an error message stating that it could not extract the field from the response data. This clearly indicates that the validation process is erroneously targeting the GET response instead of the PATCH response. The intended behavior is for the test to validate only the PATCH response; hence, the failure demonstrates that the test logic is incorrectly attempting to extract `maximumVariableAmount` from the GET response, leading to an unintended error.
