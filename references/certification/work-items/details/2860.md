Hi Master,
We are testing the Open Finance Brasil Mock Bank Sandbox Enrollments v2 FIDO registration flow from Android native applications.
#### Participant:
c8f0bf49-4744-4933-8960-7add6e590841
#### Problem:
Both ShopeePay Android and Shopee Android receive HTTP 422 from Mock Bank when calling:
POST /open-banking/enrollments/v2/enrollments/{enrollmentId}/fido-registration
Mock Bank response:
{
  "errors": [
    {
      "code": "PUBLIC_KEY_INVALIDA",
      "detail": "PUBLIC_KEY_INVALIDA"
    }
  ]
}
The two apps produce different Android native WebAuthn origins:
android:apk-key-hash:mEZKo3vP6TrPM-QueEnvv63eZ4VQl3p1-t0mDobzQrw
android:apk-key-hash:HR61U80kKgRBvqvCUNaB0-KsnyF4-341Z-zvakjhTkc
Our current Directory SSA contains HTTPS software_origin_uris only; it does not contain these Android native origins.
#### Could you please help confirm:
1. What exact validation rule causes PUBLIC_KEY_INVALIDA for the fido-registration endpoint?
2. Does Mock Bank Sandbox support Android native WebAuthn origins in the form android:apk-key-hash:<hash>?
3. If supported, should these values be registered in SSA software_origin_uris, or is another Mock Bank / Directory configuration required?
4. Does Mock Bank require a specific attestation format or credential public-key format beyond the pubKeyCredParams returned by fido-registration-options?

- Interaction ID: f011f656-5770-4089-8250-c5f4ec614083

Hi @zhidong.tan,

Thanks for the detailed report. 

Looking at the evidence, both failing calls were made against our internal POC environment, not the Mock Bank Sandbox. The host on both requests was **matls-api.mockbank.poc.raidiam.io:**

- ShopeePay, 2026-09-02T10:31:39Z, enrollment 92b4d14d-..., POST fido-registration -\> 422
- Shopee, 2026-09-03T03:54:07Z, enrollment 7c943745-..., POST fido-registration -\> 422

**mockbank.poc.raidiam.io** is an internal environment and is not the one participants should test against. Please point your future tests at the official Mock Bank Sandbox.

The Mock Bank Sandbox URIs (base URLs, discovery and endpoints) are documented here: https://gitlab.com/raidiam-conformance/open-finance/certification/-/wikis/Discovery-of-the-Mock-Bank#obtaining-the-mock-bank-uris

`"CustomerFriendlyName": "Mock Bank Sandbox" `

`"AuthorisationServerId": "7844e311-aa1f-4f67-9475-cbd989310b3e"`

`"OpenIDDiscoveryDocument": "https://auth.mockbank.openbankingbrasil.org.br/.well-known/openid-configuration"`

Once you repeat the enrollment flow against the sandbox, the fido-registration step should complete normally. Android native WebAuthn origins in the form android:apk-key-hash: are supported on the sandbox and do not need to be added to your SSA software_origin_uris.

Please retest on the sandbox and let us know if anything still fails.
