## 📝 Descrição

hi, master. we hit an issue in the FAPI/Open Finance Brasil conformance run — could you help check? thanks!

test-plan: Payment API v4 idempotency (plain_response; plan LDA6dObjD28UH if needed)

test-name: payments_api_idempotency_test-module_v4

test-id: PnPFT6zm4FeR9kB

suite: 5.1.17 (build de1cd5f7f922b42140a95bef156afd391d729209)

#### Error: 
EnsureResourceResponseReturnedJsonContentType — Response content type is not json

#### Context: 
On GET /open-banking/payments/v4/pix/payments/{paymentId} the client sent Accept: application/jwt; we returned 200 with Content-Type: application/jwt. The harness still expects JSON. Open Finance Payment v4 technical doc describes 200 for GET /pix/payments/{paymentId} as JWT, not plain JSON: [SV Pagamentos v4.0.1](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1165623604/Informa+es+T+cnicas+-+SV+Pagamentos+-+v4.0.1).

#### Ask:
Should plain_response require JSON here, or should the test accept application/jwt when appropriate? (v5 plan has no equivalent idempotency test.)

Hello @zhidong.tan. Thanks for raising this.

The log shows that the test was ultimately interrupted on the self-link GET /open-banking/payments/v4/pix/payments/{paymentId} step because the response returned 200 OK with Content-Type: application/jwt, while the conformance suite was expecting a JSON content type for the previous step.

This is why the final error recorded was EnsureResourceResponseReturnedJsonContentType: Response content type is not json. However, the first behavioral deviation appears earlier in the flow, during the **“Making PIX request with incorrect ISS”** step. 

According to the test definition, it intentionally sends a POST /payments request with an **_invalid iss_** and expects the server to reject it with 403. And 403 responses should be sent as JSON.

![image.png](/uploads/41938bc1cfd5f7fef101009497f67904/image.png){width=769 height=361}

Instead, the payment request was accepted and the flow continued. In summary, the request with invalid iss was not rejected as expected by the test

Please adjust this behavior so you can have success in this test.

Feel free to reopen this issue if needed.

Best regards
