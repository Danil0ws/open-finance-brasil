## 1. What happened and what were you expecting?

In the response of the /automatic-payments/v1/pix/recurring-payments list endpoint, the attribute 'self' is being validated. The test is attempting to retrieve the 'paymentId' attribute in the endpoint response and expects this 'paymentId' to be part of the URL sent in the 'self' attribute.

However, the 'paymentId' attribute is not specified for this endpoint. We understand that the test should retrieve the 'recurringPaymentId' attribute and verify if the 'recurringPaymentId' returned in the endpoint is present in the 'self' attribute.

Hi, 

Given the WG response, we have two behaviors being dealt with in this issue:

1. Conformance suit expectes paymentId instead of recurringPaymentId on the response for GET pix/recurring-payments endpoint. This is indeed a unexpected behavior from the conformance suit and we will fix it.
2. The self link provided in the GET pix/recurring-payments endpoint should be the same URI used to generate the response, and therefore it must not be the self link containing only the id of the first payment. The self link field should be fixed on the Server side so that it is as determined by the spec and to ensure test can be run successfully. 

Feel free to comment on this issue if any other questions are raised,

Happy to help!
