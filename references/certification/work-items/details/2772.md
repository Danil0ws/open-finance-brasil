## 📝 Descrição

O cenário payments_api_pix-withdraw-invalid-amount_test-module_v5, pertencente ao plano payments-withdraw_test-plan_v5, atualmente tenta criar um consentimento e espera receber um status code 201 quando o limite é excedido.

Historicamente, esse cenário contemplava dois fluxos possíveis:

* Esperava um status 422 quando o limite era ultrapassado;
* Caso não retornasse 422, esperava um status 201 seguido de uma falha após o redirecionamento do usuário.

Atualmente, nossa regra de negócio está retornando o status 422 conforme esperado, porém notamos que essa validação parece ter sido removida do cenário de teste. Gostaríamos de entender se essa remoção foi feita por engano ou se houve uma alteração intencional na regra de negócio que justifique essa mudança.

Essa análise é importante para garantir que os testes estejam alinhados com as regras vigentes e evitar falhas indevidas na certificação.
