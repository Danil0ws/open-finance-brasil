## 📝 Descrição

The PATCH API for Recurring Consents can be used to edit/revoke and reject a consent.
For the scenarios where the user wants to revoke/reject a consent, the revoke/reject object must be sent, but nothing is said about the rules for creditors/start date/expiration date fields. Are these fields necessary only for the editing scenario? In case of revoke/reject scenarios, if they are present in the payload, what should happen? Any validation for them?

Hi! We have received the following answer from the WG:

"The way the possibility of editing in the PATCH endpoint was built allows for the sending of data in existing objects. This edition is only valid for the Automatic Pix, which is not the subject of the test.

We intend to improve the schema of the PATCH endpoint in the next releases of the Automatic Pix, since this behavior is mapped in the GT's backlog."

In that sense, it any fields are sent on this endpoint related to Consent Edition, it should be ignored.

We are happy to help with any additional needs!
