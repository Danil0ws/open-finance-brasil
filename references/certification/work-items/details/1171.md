Hi

After digging deeper into the matter, it is possible to conclude that, when the conformance suit executes the following step as described on the test description:

```
Creates a Consent with all of the existing permissions and set expiration to be of 3 minutes
```

In the Post /consents request it sets the consent expirationDateTime":"2024-01-09T19:06:23Z".  When the conformance suit calls the **GET consents/{consentId}** endpoint after waiting for 3 minutos, hence being executed at "2024-01-09T19:07:41Z" , as described on the test summary:

```
Conformance Suite Will be set to sleep for 3 minutes
Call the Consents API for the authorized ConsentID
```

It expects the status of the consent on the response_body to be “REJECTED”. although **"status":"AUTHORISED"** was found, even though RejectedBy is set to ASPSP and Reason is set to "CONSENT_MAX_DATE_REACHED”. Pointing out the existence of a possible inconsistency with the implementation. 

According to the last available specification: 

“Caso o método **`DELETE`** seja chamado para um consentimento que já se encontra no **`STATUS REJECTED`** deve se retornar o STATUS CODE 422.”

Therefore the Conformance suit is correctly expecting a 422 response, as can be also found on the test description: 

```
Calls the DELETE Consents Endpoints
Expects 422 - Validate Error Message
```

In that sense after running internal tests on the mentioned test module, the conformance suit is operating as expected. 

To ensure a correct execution of test module, please ensure the following:

- When  **GET consents/{consentId}** endpoint is called after expirationDateTime is reached, the **status** on the response body is “REJECTED”
- When DELETE is called after **`STATUS REJECTED`**, response_status_code is 422.

Feel free to open another ticket if you get any other issue!
Happy to help!
