Context for GT evaluation:

Test module: consents_api_extension-invalid-status_test-module_v3 

This test module has the objective of validating a consent extension through a post extends done without user redirect. In this scenario (in which there is no user redirection), there is not a token with authorization code as it is not needed, therefore a token with client_credentials is used (which is the only token that can be obtained in this scenario). As the Post extends is being called with a token which has client_credentials grant_type, the conformance suit is expecting a responde_status_code 401, which as described in the available spec: 401 Cabeçalho de autenticação ausente/inválido ou token inválido.

What needs evaluation: When an access_token from client_credentials flow is used, then the security policy will be incorrect, but the access_token is a valid one, the software is able to find it because the server received a valid access_token, but the security policy is invalid, therefore, should we accept both 401 and 403 in this scenario?
