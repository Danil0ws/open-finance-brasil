## 📝 Descrição

**Description:** Current tests for automatic-payments_api_expirationDateTime_test-module_v2 and automatic-payments_api_revoked-consent_test-module_v2 incorrectly validate 401 and 403 status code as defined by the available specifications. As discussed with structure, these APIS are protected by FAPI + OpenID tokens, which define their own response body for such errors.

The issue has been discussed with the Security and Sandbox working groups, and it was concluded that these tests should validate only the HTTP status code (401 or 403) and ignore the response body. This ticket seeks to revise the tests accordingly.

**Current Behavior:**
The tests validate the response body for 401 and 403 errors, expecting specific structures defined in the API service. This may lead to failure since the response body is determined by FAPI + OpenID compliance.

**Expected Behavior:**
The tests should validate only the HTTP status code (401 or 403) without checking the response body, as per the agreement with the working groups.
