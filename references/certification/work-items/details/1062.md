Hi Bruno,

Thanks for the ticket.

Validate Authorisation Server Scopes Supported:
The test validates if the scopes supported from the well-known configuration are in line with what is published on the directory, and also the other way around. From the image you shared, it seems that the consents API is not published in the directory, but the scope is supported from the well-known perspective. To fix it the organization should publish the consents API in the directory, or remove it from the well-known if not supported.

Validate Domain ROLEs are According to the API Family Types:
This step of the test validates if the correct ROLEs are published in the directory according to the APIs that are published in the directory. Here the organization should have the PAGTO role according to the payments API published.

We note that this test is still in homologation and have some fixes to be done, so it is not mandatory to be executed for now.
