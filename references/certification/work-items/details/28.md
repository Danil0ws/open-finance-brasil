## 📝 Descrição

In both Consents API and Resources API test plans, there is a test that makes a POST to Consents with RESOURCES_READ permission only.
The consent-api-test-negative requires that we reject this request with a HTTP 400 response, wich we understand is the right behaviour, given that this consent would be useless.
The resources-api-test-no-resources requires that we accept the same consent request and fallow with the authorization flow. One way to check resources API with empty response would be including some customer API permission in this request. It needs to be fixed, no one will be able to get aproved in both tests with the same implementation.
