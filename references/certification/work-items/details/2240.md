## 📝 Descrição

Hello!

We noticed that the PATCH PIX payment endpoint has pagination, but there is no pagination for this route according to the specification.

Could you tell us why this route has pagination in the endpoint? Because until last week it wasn't like that and this started to affect our solution.

Hi,

We have analyzed the log you provided and identified the root cause of the problem.

1. **In a previous `GET` call** (`GET /automatic-payments/v2/pix/recurring-payments/`), your server is returning a `selfLink` that contains pagination parameters ( `?page=1&page-size=25`). As per the log, we observed the following `selfLink` returned by your server: 

   `"self": "https://mtls-obb.qa.oob.opus-software.com.br/open-banking/automatic-payments/v2/pix/recurring-payments/dc5894a4-198c-4d92-b581-8d7b8818422d?page=1&page-size=25"`
2. **In the subsequent step of the test**, when CS needs to perform the `PATCH` call for a specific recurring payment, it reuses the `URI` obtained from the `selfLink` of the previous `GET` response. Since this `selfLink` generated by your server already includes the pagination parameters (`?page=1&page-size=25`), the `PATCH` call is made with these parameters.

**According to the **[**pagination**](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17377470/Pagina+o#Atributos-de-Resposta)** specification:**

* The `selfLink` (the URI to request the page itself)
* When a `GET` method is called, it should return the link to the consulted resource itself.
* When a `PATCH` method is called, it should return the link to the altered resource.

**Recommendation:**

Your implementation is generating the `selfLink` with pagination parameters for an individual resource.

Please review your API's logic for constructing `selfLinks` in responses. The `selfLink` for an individual resource (like a specific `recurringPaymentId`) **doesn’t need to contain pagination parameters** (`?page=1&page-size=25`).

You can verify a successful test here -\> https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=ZPQFDKShgLdil7g&public=true
