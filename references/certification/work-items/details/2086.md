https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=jHLAaiOFoknlTop

#### Current Behavior:

The test calls the token endpoint to obtain the access token via authorization code only when it checks that the data was altered, this causes the authorization code to expire on our enviroment because the ttl is 60 seconds.

#### Expected Behavior:

We set the authorization code ttl to 60s for security reasons, should we abdicate from that to pass the test? 

Would it be feasible to obtain the access token immediately after receiving the authorization code? This would give us more time to complete the test without the code expiring.

Best practices recommend a short TTL for authorization codes (https://tools.ietf.org/html/draft-ietf-oauth-security-topics-13) and that clients exchange them as soon as possible to avoid exposure to attacks.

Furthermore, we do not find any definition for what should be the expiration time, we found only some questions: https://mailchi.mp/5f6ceef514db/open-banking-informa-10115659?e=447d7abb9f
Is this already solved?

Thanks for opening the issue!

As described in the test module, its objective is to:

> Ensure that consent edition can be performed by the account holder. This test requires action from the tester. It will poll for 10 minutes, waiting for the 'maximumVariableAmount' field to be defined and for changes to the 'useOverDraftLimit' setting. This test will required that the useOverDraftLimit is set as true on user redirection.

During step:

• Poll the the GET recurring-consents endpoint while the maximumVariableAmount is not sent back or for 10 minutes

As maximumVariableAmount was not received in GET recurring-consents, the Coformance suit executed 8 pooling sequences and was not able to continue with test.

Make sure that maximumVariableAmount is updated so that test module can continue.

Feel free to reach us in case of any concerns.
