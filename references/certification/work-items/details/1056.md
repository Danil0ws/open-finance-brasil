## 1. What happened and what were you expecting?
At test, conformity tool is trying to get access token using client_credentials using scope consentId. But in informe "https://mailchi.mp/18107e66cfae/open-banking-informa-9162397?e=49b5127a4f" is saying that we need to retrieve client_credentials without consentId (just payments).
And at "https://openfinancebrasil.atlassian.net/wiki/spaces/DraftOF/pages/191857620/DTO+EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0" in topic "7.2.2. Authorization server" is saying that "Must issue an access_token through the grant_type client credentials when consent status is "CONSUMED"". And in our case is not CONSUMED, we return "Invalid credentials". Is this correct?

Hi Daniel! Thanks for the ticket!

According to the [security specs](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/82083996/EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0+Implementers+Draft+3#7.2.2.-Authorization-server), the authorization server:

* shall not reject an authorisation request requesting scopes broader than those necessary to access data specified in the Permissions element of a linked Consent Resource object;

In that sense, although the endpoint really expects the "payments" scopes, a request with broader request shouldn't be denied.

About the point from "7.2.2. Authorization server" it does say that it should issue a token with status CONSUMED. However, it does not state that it shouldn't issue a token via client credentials when the status is not CONSUMED.

In conclusion, the token should be accepted even if broader scopes are requested, or even if status is not CONSUMED.
