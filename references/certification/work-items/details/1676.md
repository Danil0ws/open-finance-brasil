## 📝 Descrição

**Description:**

We propose a change in how the endpoints are fetched from the conformance suite test modules. Currently, the conformance suite expects the user to fill in the consent URL at the test plan configuration. This URL is used to make requests and serves as the base URL to build other resource APIs. This approach presents several issues:

- **Non-replicative of Production Environment:** In production, endpoints are fetched from the directory, whereas the current approach does not replicate this behavior.
- **Inconsistent Base URLs:** Some participants use different base URLs for consents and other resource URLs, causing test failures.
- **Interoperability Problems:** The current approach leads to interoperability issues between the Sandbox Conformance Suite and the FVP.

**Proposed Solution:**

We suggest that the conformance suite should always fetch endpoints from the directory, regardless the environment. Participants will be required to register their APIs in the sandbox directory before executing the tests. The benefits of this change include:

- **Consistency Across Environments:** Participants will experience the same behavior across both sandbox and production environments.
- **Simplified Test Plan Configuration:** Easier configuration process for the conformance suite.
- **Support for Different Base URLs:** Participants with different base URLs for consent and resources can successfully run tests.
- **Enhanced Interoperability:** Improved test interoperability between Sandbox Conformance Suite and FVP, allowing easier transfer of test modules across environments, thereby enhancing efficiency.

**Request:**

We seek confirmation on whether we can proceed with this change
