Hi!

Thank you for flagging this. We analyzed the HTTP traces and confirmed the following:

The test engine correctly creates the consent (POST /consents) with `payment.amount = "1500.00"` and `purpose = "WITHDRAW"`. The consent is successfully authorized with this value. However, when the CS proceeds to create the payment (POST /pix/payments), it sends `payment.amount = "0.01"`, which causes your server to correctly reject it with `PAGAMENTO_DIVERGENTE_CONSENTIMENTO`.

The value `"0.01"` comes directly from the `paymentAmount` field in your test plan configuration:

![image.png](/uploads/8595399d4794d496e8d0b1ff36016a25/image.png){width=236 height=109}

For this specific test, the CS overrides the consent amount to BRL 1,500.00 and BRL 1,501.00 as required by the test scenario, but it uses the configured `paymentAmount` value when constructing the POST /pix/payments request. Since your configuration has `"0.01"`, a mismatch occurs.

Let us know if you have any questions.

Best regards
