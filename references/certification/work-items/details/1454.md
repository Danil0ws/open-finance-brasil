## 1. What happened and what were you expecting?

According to the description of the module "automatic-payments_api_multiple-consents-core_test-module_v1" we are redirected to perform one of the consent approvals, so that the PARTIALLY_ACCEPTED status is validated.

But to return to the test, after the first approval, we need the callback/postlogin URI which is provided only after the consent receives all approvals. Could you confirm if this behavior is correct?

in the security documentation it says:

You should only share access to resources when presented access_token linked to active consent and with the status "AUTHORISED".

Bom dia Caio,

Pode nos indicar em qual ponto da documentação esse comportamento é descrito?
Estamos nos baseando no diagrama de sequência da payments v4, uma vez que pagamentos automáticos não possui um diagrama de sequência. (https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/305594441/Diagrama+de+Sequ+ncia+-+v4.0.0-rc.2+-+SV+Pagamentos)

![image](/uploads/d922c0868df6d9596cfc73cea6d14815/image.png)

Além disso, se considerarmos que o auth code seja disponibilizado para o primeiro aprovador a autorizar o consentimento, teremos alguns problemas de segurança, disponibilizando acesso a recursos que o aprovador não deveria ter ainda (até que o consentimento se torne AUTHORISED), dando acesso na camada de segurança para que o cliente tenha acesso a um recurso que de fato ele ainda não tem acesso. (endpoints de 'POST pix/recurring-payments/{recurringPaymentId}')

Por isso entendemos que o authCode deveria ser disponibilizado somente depois da última aprovação, quando ocorre a transição do status do consentimento para AUTHORISED.
