# Test Summary and Name

test-name: accounts-resources-test-multiple-consents

test-summary: 

Validates that the server has correctly implemented the rules set for joint accounts that require multiple consents for data to be shared.

In order to run this test, the user must provide a user that owns a joint account that can only share account data after multiple consents have been provided.

Test Behavior:
- Check if the institution has provided the field "brazilCpf_Joint_Account"
  - If the field is empty - Return WARNING with the message "Brazil CPF for Joint Account field is empty. Institution is assumed to not have this functionality" and finish the test
  - If present continue to test
- Create a CONSENT with only ACCOUNTS_READ, ACCOUNTS_BALANCES_READ and RESOURCES_READ Permissions using the CPF and CNPJ provided for joint accounts
- Expect a Success 201 
- Redirect the user to authorize the Consent - Redirect URI must contain accounts, resources and consents scopes
- Expect a Successful authorization with an authorization code created
- Call the RESOURCES API with the authorized consent
- Expect a 200 - Validate that one Account Resource has been returned and it is on the state AWAITING_AUTHORIZATION 
- Call the ACCOUNTS API
- Expect a 200 - Make sure the Server returns a 200 with an empty list on the object
- Call the ACCOUNTS BALANCES API with the Account ID of the Account on AWAITING_AUTHORIZATION 
- Expect a 403 - Validate that the field response.errors.code is STATUS_RESOURCE_AWAITING_AUTHORIZATION
- POLL the GET RESOURCES API for 5 minutes, one call every 30 seconds. 
- Continue Polling until the Account Resource returned is on the status AVAILABLE
- Call the ACCOUNTS API
- Expect a 200 - Make sure the Account Resource is now returned on the API response

# Additional Requirements

The CPF and CNPJ required for this test must be different from the ones used on the Base test.  On the configuration file add the following tooltip:

For CPF (brazilCpf_Joint_Account): The CPF that will be used on the multiple consent test.  This field should only be sent by institutions that support joint accounts. In order to run this test, the user must provide a user that owns a joint account that can only share account data after multiple consents have been provided.

For CNPJ(brazilCNPJ_Joint_Account): The CNPJ that will be used on the multiple consent test. This field should only be sent by institutions that support joint accounts. In order to run this test, the user must provide a user that owns a joint account that can only share account data after multiple consents have been provided.
