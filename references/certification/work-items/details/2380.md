## 📝 Descrição

In the current test scenario, when `deviceId` (a required field) is not provided in the request, the test expects a `422` status with `PARAMETRO_NAO_INFORMADO` error code.

According to the specification, missing mandatory attributes should return `400` (Bad Request): _"A requisição foi malformada, omitindo atributos obrigatórios, seja no payload ou através de atributos na URL."_

Should the test consider another scenario in order to achieve the `422` response?

Hi @takeo-nu.

DTO has confirmed the expected behavior for Phase 3 APIs:

* Requests are signed JWTs (header, body, signature).
  * **400** Bad Request applies to the JWT envelope itself;
  * **422** applies to the payload inside the JWT body:
    * **PARAMETRO_NAO_INFORMADO** when a required field is **omitted** (like deviceId missing);
    * **PARAMETRO_INVALIDO** when a field is present but invalid/out of spec.

Given this split, omitting deviceId should return 422 PARAMETRO_NAO_INFORMADO, not 400. Accordingly, the current test behavior is correct.

If you’d like to discuss further, feel free to reopen this issue or open a Service Desk ticket to engage the WG/DTO.
