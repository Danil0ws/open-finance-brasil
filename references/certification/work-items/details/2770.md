## 📝 Descrição

**Observed behavior**

The consents permission-groups test modules (fvp-consents_api_permission-groups_test-module_v3-3-1 and the equivalent ConsentsApiPermissionGroups modules) build the combined group "Balances & Credit Card Limits" by concatenating the Balances and Credit Card Limits permission sets. Both sets include RESOURCES_READ, so the 12th POST /consents request is sent with RESOURCES_READ duplicated:

permissions: \[ACCOUNTS_READ, ACCOUNTS_BALANCES_READ, RESOURCES_READ, CREDIT_CARDS_ACCOUNTS_READ, CREDIT_CARDS_ACCOUNTS_LIMITS_READ, RESOURCES_READ\]

---

**Expected behavior**

The combined group request lists each permission once, with RESOURCES_READ appearing a single time:

permissions: \[ACCOUNTS_READ, ACCOUNTS_BALANCES_READ, CREDIT_CARDS_ACCOUNTS_READ, CREDIT_CARDS_ACCOUNTS_LIMITS_READ, RESOURCES_READ\]

The Consents API [specification](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1378385987/Informa+es+T+cnicas+-+DC+Consentimento+-+v3.3.1) states (in a restriction phrase) that the permissions array must not contain duplicate items.
