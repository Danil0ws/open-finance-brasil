## 📝 Descrição

In v4 there is a restriction for the debtorAccount field in GET consent. There is something similar in the automatic-payments API, but the field is not mandatory, so I assume that we don't need to answer the debtorAccount even if it is sent in the request. Is that correct? What I understand is that if debtorAccount is in the response, then we have to deal with the ibgeTownCode restriction.

Olá Marcelino!

Conforme direcionamento recebido pelo GT Serviços,
o comportamento das APIs será parecido quanto ao preenchimento do objeto debtorAccount, mesmo que as restrições sejam diferentes. Isso acontece porque, mesmo a API de pagamentos automáticos não possuindo a restrição no objeto "debtorAccount" em si, tem no campo "ibgeTownCode", forçando o preenchimento do objeto "debtorAccount"quando consentimento for autorizado.
Sendo assim, o GT entende que a especificação não tem um problema e que deve-se respeitar a construção dos objetos para cada API. 

Agradecemos o contato,

Qualquer dúvida, estamos a disposição.
