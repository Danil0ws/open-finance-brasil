## 📝 Descrição

## 1\. What happened and what were you expecting?

The automatic-payments_api_expirationDateTime_test-module_v1 is executing the status revoked after the expiration, where it should be consumed, as the latest versions at [v1 specs](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/239370315/M+quina+de+Estados+-+v1.0.0-beta.5+-+SV+Pagamentos+Autom+ticos).

in that sense, the new behavior of the test will be:

<table>
<tr>
<td>

Ensure a consent is expired after the expirationDateTime is reached, and that payments can no longer be executed.<br>• Call the POST recurring-consents endpoint with sweeping accounts fields, and expirationDateTime as now + 2 minutes<br>• Expect 201 - Validate Response and ensure status as AWAITING_AUTHORISATION<br>• Redirect the user to authorize consent<br>• Call the GET recurring-consents endpoint<br>• Expect 201 - Validate Response and ensure status is AUTHORISED<br>• Set the conformance suite to sleep for 2 minutes<br>• Call the GET recurring-consents endpoint<br>• Expect 201 - Validate Response and ensure status is **CONSUMED**<br>• Call the POST recurring-payments endpoint<br>• Expect 401 - Validate Error Message
</td>
</tr>
</table>
