## 📝 Descrição

**Description:**\
When two FVP (or Conformance Suite) test executions are scheduled to run at the same time with the same alias, the tests fail. This occurs because the alias is used as the `redirect_uri`, and currently the platform does not support concurrent tests with identical aliases.

---

**Problem**

* The alias is reused across test executions and is tied to the `redirect_uri`.
* When multiple tests are scheduled simultaneously with the same alias, this creates a conflict that causes test failures.

---

**Proposed Short-Term Solution**\
Update the Test Manager to:

* Append a **random string suffix** to the alias for each scheduled test execution.
* Ensure uniqueness of the alias across simultaneous test runs.

✅ This solution is acceptable in the short term, since scheduled test modules **do not currently rely on the Org ID being present in the alias**.

---

**Follow-up / Technical Debt**\
A separate issue will be created to:

* Remove the dependency on Org ID within the alias.
* Refactor alias generation to decouple it entirely from business logic and allow for more scalable test execution.

---

**Impact**\
This will prevent test execution failures during concurrent test runs and improve the stability of the scheduling feature in both FVP and the Conformance Suite.
