#### Current Behavior:
---
In test `credit-portability_api_x-fapi_test-module_v1-1` (Credit Portability API `v1.1.0-rc.1`), for a missing or invalid `x-fapi-interaction-id` header, the suite requires the HTTP 400 response body to carry `errors[].code` equal to `PARAMETRO_INVALIDO`. The test fails on any other value, even when everything the specification mandates is met (400 status, generated `x-fapi-interaction-id` returned in the response header, body compliant with the error schema).

This requirement has no basis in the specification:

- the normative clause for this scenario prescribes only the HTTP status and the header handling — it says nothing about `errors[].code`;
- `errors[].code` is free text (`pattern: '[\w\W\s]*'`, `maxLength: 255`) with no `enum`;
- `PARAMETRO_INVALIDO` occurs exactly once in the whole specification, in a section explicitly scoped to **HTTP 422**. The suite is requiring, in a 400 response, a code the specification binds to 422.

**Impact:** this failure blocks the achievement of the 100% regulatory milestone, due on 14 September 2026.

#### Expected Behavior:
---
That test should validate only what the specification mandates: HTTP 400, the `x-fapi-interaction-id` response header carrying a valid UUID generated by the institution, and a body compliant with `ResponseErrorWithAbleAdditionalProperties` (`code`, `title`, `detail` present and within limits) — without enforcing a specific value for `code`.

If the requirement is intentional, we ask that it first be normatised in the API specification — stating the expected code and the HTTP status it binds to — before being enforced in a test.

#### Evidence:
---

**Credit Portability 1.1.0-rc.1** — [Swagger - API Portabilidade de Crédito v1.1.0-rc.1](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/2030141967/Swagger+-+API+Portabilidade+de+Cr+dito+v1.1.0-rc.1), `components.parameters.xFapiInteractionId` (the same text is replicated verbatim in every response `headers` block):


> Caso não seja recebido ou se for recebido um valor inválido, a IF Credora deve gerar um x-fapi-interaction-id e retorná-lo na resposta com o HTTP Status Code 400.

No mention of `errors[].code`.

**Only occurrence of `PARAMETRO_INVALIDO`** — Credit Portability 1.1.0-rc.1 `info.description`, under "Validações de erros sintáticos e semânticos, previstas com retorno **HTTP Code 422** - Unprocessable Entity":

> - Formatação de parâmetros: Valida se parâmetros informados obedecem a formatação especificada (PARAMETRO_INVALIDO).
