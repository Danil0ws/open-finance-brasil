The test should also allow a 401 or 201, so it enables syncronoiu or assyncronough error processing. Therfore, we should update as follows:

* Calls the POST Payments Endpoint, using the access token with the nrp-consents, authorisationFlow as HYBRID_FLOW and consentId with the corresponding ConsentID
* Expects **201 or** 422 PARAMETRO_INVALIDO - Validate Error Response

**If response is 201:**

* Call the GET Payments Endpoint
* Expects 200 with a RJCT status, and rejectionReason as DETALHE_PAGAMENTO_INVALIDO

and:

* Calls the POST Payments Endpoint, using the access token with the nrp-consents, authorisationFlow as FIDO_FLOW and without sending the consentId field
* Expects **201 or** 422 PARAMETRO_INVALIDO - Validate Error Response

**If response is 201:**

* Call the GET Payments Endpoint
* Expects 200 with a RJCT status, and rejectionReason as DETALHE_PAGAMENTO_INVALIDO
