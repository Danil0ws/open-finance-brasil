## 📝 Descrição

## 1. What Happened and what were you expecting?

This is based on the SD ticket 9086

According to open ticket 8911, we identified errors in the validations of the engines that need to be corrected, as follows:
a) Engine sends invalid subjectDN field, without converting "juridiction" field to OID.
Test Name:dcr-subjectdn
Variant:client_auth_type=mtls, fapi_auth_request_method=pushed, fapi_profile=openbanking_brazil,

________

Looking at the test we have that the following subject_dn being sent on the DCR

> "tls_client_auth_subject_dn":"UID=1be458b1-02c4-4cf1-b365-de5c0c64c090,jurisdictionCountryName=BR,businessCategory=Business Entity,serialNumber=90400888000142,CN=*.getnet.com.br,OU=b8d20b1b-e8a7-5099-8174-05ea48bcb566,O=BCO SANTANDER (BRASIL) S.A.,L=SAO PAULO,ST=SP,C=BR"

Looking at the security specification - https://github.com/OpenBanking-Brasil/specs-seguranca/blob/main/open-banking-brasil-dynamic-client-registration-1_ID2.md#certificate-distinguished-name-parsing

> Use the OIDs of the attributes defined in this specification for use in the OFB (businessCategory = OID 2.5.4.15, jurisdictionCountryName = OID 1.3.6.1.4.1.311.60.2.1.3, serialNumber = OID 2.5.4.5) with values in ASN.1 format, following the RFC4514, being that:

So the field jurisdiction is not being converted.
