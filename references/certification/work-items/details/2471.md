Hello @lheperez.

The test is expected to perform three POST /fido-registration-options requests:

* **Call the POST fido-registration-options endpoint**
  * Expect 201 - Validate Response
* **Call the POST fido-registration-options endpoint with the `same` idempotency key**
  * Expect 201 - Validate Response and ensure challenge has the `same` value as the previous request
* **Call the POST fido-registration-options endpoint with a `different` idempotency key**
  * Expect 422 - Validate Response and ensure error code as MAXIMO_CHALLENGES_ATINGIDO

![image.png](/uploads/c0b597e66986be338da384b043148620/image.png){width="876" height="384"}

So, following the summary logic, requests # 1 and # 2 must use the same idempotency key. The Suite is behaving as described, but your AS is returning an internal server error on that step, instead of accepting the request and returning 201.

Please adjust your AS behavior for this scenario to pass the test.

Feel free to reopen this issue if needed.
