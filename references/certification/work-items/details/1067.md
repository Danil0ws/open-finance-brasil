Hello @rodrigo.machado1,
Thanks for opening up the ticket! 

From the Swagger extract you provided, it seems that the issue concerns to a logged user scenarios, rather than the header validations that are being tested. The Swagger specifies that a 401 error is expected for an invalid token, while a 403 error is expected when the scope is not valid, characterizing a scenario where the user has access but not specifically for that scope.

The test failed because the endpoint requires a grant type "authorization code". A client credentials token does not identify the user as expected in an authorization code token, hence a 401 error is appropriate.

Therefore, no corrections are needed on the CS side. For the test to pass successfully, the implementation must be adjusted so that it expects a 401 error when client credentials validation fails. This is the correct response when the token has an incorrect grant type.

Feel free to open another ticket if you encounter any other issues! We're happy to help!
