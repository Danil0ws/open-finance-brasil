## 📝 Descrição

## 1\. What happened and what were you expecting?

The test payments_api_consents_rejection-reason_test-module_v3 should create a new consent for the second test case as described here:

2. Ensure consent is rejected when the user rejects it manually

   **• Call POST consent with valid payload**

   **• Expects 201 - Validate response**

   • Redirects the user to reject the consent

   • Call GET Consent

   • Expects 200 - Validate if status is "REJECTED" and rejectionReason is REJEITADO_USUARIO

However, instead of creating this consent, it's trying to reuse the same consent created on the first test case.

As it can be seen in our test log, it calls a POST on the create consent endpoint and the created consent has the id urn:BRB:4C5B98411ED4C0C9BF6FF7B35E4F4987 on the response, which is then rejected correctly because the creditor and debtor accounts are the same. Right after that it does not call the POST consents again, instead it redirects the tester to reject the very same consent from the first test case, which is already rejected.
