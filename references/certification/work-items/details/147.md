Hi Patrick,

payments-api-dcr-happyflow is using a PAGTO client, I don't see any issue in the test setup. If you can see any issue please circle in a screenshot or similar.


payments-api-dcr-test-unauthorized-client and payments-api-dcr-test-attempt-client-takeover are correctly using a DADOS client, as described in the test description of the former:

 "Obtain a software statement from the Brazil sandbox directory (**using a hardcoded client that has the DADOS role**), verify (in several different ways) that it is not possible to obtain a client with the 'payments' scope granted, and that a client credentials grant requesting the 'payments' scope fails with an 'invalid_scope' error. Note that this test overrides the 'alias' value in the configuration, so you may see your test being interrupted if other users are testing." :

![Screenshot_2021-12-20_at_15.44.55](/uploads/9bb0d48aa4ba8c77052c5687b50efbd7/Screenshot_2021-12-20_at_15.44.55.png)

There are various reasons why the AS is failing tests, mainly that it is returning "Software Statement doesn't match client certificate" when the client cert does match (and the same cert was accepted by the directory), and in other cases because it returns an error code of "invalid_software_statement" that is not defined by any of the standards instead of the expected error code.
