#### Current Behavior:

---

Related to SD ticket: **#55835**

During the following steps:

In the last flow, execute the below:\
• Call the POST Payments Consents V4 Endpoint, with the amount as with the transactionLimit sent, with the payment.date for today\
• Expect 201 - Validate Response\
• Call the POST Fido Sign Options Endpoint\
• Expect 204\
• Call the POST Consent Authorise Endpoint\
• Expect 204\
• Call POST Pix Payment Endpoint\
• Expect 201 or 422 VALOR_ACIMA_LIMITE - Validate response

In between "Call the POST Consent Authorise Endpoint" and "Call POST Pix Payment Endpoint"

Conformance Suit is Checking the created consent and Expecting AUTHORISED status trough a GET payments/v4/consents request.

As this regards the final POST Pix Payment request, in which the dailyLimit is surpassed, the Server retuned in the response for this call the following payload:

```
"status": "REJECTED",
"rejectionReason": {
      "code": "VALOR_ACIMA_LIMITE",
      "detail": "O valor ultrapassa o limite estabelecido para o vínculo de conta."
    }
```

As Conformance Suit was expecting AUTHORISED state, the test module execution resulted in Warning instead of Success. 

#### Expected Behavior:

---

Conformance Suit should expect the Consent to be in status "REJECTED" during last payment flow that surpasses dailyLimit.

Will this test module execution that resulted in "WARNING" be considered for the 100% mark?
