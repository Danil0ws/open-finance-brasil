#### Current Behavior:
---
The functional test engine is validating that the `billForestDate` field is ordered in **ascending order**, as observed in the execution logs from the homologation environment (to be attached).

When the API returns data in **descending order**, the test is marked as failed, even though this behavior is compliant with the functional documentation of the endpoint.

Impacted endpoints:
- `transactions`
- `transactions-current`

#### Expected Behavior:
---
According to the functional specification of the **transactions** endpoint, the expected ordering is:

> “The list must be ordered from the most recent transaction to the oldest one.”

That is, the correct ordering for the `billForestDate` field is **descending (most recent → oldest)**.

Therefore, when the API returns data in this order, the functional test **should not fail**.

Clarification is requested regarding which rule should prevail:
- the rule defined in the documentation (descending order), or
- the rule currently enforced by the functional test engine (ascending order).

In case of divergence, please confirm whether there is a plan for:
- correcting the test engine, or
- updating/adjusting the technical documentation.

#### Evidence:
---
- JSON logs from the homologation environment showing that the engine validates ascending ordering (to be attached).
- Failed test result related to ordering from most recent to oldest:  
  https://web.conformance.directory.openbankingbrasil.org.br/plan-detail.html?plan=EFbAZjrQ8SNX9&public=true
