Hi,

Thanks for the ticket! 

The test uses the pattern described in the latest specification, for record:
![image](/uploads/75857ff69ba133c99e74e0d34165e2df/image.png)

The payments webhook pattern cited at the test summary is indeed incorrect and we'll fix it. We'd like to apologize for that and also **inform that it does not prevent you from getting a success in the test**.

The test ID sent failed because a payment was made and the test expects to receive 2 webhook notifications:
- A Consents webhook notification as the consent status was updated to CONSUMED
- A Payments webhook notification as the payment status was updated to ACSC

But as it received only the payment webhook notification, the test indeed should fail as no consent webhook notification was found:

![image](/uploads/468fdc5af1724d409295a1904bb54492/image.png)

Therefore, there is a correction to be made at CS side regarding the payments webhook pattern cited at the test summary and we will make updates here. However, **it does not stand in the way of a successful execution in this test module. This can be achieved by adjusting the implementation to send webhook notifications for both defined endpoints.**

Feel free to open another ticket if you get any other issue! Happy to help!
