Hello everyone! Thank you for the additional explanations. As mentioned earlier, there are currently multiple versions of the consents API in use. When certification is completed, no further updates are made to the test plan, as the entire ecosystem has already been certified based on that premise. In the aforementioned cases, the conformance suite should remain unchanged for now.

We are aware that there are enhancements in the APIs that will affect the "Orientações" pages on the outermost part of the consents section. However, older versions should not be altered, as the entire ecosystem has already implemented them in their respective ways. Updates will only be applied to the latest versions.

Therefore, there are no changes to the conformance suite. The new error messages will only be applied to the new versions, while older versions will remain unaffected. We are available to assist with any further requirements you may have.

Hi,

Thanks for opening the ticket!

As correctly pointed, the test module execution resulted in failure while conformance suit was executing the following step:

> Call the POST Consents Endpoint with expirationDateTime as 2300-01-01T00:00:00Z
>
> Expects failure with a 400 Error

In this step, conformance suit made a POST /v2/consents request , sending in it's payload a "expirationDateTime":"2300-01-01T00:00:00Z" (UTC), thus operating according to what is described in the test module summary and to what is described in https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/207716438/Informa+es+T+cnicas+-+DC+Consentimento+-+v2.2.0, which is the specification to consents V2. As Consents Orientations (https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/219480491/Orienta+es+-+DC+Consentimento) was only created for consents V3, and thus linked in it's specification, this test module is behaving according to expected for the V2 of the consents API.

Feel free to open a new issue if you have any other questions,
