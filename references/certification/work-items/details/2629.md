#### Current Behavior:
---
During consent creation, there's a validation if the `purpose === 'WITHDRAW' || purpose === 'CHANGE'` and the `payloadJWS` field are not sent; it should return an error. Is this condition correct, or should the engine be passing the `payloadJWS` field?

This is based on the documentation which states the following rule:
"Ao receber um pedido de criação de consentimento que esteja marcado como WITHDRAW ou CHANGE no campo /data/payment/purpose, o PSP do Pagador (Detentor) deverá consultar os dados do agente e do facilitador do serviço dentro do payloadJWS enviado pelo ITP, assim como os outros dados pertinentes a operação solicitada."

#### Expected Behavior:
---
The test should send the payloadJWS field when creating the consent.

#### Evidence:
---
The payloadJWS field is missing when creating the consent, even though it is set in the test configuration.

Hi,

Thank you for reaching us.

The `PayloadJWS` schema defines the following restriction:

`[Restrição] Campo de envio obrigatório quando o valor presente em /data/payment/details/localInstrument for igual a APDN ou QRDN.`

\
This means the `payloadJWS` field is mandatory **only** when `localInstrument` is `APDN` or `QRDN`. In this test, the `localInstrument` is **`QRES`**, so the `payloadJWS` is **not required**.

---

**Regarding the documentation excerpt you cited:**

The passage stating that the PSP should consult the agent and facilitator data within the `payloadJWS` when `purpose` is `WITHDRAW` or `CHANGE` is a descriptive guideline about the expected behavior **when the `payloadJWS` is present** (i.e., in QRDN/APDN scenarios). It does not establish an additional mandatory condition for the field based on `purpose`. The formal obligation for sending `payloadJWS` remains tied exclusively to the `localInstrument` value, as defined in the schema restriction.
