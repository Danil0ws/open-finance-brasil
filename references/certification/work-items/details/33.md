## 📝 Descrição

This bug has been informed on the tickets 2061 and 2057

This bug has appeared with 4.1.20 plan update, and is related to the accoutns fields on both  customer-personal-data-api-test/customer-business-data-api-test

According to banco do brasil "the problem lies in the amount field with a default of 2 decimal places. EX: 1000.00. The engine is claiming that it is receiving 1000.0 and that it is out of patttern. Checking the log response, the correct information was sent, but the engine is doing the validation wrongly. In test version 4.1.19, performed yesterday, it was ok. Today, in test 4.1.20 it is no longer."

Hi I have raised a PR covering this. We were correctly handling doubles with a non-zero ending (i.e. 1000.01) however when a double had trailing zeros (i.e. 1000.00) these were being clipped to 1 d.p. by our JSON parser. 

That previous pass you found was where we were not in-fact enforcing the regex defined in the specs. This has also been changed
