Hi, Thanks for opening this issue!

As can be seen, conformance suit is validating the pattern for issuerInstitutionName according to the available specification:

https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/619348333/Informa+es+T+cnicas+-+DA+Investimentos+-+v1.0.1

![image.png](/uploads/2542887830a6eb57a75854688d135e54/image.png)

Although, it seems that the pattern defined in the specification is not appropriate if the intention is to enable multiple words separated by spaced between them. The current pattern returns multiple different matches instead of one that fetches the whole issuerInstitutionName. Also, the pattern being used does not match the provided example.

Therefore Conformance Suit is operating as expected, this issue will be sent to GT for evaluation in regards to the pattern.

To be able to pass the test module given the current Specification, this can be done by providing only one word for. issuerInstitutionName without using spaces to separate them, also avoid using special characters such as "."

One possibility of pattern that allows multiple words with spaces is:

`[\w\W\s]*`

Happy to help!
