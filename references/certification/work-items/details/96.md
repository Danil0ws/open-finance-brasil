We have identified around 50 fields on the Phase 2 specifications that request between 2 and 4 decimal cases after the comma with a type:DoubleField 

We are aware that javascript cannot represent a double with trailing 00, which won't allow orgs to pass conformance if they try to send a value of 1.0000 (which will become 1)

Raidiam recommends changing the Pattern on all the related fields change so it can accept 0 up to 4 decimal places, which won't break the existing implementations, while will also allow institutions to send an integer 

An example of this field is the BlockedAmount which has the following pattern  ^-?\d{1,15}\.\d{2,4}?
