## 📝 Descrição

During the execution of the Compliance Engine tests for the endpoint `/open-banking/accounts/v2/accounts/{accountId}/transactions`, we identified the following error:

`GetAccountTransactionsOASValidatorV2n5n1: data.partieCnpjCpf is required when data.type is CONVENIO_ARRECADACAO and data.creditDebitType is DEBITO`

After reviewing the Accounts API v2.5.1 documentation and the official Open Finance Brasil Swagger specification, we could not find any rule stating that `partieCnpjCpf` is mandatory when `type` is `CONVENIO_ARRECADACAO` and `creditDebitType` is `DEBITO`.

We also reviewed the Accounts Data Dictionary guidelines and could not find this specific validation rule documented for this scenario.

Therefore, we would like to confirm whether this validation is expected and officially required for version 2.5.1.

**Request:**

Could you please confirm whether this validation is part of the official v2.5.1 specification and, if so, provide the corresponding documentation or specification that defines this requirement?

If this rule is not part of the current specification, please review the Compliance Engine validation accordingly.

Hi @rogeriorocha083 ,

Thanks for the report and for attaching the full execution log, it made the analysis straightforward.

The short answer is that this validation is expected for Accounts API v2.5.1 and it is documented, just not in the place you looked. Let me walk you through where it comes from.

**1. The Swagger itself points to the rule**

The requirement is not expressed in the schema `required` list, which is exactly why searching there does not find it. 

It lives in the field description. In the v2.5.1 Accounts spec, the description of `partieCnpjCpf` reads:

> "Identificação da pessoa envolvida na transação: pagador ou recebedor (...). Com a IN BCB nº 371, a partir de 02/05/23, o envio das informações de identificação de contraparte tornou-se obrigatória para transações de pagamento. Para maiores detalhes, favor consultar a página `Orientações - Contas`."

So the field tells us two things: the obligation comes from `IN BCB nº 371` (in force since 02/05/2023), and the detailed conditions are on the page "Orientações - Contas".

**2. The "Orientações - Contas" table defines when it applies**

That page has a table listing, per transaction type, when the counterparty must be sent. It splits by the direction of the money (`creditDebitType`):

- pagador column, when `creditDebitType = CRÉDITO`
- recebedor column, when `creditDebitType = DÉBITO`

For `CONVENIO_ARRECADACAO`, the row is:

- pagador (`CRÉDITO`): `R`, still under evaluation by the Central Bank, so not required
- recebedor (`DÉBITO`): `S`, sending is mandatory

(Legend: `S` = mandatory, `N` = not required, `R` = under evaluation by the Central Bank.)

This is precisely what the CS enforces. It requires `partieCnpjCpf` only on the `DEBITO` side of `CONVENIO_ARRECADACAO` and not on the `CREDITO` side, mirroring that row. The message "required when type is CONVENIO_ARRECADACAO and creditDebitType is DEBITO" is a direct translation of that `S` cell.

**Conclusion**

The validation is correct and officially backed by `IN BCB nº 371` and the "Orientações - Contas" page, which the `partieCnpjCpf` field description in the v2.5.1 Swagger explicitly refers to. To pass this module, please include `partieCnpjCpf` (the recebedor's CPF or CNPJ) in the `CONVENIO_ARRECADACAO` debit transactions, as you already do for other payment types.
