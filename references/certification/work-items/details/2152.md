When running the test `automatic-payments_api_automatic-pix-consent-edition-restrictive_test-module_v2`, I'm receiving the following error:

Validate PATCH consent response: `EnsureRecurringConsentFieldsAreAsInPatchRequest: The field maximumVariableAmount has been indefinitely extended, so it should not exist in the response data.`

At the beginning of the test, the consent was created with the `maximumVariableAmount` field populated. I'm not sure why this field should not be present in the PATCH response, considering that `maximumVariableAmount` is only mutually exclusive with the `fixedAmount` field.

Could you please clarify this behavior?

Hi @rafael.podewils1 

Thanks for contacting us!

In this scenario, the **maximumVariableAmount** field was correctly sent during the initial POST recurring-consents request. This field defines the allowed variable payment amount and should only be set during the creation of the consent, not during updates.

When making a PATCH request, you should only send the fields that need to be updated. The PATCH request is intended for modifying specific fields like **creditor name and expirationDateTime**, and not for updating values like maximumVariableAmount, which has already been set in the initial POST request.

**Summary:**

- The maximumVariableAmount field should not be included in the PATCH request unless explicitly required by the test scenario.

- Only update the relevant fields such as creditor name and expirationDateTime in the PATCH request.

Please let us know if you need further assistance or clarification on this matter.
