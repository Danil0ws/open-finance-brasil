## 1. What happened and what were you expecting?

The recurringConfiguration and x-fapi-interaction-id fields are not sent during the test. 
We think the return should be http 400 as failure to send a mandatory field characterizes poor formatting of the request.
Another situation is when the test does not send x-fapi-interaction-id the return should be “PARAMETRO_NAO_INFORMADO”, the current validation is expecting PARAMETRO_INVALIDO which characterizes that the parameter was sent but does not comply with some type of validation, for example a pattern was not respected.

Hi All! Thanks for the ticket!

We have raised this question to the WG, and the test will be updated as follows:

Ensure validations are being executed at the POST recurring-consent endpoint, and a consent cannot be created in unhappy requests\
• Call the POST recurring-consents endpoint without the recurringConfiguration.sweeping field \
• Expect 422 PARAMETRO_NAO_INFORMADO **or 400** - Validate Error Message\
• Call the POST recurring-consents endpoint with the start date time as D+10 and expirationDateTime as D+5\
• Expect 422 PARAMETRO_INVALIDO - Validate Error Message\
• Call the POST recurring-consents endpoint without the x-fapi-interaction-id\
• Expect **400** - Validate Error Message and check if a x-fapi-interaction-id has been sent back

We will soon update the test accordingly and close this issue when merged
