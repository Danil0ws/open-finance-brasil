## 📝 Descrição

#### Current Behavior:
---
In the following few sweeping payments tests, the POST `/pix/recurring-payments` incorrectly sends a `MANU` payment with the optional field `proxy`, which is not allowed according to the documentation:

- `automatic-payments_api_sweeping-accounts-root-cnpj_test-module_v2`
- `automatic-payments_api_multiple-consents-core_test-module_v2`

#### Expected Behavior:
---
According to the specification ([API Automatic Payments v2.0.0-beta.2](https://raw.githubusercontent.com/OpenBanking-Brasil/openapi/main/swagger-apis/automatic-payments/2.0.0-beta.2.yml)), the field `proxy` is optional and must not be sent in the payload for POST `/pix/recurring-consents` when `localInstrument` is `MANU`:
![image](/uploads/a3a0f3d1f8917ce101e4b1b0ffcdd8e0/image.png)

That said, as the test expects a success, it should either:
- send `localInstrument` as `DICT`
- or send `localInstrument` as `MANU` but without the field `proxy`.
