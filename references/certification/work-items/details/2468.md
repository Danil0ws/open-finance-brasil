After reproducing all scenarios, we verified that it is currently not possible to manually create restricted plans without the required access. The evidence of this type of plan being created by users who were not Certification Managers is isolated and concentrated between November 2025 and January 2026. After that period, the evidence only shows the reuse of previously created plans for recurring execution of the modules, with no success in creating new ones. As there were no structural changes during that interval that would have altered this restriction, improvements were implemented in the FVP Manual logs to support the root cause analysis. Therefore, if a new execution occurs, we will be in a better position to understand the observed behavior.

Hello @emersonnow. Thanks for pointing that out.

This long-term (scheduling) test is part of the **_restricted_** FVP test plans. According to the Open Finance structure definition, these restricted plans are not intended to be available to the entire ecosystem, as they follow a different execution and ticket-opening automation logic. They are intended to be managed exclusively by the **FVP execution team**.

![image.png](/uploads/77c8821e9c441bc4b9d95f43db03c980/image.png){width="295" height="206"}

The current FVP logic should reflect this restriction, and we will adjust this specific case as soon as possible. For now, please disregard this test execution and do not run restricted test plans, as it is not expected to work in the same way as the **_open_** FVP test plans.

In addition, we’ve set this issue to confidential, since the test log you shared contains real data.

Thank you again for sharing this case.
