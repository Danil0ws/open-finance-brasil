Hi @sensedia.andre 

Regarding the scenario **enrollments_api_missing-required-risk-signals_test-module_v2-2**, this test was designed and validated by the Open Finance governance structure.

Although the specification lists multiple possible error codes (including **FALTAM_SINAIS_OBRIGATORIOS_DA_PLATAFORMA** and **PARAMETRO_NAO_INFORMADO**), for this specific scenario the expected behavior defined by the test suite is:

* When calling **POST /risk-signals** without the mandatory `deviceId` field,
* The API must return **HTTP 422** with the error code **PARAMETRO_NAO_INFORMADO**.

The intention of this test is to validate the absence of a required parameter, rather than the general lack of mandatory platform signals. Therefore, **PARAMETRO_NAO_INFORMADO** was intentionally chosen as the expected error code for this case.

If you still disagree with this behavior or believe the error code should be updated according to the specification interpretation, we can forward this topic to the Open Finance structure for further evaluation.
