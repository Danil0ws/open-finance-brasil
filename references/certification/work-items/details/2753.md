Olá @Cmerlini.

Analisamos o log do teste `personal-accounts_api_structural_test-module_v1` e a reprovação não é uma falha de comunicação do motor, o validador efetivamente identificou um campo obrigatório ausente no payload.

Na resposta do endpoint `/personal-accounts`, o primeiro registro de `data` (conta do tipo `CONTA_DEPOSITO_A_VISTA`) tem um item em `serviceBundles`, o pacote "TARIFA PAGAMENTO FOLHA/OUT", que não traz o campo `services`, que é obrigatório. É exatamente o que a mensagem do teste aponta:

> Unable to find element services on the GetPersonalAccountsOASValidatorV1 API response

O `currentElement` mostrado junto ao erro é justamente esse pacote (com `name`, `prices`, `minimum` e `maximum`, mas sem `services`).

No schema `ServiceBundle` da API Accounts (Open Data), `services` é obrigatório e deve ter ao menos um item (`minItems: 1`). É a lista dos serviços que compõem o pacote. Como referência, o segundo registro de `data` (conta `CONTA_POUPANCA`) já está correto, pois o `serviceBundles` dele inclui o `services`.

Correção: Incluir `services` no pacote "TARIFA PAGAMENTO FOLHA/OUT". Após o ajuste no payload, basta reexecutar o teste com o campo presente, a validação passa normalmente.

Encerraremos esta issue, mas fique à vontade para reabrir se necessário.

Permanecemos à disposição.
