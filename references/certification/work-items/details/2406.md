## 📝 Descrição

We have identified that the engine is triggering the payment process but not verifying whether the payment has been successfully completed. It is not calling the GET method to check the payment status and is immediately invoking the balances API.

In addition to the above behavior, please note that according to the current rules (https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17369300/Dados+Cadastrais+e+Transacionais+-+DC), the balance update is asynchronous and may take up to five minutes to be reflected in the API.

Technical Details

Current Flow:

POST /payments → Initiates payment.
Skips GET /payments/{id} for status verification.
Immediately calls GET /balances.

Expected Flow:

Trigger payment via POST /payments.
Poll GET /payments/{id} until status = COMPLETED.
After confirmation, call GET /balances to retrieve updated balance.

Problem:

The engine does not implement a status validation step before invoking the balances API.
This violates the API contract and the Open Finance Brasil guidelines, which require confirmation of payment completion before querying balances.

Suggested Fix:

Implement a status polling mechanism with retry logic and configurable timeout before calling GET /balances.
Ensure compliance with Open Finance Brasil specifications for transactional data.

Impact

Prevents successful completion of payment workflows.
Causes inconsistencies in balance reporting and downstream processes.
