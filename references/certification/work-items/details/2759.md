## 📝 Descrição

Hi Master,

We are testing the Brazil Account RP flow on iOS against the OIDF conformance suite / Mock Bank.

Test Name:fapi1-advanced-final-client-test

Test ID: gKQ1GrGnbhyB2zH

Plan ID: AY11AbDy1NcsP

#### **Participant:**

* Client platform: Shopee iOS webview flow
* Test type: Brazil Account RP conformance test
* Bank in flow: Mock Bank
* Example consentId: urn:raidiambank:consent:2dfe1c7a-56e2-4ab9-bd60-8cae0758eb02

#### **Problem:**

The test remains in WAITING after the user completes the bank authorization flow successfully.

From our logs, the following steps were completed successfully:

1. POST /of/rv/consent/create returned 200 with a valid consentId and redirectURL
2. User completed authorization on Mock Bank
3. POST /of/rv/consent/call_back returned 200
4. The consent status in our app became authorised (status=2 in our local system)

However, the OIDF suite page still stayed in WAITING, and the Browser Interaction section was empty.

#### **Could you please confirm:**

1. For fapi1-advanced-final-client-test, is it expected that the suite will remain in WAITING until the RP actually calls the exported accounts_endpoint?
2. If Browser Interaction is empty, does that mean the suite is waiting for backend/resource API calls rather than any additional manual browser action?
3. After successful authorization and callback, is calling only the authorization flow insufficient for this case, and must the RP continue with an authenticated resource request such as accounts/v2/accounts before the test can proceed?

#### **Concern:**

From the suite page and the flow behavior, it was not fully clear to us whether:

* the test was still waiting for a manual browser step, or
* it was already waiting for the RP to call the exported resource endpoint.

This is important for us because our current mobile flow completes consent authorization and updates local sharing status, but does not automatically continue to fetch account data immediately afterward.

##### **1. Consent creation succeeded**

Time: 2026-06-15 04:14:10\

##### **2. Authorization callback succeeded**

##### **3. Local consent detail/list shows the sharing is active**

Time: 2026-06-15 04:25:55 and 2026-06-15 04:25:58\

* POST /of/rv/consent/detail
* POST /of/rv/consent/list

Response summary:

* the same consent is present
* status remains authorised / active in our local system

##### **4. What we did not observe**

In the same log set, we did not observe a follow-up request to:

* the exported accounts_endpoint
* or another exported resource endpoint

That is why we would like to confirm whether this is the missing required step for the suite to move out of WAITING.
