## 1. What Happened and what were you expecting?
This test expected a 422 error response for consents created with the server unsuported permissions.

During the test service ours we are answering correctly for all suported permissions, but when the certification engine try to create a new consent with Credit Card Limits permission, which ours service does not support, we are returning a 422 error with the response body below:

*Response Body:* 
{"errors":[{"code":"CONS-0002","title":"Missing functional permissions","detail":"There are no functional permissions enough to process this request."}],"meta":{"totalRecords":1,"totalPages":1,"requestDateTime":"2023-06-05T17:43:32Z"}}

The certification engine checks if there all the necessary fields in this response, and the results of this match is 'success'. But it trying to get a 'ConsentId' field from response and are throwing a null pointer exception who makes the tast fail.

Finally, i think is not necessary looking for the 'ConsentId' during error test this, because in the specification there are no 'consentId' field on 422 response.

Public link for the tast plan: https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=K1v3XRSFZSp8UwA&public=true

Hi,

Your behavior is aligned with the [Consents 2.0.1 specification](https://openbanking-brasil.github.io/openapi/swagger-apis/consents/2.0.1.yml):

- A transmissora deve retornar, da lista de permissions requisitadas, apenas o subconjunto de permissions por ela suportada, removendo da lista as permissions de produtos não suportados e retornando HTTP Status Code 201. Caso não restem permissões funcionais, a instituição transmissora deve retornar o erro HTTP Code "422 Unprocessable Entity".

Trying to call the class "ConsentIdExtractor" seems to be an issue on the test and we will work on a correction forn it.
