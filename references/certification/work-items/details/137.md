## 📝 Descrição

# Test Details

- **Test Plan**: Functional tests for Payments API QR Code (T2)
- **Test Name**: payments-api-qres-mismatched-proxy-test

# What is happening:

The test expectes the error code COBRANCA_INVALIDA, witch is not compatible with the valid error according to the documentation: [BENEFICIARIO_INCOMPATIVEL](https://openbanking-brasil.github.io/areadesenvolvedor/#tocS_EnumErrorsCreatePayment), for proxy errors.

- Log detail: https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=1DYEBIHMHJbEIQO


# Second Test Details

- **Test Plan**: Functional tests for Payments API QR Code (T2)
- **Test Name**: payments-api-qrdn-with-qres-code-test

# What is happening:

Same thing as the previous description, with the error code PAGAMENTO_DIVERGENTE_DO_CONSENTIMENTO being expected but not being compatible with the documentation, since on the test, the payment is indeed aligned with the consent.

The suggestion in this case would be to change it to NAO_INFORMADO, since there is no code that properly describes this scenario.

- Log detail: https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=A3fsy5abQYq3S4H

There was a misunderstanding here. I wrongly inverted the payments-api-qres-mismatched-consent-payment-test with the mismatched-proxy-test

The PAGAMENTO_DIVERGENTE_DO_CONSENTIMENTO should be used only on the test: payments-api-qres-mismatched-consent-payment-test 
which can be seen here. https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=BOtUFIeBk7tBQu2&public=true as they are swapping the QR between two payments. 

For the test payments-api-qres-mismatched-proxy-test and payments-api-qrdn-with-qres-code-test the correct code should be COBRANÇA INVALIDA. 

Basically they both have the same behavior:

POST Consents

* \*Can Return a 201 Created
* \*It can also return a 422 with the error being DETALHE_PGTO_INVALIDO

POST Payments

* \*Can Return a 201 Created - Status can be PDNG or PART
* \*It can also return a 422 with the error being COBRANCA_INVALIDA

POLL on the Get

* 


* Must end with RJCT with Rejection Reason: "ELEMENT_CONTENT_FORMALLY_INCORRECT"


About the error codes being used, the decision was made by the specifications WG and approved by the Board. All issues on the QRCODE field that blocks the PSP from making the payment must be COBRANÇA_INVALIDA.

Using theses error codes, I believe we can misinterpret the problem.

In the first case, the error_code PAGAMENTO_DIVERGENTE_DO_CONSENTIMENTO suggests the permitted payment and perform the payment are divergent, that doesn't happen.
In my understanding, the problem is caused by the value of decoded QR Code which is different and I should use VALOR_INVALIDO instead of PAGAMENTO_DIVERGENTE_DO_CONSENTIMENTO

In the second details, in the documentation COBRANCA_INVALIDA is used for validation, due date and status validate (https://openbanking-brasil.github.io/areadesenvolvedor/#tocS_422ResponseErrorCreateConsent)
In my opinion, using Icaro's suggestion that the (NAO_INFORMADO) seems to be a better option.
