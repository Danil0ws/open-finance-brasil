## 📝 Descrição

![self_link_error](/uploads/0d16f217018734335ff758ffc0261c56/self_link_error.png)I'm dealing with an error here that returns the following error message: Fetch Account Current transactions with full range date parameters: Phase4bPaginationValidator: self link in the response is not the same as the request url / self link is not equal to the request url

the URL of the request in question is the following:

requestUrl : **https://matls-auth-sandbox.unicred.com.br/open-banking/accounts/v2/accounts/c082689e-0435-452f-9c26-e9ccf0af678c/transactions-current?fromBookingDate=2023-06-30&toBookingDate=2023-07-05**

the url we are making available at link.self is: **https://matls-auth-sandbox.unicred.com.br/open-banking/accounts/v2/accounts/c082689e-0435-452f-9c26-e9ccf0af678c/transactions-current?page-size=25&page=1&fromBookingDate=2023-06-30&toBookingDate=2023-07-05**

we have a difference in the urls due to the addition of the query params page and page-size.

based on the available documentation, these two parameters have minimum values ​​in the request and if they are not informed, they must default to the following values, page=1 and page-size=25. this way these parameters become part of the request leaving it in the pattern we are returning.

I believe that there may be some mistake in the construction of the validation of the url by disregarding this rule of the documentation, can you please evaluate.

I went to check the implementation carried out and the way it was done is not obeying the documentation.

In the documentation there is a passage that says if the page and page-size parameters are not informed in the requestURL, it should be considered as default values ​​page =1 and page-size =25

I understand that this is how it should be done because of what the documentation says.
