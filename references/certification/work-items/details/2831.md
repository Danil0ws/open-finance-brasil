Hi @rogeriorocha083. Thanks for bringing this up.

The validation is correct, and this is not a suite bug.

The QR code provided in the issue text does not contain the EMV field 54 (Transaction Amount). Decoding it field by field, the sequence is:

* 00 (Payload Format Indicator) -\> 26 (Merchant Account Information, Pix) -\> 52 (Merchant Category Code) -\> 53 (Transaction Currency, 986) -\> 58 (Country Code, BR) -\> 59 -\> 60 -\> 61 -\> 62 -\> 63 (CRC).

It goes straight from field 53 to field 58, with no field 54 in between. It is a static QR **without** an amount. The additional information field even reads "Teste-Saque-GenStatic".

Everything else in the QR is valid. It has the Pix merchant account information and a valid FSS (8 digits). The only missing element is the amount, which is exactly what the error reports:

`ValidateQresConfig: QRES qrCode is missing the payment amount`

This is documented in the module summary itself, which states the required input:

> "This test requires a static QR code generated by Pix Tester, which MUST contain an FSS and a value, and may or may not contain a txId."

The Pix Saque QRES module requires a static QR containing both an FSS **and a value**. The happy path validates that the payment amount strictly matches the withdraw value, so the QR must carry a determined amount for the flow to proceed.

The screenshot provided decodes a different QR code from the one in the issue text:

* Image QR: key 4004901d-bd85-4769-8e52-cb4c42c506dc, city BRASILIA, amount 202.40 present.
* Text QR: key 15651489-6f71-4b96-adef-188e7de96066, city Crateus, "Teste-Saque-GenStatic", no amount.

The error corresponds to the text QR, which has no amount. The QR shown in the image would not produce this error.

Regenerate the QR in Pix Tester including an amount (field 54), keeping the FSS. With the amount present, the module proceeds normally. And please feel free to reopen this issue if needed.
