## 📝 Descrição

**Bug Description:**
The payments_api_pixscheduling-patch-unhappy_test-module_v2 is not utilizing the most recently issued access token via client credentials, resulting in unexpected behavior. The bug is observed in the following logs:

- https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=HoDuKD8ghAYZ4GX
- https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=dFDWLeZ5fNb6bIT&public=true

**Expected Behavior:**
The system should always employ the most recent access token issued by the token endpoint when executing the payments_api_pixscheduling-patch-unhappy_test-module_v2. As the specifications do not provide explicit instructions on this matter, we should avoid enforcing a behavior that has not yet been defined.
