#### Current Behavior:
---
Currently, when we encounter errors such as "connection reset" or "read timed out," the feedback provided is insufficient to determine whether the issue originates from the server side or the client side; we have also observed that some endpoint calls fail due to temporary issues that resolve themselves upon retrying

#### Expected Behavior:
---
We request that more detailed diagnostic information be included in the error messages to help us pinpoint the source of these "connection reset" or "read timed out" issues more effectively; to mitigate the impact of these transient failures, we propose implementing automatic retries for such calls. This would help ensure that temporary unavailability does not cause the entire test to fail.

Since similar issues haven’t been reported by other participants, this suggests the problem may be server-side.

FVP Routine runs daily and closes tickets once successful execution is attained, that way assuring that tickets created to report failures, if related to temporary unavailability that may happen one day, will be automatically closed whenever the routine runs on the following day and doesn't encounter such failures.
