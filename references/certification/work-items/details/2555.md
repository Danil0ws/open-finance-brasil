## 📝 Descrição

**Current Behavior:** During the execution of the FVP Enrollments test (`fvp-enrollments_api_payments-core_open_test-module_v2-2`), we are observing a failure that did not occur previously. Near the end of the flow, right after the test verifies and confirms that the payment transaction was successfully cleared/settled, it executes a phase called **`Patch consent - Cancelling if applicable`** that attempts to cancel the payment.

The issue is that the test is performing an **immediate** payment. When calling the cancellation endpoint (`PATCH`) for an already settled transaction, our system correctly refuses the request and returns a `422 Unprocessable Entity` error with the code `PAGAMENTO_NAO_PERMITE_CANCELAMENTO`. The test ends up failing because of this response.

This behavior from the testing tool is inconsistent with the official documentation, since the cancellation endpoint was designed to operate on scheduled (SCHD) or pending (PDNG) payments.

**Expected Behavior:** The FVP tool should not trigger the cancellation endpoint for an immediate payment flow that has already been settled.

The expected behavior is that the suite reflects the Open Finance specification: if the payment is immediate, the cancellation step must be suppressed. If the goal of the test is to validate the cancellation route, it should be parameterized to generate a scheduled payment (SCHD). Our system's behavior is correct in returning the HTTP Status 422.

**Evidence:**

1. **Error Payload (HTTP 422) generated at the end of the execution:**

![image.png](/uploads/677c700a235a814716593d794ed1efee/image.png){width="900" height="425"}

2. **Official Open Finance Documentation Excerpt:**

> _"Esse endpoint deve ser usado para cancelar, a pedido do cliente pagador, as transações que estejam em uma das seguintes situações: Agendada com sucesso (SCHD) ou retida para análise (PDNG). \[...\] **Os pagamentos já liquidados não são passíveis de cancelamento**. Se não restar nenhum pagamento (ocorrência) que poderá ser cancelado, a requisição PATCH retorna HTTP Status 422 com o code PAGAMENTO_NAO_PERMITE_CANCELAMENTO."_
