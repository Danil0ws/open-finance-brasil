Authorization Layer issues should be handled by the FAPI/OAuth standards, which are clear about the 403:

 https://datatracker.ietf.org/doc/html/rfc6750#section-3.1

```
insufficient_scope
         The request requires higher privileges than provided by the
         access token.  The resource server SHOULD respond with the HTTP
         403 (Forbidden) status code and MAY include the "scope"
         attribute with the scope necessary to access the protected
         resource.
```

The expected behaviour should be a 403 as, based on the API spec that you have sent:

```
    Forbidden:
      description: O token tem escopo incorreto ou uma política de segurança foi violada
      content:
        application/json; charset=utf-8:
          schema:
            $ref: '#/components/schemas/ResponseError'
```

The token you are using is not authorized to consume the Consent with the first ConsentID only with the second CosnentID, which leads to a 403. You do have some authorization, but not enough to access the resource. 

If you were to hit the endpoint with a bad token or something that has not been issued to that client_id you would receive a 401. 

Can you please clarify the "On payment this status is 400 and seems to be a similar situation.
