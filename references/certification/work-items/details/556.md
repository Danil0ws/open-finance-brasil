## 1. What Happened and what were you expecting?
In the `payments-api-e2eid-test-v2` when the test generates a second authorization endpoint, it is being sent with the first consent_id.

For example, in my test, first the test created this consent `urn:mercadopago:3b75307d-8f49-4caa-8b2e-a07b0146ace1` and the auth endpoint was generated with this scope query param: `scope=openid%20openid%20payments%20consent:urn:mercadopago:3b75307d-8f49-4caa-8b2e-a07b0146ace1`

After this, the test create a new consent, for this was created the consent `urn:mercadopago:1366925c-71e8-41aa-8701-3114e2bad46f` and the auth endpoint was generated with this scope query param: `scope=openid%20openid%20payments%20consent:urn:mercadopago:3b75307d-8f49-4caa-8b2e-a07b0146ace1%20consent:urn:mercadopago:1366925c-71e8-41aa-8701-3114e2bad46f`. Note that the first consent is sent again in the auth endpoint.
