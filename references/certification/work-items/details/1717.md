#### Current Behavior:
---
The test is failing because it cannot find the id_token claim on token response. The test is adding: 'resources accounts consent:urn:citibank:53eee724-72ff-4b17-9e30-072757509d56'

#### Expected Behavior:
---
The FAPIBrazilAddConsentIdToClientScope step should add openid scope so that the token response is returned with the id_token claim. The test should add: 'openid resources accounts consent:urn:citibank:53eee724-72ff-4b17-9e30-072757509d56'

Hi Liege! Thanks fot he ticket!

Accordign to the [security specifciations](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/245760001/EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0+Implementers+Draft+3#7.2.2.-Authorization-server), the authorization server:

4. shall ensure access tokens are issued with sufficient scope necessary for access to data specified in the Permission element of a linked Consent Resource object;

In that sense, even when the scope ios not sent, the authorztion server should add the necessary scopes to access what was defined at the permissions on the consent. Looking at the consent for the refered test, the accounts permissions are included there:

![image.png](/uploads/71192494c1ca8b644204c0efe412f511/image.png){width=1685 height=422}And, at the specs, the scopes neede to acces the accounts endoints are:

![image.png](/uploads/36d4a1e8e585096669d17af15a13bd3b/image.png){width=228 height=99}

Which includes the openId scope. IN that sense, even when the conformance suite do not send the openid scope, your AS should add this and, therefore, send the id token. Besides that, the only resopnse type permitted by the [new profile](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/245760001/EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0+Implementers+Draft+3#5.2.2.-Authorization-server) is "code id token":

14. shall support the response_type value code id_token;

In that sense, sending the id token is not required by the conformance suite, while geeting a id token back in this case is mandatory for your instituiton. Therefore, there are no errors withg the conformance suite.

We are happy to help with any additional needs!
