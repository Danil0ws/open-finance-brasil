Hi Rodrigo! Thanks for the ticket!

The pointed known issue only specifies what the server should do in case it receives a token with the openid scope at POST Consents or POST Payments endpoints. It does not specify what the authorization server should respond on the token endpoint in the case of a request with the openid scope.

On the other side, the [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749#section-3.3) explicitly states that:

- If the issued access token scope is different from the one requested by the client, the authorization server MUST include the "scope" response parameter to inform the client of the actual scope granted

Since there's no explicit orientation different from the RFC, this orientation should be followed.

Please, feel free to reopen the issue if you think the issue remains or need any further clarification!
