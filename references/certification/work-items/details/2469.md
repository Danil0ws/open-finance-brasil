## 📝 Descrição

#### Current Behavior:

---

When running the **payments_api_no-debtor-account_test-module_v5** test from the **payments_test-plan_v5** test plan, a GET request is made to the **payments/v5/consents/{consentID}** endpoint. The response returns the **payment.porpuse** field as expected. However, the test fails with the following error: _“payment.porpuse is required when payment.type is PIX”_, even though the field is present in the response.

#### Expected Behavior:

---

The test should recognize that the **payment.porpuse** field is present in the response and should not return a failure. If **payment.type** is PIX and **payment.porpuse** is included in the response, the test should pass without any errors.

Hello @arthurkaizer. Thanks for bringing this out.

The test is checking for `payment.porpuse` (at the payment level). In your GET response, `porpuse` is present but in a different structure/order, because it’s placed inside `payment.details`. So the test validator sees `payment.details.porpuse`, not `payment.porpuse`, and raises: _“payment.porpuse is required when payment.type is PIX”_.

**Your current response structure (fails):**

```
   "accountType": "CACC"
    },
    "porpuse": "IMMEDIATE"
  }
```

**Same order, but with the braces adjusted (passes):**

```
"accountType": "CACC"
    }
  },
  "porpuse": "IMMEDIATE"
}
```

Please feel free to reopen this issue if needed.
