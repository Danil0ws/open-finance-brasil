## 1. What Happened and what were you expecting?

The consents-api-operational-limits test makes 600 requests to the server.

This makes it impractical to pass on the test. 

For example, new test suite deployments cause a 503 and we have to log back into the system. Temporary network issues also cause connections to fail, especially when you're testing 600 connections.

Sometimes, the test suite also randomly requires 2FA or a new login. 

A test that takes over an hour will likely never pass for these reasons. Also, any transient network failure automatically invalidates the entire test, even an hour into it (see test id below). 

Possible solutions include reducing the number of calls to the endpoint, or retrying connections N times instead of invalidating the entire test based on one transient failure.
