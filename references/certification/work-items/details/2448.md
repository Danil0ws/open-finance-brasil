## 📝 Descrição

In the Moto Sandbox test environment, using the optimised-journey_sweeping_payments-core_test-module-v1, there is a restriction that does not allow a single CPF (tax ID) to have more than one account.
According to the Sweeping rule, both accounts must belong to the same account holder.
Since the test environment is set up for the same institution, we are unable to complete the tests due to this limitation.

Encaminhamos o ponto para avaliação da **DTO**, e o retorno deles esclarece exatamente o comportamento esperado no contexto das **Jornadas Otimizadas (JO)**.

Conforme a DTO:

> Os dados dos recursos só podem ser transmitidos ao receptor se houver um consentimento expresso pelo cliente durante a jornada do consentimento.\
> Nos cenários de JO definidos, durante o fluxo de configuração do consentimento em tela, **uma única conta é selecionada como origem dos recursos**. Esta mesma conta é a que terá seus dados compartilhados.\
> Se o cliente possuir múltiplas contas na instituição transmissora/detentora, ele poderá escolher apenas **uma** delas na jornada.\
> Assim, todas as APIs do produto **Contas** devem responder apenas com dados da conta aprovada.
>
> * **GET /resources** → retorna somente o recurso da conta selecionada.
> * **GET /accounts** → lista apenas a conta autorizada.
> * **GET /accounts/{accountId}** → funciona somente para a conta aprovada; outra conta retorna **403 Forbidden**.
> * **GET /accounts/{accountId}/balances** → idem; somente a conta selecionada retorna dados.\
>   Esse comportamento se estende aos demais endpoints liberados via consentimento.

Portanto, mesmo que no ambiente de teste vocês esperem utilizar duas contas pertencentes ao mesmo CPF para validar a regra de Sweeping (mesmo titular), **o comportamento do ambiente segue exatamente a lógica definida pela DTO**, onde **apenas uma conta pode ser selecionada e autorizada para compartilhamento no contexto da jornada JO**.

Ou seja, a limitação que vocês encontraram **não é uma restrição técnica do Conformance**, mas sim **um comportamento deliberado da Jornada Otimizada**, que restringe o compartilhamento a apenas **uma conta por consentimento** — impedindo que múltiplas contas apareçam para o mesmo CPF.

Se precisarem realizar testes envolvendo múltiplas contas, será necessário utilizar CPFs distintos ou realizar o fluxo em ambientes que não estejam configurados com as regras da JO.

Ficamos à disposição para qualquer esclarecimento adicional.
