## 📝 Descrição

**Observed behavior**

A DCR was performed with an SSA that did not carry the software_client_uri claim. The registration was accepted and returned 201. From that point on, every request that loads the resulting client returns 400 invalid_client_metadata with the description "client_uri must be a non-empty string if provided". This includes the token endpoint, the authorisation endpoint and the client management operations, so the client could not be used, could not be updated via DCM and could not be deleted by the participant.

**Expected behavior**

software_client_uri is optional in the directory, and client_uri is OPTIONAL in RFC 7591 and in OpenID Connect Registration, although RFC 7591 states that it is RECOMMENDED that clients always send this field. The Open Finance Brasil DCR specification, in the section "Applying Server Defaults", determines that for properties neither included nor mandatory the authorisation server applies defaults rather than rejecting the request. A DCR under these conditions should therefore be accepted and produce a client that works normally on the token, authorisation and management endpoints. A client that is already in an inconsistent state should still be removable by the participant through the management endpoint.

**Notes**

The Mock Bank is built to exercise the behaviours covered by the certification test plans, and the SSAs used in those plans carry this claim. A registration without the claim is therefore a combination that the conformance suite does not exercise, and it was not covered.
