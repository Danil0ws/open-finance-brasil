## 📝 Descrição

#### Current Behavior:

---

In API [Customers v2.1.0-beta.3](https://openbanking-brasil.github.io/openapi/swagger-apis/customers/?urls.primaryName=2.1.0-beta.3#/Customers/customersGetPersonalFinancialRelations)

* **portabilitiesReceived**
* **paychecksBankLink**

Are considered optional fields. At the same time this fields contain the following characteristic: "**_minItems: 0_**_"_

While customer-personal_api_portability_test-module_v2-1 is executed, the test will simulates that the bank has received a portability, therefore, requiring sharing of employee data at the PortabilitiesReceived object.

In the following test module execution:

https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=BvJbX31ub9aqnlU

Having minItems set to 0, allows for Authorization servers to send **portabilitiesReceived** as an empty array, thus returning a failure in test module execution as Conformance Suit expects that, this field being sent, it contains the other required fields that are contained within it.

Therefore what we need clarification from WorkGroup is:

* Should the mentioned fields have "**_minItems: 0_**_"? In case the response is yes, should conformance suit then expect that this fields are sent as empty arrays?_
