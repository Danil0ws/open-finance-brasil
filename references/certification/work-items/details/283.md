Yes, you are correct here. This test was built before this change has been implemented and we end up not taking into account if the business entity field is sent or not. 

What we wanna do here is basically skip the validation for Personal Permission if business entity field is sent and skip the permission for Business Permission if the field is not sent.

Test must be updated to account for the following scenario:


> If the Business Entity field **is sent** the test should either skip the following steps or accept a 400 as a valid response
> 
> - Validates consent API V2 request for 'Personal Registration Data' permission group(s) 
> - Validates consent API V2 request for 'Personal Additional Information' permission group(s) 
> 
> If the Business Entity field **is not sent** the test should either skip the following steps or accept a 400 as a valid response
> 
> - Validates consent API V2 request for 'Business Registration Data' permission group(s) 
> - Validates consent API V2 request for 'Business Additional Information' permission group(s)

### Comentário 8
**Autor**: Erick Domingues (@erick.domingues1)
**Criado em**: 11/07/2022, 16:35:01

It's unclear to us why the behavior is incorrect here on the permissions-group-v2 test

The following payload is being sent as a request:

{"data":{"permissions":["CUSTOMERS_PERSONAL_IDENTIFICATIONS_READ","RESOURCES_READ"],"loggedUser":{"document":{"identification":"11111111111","rel":"CPF"}},"businessEntity":{"document":{"identification":"11111119999999","rel":"CNPJ"}},"expirationDateTime":"2022-07-11T16:37:31Z"}}

According to the Consents API specification - https://openbanking-brasil.github.io/openapi/swagger-apis/consents/2.0.0.yml

We have the on the Consents API that:

`    - A transmissora deve retornar, da lista de permissions requisitadas, apenas o subconjunto de permissions por ela suportada, removendo da lista as permissions de produtos não suportados e retornando HTTP Status Code 201. Caso não restem permissões funcionais, a instituição transmissora deve retornar o erro HTTP Code "422 Unprocessable Entity".`

So for this particular request, you can either return a 201, meaning you have the products and accept the request or a 422 meaning you can't accept this request as no permissions remain.
