## 📝 Descrição

The `payments-api-idempotency-test` test is expecting HTTP 403 when an invalid `iss` claim is sent in the signed payload. My implementation returned a 400 with BAD_SIGNATURE, as specified here: https://openbanking-brasil.github.io/areadesenvolvedor/#como-assinar-o-payload

> Em caso de erro
> 
> Na validação da assinatura pelo Provedor do Recurso a API deve retornar mensagem de erro HTTP com status code 400 e a resposta deve incluir na propriedade code do objeto de resposta de erro especificado na API (ResponseError) a indicação da falha com o conteúdo BAD_SIGNATURE.

Should it really be expecting a 403?

Link for the test logs: http://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=bK9U9oC7IpAAq8r
