Thanks for opening the ticket.

When the mentioned test module failed, the conformance suit was executing the following step described in the test summary:

**Call POST enrollments - Don't send an x-fapi-interaction-id - Expects 400**

Therefore the conformance suit is correctly not sending **x-fapi-interaction-id and expecting a response_status_code 400, which** was also correctly provided by your implementation.

Rather the unexpected behavior seems to be related to the presence of a incorrect  paymentId validator. We are already aware of this unexpected behavior and will be working on a solution for it. The resolution of this problem can be followed via the following link. We'll post any updates there:

https://gitlab.com/raidiam-conformance/open-finance/certification/-/issues/1170
