## 📝 Descrição

#### 1. Observed Behavior:
---
The test module `payroll-credit-portability_api_creditor-rejected-payment-error_test-module_v1` currently defines as last steps that:
> • POLL the GET /portabilities/{portabilityId} for up to 10 minutes while the status is "PAYMENT_ISSUE"
> 
> • Expect 200 - Validate the response and ensure the status is "REJECTED" and statusReason.reasonType as "VALOR_DIVERGENTE"

However, in the swagger specification ([API Payroll Credit Portability v1.0.0-beta.1](https://raw.githubusercontent.com/OpenBanking-Brasil/draft-openapi/main/swagger-apis/payroll-credit-portability/1.0.0-beta.1.yml)) the field `statusReason.reasonType` does not have the enum `VALOR_DIVERGENTE` mentioned as a valid one:

![image](/uploads/3e945879b9a3c308d3ace52b80598beb/image.png){width=540 height=400}

#### 2. Expected Behavior:
---
We need confirmation on whether the test is correct and the specification is outdated, or if the test should instead be updated to align with the current specification. If the latter applies, we believe the intended value is likely `DIVERGENCIA_DE_PAGAMENTO_EFETUADO`, based on the existing enum definitions.

Could the DTO/WG please confirm whether the current test behaviour (expecting `VALOR_DIVERGENTE`) is correct, or if it should be updated to reflect the defined enum in the API specification (expect `DIVERGENCIA_DE_PAGAMENTO_EFETUADO`)?
