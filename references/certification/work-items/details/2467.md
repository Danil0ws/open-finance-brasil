Hi @chenqi5.

When the test runs a POST /consent against your AS, the response returns:

* links.self: _`auth.risk.staging.shopee.com.br/open-banking/consents/v3/ consents/{consentId}`_
  * note: **missing `https://`**

Because this is not an absolute URL, the test suite ends up building the next request URI incorrectly (treating the host as part of the path). This matches what we see in the log for the failing call:

* request_uri: `/auth.risk.staging.shopee.com.br/open-banking/consents/v3/consents/{consentId}`

According to the Consents API v3.3.1 [specification](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1378385987/Informa+es+T+cnicas+-+DC+Consentimento+-+v3.3.1):

![image.png](/uploads/855e4791904004c58279d399643a9e90/image.png){width=522 height=115}

**Expected fix:** return links.self as an absolute URL, for example:

`https://auth.risk.staging.shopee.com.br/open-banking/consents/v3/consents/{consentId}`

Please feel free to reopen this issue if further assistance is needed.

Best regards
