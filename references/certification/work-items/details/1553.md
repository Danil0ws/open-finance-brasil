### Comentário 2
**Autor**: Christian Eloysio (@christianraidiam)
**Criado em**: 22/03/2024, 14:24:22

Hi Doris!

The test plan you are executing is the Consents V2, and therefore, should follow what's has been defined at the [Consents V2.2 Swagger](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/207716438/Informa+es+T+cnicas+-+DC+Consentimento+-+v2.2.0).

On the test plan you have sent here, you are falling two tests which expect 400, for the reasons:

1. Sending Personal and Business Permissions together at the consent
2. Only sending the Permissions for resources, which is out of the permissions groups on the swagger

For both cases, the specs for V2 Swagger states:

* Caso a instiuição receptora envie permissões divergentes ao agrupamento especificado na tabela, a transmissora deve rejeitar o pedido da receptora **dando retorno HTTP Status Code 400**.

You are currently returning the message 422 - PERMISSAO_PF_PJ_EM_CONJUNTO and  422 - COMBINACAO_PERMISSOES_INCORRETA, which are **V3 Error responses.** If you check the V2 swagger, these messages are not listed at the 422 response:

![image.png](/uploads/f0c3bfe79601403e4e2e06081c05d160/image.png){width=324 height=204}

As you mentioned, and per In441 directive, you need to be compliant with the current version. In that sense, you will need to adapt you v2 implementation to follow the v2 swagger. These responses would be compliant to v3, but for v2, you will need to return the error code 400, as mentioned at the swagger.

Please, feel free to reopen the issue if you think it still remains. We are happy to help with any additional needs!
