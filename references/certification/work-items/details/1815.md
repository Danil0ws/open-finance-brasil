## 📝 Descrição

**Description:**

There is an issue regarding the PCM Integration Specification, particularly with the `private/report` endpoint which defines the field `additionalInfo`. According to the specification, this field should be informed as defined in the spreadsheet available at [this link](https://openfinancebrasil.atlassian.net/wiki/download/attachments/37879861/Tabela%20additionalInfo%20%E2%80%93%20campos%20contexto%20e%20obrigatoriedade_v17-.xlsx?api=v2).

At the Swagger documentation, the `consentId` is described as:

> "Deve ser preenchido com a mesma string obtida no campo `.data.consentId` retornado após a chamada inicial na API `POST /consent`. Ao reportar o uso de um endpoint `/token`, o identificador único de consentimento só será reportado nos casos em que `grant_type` é do tipo `authorization_code` ou do tipo `refresh_token`, uma vez que esta informação de `consentId` é inexistente quando `grant_type` é do tipo `client_credentials`."

However, for the Automatic Payments APIs, there is no `consentId` but only the `recurringConsentId`, as defined in the [Technical Information for Automatic Payments API](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/345178397/Informa+es+T+cnicas+-+SV+Pagamentos+Autom+ticos+-+v1.0.0).

If the PCM Integration follows this documentation, the Automatic Payments APIs will cause an error in reports, as the `consentId` field will not be sent, even though it's required at these endpoints.

Similarly, to address this issue, the Enrollments APIs ([Technical Information for Enrollments API](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/591102997/Informa+es+T+cnicas+-+SV+V+nculo+de+dispositivo+-+v2.0.0-rc.1)) added the `enrollmentID` field to the API.

**Suggestion:** To resolve this issue, we suggest modifying the API so that it accommodates the Automatic Payments API scenario, where the `consentId` is not present, allowing this API to be reported correctly.
