## 📝 Descrição

## 1\. What happened and what were you expecting?

Based on [v2.1.0-rc3 documentation](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/193691826/Informa+es+T+cnicas+-+Cart+o+de+Cr+dito+-+v2.1.0-rc.3), if the parameters `page`, `page-size`, `fromTransactionDate`, `toTransactionDate` are not informed, they must default to the values: `page=1`, `page-size=25`, `fromTransactionDate="current day"` and `toTransactionDate="current day"`. Also, the order in which they return don't matter.

Today, the validation fails when the requestUrl and selfUrl are different.

HI Cássio! Thanks for the ticket

Actually, the conformance is failing the test for some other reasons, as:

* ![image.png](/uploads/cbbc505b5c5eb24c79a8fa8dbf903cf9/image.png)
  * Here, the parameters should be always starting with lowercase letters, as stated in the swagger "**f**romTransactionDate", and not "**F**romTransactionDate"
* ![image.png](/uploads/cc9cd7639c3f4e5806078b4b0e2e9b35/image.png)
  * Here, you can see that the fromTransactionDate parameter (which was sent as Uppercase since the CS calls exactly the same endpoint at the self link from the previous request) was sent with the value 2023-10-21, while the link was 2023-10-19.

In that sense, once this correction are done, there should be no problem with the conformance suite. We have already developed it in a way that the default parameters are considered not he self link. If you find any other issues related to it, please do not hesitate to reach out to us.

We are happy to help with any additional needs!
