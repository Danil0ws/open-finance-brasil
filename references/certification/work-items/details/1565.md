Hi Jaqueline! Thanks for the response!

Following the specification, the self link should be the URL Requested, without mentioning the encoding as seen below:

![image.png](/uploads/b72070b4b0e89765eb0f0f47166093ee/image.png){width=489 height=142}

What the conformance suite is doing, in that sense, is calling the self link the way it is at the response, without considering possible encodings, which is retiring a 404 for obvious reasons:

![image.png](/uploads/bb99694fe14fada865f81a28572675f3/image.png)

In that sense, since the specs does not mention encoding, and a call on the encoded url would return en error, this may cause interoperability issues, as participants would be treating the self link in the same way the CS is doing.

Based on this, you would have to send a decoded self link to have success in the test.

We are happy o help with any additional needs!
