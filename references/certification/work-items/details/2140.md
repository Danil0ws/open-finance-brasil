Hi, @fernandes-f 

Thanks for your ticket!

The error was returned in your test scenario because the payload sent in the PATCH `/recurring-consents/{recurringConsentId}` request was invalid:

![image](/uploads/dc73d42996514cac2dabcebce249bc80/image.png)

According to the specification ([API Automatic Payments v1.0.0](https://raw.githubusercontent.com/OpenBanking-Brasil/openapi/main/swagger-apis/automatic-payments/1.0.0.yml)), the content of the field `data` must match a `oneOf` schema — meaning it must be either:

- An object of type `ConsentRevocation`;
- Or an object of type `ConsentRejection`.

The empty payload sent does not fulfill either condition, as it lacks any fields to characterize a revocation or a rejection. In other words, an empty `data` object is not valid. So MB is correct in returning an error for this scenario.

To ensure a successful execution, please send the appropriate object based on the intent of your PATCH request:

![image](/uploads/bd8ad0a012c8a32e5858d54ccafed6aa/image.png)
