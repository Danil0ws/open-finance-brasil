## 1. What Happened and what were you expecting?
According to Open Banking Informa 114, the ASPSP may choose to validate payment data during user authentication/authorization flow. We are fallowing this directive as we understand it provides a better user experience, so, after identifying a problem related to the payment consent requested, we present an erro message to the user, reject the consent and redirect back to the tpp with a standard callback error response. In this scenario the test fails expecting the authorization to succeed.
Is our understanding correct? Could it be fixed?

Hi Talles,

This is an acceptable scenario as per the discussion had on https://gitlab.com/obb1/certification/-/issues/169. 

The conformance suite is still not validating those rules as they have not been set yet by the Specifications WG, however, if you send a certification request with those failures we will accept them as long as you **provide any evidence on why the failure on the redirect happened**

On your implementation the response

```
 url_fragment
{
   "state": "uOTL9fhoOy",   
   "error": "access_denied"
}
```


Would not be considered a valid PASS as there's no mention of why it failed. In this case, we would also accept a screen capture as proof as long as you inform the user on their screen what happened wrong.
