## 2. Proposed Test 

Option 1: Server should process but ignore those fields - To be included on the Accounts API Plan

- POST Consents sending the fields transactionFromDateTime = D - 80 and transactionToDateTime = D - 80 
- Expect the Server to create the Consent with a 201 - Make Sure the fields are not present on the Response
- Call the Accounts API - Fetch an Account ID
- Call the Accounts Transactions API with the provided Account ID
- Make Sure that the server is answering with transaction data from outside the period above - Meaning it ignored the fields on the request

Option 2: Server should consider sending those fields as a BAD REQUEST - Included on the Consents API Plan

- POST Consents sending the fields transactionFromDateTime = D - 80 and transactionToDateTime = D - 80 
- Server should return a 400 - BAD REQUEST

## 3. Decision point from WG

Define which behavior the test should check 1, 2, 1 +2 or a different behavior
