Hi,

After a deeper analysis of the mentioned test module, we were able to identify the true cause of the test failure. 

As correctly presented in the description of this issue, “test is trying to make a GET request on /open-banking/payments/v1/pix/recurrent-payments/paymentId”, although this behavior occurs due to the self link being provided by the server on the response_body for POST recurring-payments request, as can be seen in the image below:

![1](/uploads/27a7bbbe91a722c67e2f7c75d86a1a08/1.png)

As the conformance suit uses the self link provided in the response for POST recurring-payments to make the GET **recurrent-payments**/{paymentId} request, the conformance suit is operating as expected. To ensure that the test module can be run with success, please make sure of the following:

1. The self link in the response_body for POST recurring-payments is as intended

Feel free to open a new ticket or reopen this one if you have any more questions,
