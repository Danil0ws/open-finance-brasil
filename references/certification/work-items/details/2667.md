#### Current Behavior:

---

The test `payments_api_apdn-good-happy-path_test-module_v5` submits a POST /consents request for an immediate PIX payment (no `scheduled` object present) without the `purpose` field in the payload and does not expect any validation error in response. However, the server returns a 422 with the following error:

{ "errors": \[ { "code": "PARAMETRO_NAO_INFORMADO", "title": "Parâmetro não informado", "detail": "O campo \[purpose\] é obrigatório para type PIX." } \] }

This causes the test to fail, since the happy path scenario is not expected to return a validation error. The test is therefore not aligned with the specification, which explicitly mandates the `purpose` field whenever `payment.type = PIX`.

According to the `purpose` field specification:

"Campo de envio obrigatório quando o valor do campo /data/payment/type for igual a PIX"

This restriction is unconditional: the field is always required when `type = PIX`, regardless of whether the payment is immediate or scheduled. The subsequent constraints only restrict which values are allowed depending on the scheduling object present:

| Scenario | Required value |
|----------|----------------|
| No `scheduled` object (immediate payment) | IMMEDIATE, WITHDRAW or CHANGE |
| `scheduled/single`  | SINGLE_SCHEDULED |
| `scheduled/daily`, `weekly`, `monthly` or `custom`  | RECURRENT_SCHEDULED |

#### Expected Behavior:

---

The test `payments_api_apdn-good-happy-path_test-module_v5` should include the `purpose` field in the request payload with the value `IMMEDIATE`, since it represents a regular immediate PIX payment with no `scheduled` object. The test should then expect a successful response, with no validation errors.
