Boa tarde prezados,

Agradecemos o contato.

O teste **`automatic-payments_api_automatic-pix-retry-422-validation_test-module_v2-2`** está validando estritamente um cenário de rejeição de uma requisição de _retry_ com dados inválidos.

1. **Cenário em Dúvida:** O teste falha quando o _retry_ é enviado com o campo `date` setado como **D-1** (ou seja, uma data no passado).
2. **Expectativa do Teste:** O motor de conformidade espera o erro **`DETALHE_TENTATIVA_INVALIDO`**.

Embora o código `FORA_PRAZO_PERMITIDO` seja usado para a regra de **agendamento fora do prazo/horário permitido** ou **após a expiração do consentimento**, o código **`DETALHE_TENTATIVA_INVALIDO`** é mais aderente ao contexto de _retry_ inválido, conforme a definição específica:

* **`DETALHE_TENTATIVA_INVALIDO` (6.1.20):** **Valida se os parâmetros informados condizem com a tentativa original de pagamento**.

Ao tentar agendar um _retry_ para uma data no passado (`D-1`), o parâmetro `date` não condiz com o requisito fundamental de agendamento de um novo pagamento (que deve ser para uma data futura). O erro é, portanto, uma **inconsistência no detalhe da _nova_ tentativa** em relação às regras de negócio para _retries_.

O código **`FORA_PRAZO_PERMITIDO`** é mais assertivo para os cenários de:

1. Tentativa de agendamento fora do período/horário permitido pela instituição.
2. Data de liquidação do pagamento ser superior ao prazo de expiração do consentimento.

Qualquer dúvida estamos a disposição!
