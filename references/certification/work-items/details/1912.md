## 📝 Descrição

#### Current Behavior:
---

Good afternoon,

Thank you for contacting us.

The error pointed out by the conformance suíte  is not related to the at_hash element. 

Please regard that this test module has not yet been updated to v2.0.0-beta.2 version of Automatic Payments API.

The situation is occurring because during Conformance Suit Request to: **POST recurring-consents**, the conformance is looking for the **startDateTime** field, but it is not finding it in the response to the server's consent.

In your test, the **startDateTime** field was sent inside **recurringConfiguration**:

"recurringConfiguration": {
      "sweeping": {
        "totalAllowedAmount": "600.00",
        "startDateTime": "2024-12-22T14:48:09Z",
        "useOverdraftLimit": false
      }

![image](/uploads/7ea5fe32a35c637001564f5302e15a8f/image.png)

According to the specification:

https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/345178397/Informa+es+T+cnicas+-+SV+Pagamentos+Autom+ticos+-+v1.0.0

the **startDateTime** element must be inside "**data**".

I performed a successful test, if you want to consult:
https://web.conformance.directory.openbankingbrasil.org.br/plan-detail.html?plan=OZNQF0SQUtPFQ&public=true

**Important**: the change made to the startDateTime element was in version beta.2, but the test is being executed in beta.1, as version beta.2 has not yet been released.

Please make sure that the API follows what is defined in the specification for this version, so that test module can be successfully executed.
