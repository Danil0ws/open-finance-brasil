## 📝 Descrição

On Friday the 29th of October, a clarification email regarding idempotency was issued to the ecosystem. As part of this email an explicit test and behaviour was called for when an idempotency Key was used however the Message JWT had an Issuer was not valid for this client then the resource server was to return a 403.

There is a conflict with the security profile that treats issuer validation as part of JWT validation (correctly) and in the event of a JWT validation should reject with a 400 bad request. 

Awaiting guidance from GT Sandbox or Specifications Team

**Autor**: Ralph Bragg (@ralph.bragg)
**Criado em**: 01/11/2021, 19:53:35

As a short term solution and in the interests of ecosystem delivery, the security profile will take precedence as an invalid issuer should result in a 400 response. 

There are two processing paths a Bank could take when validating this request.
1. Access Token, Client, Software, Org -> JWKS -> Validate Request (Pass) -> 403 (issuer isn't correct).
2. JWT -> Issuer -> Org JWKS (Doesn't Exist) -> 400 Bad Request (Bad Sign, Can't find Org, other).

We will change this test to accept either a 403or400 error code however will return a WARN on the the 403. 

This issue has been flagged to GT Sandbox and will remain open until clarified.
