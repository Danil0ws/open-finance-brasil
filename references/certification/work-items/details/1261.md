Regarding the point mentioned:

1. Regarding the response_code expected, as described in https://gitlab.com/raidiam-conformance/open-finance/certification/-/issues/1064#note_1622648539, 
    - Se o header authorisation não for enviado ou for enviado errado, é esperado um erro 401
    - Se o header authorisation for válido e não for enviado o x-fapi-interaction-id,o x-fapi-customer-ip-address ou o x-customer-user-agent, é esperado um erro 400
    
    Therefore the conformance suit is operating correctly as it validates for a 400 when the x-fapi-customer-ip-address is not sent. The appropriate working group has been working on improving the documentation to make this matters clear.
    
2. We are already aware of this unexpected behavior and a ongoing issue has been opened for it, you can find it at: **[#1227](https://gitlab.com/raidiam-conformance/open-finance/certification/-/issues/1227)**. We are working to fix it and updates on this matter will be posted there
