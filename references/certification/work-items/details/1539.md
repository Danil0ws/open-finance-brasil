Thanks for opening the ticket!

The POST pix/recurring-payments call, which creates the payment, is doing it through the use of a authorization code token, provided in the header **Authorization**. When the token endpoint was called in order to receive this access token which is used to create the payment, the authorization server sent in it's response_body the following information:

**"scope":"recurring-payments openid consent:urn:BRB:4549CED9D4E1D8FA85DB9BEABD017246"**

That way the recurring-payments uses a authorization that is directly associated with the consent and thus the recurringConsentId.
