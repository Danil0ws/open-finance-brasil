## 📝 Descrição

We are constantly receiving tickets from the FVP 1.0 where the test fails to start because the DCR fails and the cause is usually the same, "Software Statement Already in Use", this issue happens because in some runs of the FVP the DCR process is executed, but the DELETE DCM process is never called, usually this happens as a consequence of an untreated error in the test module. Is there a way we can mitigate this? 
If we implement a garbage collector to remove the clients whose names contain "Ferramenta de Validação de Produção", or should we create a bypass for that rule when the request comes from the FVP engine? If we do that, will we have problems with future FVP 1.0 executions? Will we still get tickets for tests failing for that issue? Are there any consequences for recurrent tickets caused by that issue?

Hi Rodrigo,

Thanks for the ticket.

You may indeed implement a garbage collector to avoid this issue to repeat over the executions. The Software Statements used by the tool have the only purpose of executing test and should not be registered for more than 10 minutes. We recommend that you do it for the following software statements used by FVP:

- SS1: 
  - Ferramenta Validacao Producao - Serasa
  - bc97b8f0-cae0-4f2f-9978-d93f0e56a833
- SS2: 
  - Ferramenta Validacao Producao - Soluti
  - 70ee2970-038b-44d6-9300-d3af3a890154 
- SS3: 
  - Ferramenta Validacao Producao - Serpro
  - 21ef921f-7d9f-4fa5-afae-d24545d6c880 
- SS4: 
  - Ferramenta Validacao Producao - Certisign
  - f61e3065-ca7b-4982-8ff5-86dff43ece63 

Bypass the rule of multiple clients would result in a failure for another FVP test that validates if the server accept multiple clients, so we do not recommend doing that.

I am closing this ticket, but feel free to reopen it if you think your question wasn't answered.
