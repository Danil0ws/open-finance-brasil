## 📝 Descrição

## 1. Issue

As raised on https://gitlab.com/obb1/certification/-/issues/451 there are institutions that dynamically define the ResourceID, making it so that with every new created Consent a new ResourceID will be generated for the same product.

Currently the specifications aren't clear enough to define if this is or not an acceptable behavior for Accounts and Credit Cards API, so we need a clarification to know if we should or not be implementing and enforcing this stability.

Specifications:

https://openbanking-brasil.github.io/openapi/swagger-apis/accounts/2.0.1.yml

```
        accountId:
          type: string
          description: 'Identifica de forma única  a conta do cliente, mantendo as regras de imutabilidade dentro da instituição transmissora.'
```

Additionally the qualitative rules are defined below

https://openbankingbrasil.atlassian.net/wiki/spaces/OB/pages/9634563/Forma+o+e+Estabilidade+do+ID


## 2. Requirement

Define if a server can have dynamically generated ResourceIDs for every new Consent

If no, also define if a tests is required to enforce that behaviour.
