## 📝 Descrição

**Test Summary:**

Ensure payments are scheduled even if the amount is over the expected dailyLimits\
• GET an SSA from the directory and ensure the field software_origin_uris, and extract the first uri from the array\
• Execute a full enrollment journey sending the origin extracted above, extract the enrollment ID, and store the refresh_token generated ensuring it has the nrp-consents scope\
• Call the GET enrollments endpoint\
• Expect a 200 response - Validate the response and check if the status is "AUTHORISED", and extract the transactionLimit and dailyLimit sent\
• Execute full payments for today using no redirect flows with the transactionLimit sent, until the daily Limit is exceed without sending the debtorAccount field at the POST Consents\
\
In the last flow, execute the below:\
• Call the POST Payments Consents V4 Endpoint, with the amount as with the transactionLimit sent, with the payment.date 5 daily payments starting at D+1\
• Expect 201 - Validate Response\
• Call the POST Fido Sign Options Endpoint\
• Expect 204\
• Call the POST Consent Authorise Endpoint\
• Expect 204\
• Call POST Pix Payment Endpoint\
• Expect 201 - Validate Response\
• Poll GET Payments Endpoint while status is RCVD, ACCP or ACPD\
• Call Get Pix Payment {ConsentId} Endpoint\
• Expect 201 - Validate response and check all payments status is SCHD

Hello @eric.martins1. Thanks for attaching the log.

The number of payments depends on the data returned by the **GET /open-banking/enrollments/v2/enrollments/** endpoint.

According to the test summary:

> “Expect a 200 response – Validate the response and check if the status is ‘AUTHORISED’, and extract the transactionLimit and dailyLimit sent.”

In your response, the enrollment returned:

* status = AWAITING_ACCOUNT_HOLDER_VALIDATION;
* No transactionLimit or dailyLimit fields.

As a result, the test cannot classify the scenario as “scheduled daily” and proceeds with a single payment instead of five.

Once these fields are correctly populated, the test should generate the expected five payments and align with the passing behavior observed in the [mock](https://gitlab.com/raidiam-conformance/open-finance/certification/-/wikis/Payments-APIs) environment:
