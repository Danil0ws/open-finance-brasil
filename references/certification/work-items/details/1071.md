## 📝 Descrição

## 1\. What happened and what were you expecting?

In the engine test there is validation for the Endpoints, where the validation does not allow the inclusion of path variables in the URIs, causing the test to break. 

Correct endpoint example: api.itau/open-banking/invoice-financings/v2/contracts/{id}/warranties 

Example of what is expected from the test: api.itau/open-banking/invoice-financings/v2/contracts/id/warranties 

Test regex: ^([https://)?(www.)?\[-a-zA-Z0-9@:%](https://)?(www.)?%5B-a-zA-Z0-9@:%25)._+\~#=\]{2,256}.\[a-z\]{2 ,6}\\b(\[-a-zA- Z0-9@:%_+.\~#?&//=\]\*)$

We need the REGEX correction

Hi All! Here is the clarification from the WG:

"Para a questão relacionada ao regex usado no campo _endpoint_ para a validação e seu conteúdo **deve-se enviar URLs válidas sem o uso de caracteres como "{" ou "}"**, conforme [documentação de apoio.](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17891406/Disponibilidade)\
Para melhor exemplificar como deve-se enviar segue alguns exemplos:

§  URL da documentação: Enviar campo endpoint como: Enviar campo endpoint como: https://example.api/open-banking/financings/v2/contracts

§  URL da documentação: Enviar campo endpoint como:  https://example.api/open-banking/financings/v2/contracts/contractId

Click to follow link.")

§  **Endpoint com path variable, a exemplo {contractId}, deve-se enviar sem chaves {} para não apresentar erro no motor de conformidade**"

In that sense, the expected behavior is that the endpoint should not contains the "{ }".

We are happy to help with any additional needs!
