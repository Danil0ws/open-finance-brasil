Hi Liege! Thanks for the ticket!

Since the conformance suite has been updated to the new FPI profile, and, therefore, is verifying the id token encryption at all tests, we should indeed be sending the openid scope.

But, worth to remember, that this is only the case because we are trying to verify the id token on the response. Since the permissions for exchanges have already been defined at the consent creating, the Authorization server should issue the access tokens with scope necessary for access to data specified in the _Permission_ element of a linked Consent Resource object, as defined at the [security profile](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/240649123/EN+Open+Finance+Brasil+Financial-grade+API+Security+Profile+1.0#7.2.2.-Authorization-server).

Given this, we will update these tests to add the openid scope, and the id token can be checked at the test.
