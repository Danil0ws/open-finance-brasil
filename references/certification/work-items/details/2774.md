## 📝 Descrição


#### Current Behavior:
---
The conformance test payments_api_pix-withdraw-invalid-amount_test-module_v5 expects a Pix Saque consent to be successfully created (HTTP 201) even when the payment.amount differs from the amount defined in the QR Code.

According to the test flow:

POST Consents is called with a Pix Saque QRES.
payment.amount is sent as QR Code value + 1.
The test expects HTTP 201.
The user is redirected to the authorization flow.
The consent is later rejected with rejectionReason = VALOR_INVALIDO.

This behavior appears to be inconsistent with the specification requirement for amount validation.

#### Expected Behavior:
---
The consent request should be rejected during the POST Consents call when payment.amount differs from the value established in the QR Code.

The specification states:

"For all scenarios where the amount cannot be changed, the amount field must be populated with the value established in the QR Code. If the amount field is populated with a value different from the expected one, an HTTP Status 422 response with code VALOR_INVALIDO must be returned."

Therefore, when a Pix Saque consent is submitted with payment.amount different from the QR Code amount, the expected behavior is:

HTTP 422 response;
Error code VALOR_INVALIDO;
Consent should not be created;
Authorization flow should not be initiated.
