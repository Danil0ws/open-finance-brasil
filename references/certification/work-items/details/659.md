## 📝 Descrição

## 1. What Happened and what were you expecting?
Received FAILURE: Validate response: EnsureResponseCodeWas422: Was expecting a 422 response --- but the correct statuscode related to the test should be HTTP 400.

With the creation of V2, it was defined that the transaction endpoints of the accounts API (also for credit-card-accounts) should return an HTTP 422 response code in cases where a query parameter is sent semantically incorrect. In the latest versions of the Web Conformance Directory tests, this condition has also been validated for the page-size parameter, but only in these endpoints, generating an inconsistency since even in the same API, in other endpoints, an error 400 is expected when, for example, a page-size of 1001 is sent (above the defined limit).

This ticket was also issued to Sandbox Squad to validate our questioning and we received the following response:
"The definition of a 422 error launch by the current specifications is limited to the Accounts and Credit-card-accounts APIs when the occurrence of incorrect business parameters is sent, such as: delimitation of dates for the transaction period above those specified. In the case of the occurrence of page-size parameters outside the specified limits, the correct behavior would be the error 400 for all APIs."

Hi Jeremy! Thanks for the ticket!

We understand your concern, and it may not be clear in the specifications. This test was developed for  account v2 specifications, and at the time there was specific instruction at the pagination specification for a page-size=1001 response be 422, as specified by the test, with most participants having already implemented this.

In that sense, since the conformance suite always need to follow the specification at the developer portal, we cannot make any changes without it being explicitly stated at Swagger. Therefore, if you think this issue should be changed at documentation, we kindly ask you to open a service desk ticket so the squad can address this on documentation, and the conformance suite can be updated accordingly.

We are happy to help with any additional need!
