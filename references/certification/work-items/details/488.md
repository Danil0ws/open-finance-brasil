## 1. What Happened and what were you expecting?

Test is failing to set a correct payments consents payload, making the test fail because it doesn't remove the qrCode sent on the consentPayload configuration.

Down Below the payload that brings a 422 - 

```
    "creditor": {
      "name": "REGINA GEORGE",
      "cpfCnpj": "68017416245",
      "personType": "PESSOA_NATURAL"
    },
    "payment": {
      "date": "2022-11-17",
      "amount": "100.00",
      "currency": "BRL",
      "details": {
        "proxy": "68017416245",
        "localInstrument": "DICT",
        "qrCode": "00020126470014BR.GOV.BCB.PIX0111680174162450210test motor5204000053039865406100.005802BR5913REGINA GEORGE6009SAO PAULO62070503***6304EAE6",
```

Here we should be setting a standardized payload that only gets the debtor accounts, loggeduser and amount values from the consent payload, similar to how it's done with tests that use FAPIBrazilGeneratePaymentConsentRequest class

Here we are using the FAPIBrazilCreatePaymentConsentRequest which just gets the payload and re-use it

https://gitlab.com/obb1/certification/-/blob/master/src/main/java/net/openid/conformance/openbanking_brasil/testmodules/support/payments/FAPIBrazilGeneratePaymentConsentRequest.java
