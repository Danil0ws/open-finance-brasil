Hi Gutemberg,

Thanks for sending evidences of the execution.

Could you expand more on your question, it wasn't possible to understand what is wrong with the software statements used by FVP. Here is a response based on what you related:


> We made an update to the Authorization Server, adding only the scope related to the **CONTAS** role: _OpenId_

This doesn't seem to be true. If we access the well-known being tested https://auth.bs2.app-terosopenbanking.com/.well-known/openid-configuration the scopes supported include multiple scopes:
```
"scopes_supported": [
    "accounts",
    "consents",
    "credit-cards-accounts",
    "customers",
    "invoice-financings",
    "financings",
    "loans",
    "unarranged-accounts-overdraft",
    "funds",
    "treasure-titles",
    "variable-incomes",
    "credit-fixed-incomes",
    "bank-fixed-incomes",
    "resources",
    "payments",
    "recurring-payments",
    "openid"
  ],
```


> However, when attempting to run the DCR test in production environment X, an error occurred regarding the scope: _"scope must only contain Authorization Server supported scope values"_.

The server is returning this error message on the DCR attempt. However, the body from the DCR request doesn't include any scope, even so according to the [item 7.1.1.3](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/246120449/EN+Open+Finance+Brasil+Financial-grade+API+Dynamic+Client+Registration+2.0+RC1+Implementers+Draft+3#7.1.1.-Applying-Server-Defaults) the Authorisation Server "shall grant the client permission to the complete set of potential scopes based on the softwares regulatory permissions included in the software_statement"



> **Note:** The _software_statement_roles_ used in the test are configured with **DADOS** and **PAGTO**, when it should only be **CONTAS**.

Why the Software Statement should only contain CONTAS? This ROLE is for account holders only.
The software statement used by FVP contains the two ROLEs PAGTO and DADOS which allows the tool to request the scopes granted by them, according to [7.2. Regulatory Roles for OpenID and OAuth 2.0 Mappings
](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/246120449/EN+Open+Finance+Brasil+Financial-grade+API+Dynamic+Client+Registration+2.0+RC1+Implementers+Draft+3#7.2.-Regulatory-Roles-for-OpenID-and-OAuth-2.0-Mappings)
