1. What Happened and what were you expecting?

payments-consents-api-invalid-test) expects invalid payment_detail for receiving a ZZZ currency.

payments-api-negative-tests test we have a test where the consent is BRL and the payment is ZAR, the test expects a divergent payment error. 

Both returns look valid depending on which order the bank does the validation

> PAGAMENTO_DIVERGENTE -> Because the org first validates that the Payment is not valid against the created Consent

> PAGMENTE_INVALIDO/NAO_INFORMADO-> Because the org first checks if the Payment request currency field is equal to BRL

Should the test accept both error codes or one of the validations comes first?

Also worth noting that the return ZAR is valid per the regex, but invalid if you look at the description.

        currency:
          type: string
          maxLength: 3
          pattern: '^([A-Z]{3})$'
          example: BRL
          description: |
            Código da moeda nacional segundo modelo ISO-4217, ou seja, 'BRL'.  
            Todos os valores monetários informados estão representados com a moeda vigente do Brasil.
