## 📝 Descrição

**Observed Behavior**

When the data holder returns `Connection: close`, PCM events are silently dropped for endpoints invoked via `PostEnrollmentsResourceSteps(..., stopAfterResourceEndpointCall=true)`:

* `POST /enrollments/{id}/risk-signals` (204)
* `POST /enrollments/{id}/fido-registration` (204)
* `POST /consents/{id}/authorise` (204)
* `PATCH /enrollments/{id}` (204)

`PcmEventEmitter.intProcess` emits the initial `PCM processing response` log, then halts silently between `PcmEventEmitter.java#L379` and `PcmEventEmitter.java#L404`. No `PCM Event saved`, no `WARN`, no `ERROR`. The HTTP flow itself completes normally.

Requires intersection of `Connection: close` AND `stopAfter=true`. Neither alone is sufficient.

---

**Expected Behavior**

Every completed HTTP call must persist a PCM event, regardless of `Connection` header value or whether the test sequence consumes the response body. If metadata extraction fails, log `WARN` and persist the event with empty metadata, never silently halt.

---

**References**

- HTTP: [RFC 7230 §6.1](https://datatracker.ietf.org/doc/html/rfc7230#section-6.1) — `Connection: close` and `keep-alive` are both valid
- OFB: [Cabeçalhos HTTP](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17377351) — `Connection` not specified
- Apache HttpClient: [HttpResponseInterceptor](https://hc.apache.org/httpcomponents-core-ga/httpcore/apidocs/org/apache/http/HttpResponseInterceptor.html), [Connection management](https://hc.apache.org/httpcomponents-client-4.5.x/current/tutorial/html/connmgmt.html)
