Hi,

Based on the log analysis, the failure is caused by an invalid pagination link returned by the server, not by the conformance suite itself. The suite is correctly following the `next` URI provided in the previous response, but that URI is malformed. 

In the response payload, the pagination links are being returned as `.../events&page=1&page-size=25`, `.../events&page=2&page-size=25`, and so on, instead of using a valid query string format such as `.../events?page=1&page-size=25` or `.../events?page=2&page-size=25`. 

Because of this, when the suite calls the returned `next` link in the GET call, the request results in HTTP 404. 

According to the [pagination](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17377470/Pagina+o) specification, the `self` link must represent the complete URI of the current page, and the pagination links must be valid URIs for navigation. In this case, the pagination links returned by the endpoint are not compliant with that format, which is what causes the test to fail.
