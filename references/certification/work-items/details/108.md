## 📝 Descrição

As discussed on the Sandbox and Specifications WG whenever a POST is made the response must contain on its Links/Self field the URI that points to the recently created resource.

This behavior is mentioned on the RFC2616 - 10.2.2 201 which states: The request has been fulfilled and resulted in a new resource being created. The newly created resource can be referenced by the URI(s) returned in the entity of the response.

However, Looking at the existing specifications we have that:

          properties:
            self:
              type: string
              format: uri
              maxLength: 2000
              description: URI completo que gerou a resposta atual.
              example: 'https://api.banco.com.br/open-banking/api/v1/resource'
              pattern: '^(https?:\/\/)?(www\.)?[-a-zA-Z0-9@:%._\+~#=]{2,256}\.[a-z]{2,6}\b([-a-zA-Z0-9@:%_\+.~#?&\/\/=]*)$'

This is misleading given that it might induce the org to return the URI used in the POST request, which has no value whatsoever.

Given that the above statement is a consensus we have asked for this to be added on Known Problems until it gets corrected on the API swagger specification. We also reinforce that the conformance suite is enforcing this behavior, most of the time by doing a GET with the URI the passed Links/Self field.
