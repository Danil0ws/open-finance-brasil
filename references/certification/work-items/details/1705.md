## 📝 Descrição

Hi!

Running variable-incomes_api_core_test-module was noticed that the test expects a list of balances for the endpoint `/open-banking/variable-incomes/v1/investments/05c64725-2c79-48d1-be87-dbd49c8efa8a/balances`. Also, in the [documentation](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/242254346/Informa+es+T+cnicas+-+DC+Renda+Vari+vel+-+v1.1.0) the schema expected is a list of balances as shown in the image.

But there is a known problem related in [Open Finance documentation](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/167313434/1.x.x+Problemas+conhecidos) describing a that the endpoint response should be a single object as other API balances.

What implementation should we follow?

Hi Ueliton! Thanks for the ticket!

As stated on the Known Problems, the orienteation until the adjust is published is:

* Considerar o mínimo (minItens) e máximo (maxItens) de retorno de itens da lista igual a 1

In that sense, until this is officially incorporated at the spec, this response should be a list with maxItens and minItens =1. After that, the endpoint will be updated so that it expectes an object. We are happy to help with any additional needs!
