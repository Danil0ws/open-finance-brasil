Hi, @martinslm 

Thanks for the additional details!

You are correct: the Directory does not allow local URIs to be registered, so this approach should not be the one pursued here. We’d like to reiterate that for a successful test execution, you need to access the Directory Sandbox and make sure the correct well-known URL to be used in the Conformance Suite test is registered.

From our observations, the server where the automatic payments v2 routes are registered is `dc7983b6-b8fc-450d-9b3b-ebd8c8fbc5e0`. Its already registered well-known URL is:
https://openfinance.homolog.asaas.com/oidc/.well-known/openid-configuration. Hence, this value should be added in the test configuration field `discoveryUrl` under `server` to ensure the local test references the correct well-known URL in the Directory.

This adjustment should resolve the issue, as indicated in the log: [test-log-automatic-payments_api_automatic-pix-invalid-creditor_test-module_v2-private_key_jwt-pushed-openbanking_brazil-plain_response-vodtCuLLATAN9oO.zip](/uploads/c246a258305a469768315596a6788d9f/test-log-automatic-payments_api_automatic-pix-invalid-creditor_test-module_v2-private_key_jwt-pushed-openbanking_brazil-plain_response-vodtCuLLATAN9oO.zip)
