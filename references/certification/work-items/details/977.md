## 1. What happened and what were you expecting?

The third test case for the test payments_api_consents_rejection-reason_test-module_v3 expects the TEMPO_EXPIRADO_CONSUMO rejectionReason code, however, the code TEMPO_EXPIRADO_AUTORIZACAO is more suited for this.

3. Ensure consent is rejected when the authorization time expires. This step will take 5 minutes to run.
- Call POST consent with the expirationDateTime as creationDateTime + 5 minutes
- Expects 201 - Validate response
- Set the conformance suite to wait 5 minutes
- Call GET Consent
- **Expects 200 - Validate if status is "REJECTED" and rejectionReason is TEMPO_EXPIRADO_CONSUMO**

The official specification describes this in the rejectionReason detail:

- TEMPO_EXPIRADO_AUTORIZACAO: Consentimento expirou antes que o usuário pudesse confirmá-lo.
- TEMPO_EXPIRADO_CONSUMO: O usuário não finalizou o fluxo de pagamento e o consentimento expirou.

The code TEMPO_EXPIRADO_AUTORIZACAO describes the user did not "confirm" or authorize it (from AWAITING_AUTHORISATION to AUTHORISED, which has a 5 minute countdown). The code TEMPO_EXPIRADO_CONSUMO describes that the user did not start the payment flow (from AUTHORISED to CONSUMED when the payment flow is started, which has a 60 minute countdown).

The test should then expect the code TEMPO_EXPIRADO_AUTORIZACAO instead of the current TEMPO_EXPIRADO_CONSUMO code.
