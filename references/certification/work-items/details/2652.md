#### Current Behavior:

Hello!
The dcr_api_dcm-pagto-webhook-acsc_test-module-v5 test doesn't send consent id into scope while create request_uri through PAR request, and doesn't send consent id as part of scope in /auth URI. This cause an error after redirect. 

The test isn't sending purpose property into consent, and server reply with 422. But, test continues and send PAR request without consent.

Test logs affected:

* **dcr_api_dcm-pagto-webhook-schd_test-module-v5**
* **dcr_api_dcm-pagto-webhook-acsc_test-module-v5**

This matter indeed seems like a unexpected behavior from Conformance Suit.

While during consent CS sends the following type:

```
"payment": {
      "type": "PIX",
```

It is not sending **`purpose`** field, which is a required field in the following condition:

> * **Campo de envio obrigatório quando o valor do campo /data/payment/type for igual a PIX,**

By correcting this, consent should return a 201 and redirection will be able to proceed accordingly.

We are working towards a fix. Updates will be posted here,

Happy to help!
