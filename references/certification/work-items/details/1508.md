Hi thanks for opening the ticket!

First things first, the main objective of this test module is, as described in it's description:

> Ensure a payment cannot be executed if its sent prior to startDateTime

Therefore, to fulfill this objective, conformance suit sends on the Post Recurring-consents:

`"startDateTime": "2024-03-22T14:44:03Z",`

Afterwards when executing the steps:

> Call the POST recurring-payments endpoint

> Expect 422 PAGAMENTO_DIVERGENTE_CONSENTIMENTO - Validate Error Message

Conformance suit sends the Post pix/recurring-payments request_body:

`"date": "2024-03-12",`

Therefore, conformance suit is operating as expected. The test module failed because a 200 was returned by the server when conformance suit made the Post pix/recurring-payments request sending date prior to startDateTime.

To run the test module successfully, please make sure the correct response code is provided in this scenario, and remember, the Post pix/recurring-payment should comply with the  **`"Content-Type": "application/jwt",`** field on the request header.
