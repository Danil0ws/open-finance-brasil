## 1. Requirements

The payment initiation API for both "consent" and "payment" specifies the pattern below:

amount:
🇧🇷
string
minLength: 4
maxLength: 19
pattern: ^((\d{1,16}\.\d{2}))$
example: 100000.12

However, the PIX API behaves the value field with the following pattern ^\d{1,10}\.\d{2}$
https://github.com/bacen/pix-api or https://bacen.github.io/pix-api/index.html#/Cob/put_cob__txid_)

This situation is generating an unexpected error in our infrastructure, which prevents the test sequence.

Suggested actions:
1 - Adequacy of the engine to send in the test a value at most equal to that expected by the PIX API.
2 - Submission to the SPECIFICATIONS WG for pattern review
3 - Inclusion of this situation in the known problems worksheet, until the specification is revised.

## 2. Acceptance Criteria

Change value sent on the test to have 9999999999.99 so it matches the PIX limit
