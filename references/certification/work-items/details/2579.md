## 📝 Descrição

**Observed behavior**

The Mockbank response for the fido-registration-options enrollment flow is currently returning the `appid` extension under `extensions`:

```
"extensions": {
  "appid": "true"
}
```

---

**Expected behavior**

The fido-registration-options response should not include the `appid` extension for the registration flow.

According to the WebAuthn specification, `appid` applies to **authentication** only, as a compatibility mechanism for credentials previously registered with the legacy FIDO U2F API. It is not defined for registration. If any legacy registration-related handling is needed, the specification defines appidExclude instead.

---

**Suggested DTO evaluation**

As the `extensions` field is already optional in the specification, _please evaluate whether removing it from the Mockbank response would cause any impact, or whether there is any expected data that should be populated in this field for the fido-registration-options response._
