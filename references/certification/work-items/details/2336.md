**Autor**: Daniela Muller (@danielamllr)
**Criado em**: 29/09/2025, 16:54:06

Hi @joao.oliveira24 

The Conformance Suit is sending a **PATCH** request asking for the consent to be edited to change **only** the `creditor name` field to "Openflix", following the summary:

• Call the PATCH recurring-consents endpoint with consent edition, sending creditor name as "Openflix" 

The expected behavior for a **PATCH** call on a consent resource is for the server to return the updated resource, but **only** with the explicitly requested changes. All other fields not related to the edit (such as the `ibgeTownCode`) must remain unchanged. This is because the **PATCH** method is used to apply **partial modifications** to an **_existing_** resource and requires you to send **only the fields you want to change**. If you didn't send the field before the **PATCH** request (in GET recurring-consents in this case), you're adding a field and not updating it, which is not aligned with a PATCH request.

To resolve the failure, please adjust your implementation of the **PATCH /recurring-consents** endpoint to ensure the **immutability of non-edited data**:

* **Data Isolation:** Upon receiving a **PATCH**, only update the fields that were explicitly modified in the request body.
* **Validation:** Ensure that, even if the `ibgeTownCode` field is present in the original resource, it is **not updated or returned as altered** in the response if the **PATCH** did not include it in the edit request.

Please, feel free to ask in case of further questions.

Best regards!
