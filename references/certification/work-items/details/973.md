Hi,

Thank you for the ticket!

Regarding the mentioned test modules, for the first POST Consents, they either expect a `422 DETALHE_PAGAMENTO_INVALIDO` response code or a `201` response followed by an error returned by the authorization server after redirecting the user, without it sending back any authorization code. This is because the consent should be rejected with:

- `VALOR_INVALIDO` for payments_api_qres-wrong-amount-proxy_test-module_v3
- and `QRCODE_INVALIDO` at payments_api_qres-mismatched-proxy_test-module_v3.

The tests have failed because the implementation is sending back a `201` response, and the authorization server is incorrectly accepting a troubled consent request. To a successful execution, the implementation needs to be adapted to conform to the expected behavior described in the test summary.

Feel free to open another ticket if you get any other issue! Happy to help!
