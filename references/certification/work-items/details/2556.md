## 📝 Descrição

**Current Behavior:** During the execution of the FVP Enrollments test (`fvp-enrollments_api_payments-unmatching-fields_open_test-module_v2-2`), the test fails near the end of the execution flow.

`Patch consent - Cancelling if applicable: EnsureConsentResponseCodeWas200: Failed to obtain expected status`

After completing the main test phases (validating unmatching fields for the FIDO flow), the test suite executes a cleanup/cancellation phase(`Patch consent - Cancelling if applicable`) that attempts to cancel the payment using a `PATCH` request. However, the test performs an **immediate** payment flow. When calling the cancellation endpoint for an immediate payment that has no schedules, our system correctly refuses the request and returns a `422 Unprocessable Entity` error with the code `PARAMETRO_INVALIDO` ("Pagamento não possui agendamentos.").

This behavior from the testing tool is inconsistent with the official documentation, as the cancellation endpoint is designed exclusively for scheduled (SCHD) or pending (PDNG) payments.

**Expected Behavior:** The conformance suite test should not trigger the cancellation endpoint for an immediate payment flow.

The expected behavior is that the suite strictly reflects the Open Finance specification: if the payment is immediate, the cancellation step must be suppressed or bypassed during the cleanup phase. Our system's behavior is correct in returning the HTTP Status 422 since the transaction is not eligible for cancellation.

2. **Official Open Finance Documentation Excerpt:**

> _"Esse endpoint deve ser usado para cancelar, a pedido do cliente pagador, as transações que estejam em uma das seguintes situações: Agendada com sucesso (SCHD) ou retida para análise (PDNG). \[...\] **Os pagamentos já liquidados não são passíveis de cancelamento**. Se não restar nenhum pagamento (ocorrência) que poderá ser cancelado, a requisição PATCH retorna HTTP Status 422 com o code PAGAMENTO_NAO_PERMITE_CANCELAMENTO."_ _(Note: In our case, returning PARAMETRO_INVALIDO is the appropriate fallback since it lacks a schedule array entirely)._
