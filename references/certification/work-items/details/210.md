## 1. The Issue

We would like to understand what is the defined instruction regarding multiple errors to be sent on an error message for Phase 3. Given that the item **errors ** is a list, which means multiple errors can be sent.

Down below is an example of a response that has been returned for a Value sent that does not match the value on the QrCode.

```
{
  "errors": [
    {
      "code": "VALOR_INVALIDO",
      "title": "Valor inválido.",
      "detail": "O valor enviado não é válido para o QR Code informado."
    },
    {
      "code": "COBRANCA_INVALIDA",
      "title": "Cobrança inválida",
      "detail": "Validação de expiração, validação de vencimento, Status Válido."
    }
  ],
}
```

For the scenario above both errors can be assumed as valid, and thus the institution just returns both. However, it's unclear if this should be the adopted behavior

It's worth noting that the conformance suite has been set to validate only when error, so it just makes sure that at least one of the errors returned matches the error that is expected -> This approach has been defined given the non mutually exclusive behavior of error codes
## 2. Request

Define the policy regarding how the ASPSP should define which set of error codes it must send.
