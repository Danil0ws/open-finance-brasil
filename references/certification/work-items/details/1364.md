## 📝 Descrição

    Referente ao teste payments_api_idempotency_test-module_v4, onde:

"Call the POST Payments with the same idempotency key but a different payload
• Expect 422 ERRO_IDEMPOTENCIA - Validate Error Message
• Call the POST Payments, with the same payload as the previous request but a different idempotency id
• Expects 422 - CONSENTIMENTO_INVALIDO"

      Neste módulo de teste está sendo esperado um erro de idempotência, após um segundo POST /pix/payments. Porém, na primeira validação, onde se verifica o status do consentimento, só podem ser realizados POST/pix/payments caso o consentimento esteja em status "AUTHORISED". Quando ocorre o primeiro POST /pix/payments com sucesso, o consentimento é alterado de status "AUTHORISED" para "CONSUMED", e por isso o segundo POST /pix/payment retorna o erro http 422 "CONSENTIMENTO_INVALIDO" e não um erro de idempotência. Assim, solicitamos esclarecer qual deve ser a sequência correta de validações.![Idem](/uploads/959f4d7c6e12aa289d4a60d7b50e506a/Idem.JPG)

Hi,

Thanks for opening the ticket!

According to the idempotency specifications and the principles outlined by the W3C regarding HTTP idempotency, it is expected that repeated calls with the same idempotency key should not alter the outcome or produce side effects, irrespective of the payload.

Therefore as was pointed correctly, Conformance suit first executes:

* Calls the POST Payments, with the same idempotency key used at POST Consent
* Expects 201 - Validate Response

And afterwards it calls POST payments for a second time:

* Call the POST Payments with the same idempotency key but a different payload
* Expect 422 ERRO_IDEMPOTENCIA - Validate Error Message

As the Idempotency key doesn't correspond to the request body, given that the request body is different the one sent in the first POST payments call, the conformance suit expects a 422 (ERRO_IDEMPOTENCIA), which as described in the spec:

* **Validações na criação do pagamento - Síncrono (_POST /payments_)**
  * **Casos de erro sintáticos e semânticos, previstos com retorno HTTP Code 422 - Unprocessable Entity (detalhamento adicional na documentação técnica da API):**
    * Idempotência: Valida se há divergência entre chave de idempotência e informações enviadas (ERRO_IDEMPOTENCIA);

Therefore conformance suit is operating as expected and in accordance to what is described in the Idempotency specification.

To ensure test module can be run successfully, make that the implementation validates the Idempotency scenario as the Idempotency key being used is the same.

Feel free to open a new ticket if you have any other questions.
