Thanks for opening the ticket!

After analyzing the provided test id, it can be stated that the test module failed because the Consent was not in the expected state after the following steps described in the test summary description had occurred:

- Set the conformance suite to sleep for 2 minutes
- Call the GET recurring-consents endpoint
- Expect 201 - Validate Response and ensure status is Revoked, revokedBy is DETENTORA, rejectedFrom is DETENTORA and reason.code is

When the POST /recurring-consents was called at "2024-01-10T11:39:25Z”, the  "expirationDateTime" of the consent was defined as now + 2 minutes, meaning "2024-01-10T11:41:25Z”. The response returned a consent with "expirationDateTime" set to "2024-01-10T11:44:27Z". When the conformance suit validated for the expected REVOKED state on the GET recurring-consents response, it resulted in a Failure.

In that sense, the conformance Suit is working as expected. To ensure the test runs successfully, please be sure that the consent expirationDateTime is set to the one defined in the POST Request.

Feel free to open another ticket if you get any other issue!
