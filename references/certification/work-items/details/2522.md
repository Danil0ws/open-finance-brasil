## 📝 Descrição

**Current Behavior:**

At the end of the payments_api_apes-good-happy-path-without-txid_test-module_v5 test, from the payments-apes_test-plan_v5 plan, a **PATCH /open-banking/enrollments/v2/enrollments/{enrollmentId}** request is made with a body to cancel the enrollment.

First of all, this cancellation step is not mentioned in the test description. Even so, after the enrollment cancellation succeeds, the test fails when validating the notification sent by the webhook, which informs the change in the enrollment status.

\*\*Evidence:\
\*\*PlanID: Qv8taoMEzEG7q\
TestID: DNeHqlRR7dhtkie

In addition to the payments_api_apes-good-happy-path-without-txid_test-module_v5 test, the payments_api_apes-mismatched-consent-payment_test-module_v5 and payments_api_apes-code-unhappy-path-required_test-module_v5 tests also exhibited the same failure at the end.

### Comentário 5
**Autor**: Daniela Muller (@danielamllr)
**Criado em**: 26/01/2026, 17:58:32

Thank you for reporting this behavior.

After reviewing the test flow and the specification, we would like to clarify a few important points.

According to the **test summary of `payments_api_apes-good-happy-path-without-txid_test-module_v5`**, the objective of this test is to ensure that an APES payment reaches an accepted state (ACSC) when the static QR Code does not include a `TxId/transactionIdentification`. As described in the test summary, the flow **ends once the payment reaches the ACSC status**.

There is **no requirement in the test description or in the test summary for cancelling the enrollment** at the end of the flow. Therefore, we agree that the execution of the `PATCH /open-banking/enrollments/v2/enrollments/{enrollmentId}` call is **not aligned with the documented scope of this test**. We will open a **test improvement** so that this PATCH call is no longer executed as part of this test module.

Independently of this improvement, it is also important to highlight that, **for this specific test scenario, the sending of enrollment status webhooks is not mandatory according to the test summary**. As such, your implementation should not be required to emit a webhook notification for enrollment cancellation in this test, especially considering that the cancellation itself is not part of the expected flow.

Here you can verify a successful test: https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=0KZJQ5KrwmkM2G2&public=true
