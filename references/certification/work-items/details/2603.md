**What happened:**

Upon analyzing the test logs, all business validations were executed and passed successfully. The recorded error (`runInBackground called after runFinalisationTaskInBackground`) occurs because the FVP received a **second callback request** after the authorization flow had already been completed.

This second request arrives via browser with empty parameters (no authorization code), which indicates it is not a legitimate return from the authorization server, but rather a re-submission of the callback URL. It was possibly caused by a browser behavior during the redirect process (automatic retry, prefetch, or another behavior we are still investigating).

**This is not a bug in the FVP.** The test flow executed correctly from start to finish. The error is a consequence of how the redirect was processed on the executor's side, generating an additional request that the FVP did not expect at that point in the test lifecycle.

We are investigating ways to make the FVP more resilient to this type of situation, so that duplicate callback requests do not impact the final test result.
