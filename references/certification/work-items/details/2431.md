## 📝 Descrição

#### Current Behavior:

---

When making a recurring payment request to Mock Bank, sending the field **data.creditorAccount.issuer = "1"**, the Mock Bank returns an bad request (400) error:

`[{"code":"body.data.creditorAccount.issuer","title":"body.data.creditorAccount.issuer","detail":"must match "\d{4}$"}]`

#### Expected Behavior:

---

Based on the error details, it seems the creditorAccount.issuer field is being validated against the pattern \\d{4}$, which requires exactly 4 digits.

However, according to the Automatic Payments doc, we understood that the field should accept between 1 and 4 digits, not strictly 4.

![opf-automatic-payments-doc](/uploads/877a3fb61fe917bcc6d29a2bbb9ba39f/opf-automatic-payments-doc.png){width="900" height="383"}

Additional observation: When testing with a value containing exactly 4 digits, the payment was created successfully (fapi-interaction-id: "455cae02-8b8c-4f4a-93fe-80811411d202").

Could you confirm whether this current validation is correct? Thanks

#### Evidence:

---

Infos: **ApiEndpoint:** "https://matls-api.mockbank.poc.raidiam.io/open-banking/automatic-payments/v2/pix/recurring-payments" **consent-id:** "urn:raidiambank:a01872aa-332e-4c8d-b507-49dcd926578c" **fapi-interaction-id:** "36c4d6f1-7ba0-438d-b720-972c5e2358da"
