#### Current Behavior:
---
The **automatic-payments_api_invalid-scope_test-module_v2** test is currently requesting authorization via **PAR** for a request containing invalid information. The test expects no error to occur at the **PAR** endpoint and defers validation to the **/authorize** step.  

As a result, the invalid request is initially accepted, and the error is only detected later in the process, potentially exposing the end user to an error message that is not directly related to their interaction.  

#### Expected Behavior:
---
The expected behavior should be the immediate rejection of a request containing invalid information. The validation should occur at the moment the **PAR** request is processed, rather than allowing it to proceed to the authorization step.  

This approach ensures that errors are handled at the institution level, preventing them from being passed down to the end user. The current behavior negatively impacts user experience, as it presents an error that they are not responsible for resolving.  

#### Evidence:
---
According to [RFC 9126, Section 2.1](https://www.rfc-editor.org/rfc/rfc9126.html#section-2.1), the specification does not strictly define where scope validation should take place, leaving room for interpretation. However, we believe that validating the scope at the **PAR** step aligns better with expected security practices and user experience principles.
