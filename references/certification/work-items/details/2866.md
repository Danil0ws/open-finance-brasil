#### Current Behavior:

---

In the Credit Portability API v1.1.0 spec, the error code for PATCH /portabilities/{portabilityId}/cancel (response 422) is documented as CANCELAMENTO_NÃO_EFETUADO, with a tilde.

The portability-patch-unhappy module of test plan credit-portability_test-plan_v1-1 requires the spelling without the tilde, and fails responses that follow the spec.

#### Expected Behavior:

---

As a suggestion, the module could accept the published spelling. 

Reference: https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/2030141967/Swagger+-+API+Portabilidade+de+Cr+dito+v1.1.0-rc.1

Hi @takeo-nu . Thanks for bringing this up. This behavior has been adjusted.

For this response the specification declares errors\[\].code as a free-text string with no enum, so it imposes no single value. Both spellings the specifications publish are now accepted: CANCELAMENTO_NÃO_EFETUADO, as documented in the Credit Portability specification, and CANCELAMENTO_NAO_EFETUADO, as documented in the Payroll Credit Portability specification. A response using either one passes.

We are accepting both while that divergence is evaluated by the AOF Portability Product Group, and the set may be narrowed after that.

Please feel free to rerun the test and reopen this issue if needed.
