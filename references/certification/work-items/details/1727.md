#### Current Behavior:
---
Hi! The test runs through the usual steps of creating consent, accepting consent, and initiating payment. 
Afterwards it keeps polling the payment status before waiting for the webhook. However, after the first polling, 
but before the second one, the payment reaches the ASCS state and the webhooks are received. When the test
comes around to wait for the webhooks, none are received and the test fails.

#### Expected Behavior:
---
Shouldn't the test consider the received webhooks and not fail?

Hi,

Thanks for opening the ticket!

Test module execution failed due to two RecurringPaymentWebhooks being received.

In webhook test modules, the webhook calls don't necessarily need to be received during step:

> **The test will now wait for the webhook to be received**

This stage of the test module only exists to ensure Authorization server has enough time to transition consents and payments state and send the webook.

Therefore, the cause of the failure was:

1. First webhook call received at 5:32:45 PM: First Recurring Consent Webhook
   * **/test-mtls/a/Openswap-DCR/open-banking/webhook/v1/automatic-payments/v1/recurring-consents/urn:swap:da8a7b09-b7cf-401e-a13d-e577ac234d28**
2. Second webhook call received at 5:32:50 PM: First Recurring Payment Webhook
   * **/test-mtls/a/Openswap-DCR/open-banking/webhook/v1/automatic-payments/v1/pix/recurring-payments/28cdadf4-4895-47e3-9115-89aa523a8c67**
3. Third webhook call received at 5:32:55 PM: Second Recurring Payment Webhook
   * **/test-mtls/a/Openswap-DCR/open-banking/webhook/v1/automatic-payments/v1/pix/recurring-payments/28cdadf4-4895-47e3-9115-89aa523a8c67**

Now, conformance suit was expecting to receive only one webhook call for consents and one for payment, therefore throwing the observed failure.

Make sure that only one Recurring Payment Webhook call is made when payment status transitions to ACSC.

Feel free to reopen this issue or open other ones if you require further assistance,

Happy to help!
