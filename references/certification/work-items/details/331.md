The reason the test is asking for the next link is that this specific test aims to validate pagination rules. For this, it expects that the institution sends at least two pages worth of items. This behavior can be identified on the top of the page, within the test summary:

```
Test result set paging: Banks should configure a test accounts list that contains their maximum page-size + 1 item (maximum page-size must be between 25 and 1000). For example, if the bank supports a maximum page-size of 50, then they must set up a test resource with at least 51 items. The initial request should receive a response with 50 items. Requesting the 'next' link, found in the metadata, should receive a response with at least 1 item.
• Creates a Consent with the complete set of the accounts permission group ("ACCOUNTS_READ", "ACCOUNTS_TRANSACTIONS_READ", "RESOURCES_READ")
• Expects a success 201 - Expects a success on Redirect as well
• Calls GET Accounts API V2
• Expects a 200 response
• Calls GET Accounts API V2 with page size=1000
• Expects a 200 response and expect that the links and meta attributes display the next page
• Validates the number of records being return
```
