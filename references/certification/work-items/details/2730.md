## 📝 Descrição

We received a participant report (Mercado Pago) regarding the `issuerInstitutionName` field defined in the Investments API across all currently published versions (1.0.1, 1.0.2 and 1.1.0). After reviewing it against the published specs, we believe the observation is valid and would like the structure to evaluate a correction in the next version.

**Finding**

The field is declared as:

`issuerInstitutionName:
  type: string
  maxLength: 250
  minLength: 1
  pattern: \w+\W*
  example: Organização A1
  description: Nome da instituição emissora.
`

The pattern `\w+\W*` describes a single run of word characters optionally followed by non-word characters. Under strict (full-match) validation it rejects any value containing spaces, commas or periods between words — which excludes the vast majority of real Brazilian financial institution names.

It is also internally inconsistent: the spec's own `example` value, **"Organização A1"**, does not satisfy the pattern (the space between "Organização" and "A1" breaks the match). This inconsistency has been present since v1.0.1 and was carried over unchanged to v1.0.2 and v1.1.0.

**Precedent**

This was already raised internally at the v1.0.1 go-live and tracked under https://gitlab.com/raidiam-conformance/open-finance/certification/-/work_items/1867(Nov/2024). At that time, as a one-off measure to unblock the go-live, the pattern was locally adjusted to `[\w\W\s]*` only inside the conformance suite's embedded swagger. The underlying spec problem was explicitly left open for the structure to address, and the same pattern was reintroduced in v1.1.0.

**Request**

We would like the structure to evaluate adjusting the `issuerInstitutionName` pattern in the next version of the Investments API so that:

1. It accepts real institution names containing spaces, accented characters and common punctuation;
2. It is consistent with the `example` value declared in the spec itself.

For consistency, the same review should be considered for other fields in the API that currently share the `\w+\W*` pattern (e.g. `InvestmentsFund.name`, `InvestmentsFundAdmin.name`, `InvestmentsFundFundManager.name`).
