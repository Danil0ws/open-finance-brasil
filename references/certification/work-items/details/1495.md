Therefore, we will update this scenario as follows:

Ensure that consent for monthly recurring payments can be carried out and that the payment is not successfully scheduled when the amount from one of the payments does not match the consent.\
• Call the POST Consents endpoints with the schedule.daily.startDate field set as D+1, and schedule.daily.quantity as 5\
• Expects 201 - Validate response\
• Redirects the user to authorize the created consent\
• Call GET Consent\
• Expects 200 - Validate if status is "AUTHORISED" and validate response\
• Calls the POST Payments Endpoint with the 5 Payments, using the appropriate with the e2eid but one of the payments with a different amount\
• **Expects 201 or** 422 - PAGAMENTO_DIVERGENTE_CONSENTIMENTO

**If 201 is returned:**

* **Poll the Get Payments endpoint with one of the PaymentID Created while payment status is RCVD**
* **Expects 200 with a RJCT status, and rejectionReason as PAGAMENTO_DIVERGENTE_CONSENTIMENTO**

\
• Call GET Consent\
• Expects 200 - Validate if status is "CONSUMED" and validate response
