## 1. What happened and what were you expecting?

Hello there!

We have found a new issue in test payments_api_recurring-payments-patch_test-module_v4.

In this test, the conformance suit is calling the GET /pix/payments/{paymentId} with the first paymentId scheduled(SCHD) to verify if this one was cancelled(CANC). The response returns the information from the first paymentId with the end2endid E44471172202402081500myNTNpw3zwe.

After the execution, the suite was validating the values returned but the value expected is from the last paymentId scheduled. The suit was expecting to receive the end2endid E44471172202402121500hjmLBxghGLu that was generated for the last paymentId.
