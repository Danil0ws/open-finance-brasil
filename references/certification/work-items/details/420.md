## 📝 Descrição

## 1. What Happened and what were you expecting?

The accounts API test will execute 1150 API calls for each active resource/consent pair, for a total of around 3500 calls.

This leads the CS UI to become extremely slow as it's not conceived to convey that much information, leading in turn to an impossibility for some orgs to be able to authorize the second consent request.

The logging on the screen has been already reduced to display only the HTTP REQUEST and HTTP RESPONSE pairs, so it might be challenging to reduce the logging any further.

Here a few suggestions have been brought:

1. Exclude a few endpoints to be tested in favour of more critical ones
2. Exclude the need to test for a second client or for a second resource 
3. Authorize both consents at the start of the test - This solution might not solve the issue of the impossibility of loading the result, just reduce the need to interact with the test.
4. Reduce even further the logging so we don't display the intermediary requests, just the first and the last, so for balance the first call and the 420 calls.
5. Remove the validators that we do on the first API call and just validate the response codes even on those returns
6. Using Pagination on tests
