## 1. What happened and what were you expecting?
Test validates self link from consents endpoint. The endpoint is called (HTTP method GET), and returns the consent with status code 200. Test fails expecting status code 201.

Hi,

Thanks for the ticket! This behavior is not a problem, as a 201 status is meant to inform that one or possibly multiple new resources were created, which is not the case for the GET Consents.

This test is failing because at the step _"Ensure error when calling POST Consent without x-fapi-interaction id"_ the engine is incorrectly sending the `x-fapi-interaction id`. This issue is already being tracked by our team at #929 and we will make updates there as soon as possible.

Happy to help!
