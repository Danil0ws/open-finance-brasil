## 📝 Descrição

According to the Open Finance [specification ](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1600030468/Informa+es+T+cnicas+-+SV+Pagamentos+-+v5.0.0-rc.1), when localInstrument is APDN or QRDN, the payloadJWS field is mandatory.

However, in the test case payments_api_qrdn-with-qres-code_test-module_v5, the engine does not include the payloadJWS field in the request. As a result, the request fails due to an internal validation, preventing the flow from continuing.

Because of this, it is not possible to proceed with the scenario:

"Call POST Consent with localInstrument as QRDN but the “qrcode” field with a valid static QRCode"


The test engine should include the payloadJWS field when executing scenarios where localInstrument is QRDN or APDN, in accordance with the Open Finance specification.

Thank you for reaching us!

It is important to clarify that the `payloadJWS` field is a **test plan configuration input that must be provided by the participant**. The test conformance suite does not generate this value on its own — it uses the data that was previously configured by the participant in the conformance suite configs.

Therefore, if the `payloadJWS` was not included in the request, this indicates that **the field was not filled in (or was filled in incorrectly) in your test plan configuration**.

Please let us know if you need any assistance identifying which fields need to be configured in the test plan.
