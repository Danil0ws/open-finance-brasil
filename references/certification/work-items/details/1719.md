Hi Adriano,

Thanks for the ticket! We understand that there is a gap in the specification, and we will need to submit the following question to the WG Validation:

Currently, the transactionLimit and dailyLimit are defined for User Redirection and will be used to validate payments. The error for executing a payment that exceeds these limits could occur at the following moments:

1. **POST Consent**: We understand that an error at this endpoint would not be possible since the Bank does not know the limits at this point. The consent will be authorized through Enrollment or Redirection.
2. **POST Consent Authorize**: Could a synchronous error (422) be returned from this endpoint? If so, what would be the expected code? If this is the case, what status and rejectionReason should be retrieved from the GET Consents endpoint?
3. **POST Payments**: Could a synchronous error (422) be returned from this endpoint, and would the consent be consumed? If so, what would be the expected code?
4. **GET Payments**: If a 201 is retrieved from POST Payments, the payment could still go to RJCT status. In that case, what would be the rejectionReason?

In this context, what would be the expected errors? When should they happen or not?
