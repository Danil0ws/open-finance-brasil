## 📝 Descrição

#### Current Behavior:

---

O cenário fvp-consents_api_negative_test-module_v3-3-1 do plano de testes dcr-fvp-yacs_test-plan está realizando uma validação onde se espera que, ao tentar criar um consentimento com data de expiração superior a 1 ano, o sistema bloqueie essa criação:

• Creates consent api V3-3-1 request for DateTime greater than 1 year from now\
• Expects failure with a 422 Error

#### Expected Behavior:

---

Porém, essa regra foi removida no patch da api de consentimentos (3.3.1) do dia 15/12/2025, onde remove do campo a regra "Quando preenchido, o valor do campo não pode ultrapassar 12 meses. ":

* De: Data e hora de expiração da permissão. Reflete a data limite de validade do consentimento. Uma string com data e hora conforme especificação RFC-3339, sempre com a utilização de timezone UTC (UTC time format). \
  \[Restrição\] De preenchimento obrigatório nos casos em que houver validade determinada. Em casos de consentimento com prazo indeterminado o campo não deve ser enviado. Quando preenchido, o valor do campo não pode ultrapassar 12 meses. 
* Para: Data e hora de expiração da permissão. Reflete a data limite de validade do consentimento. Uma string com data e hora conforme especificação RFC-3339, sempre com a utilização de timezone UTC (UTC time format).  \
  \[Restrição\] De preenchimento obrigatório nos casos em que houver validade determinada. Em casos de consentimento com prazo indeterminado o campo não deve ser enviado.   

(https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/1378386007/Changelog+-+DC+Consentimento+-+v3.3.1+-+v3.3.0)

Ou seja, o cenário está validando uma regra que não é mais vigente.
