## 📝 Descrição

The QREs behavior allows it to be sent both with and without the amount field. 

On the test plan, we are sending a good QRES without the amount field and we expect the org to be able to correctly process this payment.

We spoke with the sandbox squad and it has been defined that this is a perfectly valid use case. As long as the rest of the information is consistent with the QRcode field, the org should be able to process this Payment. This can happen, for example, with a static Qr code used by a street seller where the amount is inserted after the QR code has been read.

On the conformance suite, we should have three test scenarios for this

(1) The QRCode will have the amount field and it will match what is sent on the PIX Payments API-> Happy path, expects ACCC

(2) The QRCode doesn't have the amount field but it's consistent with the PIX Payments API -> Happy path, expects ACCC

(3) The QRCode does have the amount field, but it diverges from the PIX Payments API -> Unhappy Path, expects either a 422 or a RJCT

We understand that this behavior should be correctly documented so the participants can understand all the correct behaviors. This discussion shall be brought to the Specs WG.
