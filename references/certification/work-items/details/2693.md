Hello, @lucas.barros7 @joao.oliveira24 and @vinicius.pacifico.

Thank you for the report. We've identified the root cause.

A recent change introduced a new dedicated configuration field (`resource.brazilQresPaymentConsent`) which the **payments_api_pix-withdraw-qres_test-module_v5** (and **pix-withdraw-invalid-amount**) now reads from instead of the generic `resource.brazilPaymentConsent`. However, the corresponding input field was never added to the configuration form UI, making it impossible to populate through the interface.

A fix is currently in progress, which:

1. Adds the **"Payment consent request JSON with QRES embedded"** field to the configuration form, mapping to `resource.brazilQresPaymentConsent`
2. Ensures all four modules in the Withdraw QRES plan use this single field as their consent source

**Workaround in the meantime:** you can unblock yourself by editing your plan configuration JSON directly and adding the `brazilQresPaymentConsent` key under `resource` with the same structure you already have in `brazilPaymentConsent`, just rename the key. The test will pass once that field is present.

We'll update this issue once the fix is merged.

Regards
