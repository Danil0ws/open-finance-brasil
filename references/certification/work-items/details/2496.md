## 📝 Descrição

**Context**

The Test manager ticket creation logic was originally developed to only consider existing Service Desk tickets when they are in a single configured “open” status (e.g., open.status = 6). If the SR is active but has a status different from 6, the automation does not find it, does not add the note, and opens a new SR.

---

**Current behavior**

1. Only SRs with **status=6** are eligible.
2. Then matchesCriteria() must pass:
   * authServerIdField == authServerId
   * testGroupField == testGroup
   * executedSegmentField == 1 (PF) or 2 (PJ)
3. The SR with the highest ID is selected (most recent).

---

**Expected behavior**

The automation should be able to update existing SRs as long as they are not closed, even if they are in a status different from the configured “open” status.
