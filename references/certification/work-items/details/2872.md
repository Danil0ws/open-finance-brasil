#### Current Behavior:

---

Durante a criação de um consentimento recorrente do tipo Sweeping (`/automatic-payments/v2/recurring-consents`), o Mock Bank está retornando erro quando a configuração de limites periódicos possui apenas alguns períodos configurados.

Foi identificado que a requisição abaixo contém apenas os limites **semanal** e **anual** configurados, sem envio dos períodos **diário** e **mensal**:

A requisição é encaminhada ao Mock Bank exatamente conforme abaixo:

Contudo o Mock Bank retorna:

`{ "meta": { "requestDateTime": "2026-09-09T18:07:34Z" }, "errors": [ { "code": "PARAMETRO_NAO_INFORMADO", "title": "Parametro não informado.", "detail": "At least one limit (quantityLimit or transactionLimit) must be provided for periodic limit" } ] }`

HTTP: 422 Unprocessable Entity

X-FAPI: 2f1c154f-8cec-4ba4-9c36-6af45eb73022

#### Expected Behavior:

---

De acordo com a estrutura do Open Finance Brasil para Recurring Consents (Sweeping), os períodos de `periodicLimits` são opcionais.

Deve ser possível:

* informar apenas `day`;
* informar apenas `week`
* informar apenas `month`;
* informar apenas `year`;
* informar combinações parciais dos períodos -\> \[Restrição\] Caso enviado o objeto, ao menos um dos campos (quantityLimit ou transactionLimit) devem ser preenchidos.
* omitir completamente períodos não utilizados.

`{ "periodicLimits": { "week": { "quantityLimit": 5, "transactionLimit": 30000.12 }, "year": { "quantityLimit": 10, "transactionLimit": 30000.12 } } }`

Nesse cenário o consentimento deve ser aceito normalmente.

Além disso, quando um período não for informado, ele não deve ser tratado como um período obrigatório com valores ausentes.

Olá, @xstrikeesdraspb 

Analisamos o caso e o comportamento do Mock Bank está correto, de acordo com a especificação.

Ao verificar a requisição efetivamente recebida pelo Mock Bank nesta chamada (`X-FAPI-Interaction-ID: 2f1c154f-8cec-4ba4-9c36-6af45eb73022`), o objeto `periodicLimits` chegou assim:

```json
"periodicLimits": {
  "day":   {},
  "week":  { "quantityLimit": 5,  "transactionLimit": 30000.12 },
  "month": {},
  "year":  { "quantityLimit": 10, "transactionLimit": 30000.12 }
}
```

Ou seja, `day` e `month` não foram omitidos. Foram enviados como objetos vazios, sem `quantityLimit` e sem `transactionLimit`.

A especificação de Pagamentos Automáticos v2.0.0 (schemas `Day`, `Week`, `Month` e `Year`) traz a restrição:

> \[Restrição\] Caso enviado o objeto, ao menos um dos campos (`quantityLimit` ou `transactionLimit`) devem ser preenchidos.

Ou seja:

- Os períodos são opcionais, então você pode omitir os que não usa.
- Mas, se o objeto do período for enviado, ele precisa conter ao menos um dos dois limites. Um período vazio (`{}`) é inválido.

Para funcionar, basta uma das opções abaixo.

Omitir os períodos não utilizados:

```json
"periodicLimits": {
  "week": { "quantityLimit": 5,  "transactionLimit": 30000.12 },
  "year": { "quantityLimit": 10, "transactionLimit": 30000.12 }
}
```

Ou preencher ao menos um limite em cada período enviado.

Caso tenha mais dúvidas, estaremos à disposição.
