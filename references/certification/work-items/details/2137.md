## 📝 Descrição

#### Current Behavior:
---
Hello everyone! I'm opening this issue to report a possible bug that we've found in recurring consent creations. In the CreateRecurringConsent object, the field quantityLimit seems not to be allowed to be null, forcing us to pass a value. The Open Finance documentation shows that when we declare a PeriodicLimits object, at least one field must be filled; however, when we send the request with the quantityLimit field set to null (indicating an unlimited limit for that period), an error is returned from the API call.

#### Expected Behavior:
---
We expect that this field can be null in scenarios where the customer wants to have a transaction value limit for that period, but without a quantity limit.

Hi, @felipeferreira3 

Thanks for the ticket!

The error occurred because, according to the specification, the field `quantityLimit` must be an integer:
![image](/uploads/8382867d032900cf6315313ff56240ef/image.png)

Therefore, MB is correct in expecting an integer value, and the error in your scenario is indeed expected. As you mentioned, the Open Finance documentation states that if the object `periodicLimits` is present, at least one of the fields (`quantityLimit` or `transactionLimit`) must be provided. However, when choosing only one, only the relevant field should be included for each period.

In your case, the correct `periodicLimits` structure should look like:

```json
"periodicLimits": {
          "day": {
            "quantityLimit": 999
          },
          "week": {
            "transactionLimit": 1000000.12
          },
          "month": {
            "quantityLimit": 999,
            "transactionLimit": 1000000.12
          },
          "year": {
            "quantityLimit": 999,
            "transactionLimit": 1000000.12
          }
        }
```

Please adjust your implementation so the request can be successfully processed by MB.

Feel free to open another ticket if you have any other issue! Happy to help!
