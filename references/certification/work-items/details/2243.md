## 📝 Descrição

#### Current Behavior:
---
Currently all tests in the `credit-portability_api_contract-term_test-module_v1` test suite are validating the response payload of the `GET /api/loas/v2/contracts/{contractId}` endpoint against the [v2.4 swagger spec](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/784728264/Informa+es+T+cnicas+-+DC+Empr+stimos+-+v2.4.0) which demands that both `postFixedRate` and `preFixedRate` be present inside  the `.data.interestRates[]` field

However this requirement has been dropped in the [v2.5.0 swagger](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/905740488/Informa+es+T+cnicas+-+DC+Empr+stimos+-+v2.5.0-beta.1) which demands that only one of `postFixedRate` and `preFixedRate` be present inside the `.data.interestRates[]` field (making a previously required response field no longer mandatory is a breaking-change and motivation enough for v2.5 to be a major release, but nevertheless...)

#### Expected Behavior:
---
In accordance with the v2.5 certification roadmap (The 50% milestone of which was today 24-06-2025) we have already implemented the v2.5 behavior in the loans API responses which is causing the credit-portability tests to fail. The tests should be tolerant of responses in both v2.4 and v2.5 formats.
