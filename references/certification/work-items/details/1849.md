#### Current Behavior:

---

We've identified what appears to be an inconsistency in the specification of Automatic Payments v2.0.0-beta.1.

The field `data.recurringConfiguration.automatic.firstPayment.creditorAccount.issuer` has the following restriction:

**\[Restriction\]**: This field is mandatory for the following account types: `CACC` (Checking Account) and `SVGS` (Savings Account).

However, it is marked as **required** in the Swagger documentation (\*), which contradicts the restriction. This restriction would only make sense if the field were optional.

This field appears in the following endpoints:

* **POST** `/recurring-consent`: Request and Response
* **GET** `/recurring-consent/{recurringConsentId}`: Response
* **PATCH** `/recurring-consent/{recurringConsentId}`: Response
* **POST** `/recurring-payments`: Response
* **GET** `/recurring-payment/{recurringPaymentId}`: Response
* **PATCH** `/recurring-payment/{recurringPaymentId}`: Response

Since the Conformance Suit relies on the Swagger specification, it will treat this field as mandatory and will not account for the restriction.

Could we please clarify this and adjust the specification or the Swagger file accordingly?
