## 📝 Descrição

#### Current Behavior

The test module `resources_api_unavailable_test-module_v3-1` validates the 403 response from `GET /accounts/{accountId}/balances` using `GetAccountsBalancesOASValidatorV2n4`, which loads `swagger-accounts-2.4.2.yml`. 

In that spec, `ResponseError.meta` references the full `Meta` schema, where `totalRecords`, `totalPages` and `requestDateTime` are all required. As a consequence, when a participant returns a 403 with a `meta` block containing only `requestDateTime` (as expected under Accounts v2.5.0), the validator fails with:

`Unable to find element totalRecords on the GetAccountsBalancesOASValidatorV2n4 API response`

#### Expected Behavior

In `swagger-accounts-2.5.0-beta.2.yml`, error responses use `ResponseErrorMetaSingle`, whose `meta` references `MetaOnlyRequestDateTime` — i.e. only `requestDateTime` is present in error meta, and `totalRecords` is **not** expected.

Reference: https://openbanking-brasil.github.io/all-services-repo/api_accounts\_-\_open_finance_brasil/?urls.primaryName=2.5.0#/Accounts/accountsGetAccountsAccountIdBalances

The Balances 403 validation in `ResourcesApiTestModuleUnavailableV3n1` (and its V3 counterpart) should be updated to use `GetAccountsBalancesOASValidatorV2n5`.

#### Evidence

https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=9AesNGyW201IvhP
