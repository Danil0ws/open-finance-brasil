## 1. What Happened and what were you expecting?

This issue happens with 6 new API resources test modules that have been created with https://gitlab.com/obb1/certification/-/merge_requests/588. 

When redirecting the user to the authorization endpoint for it to authorize the access token the conformance suite is sending the scope parameter without the resources scope. For example the on the accounts-resources test we have the following scope being sent &scope=openid%20accounts%20consent:xxxx

This eventually leads to the token being created without the resources scope, which will make the server deny the Conformance Suite from accessing the

Test must make sure that the resource scope gets added on the URI

Additionally. The test summary is not correct as it's exactly the same as the regular accounts API test.

All of the 6 test modules must have a summary that matches the real test module behavior. This is the proposed one:

Makes sure that the Resource API and the API that is the scope of this test plan are returning the same available IDs
- Create a consent with all the permissions needed to access the tested API
- Expects server to create the consent with 201
- Redirect the user to authorize at the financial institution
- Call the tested resource API
- Expect a success - Validate the fields of the response and Make sure that an id is returned - Fetch the id provided by this API 
- Call the resources API 
- Expect a success - Validate the fields of the response that are marked as AVAILABLE are exactly the ones that have been returned by the tested API
