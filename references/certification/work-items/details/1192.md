Hi Jorge,

To clarify and ensure a mutual understanding, let’s break down the sequence of steps and validations performed by the test module:

POST Payments Validation:
```
Calls the POST Payments
Expects 201 - Validate message
```
Upon receiving the response, the conformance suite, among other validations, checks the "data" field in the Post pix/payments response. According to the specification, the "data" field contained within the response_body for this request should be an array. This appears to be the area where you are currently facing issues.


GET Payments Validation:
```
Poll the Get Payments endpoint with the PaymentID Created while payment status is RCVD, ACCP or ACPD
Expectes Definitive state (ACSC) - Validate Response
```
In this step, among other validations, the conformance suit checks the "data" field contained within the response_body for the Get pix/payments/{paymentId} response. Here, as per the spec, the "data" field should be an object. This appears to be the area where you previously encountered issues.

To ensure the test module functions correctly, please make sure of the following:
- In the response for POST /pix/payments, include the "data" field as an array.
- For the GET pix/payments/{paymentId} request, maintain the "data" field as an object in the response.

Should you need further assistance or clarification, please feel free to respond to this issue or open a new ticket.
