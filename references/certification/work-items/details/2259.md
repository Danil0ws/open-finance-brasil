## 📝 Descrição

**Description:**\
The test module `automatic-payments_api_automatic-pix-scheduling-retry_2-3_test-module_v2` is failing because the condition `EnsureOnePaymentForToday` is checking whether a payment is scheduled for "today" — but it's using the system date (likely in UTC).

Since this test runs after 21:00 UTC, it is already **00:00 in UTC-3 (Brazil time)**, which causes the logic to incorrectly interpret the payment as scheduled for the _next day_.

**Proposed Fix:**

* Update the condition `EnsureOnePaymentForToday` to evaluate the scheduled date using **UTC-3** as the base timezone.
* Review similar conditions in this class to ensure consistent handling of UTC-3 where appropriate.
* ⚠️ Be cautious **not to change** conditions that are supposed to operate in **UTC** — only those that explicitly need to follow BRL time.

**Impact:**\
This issue leads to false test failures when scheduled near midnight in Brazil. Fixing it ensures test reliability and prevents avoidable re-runs.
