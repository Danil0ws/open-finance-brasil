Hi,

The general [pagination](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17377470/Pagina+o) specification, which applies broadly across all APIs and versions unless specifically overridden, states the following for the `selfLink` attribute:

* **`self`**: A URI to request the page itself.
* **When a `GET` method is called**, it must return the link to the consulted resource itself.
* **When a `POST` method is called**, it must return the link to the **created resource**.
* **When a `PATCH` method is called**, it must return the link to the **altered resource**.

This rule is fundamental: when you create a new resource via a `POST` request, the `selfLink` in the `201 Created` response **must provide the URI to individually access that newly created resource**. For a resource like a payment or a consent, this individual URI **always** includes its unique identifier (e.g., `paymentId`, `consentId`).

Therefore:

* **For `POST /payments` (or `/pix/payments` in v4), regardless of the API version (v2 or v4), the `selfLink` in the `201 Created` response must include the `paymentId` of the payment that was just created.** This allows subsequent `GET` requests to retrieve the specific payment resource.

In conclusion, the documentation for both v2 and v4 implies that the `selfLink` for a `POST` operation must point to the _specific created resource_, which inherently includes its unique identifier. The behavior of the v4 test is correct in expecting the `paymentId` in the `selfLink`. Your v2 implementation should also follow this rule for `POST` requests.
