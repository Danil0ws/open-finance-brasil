Hello @andre.marques1. Thanks for sharing the test summary.

After analysing the context, we’d like to propose a small adjustment to the 5-minute polling logic, so it works as follows:

* \[...\]
* Call the POST /consents endpoint with 'Credit Operations' permission group(s)
  * Expect 201 - Validate Response and ensure status as AWAITING_AUTHORISATION
* Redirect the user to authorize consent
* Call the GET /consents/{consentId} endpoint
  * Expect 201 - Validate Response and ensure status is AUTHORISED 
* **Call the GET /resources endpoint**
* **Expects a 200 or 202 - Validate Response**\
  **• If 202 is returned:**
  * **Start polling up to 5 minutes until 200 status is returned**
  * **Expect 200 - Validate Response**
* Call the GET Loans Contracts endpoint
* \[...\]

In this way, the 5-minute window is used specifically to wait for resources to become available (when /resources indicates “processing” via 202), rather than starting the timer before the Loans Contracts call.

We propose applying the same adjustment to:

* **credit-portability_api_received_test-module_v1** 
* **credit-portability_api_accepted_settlement_1-3_test-module_v1** 

Does the DTO team agree with this proposal?
