## 📝 Descrição

Hi Open Finance team, I would like to clarify the test plan `automatic-payments_api_automatic-pix-receiver-revoked-consent-timezone_test-module_v2-2` expectation.

#### Current Behavior:

---

After the automatic pix recurring consent is AUTHORISED, and Post /pix/recurring-payments of the firstPayment request is sent. This test case expect the first payment to only be either RCVD or ACCP, before it move on to ACSC.

![image.png](/uploads/f041c86bafb1f8049d47859fbe899d97/image.png){width="900" height="491"}

No `ACPD` allowed as a status before ACSC

![image.png](/uploads/124730e4e4e5b615ea6fa53bf493f1a8/image.png){width="645" height="214"}

#### Expected Behavior:

---

In all other test cases for functional automatic-pix, like this `automatic-pix-mensal-core_test-module_v2-2` for example.

All 3 of `RCVD, ACCP or ACPD` statuses are allowed before firstPayment is moved to ACSC.

![image.png](/uploads/84e4c173ac118940fff88d7e787b5360/image.png){width="900" height="393"}

**My question**: Is there anything special regarding payment status `ACPD` that make firstPapyment not allowed it in the automatic-pix-receiver-revoked-consent-timezone_test case?

Since our service include this status in the automatic pix payment state machine: RCVD -\> ACPD -\> ACSC , which apparently the `automatic-pix-receiver-revoked-consent-timezone_test`  case does not consider as a valid state machine.
