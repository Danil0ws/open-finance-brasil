Hi,

We have analyzed the issue raised regarding the `response_type` and confirm that the conformance suit's behavior is correct and aligned with the specifications.

The condition for sending the `response_type` "code" versus "code id_token" depends on the `fapi_response_mode` configuration that your environment is using.

* **If the configuration is `fapi_response_mode=jarm`:** CS sends the `response_type` as `"code"`. This is the expected behavior because, in this mode, the authorization response (including the code and other information) is encapsulated in a signed JWT (JARM).
* **If the configuration is `fapi_response_mode` is different from `jarm`:** CS sends the `response_type` as `"code id_token"`, which is the standard for the FAPI flow.

In the case of this test, CS is sending `response_type: "code"` because your environment's configuration is set to `fapi_response_mode=jarm`, which is correct for this scenario.

To resolve your question, we suggest that you check your `fapi_response_mode` configuration in your test environment. If you want the CS to send `response_type: "code id_token"`, you will need to adjust the configuration to a mode other than `jarm`.
