### Comentário 6
**Autor**: Matheus Mantovani (@matheus-mantovani)
**Criado em**: 25/09/2025, 18:36:15

@PioNetoSisprime Thanks for raising this.

We’ve reviewed the logs, and the observed behavior is consistent with the expected flow of this test case.

After the 201 Created response to the POST /automatic-payments/v2/pix/recurring-payments, the test does not stop immediately. By design, it continues with polling GET requests to validate the resource status until the payment has been fully processed according to the specification (i.e., consent is fully authorized and payment execution reaches a final state).

This run failed because the resource did not progress to the expected final status within the polling window. In the attached log, the payment remains in an intermediate state (ACCP) and does not reach completion (ACSC) before timeout, which causes the runner to mark the test as failed.

Additionally, we noticed that the test summary should explicitly reflect this status, so we opened a test improvement on that point.
