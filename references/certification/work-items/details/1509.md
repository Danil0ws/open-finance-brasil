Hi,

Thanks for opening the ticket! Here is a breakdown for those 3 test modules mentioned:

* automatic-payments_api_sweeping-accounts-core_test-module_v1 and automatic-payments_api_sweeping-accounts-limits_test-module_v1: This test modules do not require to use CNPJs as in automatic-payments_api_sweeping-accounts-root-cnpj_test-module_v1, as described in the test description suggests: If a brazilCpf or brazilCnpj is informed at the config, these fields will be used at both the loggedUser/businessEntity and Creditor. If not, the institution will be required to have an account registered with the CPF 99991111140. Therefore if you provide both a valid cpf and the cnpj as automatic-payments_api_sweeping-accounts-root-cnpj_test-module_v1, test module should run without errors.
* automatic-payments_api_sweeping-accounts-root-cnpj_test-module_v1: Behavior has already been changed to account for the cnpj scenario

In that sense, for the two tests mentioned at firs bullett, you should be able to register your own key and use it at the test. At the test mentioned at the second bullet, you won't have to complete a full payment process. The test will stop after a 201 is returned from POST recurringPayments and therefore, not requiring it to be a valid PIX key.
