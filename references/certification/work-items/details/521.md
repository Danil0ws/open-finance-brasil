## 1. What Happened and what were you expecting?
In the payments-api-e2eid-test-v2 test, the conformance suite executes consecutive POSTs on pix/payments using the same token associated with the same consent, expecting a 422 error with code PARAMETRO_INVALIDO, however, according to the specifications available at https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/24182882/M+quina+de+Estados+-+v2.0.0+-+Payments, consent must change to CONSUMED status after a response 422 on payment initiation, resulting in a code CONSENTIMENTO_INVALIDO in the second request.

Thus, to simulate the proposed condition, we understand that the conformance suite should create a new consent for each initiation.
