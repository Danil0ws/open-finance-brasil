## 📝 Descrição

## 1. What happened and what were you expecting?

We have doubts about the last update of the Payment API v3. The payments_api_nofunds_test-module_v3 has the statement below:

----
Ensure a payment with an amount of 9999999999.99 will lead to a RJCT Payment with SALDO_INSUFICIENTE or VALOR_ACIMA_LIMITE error

- Creates consent request_body with valid email proxy (cliente-a00001@pix.bcb.gov.br) and it’s standardized payload, however set the amount to be 9999999999.99
- Call the POST Consents API
- Expects 201 - Validate that the response_body is in line with the specifications
- Redirects the user to authorize the created consent - Expect Failure
- Ensure an error is returned and that the authorization code was not sent back
- Call the GET Consents API
- Expects 200 - Validate response - Check if Status is REJECTED and rejectionReason is SALDO_INSUFICIENTE or VALOR_ACIMA_LIMITE
---
 After the POST Consent, it expects 201 and then we have to redirect for authorization. After this, the test expects Failure. But it don't tells us what error is expected.

Could you, please, clarify it for us?

Hi Carlos! Thanks for the ticket!

The error here is the error from a failure at the authorization endpoint, as specified at [RFC 6479](https://www.rfc-editor.org/rfc/rfc6749#section-4.1.2.1): 

"If the request fails due to a missing, invalid, or mismatching redirection URI, or if the client identifier is missing or invalid, the authorization server SHOULD inform the resource owner of the error and MUST NOT automatically redirect the user-agent to the invalid redirection URI. **If the resource owner denies the access request or if the request fails for reasons other than a missing or invalid redirection URI,** the authorization server informs the client by adding the following parameters to the query component of the redirection URI using the "application/x-www-form-urlencoded" format, per [Appendix B](https://www.rfc-editor.org/rfc/rfc6749#appendix-B): "

Here, the most important thing is that the authorization_code cannot be sent back when the user is redirected, and that error field is sent back.
