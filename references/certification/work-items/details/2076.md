## 📝 Descrição

#### Current Behavior:
---
The consent sent contains a firstPayment object, indicating that an initial payment is expected. However, when creating the payment for the first time, the paymentReference attribute is sent with a value of "zero", indicating that it is an initial payment, but the amount is "0.50", which is different from the value configured in the firstPayment object of the consent. As a result, the initial payment is not created.

When making the second payment, it is expected to schedule it, sending the date for D+2, the value configured in fixedAmount, and the paymentReference "W9-2025". However, since the initial payment was not created in the previous step, I understand that the system should not expect the payment to be scheduled, but rather return a 422 error for payment divergence from the consent.


#### Expected Behavior:
---
I understand that the system should not wait for the payment to be scheduled without the first payment having been made, but rather return a 422 error due to payment discrepancy from consent.

Thanks for opening the issue!

Currently, the failure of the first payment does not cancel the consent, allowing subsequent payments to be scheduled within the Open Finance context. In Open Finance, the consent remains valid even if the first payment fails. It is understood that this behavior differs from the "arranjo Pix", this was a deliberate decision made by the WorkGroup to align with the consent model and authorization management framework of the Open Finance ecosystem.
