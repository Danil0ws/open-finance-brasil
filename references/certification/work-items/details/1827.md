#### Current Behavior:
---
When performing the test plan dcr-fvp_test-plan, the test **fvp-consents_api_bad-consents_test-module_v3** failure in validation EnsureErrorResponseCodeFieldWasParametroInvalido returning the message "Could not find error with expected code in the errors JSON array", in this test it is expected that the test Creates a Consent with an invalid x-fapi-interaction-id • Expects 400 or 422 - **PARAMETRO_INVALIDO** - Validate error message and verify that a valid x-fapi was sent back, but in this case we return status 422 with the message **SEM_PERMISSOES_FUNCIONAIS_RESTANTES**, therefore the test failed because it was a different message than expected from the test description.

---
When performing the test plan dcr-fvp_test-plan, the test fvp-consents_api_bad-consents_test-module_v3 failure in validation EnsureErrorResponseCodeFieldWasParametroInvalido returning the message "Could not find error with expected code in the errors JSON array", in this test it is expected that the test Creates a Consent with an invalid x-fapi-interaction-id • Expects 400 or 422 - PARAMETRO_INVALIDO - Validate error message and verify that a valid x-fapi was sent back But when we return status 422 with the message SEM_PERMISSOES_FUNCIONAIS_RESTANTES, we receive a validation failure, when analyzing the /consents api specification, the error message enum does not contain the message PARAMETRO_INVALIDO, as described in the swagger documentation - https://openbanking-brasil.github.io/openapi/swagger-apis/consents/3.0.1.yml
