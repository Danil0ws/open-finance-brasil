Hi, 

Thanks for opening the issue!

The field `referenceStartDate` is intentionally set to the same date of the `firstPayment.date`. Note that this should not be validated during the first payment creation, as the `referenceStartDateTime` only represents **a reference of the start date for the payment series** and not the actual payment date. Observe that in the specification, there is no restriction mentioned for the field `referenceStartDate`:

![image.png](/uploads/e42c7d1f730bbbfee4d5f91436d6baeb/image.png)

Therefore, there is no corrections on the CS side. To a successful execution, the implementation needs to be adapted so that it aligns with the specification.

Feel free to open another ticket if you get any other issue! Happy to help!
