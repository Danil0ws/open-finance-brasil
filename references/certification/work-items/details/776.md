Hi,

Thanks for the ticket!

The test steps do not conflict with each other. The specific step that expects status 400 is meant to verify if a request without the `x-fapi-interaction-id` header is correctly identified as an error. That being, this is the only request sent without the mandatory header `x-fapi-interaction-id` so it should return an error.

However, I understand there is indeed a confusing situation when the implementation incorrectly returns a pass with status 200 or 201 in this step, as yours did. Regarding that, I have created an Change of Request item at #778 for us to improve the clarity of error reporting - making it clearer for the participant, before the self link verification, when the status code is not the expected. We will provide updates on the progress in that item as soon as possible.

Therefore, the CS side is already working as expected, only going to be enhanced. To a successful execution, the implementation needs to be adapted so that it is conformant to the test summary - returning an error when the mandatory header mentioned is not sent in the request.

Feel free to open another ticket if you get any other issue! Happy to help!
