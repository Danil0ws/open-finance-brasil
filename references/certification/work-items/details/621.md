Hi Marcello and Rodrigo! 

Both your tests were reviewed and they are indeed in the same scenario.

The Conformance Suite makes the GET Payments calls using the self-link sent on the PATCH Request. In the tests mentioned, the calls are the endpoints with paymentID duplicated because these links are being sent on the PATCH Response:

- For @mahenfe_itau:
```
"links": {
    "self": "https://hom-secure.opf.api.itau/credicard-itaucard/open-banking/payments/v2/pix/payments/df6c3849-9bc5-495b-861f-53a7aa6c9926/df6c3849-9bc5-495b-861f-53a7aa6c9926"
  }
```

- And for @rodrigoMacknight:
```
"links": {
    "self": "https://resources-mtls.hml.openbanking.picpay.com/open-banking/payments/v2/pix/payments/63d812479709c70052380722/63d812479709c70052380722"
  }
```

Therefore, there is no corrections on the CS side, to a successful execution the link sent on PATCH Response has to be fixed. Feel free to reopen the ticket if you think the issue remains.
