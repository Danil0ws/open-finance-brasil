Hi,

The issue you're encountering occurs during the POST /automatic-payments/v2/pix/recurring-payments call.

While executing the test steps:

Call the POST recurring-payments endpoint with the amount of 300.00, with a different document information - Expects 422 PAGAMENTO_DIVERGENTE_CONSENTIMENTO or 201.

Your server is returning the following error:

```
"errors": [
  {
    "code": "PAGAMENTO_RECUSADO_DETENTORA",
    "title": "Pagamento recusado pela detentora.",
    "detail": "Conta de crédito informada não corresponde a conta registrada para a chave informada."
  }
]
```

However, the correct error should be:

```
"errors": [
  {
    "code": "PAGAMENTO_DIVERGENTE_CONSENTIMENTO",
    "title": "Divergência entre pagamento e consentimento",
    "detail": "creditor nao informado na criacao do consentimento"
  }
]
```
The error "PAGAMENTO_RECUSADO_DETENTORA" indicates an issue with the creditor account, where the account provided does not match the one registered for the Pix key. The test expects "PAGAMENTO_DIVERGENTE_CONSENTIMENTO" because the creditor information was not provided during the consent creation, which is why the payment was rejected.

You can refer to a successful test executed by Raidiam here: https://web.conformance.directory.openbankingbrasil.org.br/log-detail.html?log=PBZV59CVpJGz6lJ&public=true
