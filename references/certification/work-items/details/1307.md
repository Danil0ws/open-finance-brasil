## 📝 Descrição

## 1. What happened and what were you expecting?
When running the test it creates a consent with the data provided in the config:
```json
"creditors": [
  {"name":"<resource.creditorName from config>","cpfCnpj":"<resource.loggedUserIdentification from config>","personType":"PESSOA_NATURAL"}
]
```

and then proceeds to create a recurring-payment sendint the following in the payload:
```json
{
  "document": {
    "identification": "<resource.loggedUserIdentification>",
    "rel": "CPF"
  },
  "proxy":"cliente-a00001@pix.bcb.gov.br",
}
```

It just so happens that this pix-alias key belongs to cpf `999.911.111-40` which is not the logged-user nor the debtor. This fails the validations since the resolved creditor does not have the same cpf as informed in `document`.

Hi Pedro! Thanks for the ticket!

This is happening because the conformance suite is currently enabling two testing strategies, as described at the summary:

If a brazilCpf or brazilCnpj is informed at the config, these fields will be used at both the loggedUser/businessEntity and Creditor. If not, the institution will be required to have an account registered with the CPF 99991111140

To enable better testing, we will adapt the test so that, if a cpf is provided, than this value is used at the proxy. If not, we will set the existing values at the tests.
