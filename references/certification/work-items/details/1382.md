## 📝 Descrição

## 1. What happened and what were you expecting?

The test is expecting the cnpjInitiator, however there is no cnpjInitiator in the spec. 

In the POST recurring-payment there is localInstrument, cnpjInitiator, ibgeTownCode, creditorAccount and proxy.
In the response recurring-payment, besides the request fields, there is debtorAccount, cancellation, authorisationFlow and rejectionReason

Shouldn't the GET recurring-payments have the same field as the response. If it shouldn't, then the test is doing a wrong validation.

Hi, thanks for opening the ticket,

The test module failed when validating for the presence of the element cnpjInitiator in the response for the GET /pix/recurring-payments/{recurringPaymentId}. According to the most recent spec available, cnpjInitiator is indeed a required field in the response for this specific endpoint as can be seen below:

![11.png](/uploads/6a8885a7ca8e7525a29d7f44c0e135cc/11.png)

Therefore conformance suit is operating as expected according to the specification.

https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/289243438/Informa+es+T+cnicas+-+SV+Pagamentos+Autom+ticos+-+v1.0.0-rc.2
