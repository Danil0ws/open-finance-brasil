## 📝 Descrição

Hello, I've found something that might be an issue. I was running both applications locally, on my host machine, to force some scenarios so I could test the behavior. If there is a way I could share something with you to help, please let me know. I don't have a link because everything was run locally.

In `/loans/v1/contracts/{contractId}` endpoint's response, there is an object `interesRates` that contains two properties(among others): `preFixedRate` and `postFixedRate`.  By the docs, both of them should accept null but in the certification tests, `preFixedRate` is not allowed to be null while `postFixedRate` is allowed. Is it right to assume that `preFixedRate` should have the same behavior as `postFixedRate` because both of them are nullables in the documentation?

Hi Gustavo,

Thank your for your ticket. 

When looking at the [Loans API Swagger](https://openbanking-brasil.github.io/areadesenvolvedor/swagger/swagger_loans_apis.yaml) we can indeed see that both prefixed and post fixed rates do accept nullable=true parameter

```
       preFixedRate:
          type: number
          description: |
            Taxa pré fixada aplicada sob o contrato da modalidade crédito.
            p.ex. 0.0045. O preenchimento deve respeitar as 4 casas decimais, mesmo que venham preenchidas com zeros
            (representação de porcentagem p.ex: 0.1500. Este valor representa 15%. O valor 1 representa 100%)
          maxLength: 19
          example: 0.6
          nullable: true
        postFixedRate:
          type: number
          description: |
            Taxa pós fixada aplicada sob o contrato da modalidade crédito.
            p.ex. 0.0045 .O preenchimento deve respeitar as 4 casas decimais, mesmo que venham preenchidas com zeros
            (representação de porcentagem p.ex: 0.1500. Este valor representa 15%. O valor 1 representa 100%)
          maxLength: 19
          example: 0.55
          nullable: true
```

On your test execution https://gitlab.com/obb1/certification/uploads/08f938656e9d65427e7de78de35efcff/logs_preFixedRate_null.zip we can see that the behavior is incorrect for the PreFixed Rate and the null value should not throw and error. We will get one engineer to fix the issue

Thanks!
