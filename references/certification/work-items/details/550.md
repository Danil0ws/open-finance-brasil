## 📝 Descrição

In this test you are sending wrong value "BAD" in "type" field and expecting the code "PARAMETRO_INVALIDO".

In this section of the documentation (https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/18055346/Informa+es+T+cnicas+-+Pagamentos+-+v2.0.0) we have this instruction:
"1.3.2.1 Forma de pagamento: Valida se a forma de pagamento é suportada pela detentora (FORMA_PAGAMENTO_INVALIDA) Obs. No detalhe do erro, a variável “modalidade” deve ser comunicada pela detentora da forma mais clara possível - ex. modalidade de pagamento não suportada (localInstrument - QRES) ou tipo de arranjo pagamento não suportado (type – ex. Pix / TED – previsto para inclusão futura);"

By reading the documentation, our understanding is: attribute type and localInstrument should return HTTP 422 - FORMA_PAGAMENTO_INVALIDA when are misspelled or wrong.

Hi All! Thanks for the replies!

Indeed, it's known that PIX is the only currently accepted payment type, and was used only as an example here and at the swagger "(type – ex. Pix / TED – previsto para inclusão futura)".

Anyways, as stated in the swagger, the message FORMA_PAGAMENTO_INVALIDA is used to validate if "a forma de pagamento é suportada pela detentora". It means that the institution should validate if they support the payment being requested, and return this message in a negative scenario. Currently, this message is being used for institutions to indicate that they don't support payments with QR code, for example.

The message PARAMETRO_INVALIDO, on the other hand, is used to validate if "parâmetros informados obedecem a formatação especificada ", which is the case here, since "BAD" is not a payment type, and PIX is the only one supported. Besides that, 65 institutions have already passed the test, indicating that there is more people with the same understanding proposed by the module.

I totally understand that a unique message for bad format and not supported payments would simplify future implementation, but it would also bring less detail to an eventual error, making harder for the ecosystem to understand and fix it.

Does that make sense for you?
