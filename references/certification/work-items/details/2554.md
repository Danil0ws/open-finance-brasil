## 📝 Descrição

Subject: Technical Request for Generation of Alphanumeric CNPJ Test Data Linked to CPF for Mock Bank and Consent Functional Engine Dear Team, I am submitting this technical request to provision synthetic test data sets containing alphanumeric CNPJ identifiers linked to valid CPF records, to be consumed by the Mock Bank platform and the Consent Functional Engine (Motor Funcional de Consentimento). This data mass is required to support end‑to‑end functional validation, integration flows, and regression scenarios involving entity identification, customer–business relationship mapping, and consent authorization rules. The use of non‑standard alphanumeric CNPJ formats is critical for validating edge‑case handling, parser robustness, and business rule enforcement within both systems.

Technical Requirements

1. Data Composition

CNPJ values must include alphanumeric characters in predetermined positions, following the internal test pattern specification. Each CNPJ must be programmatically bound to a unique and valid CPF, ensuring referential consistency across all test layers. The CPF–CNPJ linkage must comply with the current identification mapping models used by both platforms.

2. Environment Integration

The generated test data must be deployed and accessible within the Mock Bank environment (all relevant layers: API, persistence, and service virtualization). Data must be fully compatible with ingestion, validation, and consent‑evaluation pipelines of the Consent Functional Engine.

3. Functional Expectations

Support validation of consent issuance, revocation, lookup, and cross‑entity relationship queries. Ensure compatibility with existing contract schemas, including identification blocks, payload normalization rules, and error‑handling structures. Data must allow simulation of exceptional flows (invalid formats, malformed identifiers, mixed alphanumeric structures, etc.) as required for QA coverage.

4. Documentation and Delivery Artifacts

Structured documentation describing:

Data generation logic and patterns Constraints and business rules applied CPF–CNPJ linkage schema Environment locations, endpoints, and accessibility details

Delivery of a complete data set via the designated deployment pipeline or secure repository.

Should you require additional specifications such as payload samples, validation schemas, or constraint definitions, I remain available to provide them. Thank you for your support. Kind regards, Diego Alves Gouveia Pl. Quality Analyst

Hello @DiegoCieloOPF. Thanks for sharing this request.

As described in the issue #2390:

After analysis by the DTO team, we were informed that, according to the regulator’s official roadmap, the certification and testing of the new CNPJ standard (including alphanumeric formats) are planned for **July 2026**.

* The alphanumeric CNPJ itself is a government initiative, with a start currently indicated for July 2026 ([reference](https://www.gov.br/receitafederal/pt-br/acesso-a-informacao/acoes-e-programas/programas-e-atividades/cnpj-alfanumerico)). From that month onward, alphanumeric CNPJs will begin to be issued.
* The related conformance tests are scheduled (per the Central Bank timeline) to run from 01/07 to 31/07.
* Therefore, this type of Mock Bank dataset will only be available closer to that testing window, once the corresponding API updates are implemented.

Please feel free to reopen this issue if needed. You may also raise any new questions regarding this matter via the Service Desk for the OPF Working Groups.
