## 📝 Descrição

Currently, for all Phase 3 APIs, it is required that the payload is signed as a JWT. While the [JWT RFC](https://datatracker.ietf.org/doc/html/rfc7519) provides general guidelines, specific rules for the **Payments v4 API** are detailed in the documentation:\
[How to Sign the Payload - v4.0.0 - Payments API](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/347078914/Como+Assinar+o+Payload+-+v4.0.0+-+SV+Pagamentos).

However, the same level of specificity is missing for the **Enrollments API** and the **Automatic Payments API**, even though both also require JWT-signed payloads for requests and responses.

This raises the following questions for the working group:

1. Should the **same signature rules** specified for Payments v4 be applied to the **Automatic Payments v2 API** and **Enrollments v2 API**?
2. If yes, is this clearly stated in any documentation?

**Observations**\
During our tests, we suspect that some institutions might not be validating JWT signatures correctly for these APIs.
