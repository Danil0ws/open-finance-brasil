## 📝 Descrição



#### Current Behavior:
---
When performing recurring payments with  SEMANAL, MENSAL, TRIMESTRAL, SEMESTRAL and ANUAL periodicities, the paymentReference field is being filled incorrectly for the first cycle of each recurrence.

For example, with recurringPaymentDate and referenceStartDate set to 2025-10-06, the following paymentReference values are being generated:

Weekly: R/2025-10-13/P1W
Monthly: R/2025-11-06/P1M
Quarterly: R/2026-01-06/P3M
Semiannual: R/2025-11-06/P1M
Annual: R/2026-10-06/P1Y
These values correspond to the start of the next cycle, not the current one, which is incorrect according to the business rules.


#### Expected Behavior:
---
The paymentReference field should refer to the start date of the current cycle, matching the recurrence configuration. For the first payment with recurringPaymentDate and referenceStartDate as 2025-10-06, the expected values are:

Weekly: R/2025-10-06/P1W
Monthly: R/2025-10-06/P1M
Quarterly: R/2025-10-06/P3M
Semiannual: R/2025-10-06/P6M
Annual: R/2025-10-06/P1Y
This ensures the system complies with the established rules for recurring payments and supports accurate metric collection for the ecosystem. Any deviation should result in an HTTP 422 error with the code DETALHE_PAGAMENTO_INVALIDO.
