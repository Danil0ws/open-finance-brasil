#### Current Behavior:
---
The automated test `automatic-payments_api_automatic-pix-consent-edition-account-holder_test-module_v2` is failing due to an unexpected response in the following step:

- **Call the GET `recurring-consents` endpoint**
  - The test expected a `200` response code but is receiving a `401 Unauthorized` instead.
  - The root cause of this issue is that an expired access token is being used at this stage of the test. Although a new token was previously generated, the test suite is still passing the old, expired token.

## Evidence from the JSON logs

In line **2859** of the attached file, a `POST` request was made to the token endpoint:

```
POST https://mtls-openfinance.homolog.asaas.com/oidc/token
```

With the following parameters:

```
grant_type=client_credentials
scope=recurring-payments
client_assertion=<JWT_TOKEN>
client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer
```

As a response, the access token **`uz0BGIModK9YD3uj0_BsazVmuJae2Vj1_LWKY3TQ-Kc`** was issued.

Later, in line **13429**, another `POST` request was made to the token endpoint:

```
POST https://mtls-openfinance.homolog.asaas.com/oidc/token
```

With the parameters:

```
grant_type=authorization_code
code=<AUTHORIZATION_CODE>
redirect_uri=https://web.conformance.directory.openbankingbrasil.org.br/test/a/asaas/callback
client_assertion=<JWT_TOKEN>
client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer
code_verifier=<CODE_VERIFIER>
```

In **line 14427**, a subsequent `GET` request was made using an **expired access token**, which resulted in a `401 Unauthorized` response. At no point was a request made to refresh the token before attempting this request.


#### Expected Behavior:
---
The test should refresh the access token according to the expiration details we provided.
