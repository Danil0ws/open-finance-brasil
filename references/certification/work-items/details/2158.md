## 📝 Descrição

**Description:**

In the Credit Portability API documentation ([v1.0.0-beta.1](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/905740914/Informa+es+T+cnicas+-+PC+Portabilidade+de+Cr+dito+-+CPC+-+v1.0.0-beta.1)), within the `/account-data` endpoint, the `strCode` object is defined with several fields that are conditionally required.

However, the schema currently marks `accountNumber` as **required**, despite each having a restriction that explicitly states:

> **"\[RESTRIÇÃO\] campo de preenchimento obrigatório quando campo hasFinancialAgent for igual a true"**

### Current Definition:

```
strCode: {
  ispb*: number
  name: string          // [RESTRIÇÃO]
  companyCnpj: string   // [RESTRIÇÃO]
  branchCode*: number
  hasfinancialAgent*: boolean
  accountNumber*: number // [RESTRIÇÃO]
}
```

### Problem:

* The field `accountNumber` is marked with an asterisk (`*`) indicating it's **always required**, yet its documented rule clearly states it's only required **when `hasfinancialAgent` is `true`**.

This contradiction could lead to implementation errors, as API consumers and validators may wrongly assume the field is mandatory in all scenarios.

### Suggested Fix:

* Remove the required marker (`*`) from `accountNumber` in the OpenAPI schema.
* Ensure their requirement is expressed only through conditional logic 

That way, the schema aligns with the documented business rules, ensuring clarity and correct implementation.
