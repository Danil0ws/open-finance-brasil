## 1\. What happened and what were you expecting?

The following steps from consents_api_negative_test-module_v2 have been updated to behave as expected for consents v3 specification:

Creates consent api V2 request for DateTime greater than 1 year from now

* Expects failure with a 422 Error
* Creates consent api V2 request for DateTime in the past
* Expects failure with a 422 Error

As it is a v2 test module, it should validate considering the consents v2 specification, therefore it should be:

* Creates consent api V2 request for DateTime greater than 1 year from now
* Expects failure with a 400 Error
* Creates consent api V2 request for DateTime in the past
* Expects failure with a 400 Error
