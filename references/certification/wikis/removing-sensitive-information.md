### Disclaimer

The initial structure, together with the Conformance Suite team, is currently working on developing the Conformance Suite **PRODUCTION** mode, which should run similarly to the existing CS, but with a minimal amount of logging and storage of sensible data. While this development is ongoing, please note that the  conformance suite generates a large amount of detailed logging including all functional payloads and crypto / key material so appropriate care should be taken with log management. 

## Local DataBase instance

When building the Conformance Suite image locally an instance of a MongoDB will also be created. This instance will register all of the information that is obtained during the test execution, including all of the configurations provided, which includes the public and private keys, and the data obtained when communicating to the Server. 

As sensitive data will be stored on this mongo instance it is important to check your companies IT security and data storage policies regarding the maintenance of this data.

## Submission logs

The logs generated by the conformance suite on a local execution are similar to the ones generated on the hosted version and as such will contain all of the sensitive data regarding both the credentials used and the sensible user data received. This means that the user must be aware that when sharing the logs all of that sensitive information might be exposed.

The objective of this page is to guide the user into removing this data to avoid exposing unwanted information, while still providing enough information of what happened during the conformance test.

Note that this session will only cover the cleaning of one test module and not the whole test plan. We strongly recommend not doing this on the whole Test Plan as, given the amount of information that must be removed on only one test module, the risk of leaving something behind increases substantially with the number of test modules executed.

### Selecting the HTML file from the ZIP

![image](uploads/49a356568dc5bf678607983203719f78/image.png)

Inside the test log that you want to submit, press the "Download Logs" button. This will download a ZIP file to your computer where you'll have 4 files:

- An html and html.sig
- A json and json.sig

For this example, we'll be using only the HTML file as it contains all the steps that we need to check for errors.

You can open and edit the HTML file with any text editor. In this guide, we'll be using VS Code to remove any sensitive or personal data information.

After opening the file, the structure follows a normal HTML template file and we'll be searching for specific information to delete:

### Removing Private Keys

As the conformance suite will log the credentials used to communicate with the A.S. the first thing we should do is remove all the private keys from the obtained HTML file. 

Down below is an image of the file with some of the information you should remove:

![image](uploads/c0106a7dce7907191490f15f03afd1ea/image.png)

Keys can be found, for example, in the following objects: jwks keys, jwk_string, mtls, mlts2, request_mutual_tls, server_jwks, public_client_jwks, client_jwks

E.g: jwks keys in the html:

![image](uploads/eb2efd3a02b51d132b5d04a7b2f7a579/image.png)

The private keys are logged a few times on the HTML so make sure they are completely removed before submitting the log failure evidence.

### Removing Refresh Tokens

For the next step, we should also make sure that the refresh tokens are also removed, so no Consent can be recovered in case the credentials are leaked. Those values should normally appear under "refresh_token".

![image](uploads/eb4361844528b2534caf6745e0fb4f4b/image.png)

### Removing Sensitive Information - Response and Request Bodies

Most of the response and request bodies inside the HTML file contain information that shouldn't be shared, so we're going to remove those.

In this example, we removed body information, request_body, response_body, request_mutual_tls, consent_endpoint_request, consent_endpoint_response. Any field that might contain relevant data.
