# [Open Finance] Informa #826

Atualização do Guia de Experiência do Usuário – versão 18.00.00 |

 Informamos que o time de UX disponibilizou, no dia 19/12/2025, uma nova versão do Guia de Experiência do Usuário (v18.00.00). Esta atualização de versão inclui:   - Revisão do capítulo "Fundamentos do Open Finance", que passou a se chamar “Visão Geral”; - Ajuste de texto e reorganização das tabelas em "Gestão de Portabilidade de Crédito"; - Alteração de requisito na Etapa 1 da "Jornada Básica de Iniciação de Pagamentos"; - Inclusão de requisitos na Etapa 5 da "Jornada de Vinculação de Conta (JSR)"; - Alterações das etapas 1, 2 e 3 da "Jornada de Pagamentos sem Redirecionamento (JSR)"; - Alteração do subcapítulo "Comunicação e Notificações da Jornada de Pagamentos sem Redirecionamento (JSR)"; - Revisão dos "Anexos" do Guia.   O detalhamento dos ajustes presentes nesta atualização do Guia encontra-se na página **“*Changelog* – Guia de Experiência do Usuário”**.     **Importante:** Esta versão do Guia de UX poderá ser monitorada a partir de 90 dias da sua publicação (19/12/2025) para produtos já implementados. Novos produtos, por sua vez, poderão ser monitorados a partir de 90 dias após o início de seu piloto, conforme o calendário vigente. |

 Disponibilização da versão beta.1 do motor de conformidade da API Pagamentos |

 Conforme compartilhado no Informa #812 (“*Divulgação do cronograma de certificação e implementação da v5.0.0 da API Pagamentos*”, divulgado em 11/11/2025), **a versão beta.1 do motor de conformidade para a API Pagamentos v5.0.0 foi disponibilizada em 19/12/2025.**Esta versão será utilizada para o**marco A em 29/01/2026.**    **Sucesso no marco A**  Para o marco A, as instituições devem obter sucesso nos seguintes módulos de teste:  1. payments\_api\_consents\_negative\_test-module\_v5; 2. payments\_api\_recurring-payments-custom-core\_test-module\_v5; 3. payments\_api\_recurring-payments-patch\_timezone\_test-module\_v5; 4. payments\_api\_recurring\_payments\_weekly\_test-module\_v5; 5. payments\_api\_unmatching-loggedUser\_test-module\_v5; 6. payments\_api\_scheduled-key-divergence\_test-module\_v5; 7. payments\_api\_consent-bulk-cancel\_negative\_timezone\_test-module\_v5; 8. payments\_api\_apes-good-happy-path-with-txid\_test-module\_v5; 9. payments\_api\_apes-good-happy-path-without-txid\_test-module\_v5; 10. payments\_api\_apes-code-unhappy-path-required\_test-module\_v5; 11. payments\_api\_apes-mismatched-consent-payment\_test-module\_v5.  Reforçamos que as instituições que não obtiverem sucesso no marco serão notificadas via *tickets* do Service Desk.    Mais detalhes sobre os testes podem ser consultados na página de plano de testes. |

 Alteração na data de *go live* da versão 3.3.1 (*patch*) da API Consentimento |

 Informamos que, conforme divulgado no Informa #824 (“*Lançamento da versão v3.3.1 (patch) da API Consentimento*”, enviado em 16/12/2025), a data de *go live* da API Consentimento v3.3.1 estava programada para 18/01/2026. Entretanto, por se tratar de um domingo, a data de *go live* foi ajustada para 19/01/2026 (segunda-feira).    As demais informações presentes no Informa #824 permanecem inalteradas. |

 Adição de nova seção à página de orientações das API de Investimentos |

 Informamos que à área do desenvolvedor do Portal Open Finance foi atualizada com a **adição de uma nova seção à página “Orientações - [DC] Investimentos”**, conforme detalhado abaixo:   - “*Orientações de preenchimento para dados das APIs de Investimentos*   - *Os campos /data/remuneration/preFixedRate e /data/remuneration/postFixedIndexerPercentage, do endpoint GET investments/{investmentId}, passam a ser de envio obrigatório quando se tratar de produto com remuneração híbrida, a partir da versão 1.1.0. Não é necessário o reprocessamento de históricos de contratos cuja posição seja igual a zero para atender à nova regra.”*   Reforçamos que os ajustes dos dados enviados nos campos **/data/remuneration/preFixedRate**e **/data/remuneration/postFixedIndexerPercentage**, do *endpoint* **GET investments/{investmentId}**,devem ser aplicados somente aos contratos de clientes que ainda possuam posição diferente de zero, a partir do *go live* da versão 1.1.0 da API.
