# [Open Finance] Informa #890

FVP Manual — Atualização dos Ciclos de Testes de Aberta e Restrita |

 Conforme comunicado no Informa nº 572 (“Novo modelo de execução da FVP (3.0)”, enviado em 30/04/2024), as instituições para as quais o fornecedor responsável pela execução dos testes restritos da FVP Manual não possui conta aberta devem executar os testes abertos da FVP Manual para todos os seus servidores PF e PJ, quando aplicável.    A relação de marcas para as quais o fornecedor possui conta aberta pode ser consultada no dashboard da FVP. De acordo com o Informa nº 691 (“Novo processo de acesso à plataforma de visualização de dados do Open Finance”, enviado em 27/01/2025), a gestão de acesso à Plataforma de Visualização de Dados do Open Finance Brasil — que inclui os dashboards da Estrutura — deve ser realizada pelo administrador da instituição no Diretório de Participantes.    **Novo Cronograma dos Ciclos**  O cronograma completo dos ciclos da FVP passará a ocorrer mensalmente a partir de Junho/2026. Seguindo o novo formato, cada ciclo terá início no primeiro dia do mês e será encerrado no respectivo último dia.  O planejamento até dezembro de 2026 para a FVP Manual **Aberta** e **Restrita** encontra-se detalhado abaixo.     **Documentação e Painéis de Acompanhamento**  Os planos de testes detalhado para a execução da FVP Manual Aberta pode ser consultado na seção Plano de Testes do Guia de Operação da FVP, disponível na Área do Desenvolvedor. |

 Disponibilização da versão estável do motor de conformidade e orientações gerais para a certificação da API Pagamentos v5.0.0 |

 Conforme divulgado no Informa #812, comunicamos que o processo de certificação da API Pagamentos v5.0.0 ocorrerá entre 12/05/2026 até 20/05/2026, com atenção especial para as seguintes datas:     De 12/05/2026 a 17/05/2026 - Disponibilização do motor v5.0.0 e período de reexecuções de testes    A versão estável do motor está incluindo as seguintes breaking changes:      **1 - Plano: Functional Tests for Payments API - Based on Swagger version: v5.0.0**  - **Modulo**: payments\_api\_idempotency\_test-module\_v5 - **Descrição da alteração:** Alteração no fluxo do teste para que o cancelamento (PATCH) seja executado somente após a confirmação de que o pagamento atingiu um status válido (SCHD ou PDNG)  **2 - Plano: Functional Tests for Payments Withdraw QRES API-Based on Swagger version: v5.0.0**  - **Módulo**: Todos os módulos desse plano - **Descrição da alteração**: Alteração na configuração do plano para que o usuário forneça um QRCode estático  **3 - Plano: Functional QRDN Tests for Payments API - Based on Swagger version: v5.0.0**  - **Módulo**: payments\_api\_qrdn-code-enforcement\_test-module\_v5 - **Descrição da alteração**: Validação do IBGETOWNCODE que passou a ser obrigatório    **4 - Plano: Functional APDN Tests for Payments API - Based on Swagger version: v5.0.0**  - **Módulo**: payments\_api\_apdn-good-happy-path\_test-module\_v5 - **Descrição da alteração**: O campo purpose é sempre obrigatório quando payment.type = PIX, sem exceção. A correção foi incluir esse campo no payload com um valor válido para o cenário de pagamento imediato.  Adicionalmente para a versão estável foi adicionado novo módulo:    **•    Plano: Functional Tests for Payments Withdraw QRES API-Based on Swagger version: v5.0.0**  - **Módulo**: payments\_api\_pix\_consents\_multi\_authorization\_permission\_test-module\_v5 - **Descrição da alteração**: valida rejeição de consentimento por Permissão Insuficiente – Múltiplas Alçadas  **De 12/05/2026 a 18/05/2026:** Submissão dos pedidos de certificação   Durante o período de submissão da certificação, as instituições devem submeter um ticket único no Service Desk, contemplando evidências de sucesso de todos os planos de testes aplicáveis à API de Pagamentos v5.0.0 através da categoria: requisições>enviar pedido de certificação.   Nesta categoria haverá duas opções na lista suspensa de API certificada:  - **Com JSR**  - **Sem JSR**       Instituições que não ofertarem a jornada sem redirecionamento estão dispensadas de incluir os planos QRDN e APDN, mas deverão submeter os demais 5 planos de teste:    •    Functional Tests for DCR DCM - PAGTO Role - Webhook V5 - Based on Swagger version: 1.3.0  •    Functional APES Tests for Payments API - Based on Swagger version: v5.0.0;   •    Functional Tests for Payments API - Based on Swagger version: v5.0.0;   •    Functional Timezone Tests for Payments API - Based on Swagger version: v5.0.0;   •    Functional Tests for Payments Withdraw QRES API - Based on Swagger version: v5.0.0      A certificação será processada apenas para instituições que submeterem planos de teste criados a partir da data de sua última alteração (Breaking change) a relação completa de planos e respectivas datas estão na tabela abaixo:         \*Observação: A data de criação de cada plano de teste será validada no pedido de certificação. Planos de teste criados em datas anteriores às descritas acima não serão aceitos.  O motor será disponibilizado em 12/05/2026. Solicitamos que os testes sejam realizados em D+1.     **20/05/2026:** Publicação no diretório      As instituições que obtiveram o sucesso no processo de certificação devem realizar a publicação da nova versão no diretório.    **21/05/2026 a 20/08/2026** – Período de convivência da V4 com a V5 de Pagamentos    O período de convivência entre as versões V4.0.1 e V5.0.0 da API de Pagamentos ocorrerá de 21/05/2026 a 20/08/2026. Durante esse período, ambas as versões devem permanecer disponíveis simultaneamente, permitindo que fluxos de pagamento sejam realizadas em qualquer uma das versões, em conformidade com os princípios de retrocompatibilidade.    **10/06/26 a 10/08/2026** - Marcos intermediários para ITPs    Durante o período de convivência, as instituições iniciadoras de pagamento (ITPs) que utilizam a API de Pagamentos na versão V4.0.1 deverão migrar suas chamadas para as novas versões, conforme os marcos percentuais definidos no cronograma. O objetivo desses marcos é evitar migrações tardias, cenário identificado em evoluções anteriores dos produtos do ecossistema e que resultou em impactos operacionais.    **10/06/2026:** Marco de 10%  **10/07/2026:** Marco de 50%  **10/08/2026:** Marco de 100% |
