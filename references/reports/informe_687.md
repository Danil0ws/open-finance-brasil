# [Open Finance] Informa #687

Alterações e disponibilização do motor para a v2.1.0 da API Vínculo de Dispositivo       **O motor de conformidade da versão 2.1.0 da API Vínculo de Dispositivo foi disponibilizado em 17/01/2025.**Conforme comunicado no Informa #677 (“Lançamento da versão 2.1.0 (*minor*) da API Vínculo de dispositivo”, enviado em 20/12/2024), **até 30/01/2025 as instituições deverão reexecutar com sucesso 2 módulos de teste que tiveram alteração relevante:**   - enrollments\_api\_webhook-revoked\_test-module\_v2   - Na *response* do POST fido-registration-options o *endpoint* será validado se o valor de software\_client\_name contido na SSA corresponde ao campo data.rp.name - enrollments\_api\_excessive-transactionLimit\_test-module\_v2   - No POST consent authorise, o campo userHandle será enviado vazio |

 Orientação para preenchimento das planilhas de reporte - Fase 3       Foi aprovada, em 12/12/2024, pelo Conselho de Administração a adição de duas colunas “Produto” e “Authorization Flow” na aba “Funil API Pagam” para os reportes da planilha de Fase 3, enviada ao time de Painel de Indicadores semanalmente ([indicadores@openfinancebrasil.org.br](mailto:indicadores@openfinancebrasil.org.br "mailto:indicadores@openfinancebrasil.org.br")).  Após recebimento de dúvidas de participantes sobre a metodologia de cálculo para preenchimento, esclarecemos que, na impossibilidade da detecção do valor da coluna “Authorization flow”, o valor “HYBRID\_FLOW” deve ser assumido. Essa situação só ocorre se apenas a API POST/consents for chamada e nenhuma outra. Ou seja, caso a iniciadora realize a chamada POST/consents e, em seguida, realize a chamada POST/fido-sign-options, este consentId deverá ser considerado como sendo do tipo “FIDO\_FLOW”.  Adicionalmente, esclarecemos que, para o preenchimento da coluna “Produto”, deverá ser levada em consideração a seguinte lógica para cada uma das opções:   - **"IMMEDIATE"**: quando preenche o campo “date” e não preenche o campo “schedule”; - **"SCHEDULED"**: campo “schedule” preenchido com o objeto do tipo “ScheduleSingle” ; - **"RECURRENT"**: preenchido campo “schedule” com outros objetos diferente do tipo “ScheduleSingle”. |
