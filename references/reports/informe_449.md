# [Open Finance] Informa #449

Nova instituição apta a iniciar serviço de iniciação de pagamentos Pix – Iniciador A Estrutura do Open Finance Brasil informa que a seguinte instituição cumpriu todas as etapas do processo de onboarding de iniciadoras com sucesso e, portanto, está apta a iniciar o serviço de iniciação de transações de pagamento Pix no contexto do Open Finance Brasil: Iniciador.     Com essa atualização, há atualmente 24 instituições que estão aptas a iniciar o serviço de iniciação de transação de pagamento Pix:   - Banco Bradesco - Banco BTG Pactual - Banco BV - Banco do Brasil - Banco Mercantil do Brasil - Banco Santander - Banco XP - Celcoin - Crystal BMC - Ebanx IP - Efí - Hub Pagamentos - Iniciador - Inter - Itaú Unibanco - Mercado Pago - Nubank - Parati - PicPay - Quanto Network - Sicoob - SICREDI - U4C - Unicred   Novas instituições serão incluídas na listagem oportunamente. |

 Publicação de versões da API de Iniciação de Pagamento específicas para o piloto da Jornada sem redirecionamento Informamos que foram publicadas as versões 2.1.0 e 3.1.0 da API de Pagamentos. Essas versões contém um *scope* de segurança específico para as instituições que desejarem implementar a jornada sem redirecionamento.   - Hoje (06/09/2023), as versões vigentes da API de Pagamentos são a 2.0.0 para instituições que não participam do piloto da jornada sem redirecionamento e 2.1.0 para as instituições que participam do piloto da jornada sem redirecionamento; - A versão 3.0.0 deverá ser implementada de acordo com cronograma apresentado no Informa #417 (“Cronograma dos próximos versionamentos *majors* da API de Iniciação de Pagamentos”, publicado em 04/07/2023); - As versões 2.1.0 e 3.1.0 deverão ser implementadas apenas pelos participantes do piloto da jornada sem redirecionamento. Posteriormente, será publicado um informe sobre a transição de versão para participantes que não estão no piloto.   Abaixo, apresentamos os cenários de quais versões deverão ser consumidas para as diferentes possibilidades de combinação entre iniciadoras e detentoras, participantes ou não do piloto da jornada sem redirecionamento (JSR): |

 Os seguintes cenários poderão ocorrer e a versão consumida deverá ser seguida conforme orientações abaixo:   - Iniciadora que está no piloto com detentora que está no piloto na v2.1.0 - iniciadora consome a v2.1.0 da API de Pagamentos utilizando o fluxo de JSR; - Iniciadora que está no piloto com detentora que está no piloto na v3.1.0 – iniciadora consome a v3.1.0 da API de Pagamentos utilizando o fluxo de JSR; - Iniciadora que está no piloto com a detentora que não está no piloto – iniciadora consome a v2.0.0 da API de Pagamentos utilizando o fluxo FAPI – Hybrid Flow ou CIBA Flow; - Iniciadora que não está no piloto com a detentora que não está no piloto – iniciadora consome a v2.0.0 da API de Pagamentos utilizando o fluxo FAPI– Hybrid Flow ou CIBA Flow; - Iniciadora que não está no piloto com a detentora que está no piloto na v2.1.0 – A iniciadora envia requisições no formato v2.0.0. A detentora deverá ser capaz de tratar os dados, independentemente de estar na v2.0.0 ou v2.1.0, utilizando fluxo FAPI Hybrid Flow ou CIBA Flow; - Não há possibilidade de uma iniciadora que não está no piloto consumir a versão 3.1.0 da API de Pagamentos de uma detentora que está no piloto. Essa impossibilidade é devido ao cronograma de entrega e certificação das versões da API de Iniciação de Pagamentos.   Ressaltamos que os participantes do piloto não deverão registrar as URLs das versões 2.1.0 e 3.1.0 no Diretório de participantes. As instituições que participam do piloto deverão trocar as URLs de serviços das versões 2.1.0 e 3.1.0 da API de Pagamentos entre si via canal do Slack (jsr-piloto).     Além disso, informamos que os motores funcionais das versões 2.1.0 e 3.1.0 da API de Pagamentos serão entregues em 15/10/2023. |
