# [Open Finance] Informa #278

Atualização no processo de certificação – Suspensão temporária da publicação de *authorisation servers*  O repositório do GitHub onde são publicadas as certificações está passando por mudanças, o que impedirá a validação da certificação de novas APIs entre **30/11/2022 e 05/12/2022. Dessa forma, a publicação ou alteração de a*uthorisation servers* em produção estará suspensa nesse período**.     Caso alguma instituição esteja com implementação prevista para essas datas, favor abrir um ticket na categoria: **Solicitação de informação > Diretório**, com o título **“APOIO PARA PUBLICAÇÃO DE API NO DIRETÓRIO”,** para que o fornecedor possa apoiar na publicação assistida dos endpoints**.**     Além disso, o modelo dos termos e condições para submissão de pedidos de certificação também foi migrado para a página:   <https://github.com/OpenBanking-Brasil/specs-directory/tree/main/conformance/documents/TnC> |

 Prazo para adequação ao comportamento de restrição de registros por aplicação  Comunicamos ao ecossistema Open Finance Brasil que, de acordo com definição do Conselho Deliberativo, **deverá ser implementado até 30/11/2022 pelos participantes do Open Finance o comportamento descrito no Informa 199** (“Comportamento esperado na tentativa de novo registro DCR com mesmo Software Statement e no mesmo servidor”) – enviado em 03/08/2022:   - **Participantes transmissores de dados e/ou detentores de conta não devem permitir a realização de novos procedimentos DCR (Dynamic Client Registration) para um Software Statement já cadastrado anteriormente** em seu Authorisation Server. Em caso de tentativa de novo registro, deve-se utilizar o procedimento de Error Response definido no item 3.2.2 da RFC7591.   Reiteramos que foi realizada atualização do item 9.3.1 Registro de cliente – POST /register da documentação Open Finance Brasil Financial-grade API Dynamic Client para formalizar este entendimento. |
