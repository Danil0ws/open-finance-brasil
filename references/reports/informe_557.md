# [Open Finance] Informa #557

DCR/DCM - Orientações importantes sobre riscos do uso do verbo DELETE para registro de clients Oauth Comunicamos ao ecossistema que, de acordo com as RFCs e documentação de DCR/DCM, os clientes devem ser tratados de forma imutável e a sua manutenção deve ser feita exclusivamente por meio do verbo PUT através das APIs de DCM.    O verbo DELETE deve ser utilizado exclusivamente quando um *software statement* for inativado, visto que, com a inativação do cliente, todos os consentimentos vinculados a ele se tornam inacessíveis - Não é possível acessar um consentimento com outro cliente, mesmo que seja criado um novo cliente posteriormente.     **A exclusão de um cliente através da utilização do verbo DELETE do DCM acarretará perda de acesso aos consentimentos (*tokens*) criados através deste cliente**, ou seja, todos os pagamentos de longo prazo, incluindo agendamento, pagamentos automáticos e consentimentos de compartilhamento de dados serão perdidos e não poderão ser restaurados.     É crucial a observância das devidas documentações, especialmente, as documentações de DCR e RFC 7592, disponíveis nos links a seguir (lista não exaustiva). |

 Alteração do SLA dos *endpoints* classificados com frequência média-alta Comunicamos que o valor do SLA dos *endpoints* classificados com frequência média-alta foi alterado de 2000ms para 1500ms, conforme Instrução Normativa BCB nº 456.  As páginas “Referência” e “Desempenho” presente na seção “Requisitos não Funcionais” da área do desenvolvedor do Portal do Open Finance Brasil foram atualizadas com os novos valores.     Além disso, informamos que, atualmente, as APIs com *endpoints* classificados com frequência média-alta são:   - [DC] API Investimentos - Renda Fixa Bancária; - [DC] API Investimentos - Renda Fixa Crédito; - [DC] API Investimentos - Títulos do Tesouro Direto; - [DC] API Investimentos - Fundos de Investimento. |

 Lançamento da versão beta (v2.0.0-beta.1) da API Seguros (Fase 4A) Informamos que a Área do Desenvolvedor do Portal Open Finance Brasil foi atualizada no dia 28/03/2024 com a documentação da nova versão 2.0.0-beta.1 da API de Seguros.    É imprescindível que as instituições comecem a desenvolver esta API a partir do lançamento desta versão (beta) para não prejudicar o período de certificação e *go live*, em 31/05/2024, conforme o cronograma divulgado no Informa #538 (“Lançamento da versão beta (v2.0.0-beta.1) das APIs de Títulos de Capitalização e Previdência (Fase 4A)”, enviado em 04/03/2024).    Durante o desenvolvimento nas instituições, poderão ser reportadas à Estrutura melhorias e necessidades de correções desta API. A partir de 01/04/2024, será disponibilizado um período de consulta ao ecossistema, que se encerra em 19/04/2024. Sugestões encaminhadas após o período de consulta não serão consideradas para este versionamento.   - As sugestões devem ser encaminhadas por meio da abertura de ticket no Service Desk, seguindo a opção: Solicitações de Melhorias > APIs. |
