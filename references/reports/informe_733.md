# [Open Finance] Informa #733

Qualidade de Dados - Melhorias nos Tickets do MQD a partir de 04/05/2025 Informamos que, a partir do próximo domingo, dia 04/05/2025, os tickets abertos diariamente para as instituições participantes enviados pela automação do MQD trarão algumas melhorias.     Em relação aos tickets operacionais (D+1), que são analisados diariamente, será aberto um único ticket que conterá em sua descrição todas as APIs que não estão sendo reportadas. Isso difere do modelo atual, onde existe um ticket para cada API, o que reduzirá significativamente o total de tickets a serem analisados caso apresente algum tipo de problema de reporte.     Quanto aos tickets de qualidade, analisados semanalmente, estes serão criados indicando apenas os novos problemas encontrados na última análise, após comparação com os problemas identificados na análise imediatamente anterior. Desta forma, será apresentado à instituição apenas os tickets com novos problemas, evitando retrabalho na análise.     Ressaltamos que as categorias utilizadas na abertura dos tickets seguem inalteradas.     Informações adicionais sobre o envio dos tickets podem ser através do Service Desk > Motor de Qualidade de Dados > Informações. |

 API Pagamentos automáticos - Orientação ao cadastro de FamilyTypes    Conforme comunicado no Informa #726 (*“Transferências Inteligentes – Cronograma de implementação da v2.1.0 (minor) da API Pagamentos automáticos”*, enviado em 16/04/2025), o *go live* da v2.1.0 (*minor*) da API Pagamentos automáticos ocorrerá em 05/05/2025.      **Atualização do cadastro de *FamilyTypes***     A partir de 05/05/2025, o cadastro de *FamilyTypes* dessa API ocorrerá através da segmentação por produto e as detentoras devem cadastrar todas as *FamilyTypes* abaixo, de acordo com o produto que ofertarem:   - **Transferências Inteligentes**    - payments-recurring-consents   - payments-pix-recurring-payments - **Pix Automático**    - payments-recurring-consents-automatic   - payments-pix-recurring-payments-automatic  As novas classes de *FamilyTypes* adicionadas no Diretório tem como objetivo diferenciar os fluxos de serviço ofertados pelas instituições detentoras de conta entre os produtos Transferências Inteligentes e Pix Automático. A partir dessas informações, instituições iniciadoras conseguem estruturar uma jornada personalizada, identificando se o fluxo se aplica a pessoa física (PF), pessoa jurídica (PJ) ou a ambas.      **Identificação de jornadas PF/PJ**  - **Instituições iniciadoras** deverão utilizar o *FamilyType* utilizado no cadastro do diretório para identificar se a marca oferta o produto Transferências inteligentes ou Pix Automático. - **Instituições detentoras** que não ofertem o produto Pix Automático para o público PJ e já tenham realizado o processo de *opt-out* junto ao arranjo Pix, podem rejeitar a chamada utilizando o status code 422 e *rejectionreason* FUNCIONALIDADE\_NÃO\_HABILITADA.  **Prazos para detentoras:**  - **05/05/2025**   - Nessa data, todas as instituições detentoras de conta deverão realizar a atualização v2.1.0 da API Pagamentos automáticos no Diretório de participantes. - **05/05/2025 – 15/05/2025**   - A partir de 05/05/2025, as instituições deverão realizar a segmentação das *FamilyTypes* por produto e terão até 15/05/2025 para realizar essa alteração. Durante esse prazo, não será considerada desconforme a instituição que não realizar atualização no diretório.   - Recomendamos que a atualização do cadastro de *FamilyTypes* ocorra em conjunto com a atualização da v2.1.0 da API Pagamentos automáticos no Diretório de participantes.  **Prazos para iniciadoras:**  - **05/05/2025 – 15/06/2025**   - Instituições iniciadoras devem realizar o processo de *discovery* referente às novas *FamilyTypes* no Diretório até 15/06/2025, de modo a ofertar a experiência correta aos usuários.   **Esse informa revoga o Informa #567 (*“Utilização de FamilyType para publicação da API de Pagamentos automáticos (Transferências Inteligentes)"*, enviado em 18/04/2024).**      Para maiores informações, sugerimos acessar os links de documentação abaixo: |
