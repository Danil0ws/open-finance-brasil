# [Open Finance] Informa #747

Disponibilização da versão beta.1 do motor de conformidade para API Empréstimos Conforme compartilhado no Informa #716 (“*Divulgação do cronograma de certificação e homologação do produto Portabilidade de Crédito Pessoal Clean (CPC)*”, divulgado em 28/03/2025), a **versão beta.1 do motor de conformidade para a API Empréstimos foi disponibilizada em 30/05/2025 e será utilizada para o marco de 50%** em 24/06/2025.  Mais detalhes sobre os testes podem ser consultados na página de plano de testes desta API. |

 Dados do cliente - Disponibilização do motor de conformidade e esclarecimento sobre a versão *patch*da API Dados cadastrais (v2.2.1) Informamos que a disponibilização do motor de conformidade da API Dados cadastrais v2.2.1 ocorreu em 02/06/2025 e, conforme comunicado no Informa #714 (“*Dados do cliente - Lançamento da versão patch da API Dados cadastrais (2.2.1)*”, de 25/03/2025), as instituições deverão atualizar a versão dessa API no Diretório até 23/06/2025.    Ainda em referência ao Informa #714, em 24/03/2025, foi publicada a versão 2.2.1 da API Dados cadastrais. Um esclarecimento sobre as propostas contempladas por esse versionamento está descrito abaixo:   - **PDC-421**: Propõe a realocação da Tabela Descritiva de Possibilidades de Retorno da página “Orientações – [DC] Dados cadastrais” para a página de “Informações Gerais – [DC] Dados cadastrais”.   - Neste momento, não há inclusão de testes específicos relativos à tabela supracitada. - **PDC-426:** Propõe a remoção dos atributos ***minLength* e*maxLength***do campo *economicActivities.code,* bem como a alteração da descrição.   - Não há impacto no plano de testes do motor de conformidade. Para a validação do retorno do campo, deve-se considerar somente o*pattern* da especificação, que já limita o tamanho mínimo e máximo.   Destacamos que, para esse versionamento, **as instituições necessitam apenas atualizar o *endpoint*relativo a essa API no Diretório para a versão atual** e, assim, estarão em conformidade com a especificação.    Adicionalmente, **reforçamos que não será necessária recertificação**. Instituições que realizarem alterações em suas implementações deverão realizar testes no motor de conformidade antes da publicação em produção.    Em caso de dúvidas ou sugestões, solicitamos a abertura de ticket através do Service Desk. |

 LEMBRETE - Marco de 40% para a API Portabilidade de crédito Conforme comunicado no Informa #716 (“*Divulgação do cronograma de certificação e homologação do produto Portabilidade de Crédito Pessoal Clean (CPC)*”, divulgado em 28/03/2025), em 03/06/2025, ocorreu o marco de 40% para a API Portabilidade de crédito v1.0.0.  Para este marco foi utilizada a versão beta.2 do motor de conformidade, cujos detalhes sobre os testes podem ser consultados na página de plano de testes desta API e no Informa #744 (“*LEMBRETE - Disponibilização da versão beta.2 do motor de conformidade e marco de 40% para API Portabilidade de crédito*”, divulgado em 23/05/2025). |

 Atualização sobre a exclusão de clients na FVP e distinção entre *software statements* Informamos que há uma atualização nas orientações relacionadas à exclusão de clientId na Ferramenta de Validação em Produção (FVP), considerando a diferenciação entre o *software statement* padrão e o novo *software statement* para a execução dos testes de longa duração.    Conforme comunicado no Informa #668 (“*Rotina de deleção de clients pendentes na FVP Manual*”, enviado em 03/12/2024), é responsabilidade da instituição realizar a checagem diária e a exclusão de eventuais *clients* remanescentes de execuções anteriores das FVPs. Entretanto, com a introdução do novo *software statement*para testes de longa duração, aplicam-se as seguintes diretrizes:   - ***Software statements* padrão (atuais)**: É mantida a necessidade da checagem diária e deleção dos *clients* remanescentes associados aos seguintes SSIDs:   - bcc3ba64-faf5-456c-a162-8fef7ee67170;   - bc97b8f0-cae0-4f2f-9978-d93f0e56a833;   - 70ee2970-038b-44d6-9300-d3af3a890154. - **Novo *software statement***: O *client* não deverá ser deletado, uma vez que o mesmo clientId será usado em novos testes SSID:   - 44ffd907-2318-496b-ad91-07bbb0a836da.   Reforçamos que, para o *software statement* padrão, mantem-se a sugestão de realizar a exclusão preferencialmente entre **22h e 6h**, a fim de evitar interferências na execução dos testes conduzidos pela Associação Open Finance.    Em caso de dúvidas, sugerimos consultar o item 5 do **Guia de Operação da Ferramenta de Validação em Produção**, que contém a relação dos *clients* de teste e as instruções detalhadas. |
