# [Open Finance] Informa #645

Lançamento da versão *minor* (v3.1.0) da API Consentimento **Especificações**  Informamos que a área do desenvolvedor do Portal do Open Finance Brasil foi atualizada, em 18/10/2024, com a documentação da versão *minor* da API Consentimento (v3.1.0).    A documentação da API contemplou as seguintes alterações:   - Alteração da descrição dos campos code, title e detail do código de erro 422 e adição de dois novos *status* de erro ao campo code - Adição de dois novos cenários para o código HTTP 422 na tabela "Mapeamento de mensagens retornadas pela API Consentimento” da página “Orientações - [DC] Consentimento” - Alteração da descrição do campo expirationDatetime - Adição do status ERRO\_NAO\_MAPEADO aos campos code, title e detail   **Cronograma**  Informamos que o cronograma da API Consentimento (v3.1.0) foi aprovado conforme abaixo:       A imagem anexada é uma tabela que apresenta o cronograma de atividades para a API Consentimento 3.1.0, com prazos de implementação entre outubro e novembro de 2024. A tabela tem duas colunas principais: a primeira descreve as atividades a serem realizadas, e a segunda apresenta as datas correspondentes a cada atividade.  Atividades e cronograma:  Publicação da versão 3.1.0 – Está marcada para o dia 18/10/2024 (representada por um triângulo). Atualização do mock bank e testes contra o motor – O período para esta atividade vai de 21/10/2024 a 04/11/2024 (representado por uma barra horizontal).  Lançamento da v2.0.0 (estável) e flexibilização do período de convivência da API Vínculo de dispositivo **Publicação da especificação**  Informamos que a área do desenvolvedor do Portal Open Finance Brasil foi atualizada no dia 18/10/2024 com a documentação da v2.0.0 (estável) da API Vínculo de dispositivo.    Dentre as alterações, destacamos:   - Ajuste da descrição do *endpoint* “POST /consents/{consentId}/authorise” - Ajuste na restrição do campo “/data/expirationDateTime” nos *responses* de sucesso dos *endpoints* “POST /enrollments” e “GET /enrollments/{enrollmentId}” - Adição de novo *header* no *endpoint* “POST /consents/{consentId}/authorise”   - **As ITPs e instituições detentoras de conta deverão estar adequadas e enviando o header, em casos de transações por NFC, até 31/01/2025**  Para acessar todas as alterações, sugerimos consultar o *changelog* entre as versões 2.0.0 e 2.0.0-rc.1.     **Período de convivência**  Adicionalmente, informamos que o período de convivência entre as versões 1.3.1 e 2.0.0 da API Vínculo de dispositivo será flexibilizado para as instituições que já dispõem de operação na Jornada sem redirecionamento (com contrato bilateral).  - Dessa forma, ambas as versões poderão coexistir durante o período de piloto, que se inicia em 14/11/2024 e estende-se até 27/02/2025 às 23:59, de acordo com o Informa #610 (“Divulgação do cronograma de implementação da jornada sem redirecionamento”, publicado no dia 29/07/2024)   Reforçamos que a remoção da API do Diretório deverá ocorrer em qualquer horário do dia 28/02/2025 (não poderá haver chamadas durante esse dia).    As instituições que já publicaram a versão 1.3.1 da API Vínculo de dispositivo precisarão reexecutar os módulos de teste que sofreram ajustes e os novos módulos para fim de certificação na v2.0.0.     Em complemento, informamos que as datas de início do piloto e o *go live* se mantêm conforme comunicado no Informa #610.
