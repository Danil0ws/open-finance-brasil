# [Open Finance] Informa #905

Orientações sobre o Campo "idConciliacaoRecebedor" na Liquidação de Pagamentos Recorrentes do Pix Automático via Open Finance |

 A Associação Open Finance Brasil gostaria de reforçar as orientações direcionadas às instituições detentoras de conta quanto à operacionalização do campo “idConciliacaoRecebedor” na mensagem pacs.008, no contexto do processo de liquidação de pagamentos recorrentes de Pix Automático.  Foi identificado um volume expressivo de rejeições com o código de erro "CH16" durante o processo de liquidação dos pagamentos recorrentes do Pix Automático. Trata-se de um erro retornado pelo SPI, decorrente de comportamentos inadequados por parte das instituições detentoras no envio da mensagem de liquidação.    Para a correta execução da operação, as instituições detentoras de conta devem observar os seguintes requisitos nas liquidações de pagamentos recorrentes provenientes do Pix Automático do Open Finance:     1. Incluir obrigatoriamente o campo “cnpjIniciadorPagamento” na mensagem pacs.008;   2. Não realizar a criação de recorrência por meio da mensagem pain.012;   3. Não preencher/enviar o campo “idConciliacaoRecebedor”.    Cabe esclarecer que, a partir da versão 5.11.1 do catálogo de mensagens, o campo “idConciliacaoRecebedor” passou a ser opcional. Essa alteração contempla os cenários de transações originadas via Open Finance nos quais não há estabelecimento de recorrência entre o PSP Recebedor e o PSP Pagador (como nas jornadas 2 e 3 do arranjo), não havendo, portanto, valor aplicável para esse campo.     Com a adoção dos ajustes indicados acima, as instituições detentoras deverão estar aptas a liquidar corretamente os pagamentos de Pix Automático originados via Open Finance. |

 Cadastro de endpoints de Dados Abertos no Diretório Sandbox |

 Informamos que os testes de CNPJ alfanumérico, em desenvolvimento conforme cronograma previsto no Informa #904 (CNPJ Alfanumérico | Testes em Ambiente de Sandbox - Open Finance Brasil ), utilizarão os endpoints de recursos cadastrados no Diretório Sandbox,***incluindo aqueles relacionados às APIs de Dados Abertos***.    Nesse sentido, reforçamos que os endpoints de Dados Abertos cadastrados no ambiente Sandbox devem ser distintos daqueles cadastrados no Diretório de Produção, uma vez que os testes exigirão a disponibilização de dados específicos para validação dos cenários com CNPJ alfanumérico. |
