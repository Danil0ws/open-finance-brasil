# [Open Finance] Informa #907

Orientações sobre o tratamento de Zeros à Esquerda em Números de Conta no SPI |

 Foi identificado que, a partir da versão 5.12.1 do catálogo de mensagens, o SPI passou a considerar os campos "contaUsuarioPagador" e "contaUsuarioRecebedor" como Text. Tal mudança trouxe dúvida com relação ao preenchimento de zeros a esquerda em transações iniciadas por inserção manual, uma vez que o usuário pagador pouco conhece sobre os zeros a esquerda na conta recebedora. A dúvida se sustenta pelo fato de que para Text, os valores "0001" e "1" são diferentes, o que não é verdade quando temos o tipo Numeric, onde "0001" e "1" são numericamente iguais.  Sobre esse tema, foi solicitado esclarecimento ao Banco Central, que orientou que as instituições detentoras de conta devem **desconsiderar** os zeros à esquerda nos números de conta do pagador e do recebedor. Em outras palavras, os detentores de conta devem considerar as contas "0001" e "1" como iguais, mesmo sendo do tipo Text.    **Exemplo Prático:**  As representações abaixo referem-se à mesma conta e devem ser tratadas como equivalentes pelas ITP e PSP: |

 Lembrete dos marcos de migração durante o período de convivência da API Pagamentos v5.0.0 |

 Reforçamos às Instituições Iniciadoras de Transação de Pagamento (ITPs) a obrigatoriedade do cumprimento dos marcos estabelecidos para o período de convivência entre as versões v4.0.1 e v5.0.0 da API Pagamentos, compreendido entre 21/05/2026 e 20/08/2026, conforme já comunicado por meio do*[Informa 896](https://us5.campaign-archive.com/?u=49f5ff8910ce85bdb1d9a7864&id=4432150172).*  Durante esse período, as ITPs deverão promover a migração gradual de suas chamadas para a API Pagamentos v5.0.0, observando os seguintes marcos mínimos:   - Até 10/06/2026: 10% das chamadas;  - Até 10/07/2026: 50% das chamadas;  - Até 10/08/2026: 100% das chamadas.   Os marcos têm como objetivo promover uma adoção gradual da nova versão da API e garantir uma transição segura e ordenada antes do encerramento do período de convivência.  As instituições que não atingirem sucesso nos marcos serão notificadas via tickets do Service Desk.     **Retrocompatibilidade**  As informações de retrocompatibilidade entre as versões v4.0.1 e v5.0.0 da API Pagamentos estão disponíveis na Área do Desenvolvedor e podem ser consultadas por meio dos links disponíveis abaixo. |

 Abertura Indevida de Tickets – API Contas |

 Comunicamos que possíveis tickets abertos para as instituições referente a obrigatoriedade de implementação do endpoint */accounts/{accountId}/reserved-balances* para API Contas, **deverão ser desconsiderados para as instituições que não possuem esse produto disponível**, visto que esse endpoint é opcional a depender da disponibilidade do produto “Cofrinho” em portifólio.  Os tickets abertos de forma indevida serão encerrados até a data de 16/06/2026. |
