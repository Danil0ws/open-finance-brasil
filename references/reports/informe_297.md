# [Open Finance] Informa #297

Importante: Evolução dos testes do motor de conformidade funcional da API de Payments v2.0.0    Visando manter as datas previstas do cronograma de certificação da API de Payments v2.0.0, **pedimos reforço na execução dos testes do motor de conformidade** para que estes possam atingir a maturidade, **especialmente os seguintes módulos obrigatórios**:   - api-qrdn-good-proxy-test - pixscheduling-patch-iniciadora - contenttype-jwt-refreshtoken - pixscheduling-patch-unhappy - pixscheduling-patch-detentora - api-idempotency-test    Alguns dos módulos do plano foram corrigidos nos últimos dias e, por isso, é necessário criar um novo plano para garantir que estejam executando com a versão mais atualizada.     Caso encontrem dificuldade ou queiram questionar o comportamento de algum teste, pedimos que abram um *issue* no Gitlab o mais breve possível.     **Testes condicionais**  Adicionalmente, esclarecemos que os testes de temporização e múltiplas alçadas são condicionais, ou seja:  - **Para instituições que tenham a respectiva funcionalidade: a execução é obrigatória** - Para as instituições que não tenham a funcionalidade: pedimos que pulem os respectivos testes. Como o controle será feito pelas execuções dos testes, a execução fará com que sua instituição seja contabilizada na expectativa de sucesso.    Os módulos condicionais são os seguintes:  - Temporização:   - api-temporization-conditional   - api-canc-temporization-conditional - Múltiplas alçadas:   - api-multiple-consents-conditional   - api-multiple-consents-canc-detentora-conditional   - api-multiple-consents-no-funds-conditional   - api-multiple-consents-canc-iniciadora-conditional |
